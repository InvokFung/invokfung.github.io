e:T2855,A single EC2 in a single AZ is a single point of failure. The third post in the series puts the compute from Post 02 into the network from Post 01 and turns it into a system that survives an AZ outage and a traffic spike without human intervention. This is the textbook "3-tier" shape — load balancer in front, Auto Scaling Group across AZs, optional managed data behind. The patterns here form the spine of nearly every classical AWS workload.

> Series map: 00 Foundations → 01 Network First → 02 Compute & Storage → 03 Scale & Survive (this post) → 04 Managed Data → 05 Serverless & Events → 06 Workflow Orchestration → 07 Observability & Security → 08 IaC.

Learning Outcome

- Pick between ALB, NLB, GLB, and the legacy CLB.- Configure target groups with sane health checks.- Build an Auto Scaling Group across multiple AZs.- Write scaling policies: target tracking, step, scheduled.- Apply the "warm pool" + "instance refresh" pattern for safe rollouts.- Combine ALB + ASG + private subnets into the textbook 3-tier reference architecture.

Chapter 1 — The load balancer family

| LB | Layer | Protocols | When ||----|-------|-----------|------|| Application LB (ALB) | 7 | HTTP, HTTPS, WebSocket, gRPC | web APIs, microservices, host/path routing || Network LB (NLB) | 4 | TCP, UDP, TLS | extreme throughput, static IP, non-HTTP || Gateway LB (GLB) | 3 | IP via GENEVE | inserting 3rd-party network appliances || Classic LB (CLB) | 4 + 7 (legacy) | HTTP, TCP | only existing deployments |

Most workloads use ALB. Reach for NLB when you need raw TCP, sub-millisecond latency, or a static IP that doesn't change. GLB is niche (firewall/IDS vendors). CLB is deprecated for new use.

ALB headline features

- Host-based routing —  → service A,  → service B.- Path-based routing —  → service A,  → service B.- Header / query-param matching in listener rules.- WebSocket and gRPC support.- TLS termination with certs from ACM.- AWS WAF integration.- Cognito / OIDC authentication at the listener.- Sticky sessions via cookies.

NLB headline features

- Static per-AZ IP (or your own Elastic IPs).- Millions of requests/sec with sub-millisecond added latency.- Preserves the client source IP at the backend.- Supports the  protocol for backends that want the original peer IP.

Chapter 2 — Target groups

A target group is a registered list of "things that can serve traffic". A listener forwards based on rules to one or more target groups.

Target types:- instance — by EC2 instance ID- ip — for ECS tasks, on-prem hosts via Direct Connect- lambda — invoke a Lambda per request (ALB only)- alb — chain an ALB behind an NLB (advanced)

Health checks (the make-or-break setting)

| Setting | Reasonable default ||---------|---------------------|| Protocol | HTTP / HTTPS || Path |  (your app implements) || Interval | 15-30 sec || Timeout | 5 sec || Healthy threshold | 2 || Unhealthy threshold | 2-3 |

Watch out: an overly aggressive check (1 second, 1 failure → unhealthy) marks healthy targets bad during minor blips. An overly relaxed check (60 seconds, 5 failures) lets bad targets serve traffic for minutes.

Three common health-check mistakes

1. The  endpoint also checks a downstream DB → a single DB hiccup marks every target unhealthy → outage. Make  a shallow liveness check; add  for dependency health.2. The endpoint requires auth. The LB has no credentials → 401 → all targets appear unhealthy.3. The endpoint runs an expensive query. ALB poll × target count multiplies the load.

Chapter 3 — Listeners and routing rules

Common patterns:

- HTTP → HTTPS redirect — a port 80 listener with a single redirect rule to 443.- Canary — header/cookie-based routing to a small target group running a new version.- Maintenance page — fixed-response rule returning a static 503 + HTML.- Weighted target groups — split a percentage of traffic for blue/green.

Chapter 4 — Auto Scaling Group (ASG)

An ASG maintains a fleet of EC2 instances at a target capacity, replaces unhealthy ones automatically, and scales up/down based on policies.

Anatomy

- Launch template — AMI, instance type, key, SGs, user data. (Replaces older "launch configuration".)- Min / Desired / Max — capacity bounds.- VPC zone identifier — list of subnets (one per AZ).- Health-check type —  (instance status) or  (target-group health). Always pick  if the ASG is behind a load balancer.- Target groups — the ASG registers / deregisters instances automatically as they come and go.

A minimal ASG

runs on first boot — install your app, fetch config, register with discovery.

Chapter 5 — Scaling policies

Target tracking (start here)

Pick a metric and a target; AWS adds/removes instances to keep the metric there.

- "Average CPU = 50%" → scale out when > 50, in when < 50.- "ALB requests per target = 200" → scale to meet load.

Step scaling

Trigger at thresholds; add/remove a configurable count per step. Use when target tracking can't express the logic — e.g., asymmetric scale-out vs scale-in speeds.

Scheduled

Predictable patterns deserve scheduled scaling — flash sale, market open, weekday morning ramp.

Trick: schedule warm-up 15 minutes before a known spike. EC2 + ASG instances take 1-3 minutes from request to "in service".

Chapter 6 — Cooldowns, warm pools, instance refresh

Cooldown

A waiting period after a scaling action before evaluating again — prevents oscillation when metrics dip slightly post-action.

Warm pool

A pool of pre-initialised but stopped instances. When the ASG needs to scale, it starts (rather than provisions) one — seconds vs minutes. Cost: EBS storage of the warm instances.

Instance refresh

When you publish a new launch-template version (new AMI, new user-data),  rolls existing instances out in batches.

Pair with ALB weighted target groups or canary listener rules for safe rollouts.

Chapter 7 — The textbook 3-tier reference

Tier rules:- ALB lives in public subnets across ≥ 2 AZs.- App tier lives in private subnets across the same AZs.- DB tier lives in isolated subnets, accessible only from the app SG.- Each tier's security group only accepts traffic from the tier above's SG.- Outbound from app tier to internet via NAT (only for pulling packages, calling external APIs).

This shape survives:- a single instance failure (ASG replaces it)- a single AZ failure (other AZs absorb traffic)- a deploy with bad code (canary catches it; instance refresh rolls back)- a traffic spike (ASG scales out)

Chapter 8 — Cost considerations

| Item | Approx (us-east-1) ||------|---------------------|| ALB | USD 16 / month base + LCU hours || NLB | USD 16 / month + NLCU || Data transfer out | USD 0.09/GB after 100 GB free || EC2 t3.micro | USD 7.50 / month at 24/7 on-demand || NAT gateway | USD 32 / month + USD 0.045 / GB processed || RDS db.t4g.micro multi-AZ | USD 25-30 / month |

A minimal 3-tier shop: ASG of 2 × t3.micro + ALB + RDS Multi-AZ + 1 NAT ≈ USD 100 / month before traffic. Per-AZ NATs add USD 32 each for HA.

Watch out: ALB LCU (Load Balancer Capacity Units) is metered on connections, requests, processed bytes, and rule evaluations. A high-traffic ALB can cost more than the EC2 behind it.

Chapter 9 — Beyond EC2 + ASG

Modern compute alternatives to consider for the app tier:

- ECS Fargate — containers without managing EC2 hosts.- EKS — Kubernetes managed control plane.- App Runner — push a container, AWS does the rest.- Lambda behind ALB — short-lived, infrequent endpoints (Post 05).

EC2 + ASG remains right when you need OS access, GPU, NVMe, or want the lowest level of abstraction. Otherwise consider going up the stack — Post 05 covers serverless, future posts cover containers.

Chapter 1 — ConfigMaps and Secrets

Terminology

- ConfigMap — a namespaced API object holding non-confidential key/value data, consumed by Pods as environment variables, command-line arguments, or files.- Projection — the act of a kubelet rendering a ConfigMap or Secret into a Pod's filesystem.- Hot reload — the application noticing a configuration change without being restarted.- Immutable object — a ConfigMap or Secret marked , which can never be updated, only replaced.

Two ways to consume it, with very different behaviour

The difference is the single most useful fact in this chapter:

| Consumption | Updates when the ConfigMap changes? ||-------------|-------------------------------------||  /  | No. Environment variables are set once at container start. Editing the ConfigMap changes nothing until the Pod is recreated. || Volume mount | Yes, eventually — the kubelet re-projects the files in place. || Volume mount with  | No. A  mount is resolved once and never refreshed. |

The propagation delay

Mounted files do not update instantly. The kubelet refreshes projected volumes on its periodic sync, using a locally cached copy of the object. The worst-case delay is therefore roughly the kubelet sync period (, default 1 minute) plus the ConfigMap/Secret cache propagation delay (watch-based by default; the TTL-based strategy defaults to another minute). In practice, budget for changes appearing within about two minutes, not immediately.

Three further caveats:

- Updates are atomic per volume. The kubelet writes a new timestamped directory and swings a symlink, so an application never reads a half-updated set of files. Watch the directory, not the file inode — many file watchers miss the symlink swap.- The application still has to do something. A file changing on disk is not a reload; something must re-read it. Either implement a watcher, or accept a restart.-  is the classic trap. It is used to drop a single file into a directory that already has other content (), and it silently opts you out of updates entirely.

> Common pitfall: "I edited the ConfigMap and nothing happened." Check which of the three consumption forms you used. If it is  or , nothing will happen. Roll the Deployment.

Secrets, and what they actually protect

A Secret looks exactly like a ConfigMap with a different  and a  convenience field.

The blunt truth

A Secret is base64-encoded, not encrypted. Base64 is an encoding, not a cipher;  prints the password, and anyone with  permission in that namespace can do it. By default the value also sits in etcd in plain text, which means an etcd backup, a stolen disk snapshot, or a compromised control-plane node exposes it.

What a Secret actually buys you over a ConfigMap:

- It is a distinct resource kind, so RBAC can be written against it separately (Post 07). This is the real benefit.- Its values are not printed by .- The kubelet stores projected Secret volumes in , so they do not touch the node's disk.- It is only distributed to nodes running a Pod that requests it.

What it does not buy you: encryption, audit of reads by the application, rotation, or safety from anyone who can  into the Pod.

Making Secrets meaningfully secret

| Layer | Mechanism | What it fixes ||-------|-----------|---------------|| Encryption at rest | API server  with /, or a KMS provider (AWS KMS, GCP KMS, Vault) | plaintext in etcd and in etcd backups || Least privilege | RBAC: no wildcard ; separate namespaces per team | who can read them || External store | External Secrets Operator or Vault Agent injector — the truth lives in AWS Secrets Manager / Vault / GCP Secret Manager and is synced or injected | rotation, central audit, no secret in Git || Direct mount | Secrets Store CSI driver — mounts secrets from an external store into the Pod as files, optionally syncing a Kubernetes Secret | the secret never needs to exist as a Kubernetes object at all || Git safety | Sealed Secrets (encrypt with a cluster public key, commit the ciphertext) or SOPS + age | committing manifests to a repository (Post 07) |

On managed Kubernetes, prefer workload identity over any stored credential: EKS IAM Roles for Service Accounts, GKE Workload Identity, AKS Workload Identity all let a Pod obtain short-lived cloud credentials from its ServiceAccount token. A secret that is never issued cannot leak.

> Watch out: enabling encryption at rest does not retroactively encrypt existing Secrets. After changing the , rewrite every Secret () so they are re-persisted through the new provider.

Chapter 3 — Storage

Terminology

- Volume — a directory available to the containers in a Pod, with a lifetime tied to the Pod.  is scratch space that vanishes with the Pod; , ,  and  are read-only data sources.- PersistentVolume (PV) — a cluster-scoped object representing a real piece of storage (an EBS volume, a Ceph RBD image, an NFS export).- PersistentVolumeClaim (PVC) — a namespaced request for storage: size, access mode, class. Pods reference PVCs, never PVs.- StorageClass — a named recipe describing how to provision a PV on demand: which provisioner, which parameters, which reclaim and binding policy.- CSI (Container Storage Interface) — the standard gRPC contract between Kubernetes and a storage vendor's driver.

The indirection exists so that a workload author can ask for "20 GiB, fast, exclusive" without knowing whether the cluster runs on AWS, on-prem Ceph, or a laptop.

Static versus dynamic provisioning

Static: an administrator creates PVs by hand and users claim them. Necessary for pre-existing storage (an NFS export, a restored snapshot). Dynamic: the user creates a PVC naming a StorageClass, and the CSI driver provisions a matching PV automatically. Dynamic is the default in every managed cloud and is what you should use unless you have a specific reason not to.

Access modes — and the mistake everyone makes

| Mode | Short | Meaning ||------|-------|---------|| ReadWriteOnce | RWO | mounted read-write by one node (several Pods on that node may share it) || ReadOnlyMany | ROX | mounted read-only by many nodes || ReadWriteMany | RWX | mounted read-write by many nodes || ReadWriteOncePod | RWOP | mounted read-write by exactly one Pod (GA in Kubernetes 1.29) |

The mistake: assuming RWX is available. It usually is not. Block storage — EBS, GCE PD, Azure Disk, most on-prem SANs — is RWO only, because a block device cannot safely be mounted read-write on two machines at once. RWX requires a file protocol: NFS, EFS, Azure Files, CephFS, Filestore. If your design has three replicas of a Deployment all writing to one shared volume, either budget for a networked filesystem (slower, more expensive, another thing to operate) or redesign so each replica owns its own volume — which is what a StatefulSet gives you.

Note also that RWO is per node, not per Pod. Two Pods of the same Deployment that happen to land on the same node can both write to one RWO volume and corrupt each other. RWOP exists precisely to prevent that.

Reclaim policy

Set on the StorageClass (inherited by dynamically provisioned PVs) or directly on a static PV:

- Delete — deleting the PVC deletes the PV and the underlying disk. The default for dynamic provisioning. Convenient; also how data gets destroyed by a careless .- Retain — the PV survives in  state, the data stays, and an administrator must manually clean up or re-bind. The correct choice for anything you would be upset to lose.- Recycle — deprecated, do not use.

> Watch out: for production databases, either use  or make sure the StorageClass's  behaviour is compensated by real, tested, off-cluster backups. "The PVC was deleted" should not be an unrecoverable event.

volumeBindingMode and the zone-mismatch bug

This setting fixes a failure that is baffling the first time you hit it.

-  — the PV is provisioned as soon as the PVC is created, before any Pod exists. In a multi-zone cluster the provisioner has to guess a zone. If the scheduler later places the Pod in a different zone, the Pod cannot mount the volume and stays  forever with a  event. Zonal block storage cannot cross zones.-  — provisioning is deferred until a Pod that uses the PVC is scheduled. The scheduler picks a node first, considering all its normal constraints, and then the volume is created in that node's zone.

Use  on every zonal block-storage class. It is the default on modern managed clusters for exactly this reason.

CSI in one paragraph

Every storage integration is now an out-of-tree CSI driver: a controller Deployment that handles create/delete/attach and a node DaemonSet that handles mount/unmount, both speaking a standard gRPC interface. The in-tree cloud provider volume plugins have been migrated to CSI and removed. Practical consequences: driver features arrive on the vendor's schedule rather than Kubernetes releases; snapshots (, ), cloning, expansion (, then edit the PVC's requested size) and topology awareness are all standard CSI capabilities you can rely on if the driver advertises them.

Chapter 5 — DaemonSets, Jobs and CronJobs

DaemonSet

Runs exactly one Pod per node (optionally a filtered subset), and automatically adds a Pod when a node joins the cluster. This is the right shape for anything that is a property of the node rather than of the application: log collectors, metrics exporters (), CNI agents, CSI node plugins, security agents.

Without the , a DaemonSet skips tainted nodes — usually the opposite of what a node agent wants. Taints and tolerations are covered in Post 06.

Job

Runs Pods until a specified number complete successfully, then stops.

-  +  express a work queue or a fixed fan-out. With , each Pod knows which slice of work is its own — the cleanest way to shard a batch job without an external queue.-  counts Pod failures, with exponential back-off between retries (10s, 20s, 40s, capped). Set it deliberately:  on a job that fails deterministically wastes six retries and about ten minutes of back-off (10 + 20 + 40 + 80 + 160 + 320 s = 630 s).-  is the difference between a tidy cluster and 4,000  Pods.- The Pod-level  must be  or .

> Trick: a Job with a sidecar used to hang forever, because the Job only completes when all containers exit and the sidecar never did. Use a native sidecar ( with , stable since 1.33 — Post 04): Kubernetes terminates it automatically once the main container finishes.

CronJob

Creates a Job on a schedule.

matters more than it looks:

- Allow (default) — a run that overruns its interval simply overlaps with the next one. Fine for idempotent work, catastrophic for a job that takes a lock or writes a shared file.- Forbid — skip the new run if the previous one is still going. The safe default for most reporting and maintenance jobs.- Replace — kill the running Job and start a fresh one.

The missed-schedule trap

The CronJob controller does not have perfect memory. When it wakes up, it counts the schedules it missed since it last ran. If it finds more than 100 missed schedules, it gives up entirely, schedules nothing, and records an event saying so — the CronJob then silently never fires again until it is edited or recreated. This happens after a long control-plane outage, after restoring an old cluster backup, or after a CronJob is created with a schedule in the past.

interacts with this: if set, the controller only counts misses within that window, which keeps the count small and avoids the lockout — but it also means a run more than that many seconds late is dropped rather than started. Setting it to a value shorter than the controller's own check interval can cause runs to be missed altogether.

> Watch out: always alert on "expected CronJob has not produced a successful Job in N intervals". Do not alert on the CronJob object being healthy — it looks perfectly healthy while firing nothing at all.

Chapter 7 — Should the database be on Kubernetes at all?

The honest answer is "sometimes", and the reasoning matters more than the verdict.

The case against

- The failure modes are unfamiliar. A node drain, a spot-instance reclaim, a memory limit hit, an eviction under disk pressure, a CNI hiccup — each is routine for a stateless service and each is a potential data event for a database.- You are now operating two hard systems. Kubernetes upgrades every few months; the database has its own upgrade path. The intersection is where the incidents live.- Managed services are genuinely good. RDS, Aurora, Cloud SQL, Atlas and their peers give you backups, PITR, failover, patching and a support contract for a price that is usually less than the engineer-time you would spend replicating them badly.- Storage performance is a layer deeper. Network-attached block storage under a CSI driver under a container runtime has more moving parts and more tail latency than a local NVMe device.

The case for

- You already run Kubernetes for everything else, and the operational uniformity — same deploy pipeline, same secrets, same observability, same RBAC — is worth real money.- On-prem, sovereign or air-gapped requirements rule out managed services entirely.- A mature operator exists for your database. This is the pivotal question. CloudNativePG for Postgres, Strimzi for Kafka, the MongoDB and Percona operators, Vitess for MySQL — these encode failover, backup and upgrade as controllers. Running a database on Kubernetes with a mature operator is a different activity from running one with a hand-written StatefulSet.- Many identical database instances. Per-tenant or per-environment databases are exactly where declarative provisioning pays off.

A decision rule

| Situation | Reasonable call ||-----------|-----------------|| Managed service available, no sovereignty constraint, small team | Use the managed service. || Already deep in Kubernetes, mature operator exists, platform team on call | On Kubernetes, via the operator. || On-prem or air-gapped | On Kubernetes — it is likely the best option available || Small dataset, low QPS, one instance | plain VM or managed; the cluster adds cost without benefit || Hand-written StatefulSet, no operator, no runbook, production data | Do not. |

For a fuller treatment of this exact trade-off in one ecosystem — operator choice, production checklist, cost and compliance — see , which covers the same decision for MongoDB with the concrete numbers and the operator landscape spelled out.

Whatever you choose, the non-negotiables are the same: tested restores (not just backups), storage with a  reclaim policy or an equivalent guard, a PodDisruptionBudget so a node drain cannot take quorum (Post 06), anti-affinity so replicas are not co-located, and monitoring that alerts on replication lag rather than on Pod count.

Chapter 1 — The problem Kubernetes solves (and when you do not need it)

Terminology

- Orchestrator — a system that decides which container runs where, restarts it when it dies, and keeps its identity on the network stable while the underlying process moves.- Desired state — a declaration of what the cluster should look like, stored in the API server. Actual state — what is really running, as reported by the nodes.- Reconciliation — the continuous work of shrinking the gap between the two.- Controller — a process whose entire job is one reconciliation loop for one kind of object.- Node — a machine that runs workloads. Control plane — the components that store desired state and drive reconciliation.

What breaks at fleet scale

Compose (Post 02) works beautifully on a single host and stops working the moment you need any of the following:

| Need | Single host with Compose | Kubernetes ||------|--------------------------|------------|| Survive a host dying | you notice, you fix it | scheduler places replacements on surviving nodes || Run 40 replicas across 6 machines | write your own placement | scheduler does bin-packing || Roll out a new version with no downtime | scripted, bespoke, fragile | built-in rolling update with health gating || Stable address for a moving process | hardcode IPs or add Consul | Service + cluster DNS || Express "3 of these, always" | none | a single declarative object |

The common thread is convergence. Every one of those is "keep reality matching a description", which is exactly the loop Kubernetes implements once and reuses for everything.

When you do not need Kubernetes

This deserves to be said plainly, because the cost of Kubernetes is real: a control plane to run or pay for, a YAML surface area to learn, an upgrade treadmill roughly every four months, and an on-call rotation that now has to understand a distributed system underneath the application.

Do not reach for Kubernetes when:

- You run one or two services on one or two machines and a few minutes of downtime is acceptable. Compose plus a systemd unit and a restart policy is genuinely simpler and genuinely reliable.- Your workload is bursty and stateless — a managed serverless or PaaS runtime (Cloud Run, Fargate, App Runner, Fly, Render) removes the entire operational tier.- You have no platform owner. Kubernetes without someone responsible for it degrades into an unpatched cluster running a version nobody dares upgrade.- The team is three engineers shipping a product. The orchestration you save is smaller than the orchestration you acquire.

Reach for Kubernetes when you have many services, more than one team deploying, an existing cluster to piggyback on, an on-prem or sovereign requirement, or a genuine need for the ecosystem (operators, service mesh, policy engines) built on its API.

> Watch out: "we might need to scale later" is not a reason to adopt Kubernetes today. Migrating a containerised app onto Kubernetes later is a bounded, well-trodden project. Running a cluster you do not need for two years is not.

Kubernetes talks to runtimes over the CRI. Docker Engine never implemented CRI natively; a shim called  translated, and that shim was removed from the kubelet in Kubernetes 1.24 (2022). That is the whole of the "Kubernetes deprecates Docker" story, and it changes nothing about your workflow:  produces OCI images, and containerd — which Docker itself uses underneath — runs them identically.

Chapter 5 — Pods, ReplicaSets and Deployments

Why the Pod, not the container

A Pod is one or more containers that are scheduled together, share a network namespace and an IP address, can share volumes, and live and die as a unit. It is the smallest thing Kubernetes schedules.

The reason for the extra layer is that some containers are genuinely useless alone. A log shipper that tails  must be on the same filesystem as the app. A proxy that terminates mTLS for the app must be on the same network stack as the app. Making the group the schedulable unit means those helpers can be separate images with separate lifecycles and still be guaranteed co-location.

What is shared

- Network namespace — every container in the Pod sees the same interfaces and the same IP. They reach each other over , and they must not bind the same port. This is the most common Pod authoring bug: two containers both listening on 8080.- IPC namespace and hostname.- Volumes — declared at Pod level, mounted independently in each container.

Not shared by default: the filesystem (each container keeps its own image root) and the PID namespace (opt in with ).

Init containers

Init containers run to completion, in order, before any app container starts. If one fails, the kubelet restarts it (subject to the Pod restart policy) and the app containers never start.

Use them for schema migrations, waiting on a dependency, fetching config into a shared volume, or setting kernel parameters in a privileged container so the app container needs no privileges.

Sidecars — including the native kind

Historically a "sidecar" was just a second entry in , and it had two well-known defects: it could start after the app container needed it, and in a Job it would keep running forever after the main container exited, so the Job never completed.

Kubernetes solved this by giving init containers a , which turns them into native sidecars: they start in init order (so before the app), they keep running alongside it, and they are terminated automatically after the app containers exit. The feature was alpha in 1.28, beta and on by default in 1.29, and graduated to stable in Kubernetes 1.33.

> Trick: if a Job of yours has ever hung at "1 of 2 containers still running", the native sidecar is the fix. On clusters older than 1.29, fall back to having the main container write a sentinel file that the sidecar watches for and exits on.

You almost never write a bare Pod

A Pod on its own is not rescheduled if its node dies. Write a Deployment, StatefulSet, DaemonSet, or Job — all of which manage Pods for you. Bare Pods are for debugging ().

ReplicaSet

A ReplicaSet has exactly one job: ensure N Pods matching this selector exist. It counts, and it creates or deletes to close the gap. You rarely write one directly.

Deployment

A Deployment manages ReplicaSets to provide versioned, controlled rollouts. Change the Pod template and the Deployment controller creates a new ReplicaSet, scales it up while scaling the old one down, and keeps the old one around at zero replicas so you can roll back.

How kube-proxy implements it

A Service IP is not owned by any interface — nothing is listening on it. kube-proxy watches Services and EndpointSlices and programs the node's networking so that packets addressed to the virtual IP are rewritten to a real Pod IP:

- iptables mode (long-standing default) — NAT rules with probabilistic jumps. Simple and robust, but rule count grows with Service × endpoint count, so very large clusters see slow reprogramming.- IPVS mode — kernel load balancing with hash tables: better at scale, real scheduling algorithms.- nftables mode — the modern replacement for the iptables backend, fixing its scaling behaviour; the direction of travel.- eBPF datapaths (Cilium and friends) can replace kube-proxy entirely.

The decision is made per connection, in the kernel, on the client's node — no hop through a central box. It is also L4 only, so long-lived HTTP/2 or gRPC connections pin to one backend and will not rebalance. For L7 balancing you need an Ingress, a Gateway, or a mesh (Post 07).

Why network before compute

A tempting shortcut is to "just launch an EC2" and figure out the network later. The cost: every later change (adding a database, fronting with a load balancer, going multi-AZ, locking down for security review) becomes a re-architecture. Network-first means picking a small set of decisions once and reusing them for the next decade.

The decisions:- Which region.- VPC CIDR range (which private IPs you'll own).- Subnet layout (how many AZs, public/private/isolated).- Internet egress path (IGW + NAT or VPC endpoints).- Security group baseline (who can talk to whom).

Chapter 2 — The 3-AZ subnet layout

Three reasons this shape is the industry default:

1. Failure isolation. An AZ outage takes down at most a third of capacity. Combined with a load balancer (Post 03), the service stays up.2. Blast radius for security. Chapter 5 — Security groups (your everyday firewall)

A security group is stateful: if a request matches an outbound rule, the reply is automatically allowed (and vice versa). You only configure one direction, not both.

Default behaviour: no inbound, all outbound.

Rules contain:- Protocol (TCP / UDP / ICMP / all)- Port range- Source / destination (CIDR, another security group, or a prefix list)

Reference SGs by ID, not by IP

When both ends are AWS resources, reference the other side's security group rather than its IP range. As IPs change (autoscaling, recreation), the SG reference stays correct.

Chapter 6 — NACLs (the backup layer)

A Network ACL is stateless and applied per subnet. Default rules allow all inbound + outbound. Custom NACLs default to deny.

NACLs are evaluated in order (rule numbers); the first match wins.

In practice most teams don't touch NACLs — security groups do all the real work. Reserve NACLs for blanket per-subnet rules (e.g., "isolated subnets reject any outbound traffic at all") or defence-in-depth against compromised SG state.

Chapter 2 — Tags lie, digests do not

A tag is a mutable pointer. Anyone with push access can move , and upstream maintainers routinely move , , and even patch tags to new builds. Two machines pulling  an hour apart can therefore run different code, with no error anywhere.

A digest is the hash of the manifest bytes.  is either the exact image you tested or a failed pull. There is no third outcome.

The rule: tags for humans, digests for machines.

| Context | Reference by ||---------|-------------|| A person reading a README or  in a tutorial | tag ||  in a Dockerfile you must rebuild identically | tag + digest || A Kubernetes manifest or Compose file in production | digest (or a tag pinned by your GitOps tooling, Post 07) || A rollback | the previous digest — tags may have moved || An audit trail ("what was running at 03:00?") | digest, recorded at deploy time |

Practical middle ground: keep readable tags in the repository and record the digest at deploy time. Kubernetes writes the resolved digest into the Pod status (), and an admission policy can require digest references outright (Post 07).

> Common pitfall:  with a moving tag means nodes keep whatever they cached first. Half the fleet runs the old bytes, half the new, and both report the same tag. Digests remove the class of bug entirely.

Chapter 4 — Vulnerability scanning without drowning

Terminology

- CVE — a public identifier for one vulnerability ().- Scanner — a tool that inventories the packages in an image and matches them against vulnerability databases.- Fixed / unfixed — whether the distribution has published a patched version yet.- VEX — a machine-readable statement that a given CVE is not exploitable in your product, so scanners can suppress it with a documented reason.

Running a scan

Registries also scan: ECR (, with the deeper Amazon Inspector integration), GHCR/Dependabot for some ecosystems, Docker Scout for Hub.

Reading the output without drowning

A first scan of a  image can report hundreds of findings. Most of them are not action items. Triage in this order:

1. Severity and fix availability first.  collapses the list to what you can actually act on today.2. Is the vulnerable component reachable? A CVE in a CLI tool your service never invokes is real but low-priority; a CVE in your TLS library is not.3. Is it in the base image or in your dependencies? Base-image CVEs are fixed by rebuilding on a newer base; dependency CVEs are fixed by bumping a lockfile.4. Suppress with a reason, never silently.  (with an expiry date and a comment) or a VEX document records why something was accepted.5. Gate on a policy you can hold to. "No CRITICAL with a fix available" is enforceable; "zero CVEs" is not, and a gate everyone bypasses protects nothing.

The base-image strategy that actually reduces CVE count

Scanning does not fix anything. What reduces findings, in order of effect:

| Action | Effect ||--------|--------|| Rebuild regularly on a fresh base | most OS-package CVEs disappear because the base was patched upstream || Ship a smaller base (slim, distroless, ) | fewer packages, fewer CVEs, less to patch — often a large drop || Remove build tooling from the runtime stage (Post 01) | compilers and headers stop counting toward your attack surface || Automate base bumps (Renovate/Dependabot on the  digest) | the pin stays current without a human remembering || Track your own dependency lockfiles | application-level CVEs, which no base change fixes |

> Trick: a weekly scheduled rebuild-and-scan of the unchanged source is one of the highest-value pipelines you can add. Your code did not change; your base image did, and so did the vulnerability database.

Chapter 5 — SBOMs, provenance, and signing

SBOM

A Software Bill of Materials lists every component in an artifact — OS packages, language dependencies, versions, licences. Two mainstream formats: SPDX (ISO standard, licence-focused) and CycloneDX (OWASP, security-focused). Either is fine; pick one and be consistent.

Why it matters: when the next widely-exploited library CVE lands, the question "are we affected, and where?" becomes a query over stored SBOMs instead of a week of archaeology. It is also increasingly a procurement and compliance requirement.

Provenance

Provenance answers how the artifact was built: which source commit, which builder, which parameters. BuildKit emits it as an in-toto attestation (), and the SLSA framework defines levels for how tamper-resistant that claim is. Provenance produced by your CI, signed by your CI's identity, is what lets a policy say "only images built by this pipeline from this repository may run".

Signing with cosign

Classic key-based signing works, but key management is the hard part. Keyless signing (Sigstore) removes the long-lived key: your CI job authenticates with an OIDC token, Fulcio issues a short-lived certificate bound to that identity, the signature is recorded in the Rekor transparency log, and the certificate expires minutes later.

> Watch out:  with no identity flags checks only that a signature exists. The security comes from asserting the expected identity and issuer. A verification step that accepts any signer is theatre.

Enforcement belongs at admission time in the cluster — an admission controller (Kyverno, Sigstore Policy Controller, Gatekeeper) that rejects Pods whose images are unsigned, unscanned, or not from an allowed registry. That is Post 07 material; the point here is that signing is only useful if something checks it.

Chapter 1 — The write-ahead log

Terminology

- WAL — the write-ahead log. Every change to a data page is described in a WAL record that is flushed to durable storage before the page itself is written.- LSN — Log Sequence Number, a monotonically increasing byte position in the WAL stream (). The universal currency of replication and recovery.- WAL segment — a WAL file, 16 MB by default.- Checkpoint — a point at which all dirty shared buffers are flushed to the data files, allowing WAL before that point to be recycled.- Full page write — the first change to a page after a checkpoint writes the entire 8 KB page into the WAL, not just the delta.

The write-ahead rule is what makes crash recovery possible: after a crash, PostgreSQL replays WAL from the last checkpoint forward, reconstructing every committed change.  returns only once the commit record is durably flushed — this is exactly the D in ACID, and it is why  is a data-loss setting, not a performance setting.

Full page writes

Operating systems and storage do not guarantee that an 8 KB page write is atomic. A crash mid-write can leave a torn page: half old, half new — a page WAL deltas cannot be applied to, because the base is corrupt.  (the default) solves this by writing a complete image of the page the first time it is modified after each checkpoint, giving recovery a known-good base to replay from.

The cost is WAL volume, and it is the reason WAL generation spikes immediately after every checkpoint. It is also the reason random-write workloads (see UUIDv4 keys in post 06) generate far more WAL than sequential ones: they touch more distinct pages, so more of them need full images.

Failover and split brain

Promotion itself is trivial:

The danger is split brain: the old primary is not actually dead — it was unreachable — and it keeps accepting writes while the new primary also accepts writes. Two divergent timelines, both containing real customer data, and no automatic way to merge them.

Automatic failover therefore requires more than a health check:

- Fencing / STONITH — make certain the old primary cannot accept writes: kill the instance, revoke its network path, or detach its storage.- Quorum — the decision to promote must be made by a majority of an odd-numbered set of observers, not by one watcher that may itself be the partitioned party.- A single write endpoint — clients must reach the primary through a VIP, a proxy, or  in a multi-host connection string, so promotion actually redirects them.

Use Patroni (with etcd/Consul/Kubernetes for consensus) or repmgr. Hand-rolled failover scripts are the classic source of split-brain incidents, and  — which can resynchronise a diverged old primary — only helps if the divergence is small and  or data checksums were enabled beforehand.

Chapter 4 — Logical replication

Streaming replication copies bytes. Logical replication decodes the WAL into row-level changes and applies them as ordinary inserts, updates and deletes on the subscriber. That makes it selective and cross-version.

What it can do that physical replication cannot: replicate a subset of tables, replicate between different major versions, replicate into a differently-indexed target, filter rows ( clauses on publications, PostgreSQL 15+) and columns (15+), and support two-way or many-to-one topologies.

What it does not do, and these bite:

- DDL is not replicated. Schema changes must be applied on both sides, subscriber first for additive changes.- Sequence values are not replicated (through PostgreSQL 18). At cutover you must advance every sequence on the subscriber manually with .- Every replicated table needs a replica identity — a primary key, or  (which makes updates and deletes far more expensive), otherwise updates and deletes cannot be applied.- Large objects are not replicated. Truncate is (11+), but only for tables in the publication.

Major-version upgrade via logical replication

This is logical replication's most valuable use, because it reduces the downtime of a major upgrade from "however long  takes" to "however long a DNS or proxy switch takes".

Chapter 5 — Connection pooling

PostgreSQL forks one operating-system process per connection. Each backend carries its own memory ( allocations, catalogue caches, prepared statement plans), typically several megabytes at rest and much more under load. Consequences:

- Establishing a connection costs a  plus catalogue loading — milliseconds, which is enormous compared to a 0.3 ms query.- Idle connections are not free; they hold memory and appear in every snapshot computation.- Throughput peaks at a fairly small number of active backends — roughly in the neighbourhood of the core count plus effective spindle count — and declines beyond it as lock contention and context switching dominate. Raising  to 2000 does not raise throughput; it lowers it.

This is why a pooler is near-mandatory for any application with more than a handful of application servers, and why serverless platforms that open a connection per request need one absolutely.

17:T7f72,Groups have one operation. Most of the algebra you already use has two: integers, polynomials and matrices can be added and multiplied, and the distributive law ties the two together. A structure with both is a ring. This post builds ring theory the same way posts 01–03 built group theory: definitions and examples, then substructures (ideals play the role of normal subgroups), quotients and a First Isomorphism Theorem. Two questions then drive the rest. Which rings behave like $\mathbb{Z}$, with unique factorisation? And how do you manufacture new fields, such as $\mathbb{C}$ or a field with 4 elements? The answer to the second, "take polynomials modulo an irreducible polynomial", is the starting point of Galois theory in post 05.

> Series map: 00 Integers, Relations & Modular Arithmetic → 01 Groups & Subgroups → 02 Cosets, Lagrange & Quotient Groups → 03 Homomorphisms, Group Actions & Sylow → 04 Rings, Ideals & Fields (this post) → 05 Field Extensions & Galois Theory.

Chapter 1 — Rings

Terminology

- Ring — a set $R$ with two operations $+$ and $\cdot$ such that:1. $(R, +)$ is an abelian group, with identity $0$ and inverses $-a$;2. multiplication is associative: $(ab)c = a(bc)$;3. there is a multiplicative identity $1$ with $1a = a1 = a$;4. the distributive laws hold: $a(b + c) = ab + ac$ and $(a + b)c = ac + bc$.- Convention. In this series every ring has a $1$ (some books call these "rings with unity" and allow rings without one). Multiplication need not be commutative.- Commutative ring — a ring with $ab = ba$ for all $a, b$.- Zero ring — $\{0\}$ with $1 = 0$. It is the only ring in which $1 = 0$ (if $1 = 0$ then $a = 1a = 0a = 0$).- Unit — an element $u$ with a two-sided inverse: $uv = vu = 1$. The units form a group $R^\times$ under multiplication.- Zero divisor — a nonzero $a$ for which some nonzero $b$ has $ab = 0$ or $ba = 0$.- Integral domain — a commutative ring with $1 \ne 0$ and no zero divisors.- Field — a commutative ring with $1 \ne 0$ in which every nonzero element is a unit.- Division ring — like a field but not necessarily commutative (the quaternions are the standard example).

Examples

| Ring | Commutative? | Units | Zero divisors? ||---|---|---|---|| $\mathbb{Z}$ | yes | $\pm 1$ | none (domain) || $\mathbb{Q}, \mathbb{R}, \mathbb{C}$ | yes | all nonzero | none (fields) || $\mathbb{Z}/n\mathbb{Z}$ | yes | classes with $\gcd(a, n) = 1$ | yes, unless $n$ is prime || $M2(\mathbb{R})$, $2\times 2$ real matrices | no | matrices with $\det \ne 0$ | yes || $\mathbb{R}[x]$, real polynomials | yes | nonzero constants | none || $\mathbb{Z}[i] = \{a + bi : a, b \in \mathbb{Z}\}$ | yes | $\pm 1, \pm i$ | none || $C[0,1]$, continuous functions, pointwise operations | yes | functions with no zero | yes |

A few of the entries, worked out:

- $\mathbb{Z}/12\mathbb{Z}$. The units are $1, 5, 7, 11$ (coprime to 12; each is its own inverse, e.g. $5 \cdot 5 = 25 \equiv 1$). Every other nonzero class is a zero divisor: $2 \cdot 6 = 12 \equiv 0$, $3 \cdot 4 \equiv 0$, $8 \cdot 3 \equiv 0$, and so on, giving $2, 3, 4, 6, 8, 9, 10$. In $\mathbb{Z}/n\mathbb{Z}$ every nonzero element is either a unit or a zero divisor: if $d = \gcd(a, n) > 1$, then $a \cdot (n/d) \equiv 0$ with $n/d \not\equiv 0$.- Matrices. $\begin{pmatrix} 1 & 0 \\ 0 & 0 \end{pmatrix}\begin{pmatrix} 0 & 0 \\ 0 & 1 \end{pmatrix} = \begin{pmatrix} 0 & 0 \\ 0 & 0 \end{pmatrix}$, although neither factor is zero.- Gaussian integers. Use the norm $N(a + bi) = a^2 + b^2 = (a+bi)(a-bi)$, which is multiplicative: $N(zw) = N(z)N(w)$. If $uv = 1$ then $N(u)N(v) = 1$ in the positive integers, so $N(u) = 1$, and $a^2 + b^2 = 1$ leaves $\pm 1, \pm i$.- Functions. Let $f$ be zero on $[0, \tfrac12]$ and $g$ zero on $[\tfrac12, 1]$, both continuous and not identically zero (for example $f(t) = \max(0, t - \tfrac12)$, $g(t) = \max(0, \tfrac12 - t)$). Then $fg = 0$.

First consequences of the axioms

For all $a, b$ in a ring:

1. $0 \cdot a = a \cdot 0 = 0$. Proof: $0a = (0 + 0)a = 0a + 0a$; subtract $0a$ from both sides.2. $(-a)b = a(-b) = -(ab)$. Proof: $ab + (-a)b = (a + (-a))b = 0b = 0$.3. $(-a)(-b) = ab$, and in particular $(-1)^2 = 1$.

Cancellation. In an integral domain, if $a \ne 0$ and $ab = ac$ then $b = c$, because $a(b - c) = 0$ forces $b - c = 0$. This is exactly what fails in $\mathbb{Z}/12\mathbb{Z}$: $2 \cdot 1 = 2 \cdot 7$ but $1 \ne 7$.

Every field is an integral domain: if $a \ne 0$ and $ab = 0$, then $b = a^{-1}ab = 0$. The converse fails ($\mathbb{Z}$), except for finite rings:

Theorem. A finite integral domain is a field.

Proof. Let $R$ be a finite domain and $a \ne 0$. The map $\mua : R \to R$, $x \mapsto ax$, is injective by cancellation. An injective map from a finite set to itself is surjective, so $ax = 1$ for some $x$. Since $R$ is commutative, $x$ is a two-sided inverse. ∎

Corollary. $\mathbb{Z}/n\mathbb{Z}$ is a field if and only if $n$ is prime. (If $n = ab$ with $1 < a, b < n$, then $a$ and $b$ are zero divisors. If $n = p$ is prime, $\mathbb{Z}/p\mathbb{Z}$ has no zero divisors because $p \mid ab$ implies $p \mid a$ or $p \mid b$, post 00; so it is a finite domain.) This field is written $\mathbb{F}p$.

Characteristic

The characteristic of a ring $R$ is the least $n \ge 1$ with $n \cdot 1 = 1 + 1 + \cdots + 1 = 0$ ($n$ terms), or $0$ if there is no such $n$. So $\operatorname{char}\mathbb{Z} = \operatorname{char}\mathbb{Q} = 0$ and $\operatorname{char}\mathbb{Z}/n\mathbb{Z} = n$.

Theorem. The characteristic of an integral domain is $0$ or a prime.

Proof. Suppose $\operatorname{char} R = n > 0$ and $n = ab$ with $1 \le a, b < n$. Then $0 = n \cdot 1 = (a \cdot 1)(b \cdot 1)$. In a domain one factor is $0$, contradicting the minimality of $n$. And $n \ne 1$ because $1 \ne 0$. ∎

> Watch out: characteristic is about $n \cdot 1$, not about the size of the ring. The infinite field $\mathbb{F}p(t)$ of rational functions over $\mathbb{F}p$ has characteristic $p$.

Chapter 2 — Homomorphisms, ideals and quotient rings

Terminology

- Subring — a subset $S \subseteq R$ containing $1$ that is closed under $+$, $-$ and $\cdot$. Example: $\mathbb{Z} \subset \mathbb{Z}[i] \subset \mathbb{C}$.- Ring homomorphism — a map $\varphi : R \to S$ with $\varphi(a + b) = \varphi(a) + \varphi(b)$, $\varphi(ab) = \varphi(a)\varphi(b)$ and $\varphi(1) = 1$.- Kernel — $\ker\varphi = \{a : \varphi(a) = 0\}$.- Ideal — an additive subgroup $I \subseteq R$ that absorbs multiplication: $r a \in I$ and $a r \in I$ for all $r \in R$, $a \in I$. (For commutative rings one condition suffices.)- Principal ideal — in a commutative ring, $(a) = aR = \{ra : r \in R\}$, the smallest ideal containing $a$. More generally $(a1, \dots, ak) = \{r1a1 + \cdots + rkak\}$.

Examples of homomorphisms: reduction $\mathbb{Z} \to \mathbb{Z}/n\mathbb{Z}$; evaluation $\mathbb{R}[x] \to \mathbb{C}$, $f \mapsto f(i)$; complex conjugation $\mathbb{C} \to \mathbb{C}$; the inclusion of a subring.

Ideals are the kernels

Theorem. The kernel of a ring homomorphism is an ideal.

Proof. It is an additive subgroup, being the kernel of a homomorphism of additive groups (post 03). If $\varphi(a) = 0$ then $\varphi(ra) = \varphi(r) \cdot 0 = 0$ and $\varphi(ar) = 0$. ∎

Ideals are to rings what normal subgroups are to groups: exactly the things you can take a quotient by. Two quick facts:

- If an ideal $I$ contains a unit $u$, then $I = R$: for any $r$, $r = (ru^{-1})u \in I$. So a proper ideal contains no units, and in particular does not contain $1$.- A commutative ring $R$ with $1 \ne 0$ is a field if and only if its only ideals are $\{0\}$ and $R$. (If $R$ is a field, any nonzero ideal contains a unit. Conversely, for $a \ne 0$, $(a) = R \ni 1$, so $ra = 1$ for some $r$.) Consequently every ring homomorphism from a field to a nonzero ring is injective: its kernel is a proper ideal (it misses 1), hence $\{0\}$.

Theorem. Every ideal of $\mathbb{Z}$ is $n\mathbb{Z} = (n)$ for a unique $n \ge 0$.

Proof. Let $I \ne \{0\}$ and let $n$ be the least positive element of $I$. For $a \in I$ divide: $a = qn + r$ with $0 \le r < n$. Then $r = a - qn \in I$, so $r = 0$ by minimality, and $a \in (n)$. ∎

In $\mathbb{Z}$, $(a, b) = (\gcd(a, b))$: for example $(4, 6) = (2)$. This is Bézout's identity from post 00 in ideal language.

Quotient rings

Let $I$ be an ideal of $R$. The additive cosets $a + I$ form an abelian group $R/I$ (post 02). Define multiplication by $(a + I)(b + I) = ab + I$.

Well defined. If $a' = a + i$ and $b' = b + j$ with $i, j \in I$, then $a'b' = ab + (aj + ib + ij)$, and the bracket lies in $I$ because $I$ absorbs multiplication. This is precisely where "ideal" (rather than just "subring") is needed. The ring axioms for $R/I$ follow from those of $R$, with $1 + I$ as identity, and $\pi : R \to R/I$, $a \mapsto a + I$, is a surjective homomorphism with kernel $I$.

Theorem (First Isomorphism Theorem for rings). If $\varphi : R \to S$ is a ring homomorphism, then $R/\ker\varphi \cong \operatorname{im}\varphi$ via $a + \ker\varphi \mapsto \varphi(a)$.

Proof. By the group version (post 03) the map $\bar\varphi$ is a well-defined isomorphism of additive groups. It is multiplicative: $\bar\varphi((a + K)(b + K)) = \bar\varphi(ab + K) = \varphi(ab) = \varphi(a)\varphi(b)$; and $\bar\varphi(1 + K) = \varphi(1) = 1$. ∎

Worked applications:

- $\mathbb{Z}[x]/(x) \cong \mathbb{Z}$. Evaluation at 0, $f \mapsto f(0)$, is surjective, and its kernel is the polynomials with zero constant term, which is $(x)$.- $\mathbb{R}[x]/(x^2 + 1) \cong \mathbb{C}$. Evaluation at $i$ is surjective ($a + bx \mapsto a + bi$). Its kernel contains $x^2 + 1$; Chapter 6 shows that $(x^2 + 1)$ is a maximal ideal, so the kernel (a proper ideal containing it) is exactly $(x^2 + 1)$.- $\mathbb{Z}[x]/(2, x) \cong \mathbb{Z}/2\mathbb{Z}$. The map $f \mapsto f(0) \bmod 2$ is surjective with kernel $\{f : f(0) \text{ even}\} = (2, x)$.- Chinese Remainder Theorem. If $\gcd(m, n) = 1$, the map $\mathbb{Z} \to \mathbb{Z}/m \times \mathbb{Z}/n$, $a \mapsto (a \bmod m, a \bmod n)$, is a surjective ring homomorphism (surjective by post 00's CRT) with kernel $(m) \cap (n) = (mn)$. So $\mathbb{Z}/mn\mathbb{Z} \cong \mathbb{Z}/m\mathbb{Z} \times \mathbb{Z}/n\mathbb{Z}$ as rings, and taking units gives $\phi(mn) = \phi(m)\phi(n)$ for Euler's function.

> Trick: the fastest way to understand $R/I$ is again to find a surjective homomorphism out of $R$ whose kernel is $I$. Evaluation maps are the usual candidates for polynomial rings.

Chapter 3 — Prime and maximal ideals

From here on, "ring" means commutative ring with $1$.

Terminology

- Prime ideal — a proper ideal $P$ such that $ab \in P$ implies $a \in P$ or $b \in P$.- Maximal ideal — a proper ideal $M$ such that no ideal lies strictly between $M$ and $R$: if $M \subseteq J \subseteq R$ then $J = M$ or $J = R$.

In $\mathbb{Z}$: $(p)$ for a prime $p$ is prime (this is Euclid's lemma) and maximal; $(0)$ is prime (because $\mathbb{Z}$ is a domain) but not maximal, since $(0) \subsetneq (2) \subsetneq \mathbb{Z}$; $(6)$ is neither, since $2 \cdot 3 \in (6)$ but $2, 3 \notin (6)$.

The two quotient theorems

Theorem. $P$ is a prime ideal of $R$ if and only if $R/P$ is an integral domain.

Proof. $R/P$ is not the zero ring exactly when $1 \notin P$, i.e. when $P$ is proper. In $R/P$, the product $(a + P)(b + P) = ab + P$ is zero exactly when $ab \in P$, and $a + P$ is zero exactly when $a \in P$. So "no zero divisors in $R/P$" says word for word "$ab \in P \Rightarrow a \in P$ or $b \in P$". ∎

Theorem. $M$ is a maximal ideal of $R$ if and only if $R/M$ is a field.

Proof. ($\Rightarrow$) Let $a + M \ne 0$, i.e. $a \notin M$. The ideal $M + (a) = \{m + ra\}$ strictly contains $M$, so by maximality it is $R$ and contains $1$: $1 = m + ra$ for some $m \in M$, $r \in R$. Then $(r + M)(a + M) = ra + M = 1 - m + M = 1 + M$, so $a + M$ is a unit. Also $1 + M \ne 0$ because $M$ is proper.

($\Leftarrow$) If $R/M$ is a field, $M$ is proper. Let $M \subsetneq J$ and pick $a \in J \setminus M$. Then $a + M$ has an inverse $r + M$, so $ra - 1 \in M \subseteq J$. Since $ra \in J$, also $1 \in J$ and $J = R$. ∎

Corollary. Every maximal ideal is prime (a field is a domain).

Examples in $\mathbb{Z}[x]$.

- $(x)$ is prime but not maximal: $\mathbb{Z}[x]/(x) \cong \mathbb{Z}$ is a domain but not a field. Indeed $(x) \subsetneq (2, x) \subsetneq \mathbb{Z}[x]$.- $(2, x)$ is maximal: $\mathbb{Z}[x]/(2, x) \cong \mathbb{Z}/2\mathbb{Z}$, a field.- $(x^2 + 1)$ is prime but not maximal: $\mathbb{Z}[x]/(x^2+1) \cong \mathbb{Z}[i]$, a domain that is not a field.

A standard existence result (it needs Zorn's lemma): every proper ideal of a ring with $1$ is contained in a maximal ideal.

Chapter 4 — Polynomial rings over a field

Let $F$ be a field. $F[x]$ is the ring of polynomials $a0 + a1x + \cdots + anx^n$ with $ai \in F$. If $an \ne 0$, the degree is $n$ and $an$ is the leading coefficient; the polynomial is monic if $an = 1$. The zero polynomial has no degree (some books use $-\infty$).

Degree, units, roots

If $R$ is a domain, the leading coefficient of $fg$ is the product of the leading coefficients, which is nonzero. Hence, for nonzero $f, g$:

$$\deg(fg) = \deg f + \deg g,$$

$R[x]$ is again a domain, and the units of $F[x]$ are the nonzero constants (a unit $f$ has $\deg f + \deg f^{-1} = 0$).

Theorem (division algorithm). For $f, g \in F[x]$ with $g \ne 0$ there are unique $q, r \in F[x]$ with $f = qg + r$ and either $r = 0$ or $\deg r < \deg g$.

Proof sketch. Existence by induction on $\deg f$: if $\deg f \ge \deg g = m$, subtract $(an/bm)\,x^{n-m}g$ to kill the leading term of $f$ and apply induction to the result. Dividing by $bm$ is where a field is used. Uniqueness: if $qg + r = q'g + r'$ then $(q - q')g = r' - r$; the right side has degree $< m$, so $q = q'$ by the degree formula, and then $r = r'$. ∎

Worked example. Divide $f = x^4 + 3x^3 - 2x + 5$ by $g = x^2 + x + 1$ in $\mathbb{Q}[x]$:

$$x^4 + 3x^3 - 2x + 5 = (x^2 + x + 1)(x^2 + 2x - 3) + (8 - x).$$

(Check: $(x^2 + x + 1)(x^2 + 2x - 3) = x^4 + 3x^3 - x - 3$, and adding $8 - x$ gives $f$.)

Factor theorem. $a$ is a root of $f$ if and only if $(x - a) \mid f$ (divide by $x - a$; the remainder is the constant $f(a)$). So a nonzero polynomial of degree $n$ over a domain has at most $n$ roots.

> Common pitfall: over a ring with zero divisors this fails. In $\mathbb{Z}/8\mathbb{Z}$, $x^2 - 1$ has four roots: $1, 3, 5, 7$ (each squares to $1$ mod 8).

F[x] is a principal ideal domain

A principal ideal domain (PID) is an integral domain in which every ideal is principal.

Theorem. If $F$ is a field, $F[x]$ is a PID.

Proof. Let $I \ne \{0\}$ be an ideal and let $g \in I$ be nonzero of least degree. For $f \in I$ write $f = qg + r$. Then $r = f - qg \in I$ and, if $r \ne 0$, $\deg r < \deg g$, contradicting minimality. So $r = 0$ and $I = (g)$. ∎

The proof is the one for $\mathbb{Z}$ with "size" replaced by "degree". As in $\mathbb{Z}$, $(f, g) = (\gcd(f, g))$, and the Euclidean algorithm computes the gcd:

$$\begin{aligned}x^6 - 1 &= x^2\,(x^4 - 1) + (x^2 - 1), \\x^4 - 1 &= (x^2 + 1)(x^2 - 1) + 0,\end{aligned}$$

so $\gcd(x^6 - 1, x^4 - 1) = x^2 - 1$.

> Watch out: $\mathbb{Z}[x]$ is not a PID, although $\mathbb{Z}$ is. Suppose $(2, x) = (h)$. Then $h \mid 2$, so $h$ is a constant $\pm 1$ or $\pm 2$. $h = \pm 1$ is impossible because $(2, x)$ is proper (its quotient is $\mathbb{Z}/2$). $h = \pm 2$ is impossible because $x \notin (2)$.

Irreducibility tests

A nonzero non-unit $f \in F[x]$ is irreducible if it is not a product of two polynomials of smaller degree. Irreducible polynomials are the "primes" of $F[x]$, and whether $f$ is irreducible depends on the field: $x^2 - 2$ is irreducible over $\mathbb{Q}$ but factors as $(x - \sqrt2)(x + \sqrt2)$ over $\mathbb{R}$; $x^2 + 1$ is irreducible over $\mathbb{R}$ but not over $\mathbb{C}$.

1. Degree 2 or 3. A polynomial of degree 2 or 3 over a field is irreducible if and only if it has no root in the field (any factorisation includes a linear factor).2. Rational root test. If $f = anx^n + \cdots + a0 \in \mathbb{Z}[x]$ and $p/q$ in lowest terms is a root, then $p \mid a0$ and $q \mid an$.3. Gauss's lemma. A polynomial in $\mathbb{Z}[x]$ that factors in $\mathbb{Q}[x]$ into factors of lower degree already factors in $\mathbb{Z}[x]$ into factors of those same degrees. So it suffices to look for integer factorisations.4. Eisenstein's criterion. Let $f = anx^n + \cdots + a0 \in \mathbb{Z}[x]$ and $p$ a prime with $p \nmid an$, $p \mid ai$ for all $i < n$, and $p^2 \nmid a0$. Then $f$ is irreducible in $\mathbb{Q}[x]$.5. Reduction mod $p$. Let $f \in \mathbb{Z}[x]$ and let $p$ be a prime not dividing the leading coefficient. If the reduction $\bar f \in \mathbb{F}p[x]$ is irreducible (of the same degree), then $f$ is irreducible in $\mathbb{Q}[x]$.

Worked examples:

- $x^3 - 2$: Eisenstein with $p = 2$. Also, the rational root test leaves only $\pm 1, \pm 2$, none of which is a root.- $x^3 + 2x + 1$: candidates $\pm 1$ give $4$ and $-2$, so no rational root; degree 3, so irreducible over $\mathbb{Q}$.- $x^5 - 4x + 2$: Eisenstein with $p = 2$ ($2 \mid -4$, $2 \mid 2$, $4 \nmid 2$). This polynomial returns in post 05.- Cyclotomic polynomial $\Phi5(x) = x^4 + x^3 + x^2 + x + 1 = (x^5 - 1)/(x - 1)$. Eisenstein does not apply directly, but $f(x)$ is irreducible exactly when $f(x+1)$ is, and$\Phi5(x + 1) = x^4 + 5x^3 + 10x^2 + 10x + 5$, which is Eisenstein at $5$.- $x^4 + 5x^3 + 3x^2 + 7x + 11$: reduce mod 2 to $x^4 + x^3 + x^2 + x + 1$, which is irreducible in $\mathbb{F}2[x]$. So the original is irreducible over $\mathbb{Q}$.

> Common pitfall: "no rational roots" proves irreducibility only in degree 2 and 3. $x^4 + 4$ has no rational root, yet $x^4 + 4 = (x^2 + 2x + 2)(x^2 - 2x + 2)$.

> Common pitfall: the reduction test only works one way. $x^2 + 1$ is irreducible over $\mathbb{Q}$, but mod 2 it is $(x + 1)^2$. A reducible reduction proves nothing; so does a failed Eisenstein check.

Chapter 5 — Unique factorisation

Terminology

In an integral domain $R$:

- $a$ divides $b$, written $a \mid b$, if $b = ac$ for some $c \in R$.- $a$ and $b$ are associates if $a = ub$ for a unit $u$ (for example $2$ and $-2$ in $\mathbb{Z}$, or $1 + i$ and $i(1+i) = -1 + i$ in $\mathbb{Z}[i]$).- A nonzero non-unit $p$ is irreducible if $p = ab$ forces $a$ or $b$ to be a unit.- A nonzero non-unit $p$ is prime if $p \mid ab$ forces $p \mid a$ or $p \mid b$ (equivalently, $(p)$ is a prime ideal).- Unique factorisation domain (UFD) — a domain in which every nonzero non-unit is a product of irreducibles, uniquely up to order and associates.- Euclidean domain — a domain with a function $N : R \setminus \{0\} \to \mathbb{Z}{\ge 0}$ such that for all $a$ and $b \ne 0$ there are $q, r$ with $a = qb + r$ and $r = 0$ or $N(r) < N(b)$.

Prime implies irreducible in any domain: if $p$ is prime and $p = ab$, then $p \mid ab$, say $p \mid a$, so $a = pc$ and $p = pcb$; cancelling gives $cb = 1$, so $b$ is a unit. The converse holds in a UFD (and so in a PID) but fails in general, which is exactly how unique factorisation breaks.

The hierarchy

$$\text{fields} \subset \text{Euclidean domains} \subset \text{PIDs} \subset \text{UFDs} \subset \text{integral domains}.$$

- Euclidean ⇒ PID: the proof that $F[x]$ is a PID works verbatim with $N$ in place of degree.- PID ⇒ UFD: a standard theorem (existence uses the fact that increasing chains of ideals in a PID stop; uniqueness uses "irreducible ⇒ prime" in a PID).- Every inclusion is strict, as the diagram's examples show.

Gaussian integers are Euclidean

Take $N(a + bi) = a^2 + b^2$. To divide $\alpha$ by $\beta$, compute $\alpha/\beta$ in $\mathbb{C}$ and round each coordinate to the nearest integer to get $q$; the rounding error has both coordinates at most $\tfrac12$, so $N(\alpha/\beta - q) \le \tfrac14 + \tfrac14 < 1$ and $r = \alpha - q\beta$ has $N(r) < N(\beta)$.

Worked example. Divide $7 + 2i$ by $2 - i$:

$$\frac{7 + 2i}{2 - i} = \frac{(7 + 2i)(2 + i)}{5} = \frac{12 + 11i}{5} = 2.4 + 2.2i.$$

Round to $q = 2 + 2i$. Then $r = (7 + 2i) - (2 + 2i)(2 - i) = (7 + 2i) - (6 + 2i) = 1$, and $N(1) = 1 < N(2 - i) = 5$. So $\mathbb{Z}[i]$ is a PID and a UFD.

A domain without unique factorisation

Let $R = \mathbb{Z}[\sqrt{-5}] = \{a + b\sqrt{-5} : a, b \in \mathbb{Z}\}$ with norm $N(a + b\sqrt{-5}) = a^2 + 5b^2$, again multiplicative. In $R$,

$$6 = 2 \cdot 3 = (1 + \sqrt{-5})(1 - \sqrt{-5}).$$

- Norms. $N(2) = 4$, $N(3) = 9$, $N(1 \pm \sqrt{-5}) = 1 + 5 = 6$.- Units. $N(u) = 1$ forces $a^2 + 5b^2 = 1$, so $u = \pm 1$.- All four factors are irreducible. A proper factor of an element of norm 4, 9 or 6 would have norm 2 or 3. But $a^2 + 5b^2 = 2$ or $3$ has no integer solutions ($b \ne 0$ gives at least 5; $b = 0$ needs $a^2 \in \{2, 3\}$).- The factorisations really differ. $2$ is not an associate of $1 \pm \sqrt{-5}$ (the only units are $\pm 1$, and the norms 4 and 6 differ).

So $R$ is not a UFD. Equivalently, $2$ is irreducible but not prime: $2 \mid (1 + \sqrt{-5})(1 - \sqrt{-5})$, but $2$ divides neither factor, since $(1 \pm \sqrt{-5})/2 \notin R$.

The other separating examples, stated without proof: $\mathbb{Z}[x]$ and $F[x, y]$ are UFDs (Gauss: $R$ a UFD implies $R[x]$ a UFD) but not PIDs, as shown for $(2, x)$ above; and $\mathbb{Z}\big[\tfrac{1 + \sqrt{-19}}{2}\big]$ is a PID that is not Euclidean (Dummit & Foote, §8.1–8.2).

Chapter 6 — Building fields from polynomials

Theorem. Let $F$ be a field and $p \in F[x]$ nonconstant. Then $F[x]/(p)$ is a field if and only if $p$ is irreducible.

Proof. In a PID, $(p)$ is maximal exactly when $p$ is irreducible. If $p$ is irreducible and $(p) \subseteq (h)$, then $h \mid p$, so $h$ is a unit (and $(h)$ is everything) or an associate of $p$ (and $(h) = (p)$). If $p = ab$ with $a, b$ of lower degree, then $(p) \subsetneq (a) \subsetneq F[x]$. Now apply "maximal ⇔ quotient is a field" from Chapter 3. ∎

What the elements look like. By the division algorithm every class has exactly one representative of degree $< n = \deg p$. So $F[x]/(p)$ is an $n$-dimensional vector space over $F$ with basis $1, \alpha, \dots, \alpha^{n-1}$, where $\alpha = x + (p)$ is a root of $p$. If $F = \mathbb{F}q$ is finite, the field has $q^n$ elements. To multiply, multiply polynomials and reduce with $p(\alpha) = 0$; to invert, use the extended Euclidean algorithm (since $\gcd(f, p) = 1$, there are $s, t$ with $sf + tp = 1$, so $s = f^{-1}$).

The complex numbers

$x^2 + 1$ has no real root, so it is irreducible over $\mathbb{R}$ and $\mathbb{R}[x]/(x^2 + 1)$ is a field whose elements are $a + b\alpha$ with $\alpha^2 = -1$:

$$(a + b\alpha)(c + d\alpha) = ac + (ad + bc)\alpha + bd\,\alpha^2 = (ac - bd) + (ad + bc)\alpha.$$

That is exactly complex multiplication, and the evaluation map of Chapter 2 is the isomorphism with $\mathbb{C}$. Example: $(3 + 2\alpha)(1 - \alpha) = 3 - 3\alpha + 2\alpha - 2\alpha^2 = 5 - \alpha$, matching $(3 + 2i)(1 - i) = 5 - i$.

A field with 4 elements

Over $\mathbb{F}2$, $x^2 + x + 1$ has no root ($0 \mapsto 1$, $1 \mapsto 1$), so it is irreducible and $\mathbb{F}4 = \mathbb{F}2[x]/(x^2 + x + 1)$ is a field with elements $0, 1, \alpha, \alpha + 1$ and the rule $\alpha^2 = \alpha + 1$ (since $-1 = 1$ in characteristic 2).

Addition (coefficients add mod 2):

| $+$ | $0$ | $1$ | $\alpha$ | $\alpha+1$ ||---|---|---|---|---|| $0$ | $0$ | $1$ | $\alpha$ | $\alpha+1$ || $1$ | $1$ | $0$ | $\alpha+1$ | $\alpha$ || $\alpha$ | $\alpha$ | $\alpha+1$ | $0$ | $1$ || $\alpha+1$ | $\alpha+1$ | $\alpha$ | $1$ | $0$ |

Multiplication:

| $\times$ | $0$ | $1$ | $\alpha$ | $\alpha+1$ ||---|---|---|---|---|| $0$ | $0$ | $0$ | $0$ | $0$ || $1$ | $0$ | $1$ | $\alpha$ | $\alpha+1$ || $\alpha$ | $0$ | $\alpha$ | $\alpha+1$ | $1$ || $\alpha+1$ | $0$ | $\alpha+1$ | $1$ | $\alpha$ |

Two entries in detail: $\alpha(\alpha + 1) = \alpha^2 + \alpha = (\alpha + 1) + \alpha = 1$, and $(\alpha + 1)^2 = \alpha^2 + 2\alpha + 1 = \alpha^2 + 1 = \alpha$. Every nonzero element has an inverse, and the multiplicative group $\{1, \alpha, \alpha + 1\}$ is cyclic of order 3.

> Common pitfall: $\mathbb{F}4$ is not $\mathbb{Z}/4\mathbb{Z}$. In $\mathbb{Z}/4\mathbb{Z}$, $2 \cdot 2 = 0$, so it is not even a domain. The additive group of $\mathbb{F}4$ is $\mathbb{Z}/2 \times \mathbb{Z}/2$, not $\mathbb{Z}/4$.

A field with 8 elements

$x^3 + x + 1$ has no root in $\mathbb{F}2$ ($0 \mapsto 1$, $1 \mapsto 1$), so, being cubic, it is irreducible, and $\mathbb{F}8 = \mathbb{F}2[x]/(x^3 + x + 1)$ has $2^3 = 8$ elements $c0 + c1\alpha + c2\alpha^2$ with $\alpha^3 = \alpha + 1$. The powers of $\alpha$ run through all 7 nonzero elements:

| $k$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 ||---|---|---|---|---|---|---|---|| $\alpha^k$ | $1$ | $\alpha$ | $\alpha^2$ | $\alpha + 1$ | $\alpha^2 + \alpha$ | $\alpha^2 + \alpha + 1$ | $\alpha^2 + 1$ |

and $\alpha^7 = \alpha \cdot \alpha^6 = \alpha^3 + \alpha = 1$. This "log table" makes multiplication easy: $\alpha^i \cdot \alpha^j = \alpha^{(i + j) \bmod 7}$. For example $(1 + \alpha)^{-1} = (\alpha^3)^{-1} = \alpha^4 = \alpha^2 + \alpha$; check: $(1 + \alpha)(\alpha^2 + \alpha) = \alpha^3 + \alpha = 1$.

Post 05 proves that for every prime power $p^n$ there is exactly one field of that size, up to isomorphism.

Practice Exercises

1. List the units and the zero divisors of $\mathbb{Z}/15\mathbb{Z}$.

<details><summary>Solution</summary>

Units are the classes coprime to 15: $1, 2, 4, 7, 8, 11, 13, 14$ (there are $\phi(15) = 8$). The other nonzero classes, $3, 5, 6, 9, 10, 12$, are zero divisors: for example $3 \cdot 5 = 15 \equiv 0$ and $6 \cdot 5 = 30 \equiv 0$.

</details>

2. Show that $(x)$ is a prime ideal of $\mathbb{Q}[x]$ that is also maximal, while in $\mathbb{Z}[x]$ it is prime but not maximal. What changes?

<details><summary>Solution</summary>

Evaluation at 0 gives $\mathbb{Q}[x]/(x) \cong \mathbb{Q}$, a field, so $(x)$ is maximal in $\mathbb{Q}[x]$. The same map gives $\mathbb{Z}[x]/(x) \cong \mathbb{Z}$, a domain but not a field, so $(x)$ is prime but not maximal in $\mathbb{Z}[x]$; indeed $(x) \subsetneq (2, x)$. What changed is the coefficient ring: the quotient is the coefficient ring itself.

</details>

3. Decide whether $x^3 + 2x + 1$ is irreducible over $\mathbb{Q}$ and over $\mathbb{F}3$.

<details><summary>Solution</summary>

Over $\mathbb{Q}$: the rational root test leaves $\pm 1$, giving values $4$ and $-2$; no root, degree 3, so irreducible. Over $\mathbb{F}3$: $f(0) = 1$, $f(1) = 4 \equiv 1$, $f(2) = 13 \equiv 1$; no root, so irreducible, and $\mathbb{F}3[x]/(x^3 + 2x + 1)$ is a field with $27$ elements.

</details>

4. Use Eisenstein's criterion to show $x^4 + 10x + 5$ is irreducible over $\mathbb{Q}$. Why does "it has no rational root" not suffice on its own?

<details><summary>Solution</summary>

With $p = 5$: $5 \nmid 1$ (leading coefficient), $5$ divides $0, 0, 10, 5$, and $25 \nmid 5$. So it is irreducible. Absence of roots only rules out linear factors; a quartic could still split into two quadratics, as $x^4 + 4$ does.

</details>

5. In $\mathbb{F}4 = \mathbb{F}2[x]/(x^2 + x + 1)$, compute $\alpha^3$, $(\alpha + 1)^2$ and $\alpha^{-1}$.

<details><summary>Solution</summary>

$\alpha^3 = \alpha \cdot \alpha^2 = \alpha(\alpha + 1) = \alpha^2 + \alpha = 1$. $(\alpha + 1)^2 = \alpha^2 + 1 = \alpha$ (the cross term $2\alpha$ is $0$). Since $\alpha(\alpha + 1) = 1$, $\alpha^{-1} = \alpha + 1$.

</details>

6. Show that $3$ is irreducible but not prime in $\mathbb{Z}[\sqrt{-5}]$, using $9 = (2 + \sqrt{-5})(2 - \sqrt{-5})$.

<details><summary>Solution</summary>

$N(3) = 9$. A proper factor would have norm 3, and $a^2 + 5b^2 = 3$ has no integer solution, so $3$ is irreducible. Next, $(2 + \sqrt{-5})(2 - \sqrt{-5}) = 4 + 5 = 9$, so $3$ divides this product. But $3$ divides neither factor, since $(2 \pm \sqrt{-5})/3 \notin \mathbb{Z}[\sqrt{-5}]$. So $3$ is not prime.

</details>

7. Show that $\mathbb{Z}[i]/(2 + i) \cong \mathbb{Z}/5\mathbb{Z}$.

<details><summary>Solution</summary>

Let $\psi : \mathbb{Z} \to \mathbb{Z}[i]/(2 + i)$ be the natural map. It is surjective: $i \equiv -2$ modulo $(2 + i)$, so $a + bi \equiv a - 2b$, an integer. Its kernel contains $5 = (2 + i)(2 - i)$. If an integer $n$ lies in $(2 + i)$, then $n = (2 + i)\gamma$ and $n^2 = N(n) = 5N(\gamma)$, so $5 \mid n^2$ and $5 \mid n$. So the kernel is $5\mathbb{Z}$, and the First Isomorphism Theorem gives $\mathbb{Z}/5\mathbb{Z} \cong \mathbb{Z}[i]/(2 + i)$.

</details>

Cheat-sheet

| Concept | Key fact ||---|---|| Ring (this series) | abelian group under $+$, associative $\cdot$ with $1$, distributive || Unit / zero divisor | invertible / nonzero with $ab = 0$ for some nonzero $b$ || Integral domain | commutative, $1 \ne 0$, no zero divisors; cancellation holds || Field | every nonzero element a unit; finite domain is a field || Characteristic | least $n$ with $n \cdot 1 = 0$; a domain has 0 or a prime || Ideal | additive subgroup absorbing multiplication; exactly the kernels || First Isomorphism Theorem | $R/\ker\varphi \cong \operatorname{im}\varphi$ || Prime ideal | $R/P$ is a domain || Maximal ideal | $R/M$ is a field; maximal implies prime || $F[x]$ | division algorithm; PID; degree-$n$ polynomial has at most $n$ roots || Irreducibility | deg 2–3: no roots; rational roots; Eisenstein; reduce mod $p$ || Hierarchy | field ⊂ Euclidean ⊂ PID ⊂ UFD ⊂ domain, all strict || Non-UFD | $6 = 2 \cdot 3 = (1+\sqrt{-5})(1-\sqrt{-5})$ in $\mathbb{Z}[\sqrt{-5}]$ || New fields | $F[x]/(p)$ is a field exactly when $p$ is irreducible; size $q^n$ || $\mathbb{F}4$ | $\mathbb{F}2[x]/(x^2+x+1)$, $\alpha^2 = \alpha + 1$ || $\mathbb{F}8$ | $\mathbb{F}2[x]/(x^3+x+1)$, $\alpha^3 = \alpha + 1$, $\alpha$ has order 7 |

What's next

Post 05 turns the construction of Chapter 6 into a theory. If $p$ is irreducible over $F$, the field $F[x]/(p)$ contains a root of $p$, so it is an extension of $F$ of degree $\deg p$. Degrees multiply in towers, which already settles the Greek problems of doubling the cube and trisecting an angle. Adding all the roots of a polynomial gives its splitting field, and the automorphisms of that field form its Galois group. The Fundamental Theorem of Galois Theory matches subfields with subgroups, and it explains why there is no formula in radicals for the roots of a general quintic.
