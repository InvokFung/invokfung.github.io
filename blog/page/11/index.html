PostgreSQL Course — 05 · Transactions, MVCC, Isolation and Locking
Created2026-06-29|Database PostgreSQL
A transaction is the unit in which a database promises to be correct. PostgreSQL implements that promise with MVCC — multi-version concurrency control — where writers never block readers and readers never block writers, because every row can exist in several versions at once. That design explains almost everything else in this post: why an writes a new row instead of editing one, why exists at all, why an idle transaction can quietly break your cluster, and why hands you an error instead of a lock. This post covers the mechanics, the four isolation levels as PostgreSQL actually implements them, explicit locking, deadlocks, and the vacuum consequences. > Series map: 00 Foundations & Setup → 01 SQL Fundamentals & Data Types → 02 Joins, Aggregation & Window Functions → 03 Indexes & the Query Planner → 04 Query Optimization & Statistics → 05 Transactions, MVCC, Isolation & Locking (this post) → 06 Schema Design, Normalization & JSONB → 07 Operations, Backup, Replication & Security. Chapter 1 — ACID, stated precisely Terminology - Atomicity — a transaction's effects are all applied or none are. PostgreSQL gets this from the commit record in the WAL: until the commit record is durable, the transaction's tuples are simply invisible.- Consistency — the database moves from one state satisfying all declared constraints to another. This is the application's and the schema's property; the database enforces it through constraints, not by magic.- Isolation — concurrent transactions produce a result consistent with some acceptable ordering. How strong that guarantee is depends on the isolation level (Chapter 3).- Durability — once returns, the effects survive a crash. Provided by write-ahead logging plus ; weakened deliberately by .- Anomaly — a concurrency outcome that a given isolation level permits: dirty read, non-repeatable read, phantom read, lost update, write skew. Every statement in PostgreSQL runs in a transaction. Outside an explicit , each statement is its own transaction that commits on success — "autocommit". There is no such thing as an unwrapped statement. Snapshots and visibility A snapshot records: the next unassigned transaction ID, and the list of transactions in flight. A tuple is visible if its committed before the snapshot and its either is zero or belongs to a transaction that had not committed at snapshot time. - READ COMMITTED takes a new snapshot at the start of each statement. Two identical s in one transaction can return different data.- REPEATABLE READ and SERIALIZABLE take one snapshot at the first statement and keep it for the whole transaction. SERIALIZABLE and SSI PostgreSQL 9.1 and later implement with Serializable Snapshot Isolation (SSI). It runs on top of snapshot isolation and tracks read/write dependencies between concurrent transactions with predicate locks (SIREAD locks). When it detects a dependency cycle that could not occur in any serial ordering, it aborts one of the transactions with SQLSTATE . Properties worth internalising: - It does not block. That abort is the feature. The retry loop is mandatory Any code path that uses or must be prepared to run the whole transaction again. This is not optional error handling; it is part of the contract. Rules for the retry body: - Retry the whole transaction, not the failing statement. The snapshot is gone; re-reading is the point.- Never leave side effects outside the transaction inside the retried block — no emails, no queue publishes, no HTTP calls. PostgreSQL detects it after (default ) and aborts one transaction with SQLSTATE . Reproducing one Two sessions: Reading the log entry Everything you need is there: two PIDs, the statement each was executing, and the tuple involved. The fix: consistent lock ordering Deadlocks come from two transactions acquiring the same set of locks in different orders. Impose a global order — sorting by primary key is the standard choice — and the cycle becomes impossible. Other reliable mitigations: keep transactions short, do not interleave user think-time inside a transaction, and touch tables in the same order everywhere in the codebase. Chapter 7 — Long transactions, wraparound, and "idle in transaction" Why long transactions are expensive Vacuum can only remove a dead tuple if no snapshot in the entire cluster could still see it. One transaction that started an hour ago and is still open pins the global horizon at its own snapshot. For that hour, no dead tuple newer than it can be removed anywhere in the database — even in tables that transaction has never touched. The result is bloat everywhere, slowly, invisibly, until someone notices the disk. is the worst state on that list: the client issued , did some work, and then went off to call an external API or wait on a user. It holds its snapshot, holds any locks it took, and consumes a connection slot, while doing nothing. Defences, all of which should be set in production: Set them per role rather than globally when a reporting user legitimately needs longer. Transaction ID wraparound Transaction IDs are 32-bit. PostgreSQL treats them as a circle: from any XID, roughly 2 billion are "in the past" and 2 billion are "in the future". A tuple whose fell more than 2 billion transactions behind would suddenly appear to be from the future — invisible. To prevent that, old tuples are frozen: marked as unconditionally visible, so their no longer matters. Chapter 6 — Encryption at rest Self-hosted (Enterprise / Atlas): - WiredTiger native encryption — AES-256 with keys from KMIP, Vault, Azure Key Vault, GCP KMS, AWS KMS, or a local keyfile.- Atlas: enabled by default with customer-managed keys (CMK) optional on dedicated tiers. Chapter 7 — Client-Side Field-Level Encryption (CSFLE) Sensitive fields are encrypted by the driver before they leave the application. The server only ever sees ciphertext. Algorithm matters: - Deterministic — same plaintext → same ciphertext. Allows equality lookups ().- Random — same plaintext → different ciphertext each time. Hides distribution + frequency but no equality lookups. The driver intercepts queries + writes, encrypts/decrypts as needed. Server, admins, backups, replicas all see ciphertext only. Key Management: data keys are encrypted by a master key held in your KMS (AWS KMS, Azure Key Vault, GCP KMS, KMIP). The key vault collection stores encrypted data keys; the master key never leaves the KMS. Constraints with CSFLE: - Only equality queries on deterministically-encrypted fields.- No range / sort / aggregation on encrypted fields.- For "range queries on encrypted data" → use Queryable Encryption. Chapter 8 — Queryable Encryption (GA in 7.0) Queryable Encryption extends field-level encryption to support equality + range + prefix queries on encrypted data — without ever decrypting on the server. Use cases: - PII fields needing search (email lookup for password reset).- Salaries, balances, ages — range queries while keeping plaintext invisible to DBAs.- Compliance (HIPAA, GDPR) — data is encrypted to ops staff but still queryable to apps with the right key. Caveats: slower than unencrypted queries; some index types unsupported; key management complexity. Plan carefully. Atlas: Queryable Encryption is supported on dedicated tiers + recent Mongo versions. Linear Algebra — 04 · Eigenvalues, Eigenvectors and Diagonalization
Created2026-06-26|Mathematics Linear Algebra
Most vectors change direction when a matrix acts on them. A few special directions do not: the matrix only stretches, shrinks or flips them. Those directions are the eigenvectors, and the stretch factors are the eigenvalues. If a matrix has enough eigenvectors to form a basis, then in that basis it is diagonal — every hard question about the matrix (its powers, its long-run behaviour, the differential equation it drives) splits into $n$ independent one-dimensional questions. This post builds the theory with proofs, then uses it on Fibonacci numbers, a Markov chain, a system of differential equations, and the power-iteration algorithm. It relies on the determinant and on change of basis from Linear Algebra 03. > Series map: 00 Vectors & Linear Systems → 01 Matrix Algebra, Inverses & LU → 02 Vector Spaces, Basis & Dimension → 03 Linear Maps, Change of Basis & Determinants → 04 Eigenvalues & Diagonalization (this post) → 05 Inner Products, Spectral Theorem & SVD. Learning Outcome - Define eigenvalues, eigenvectors and eigenspaces, and describe them geometrically for common maps of the plane.- Find eigenvalues from the characteristic polynomial and eigenvectors from null spaces, for $2 \times 2$ and $3 \times 3$ matrices.- Distinguish algebraic from geometric multiplicity, and prove that eigenvectors for distinct eigenvalues are independent.- Decide whether a matrix is diagonalizable, and write $A = PDP^{-1}$ when it is.- Compute $A^k$ and solve difference equations (Fibonacci, Markov chains) by diagonalization.- Handle complex eigenvalues, and use trace = sum and determinant = product of the eigenvalues as checks.- State and use the Cayley–Hamilton theorem; recognise a defective matrix and state the Jordan form.- Solve $x' = Ax$ with $e^{At} = Pe^{Dt}P^{-1}$, and explain how power iteration finds the dominant eigenvalue. Chapter 1 — Eigenvalues and eigenvectors Terminology - Eigenvector of a square matrix $A$ (or a linear operator $T: V \to V$) — a nonzero vector $v$ with $Av = \lambda v$ for some scalar $\lambda$.- Eigenvalue — a scalar $\lambda$ for which such a nonzero $v$ exists. "Eigen" is German for "own" or "characteristic".- Eigenspace $E\lambda = \{v : Av = \lambda v\} = N(A - \lambda I)$ — all eigenvectors for $\lambda$, together with $0$. It is a subspace.- Spectrum — the set of all eigenvalues of $A$.- Diagonalizable — similar to a diagonal matrix: $A = PDP^{-1}$ with $D$ diagonal and $P$ invertible. The zero vector is excluded as an eigenvector because $A0 = \lambda 0$ holds for every $\lambda$ and would say nothing. The eigenvalue $\lambda = 0$, on the other hand, is allowed: $Av = 0v$ with $v \neq 0$ means $v$ is in the null space, so $0$ is an eigenvalue exactly when $A$ is singular. What it means geometrically $Av = \lambda v$ says: the line through $v$ is mapped into itself. Along that line, $A$ acts as multiplication by the number $\lambda$. If $\lambda > 1$ the line is stretched, $0 < \lambda < 1$ shrinks it, $\lambda < 0$ flips it, $\lambda = 0$ collapses it to the origin. The maps of the plane from Linear Algebra 03: | Map | Eigenvalues and eigen-directions ||-----|----------------------------------|| Projection onto a line $L$ | $1$ on $L$ (kept), $0$ on the perpendicular line (killed) || Reflection in a line $L$ | $1$ on $L$, $-1$ on the perpendicular line || Rotation by $\theta$, $0 < \theta < 180°$ | no real eigenvector — every direction turns; complex eigenvalues $e^{\pm i\theta}$ (Chapter 6) || Shear $\begin{pmatrix} 1 & k \\ 0 & 1\end{pmatrix}$, $k \neq 0$ | only $1$, only along the $x$-axis — not enough eigenvectors (Chapter 4) || Scaling $\operatorname{diag}(a, b)$ | $a$ along $e1$, $b$ along $e2$ | Running example. Throughout the post, $$A = \begin{pmatrix} 4 & 1 \\ 2 & 3 \end{pmatrix}.$$ Check two directions: $A(1, 1) = (5, 5) = 5(1, 1)$ and $A(1, -2) = (2, -4) = 2(1, -2)$. So $(1,1)$ is an eigenvector with eigenvalue 5 and $(1, -2)$ is one with eigenvalue 2. A vector off these lines turns: $e1 = (1,0)$ goes to $(4, 2)$, a turn of about $26.6°$ counter-clockwise, and $e2 = (0,1)$ goes to $(1, 3)$, a turn of about $18.4°$ clockwise. ![The map A = [[4,1],[2,3]] applied to vectors of the unit circle: the eigen-directions (1,1) and (1,-2) stay on their own lines and are stretched by 5 and 2, while e1 and e2 are turned; the unit circle becomes an ellipse.](/assets/linalg/diagram04eigendirections.svg) Chapter 2 — The characteristic polynomial From a nonlinear problem to a determinant $Av = \lambda v$ has two unknowns multiplied together ($\lambda$ and $v$), so it is not a linear system. Rewrite it as $$(A - \lambda I)v = 0, \qquad v \neq 0.$$ A nonzero solution exists exactly when $A - \lambda I$ is singular, which by Linear Algebra 03 happens exactly when its determinant is zero. So: Theorem 1. $\lambda$ is an eigenvalue of $A$ if and only if $\det(\lambda I - A) = 0$. The function $pA(\lambda) = \det(\lambda I - A)$ is the characteristic polynomial of $A$. Expanding the determinant with the Leibniz formula shows it is a polynomial of degree $n$ with leading coefficient 1. (Some books use $\det(A - \lambda I) = (-1)^n pA(\lambda)$; the roots are the same.) The recipe is therefore two steps: (1) find the roots of $pA$; (2) for each root $\lambda$, find the null space of $A - \lambda I$ by elimination. The shortcut for 2 × 2 matrices For $A = \begin{pmatrix} a & b \\ c & d\end{pmatrix}$, $$pA(\lambda) = (\lambda - a)(\lambda - d) - bc = \lambda^2 - (a + d)\lambda + (ad - bc) = \lambda^2 - (\operatorname{tr}A)\,\lambda + \det A.$$ Worked example. For the running example, $\operatorname{tr}A = 7$ and $\det A = 12 - 2 = 10$: $$pA(\lambda) = \lambda^2 - 7\lambda + 10 = (\lambda - 5)(\lambda - 2).$$ For $\lambda = 5$: $A - 5I = \begin{pmatrix} -1 & 1 \\ 2 & -2\end{pmatrix}$, whose null space is spanned by $(1, 1)$. For $\lambda = 2$: $A - 2I = \begin{pmatrix} 2 & 1 \\ 2 & 1\end{pmatrix}$, null space spanned by $(1, -2)$. This matches Chapter 1. > Trick: After finding a $2 \times 2$ matrix $A - \lambda I$, you do not need to row-reduce. If the first row is $(p, q)$, then $(q, -p)$ (or $(-q, p)$) is in the null space. The second row must be a multiple of the first — if it is not, $\lambda$ was computed wrongly. A 3 × 3 example with a repeated eigenvalue $$B = \begin{pmatrix} 2 & 1 & 1 \\ 1 & 2 & 1 \\ 1 & 1 & 2 \end{pmatrix}, \qquad pB(\lambda) = \lambda^3 - 6\lambda^2 + 9\lambda - 4 = (\lambda - 4)(\lambda - 1)^2.$$ (A quick way to see this: $B = I + J$ where $J$ is the all-ones matrix. $J$ has rank 1, so $0$ is an eigenvalue of $J$ with a two-dimensional eigenspace, and $J(1,1,1) = 3(1,1,1)$. Adding $I$ adds 1 to every eigenvalue.) - $\lambda = 4$: $B - 4I$ has null space spanned by $(1, 1, 1)$.- $\lambda = 1$: $B - I = J$, every row is $(1, 1, 1)$, so the null space is the plane $x + y + z = 0$, spanned by $(-1, 1, 0)$ and $(-1, 0, 1)$. The eigenvalue 1 is a double root and has a two-dimensional eigenspace. That is the good case, as Chapter 3 explains. Easy cases and invariance - Triangular matrices: $\lambda I - A$ is triangular, so $pA(\lambda) = \prod (\lambda - a{ii})$. The eigenvalues are the diagonal entries.- Similar matrices have the same characteristic polynomial. If $B = P^{-1}AP$ then $\lambda I - B = P^{-1}(\lambda I - A)P$, so by the product rule $\det(\lambda I - B) = \det(\lambda I - A)$. So eigenvalues belong to the operator, not to a particular matrix of it (Linear Algebra 03, similarity invariants).- $A$ and $A^T$ have the same characteristic polynomial (because $\det M^T = \det M$), but usually different eigenvectors. > Common pitfall: Row operations change eigenvalues. Row-reducing $A$ first and then reading off the diagonal gives the pivots, not the eigenvalues. Row-reduce $A - \lambda I$ (to find eigenvectors), never $A$. Trace and determinant from the eigenvalues Over $\mathbb{C}$, every polynomial factors completely (fundamental theorem of algebra), so $pA(\lambda) = (\lambda - \lambda1)\cdots(\lambda - \lambdan)$, with eigenvalues repeated by multiplicity. Theorem 2. $\operatorname{tr} A = \lambda1 + \dots + \lambdan$ and $\det A = \lambda1 \lambda2 \cdots \lambdan$. Proof. Put $\lambda = 0$ in $\det(\lambda I - A) = \prod(\lambda - \lambdai)$: $\det(-A) = \prod(-\lambdai)$, that is $(-1)^n \det A = (-1)^n \prod \lambdai$. For the trace, compare the coefficients of $\lambda^{n-1}$. On the right it is $-\sum \lambdai$. On the left, in the Leibniz expansion of $\det(\lambda I - A)$, any term other than the diagonal product uses at most $n - 2$ diagonal entries, so has degree at most $n - 2$ in $\lambda$. The diagonal product $\prod(\lambda - a{ii})$ contributes $-\sum a{ii} = -\operatorname{tr}A$. ∎ Checks: for $A$, $5 + 2 = 7 = \operatorname{tr}A$ and $5 \cdot 2 = 10 = \det A$. For $B$, $4 + 1 + 1 = 6$ and $4 \cdot 1 \cdot 1 = 4 = \det B$. Chapter 3 — Multiplicities and independence Two kinds of multiplicity For an eigenvalue $\lambda0$: - Algebraic multiplicity — how many times $\lambda0$ is a root of $pA$ (the power of $(\lambda - \lambda0)$ in the factorisation).- Geometric multiplicity — $\dim E{\lambda0} = \dim N(A - \lambda0 I)$, the number of independent eigenvectors for $\lambda0$. Theorem 3. $1 \le \text{geometric multiplicity} \le \text{algebraic multiplicity}$. Proof. The lower bound holds because an eigenvalue has at least one eigenvector. For the upper bound let $g = \dim E{\lambda0}$ with basis $v1, \dots, vg$, and extend it to a basis $v1, \dots, vn$ of $\mathbb{R}^n$. With $P = (v1 \cdots vn)$, the first $g$ columns of $P^{-1}AP$ are $\lambda0 e1, \dots, \lambda0 eg$, so $$P^{-1}AP = \begin{pmatrix} \lambda0 Ig & X \\ 0 & Y \end{pmatrix}.$$ Similar matrices share the characteristic polynomial, and the block triangular determinant rule gives $pA(\lambda) = (\lambda - \lambda0)^g \det(\lambda I - Y)$. So $(\lambda - \lambda0)^g$ divides $pA$, and the algebraic multiplicity is at least $g$. ∎ In the example $B$, the eigenvalue 1 has algebraic multiplicity 2 and geometric multiplicity 2. For the shear $\begin{pmatrix} 1 & 1 \\ 0 & 1\end{pmatrix}$, the eigenvalue 1 has algebraic multiplicity 2 but geometric multiplicity 1. That gap is exactly what stops a matrix from being diagonalizable. Eigenvectors for different eigenvalues are independent Theorem 4. If $v1, \dots, vk$ are eigenvectors of $A$ for distinct eigenvalues $\lambda1, \dots, \lambdak$, then $v1, \dots, vk$ are linearly independent. Proof. Suppose not. Let $m$ be the smallest index such that $vm$ is a combination of $v1, \dots, v{m-1}$; then $v1, \dots, v{m-1}$ are independent, and $m \ge 2$ since $v1 \neq 0$. Write $$vm = c1 v1 + \dots + c{m-1} v{m-1}.$$ Apply $A$: $\lambdam vm = c1 \lambda1 v1 + \dots + c{m-1}\lambda{m-1} v{m-1}$. Subtract $\lambdam$ times the first equation: $$0 = c1(\lambda1 - \lambdam) v1 + \dots + c{m-1}(\lambda{m-1} - \lambdam) v{m-1}.$$ By independence each $ci(\lambdai - \lambdam) = 0$, and since the eigenvalues are distinct, each $ci = 0$. Then $vm = 0$, which is impossible for an eigenvector. ∎ The same argument shows more: if you take a basis of each eigenspace and put them together, the combined list is still independent. So the sum of the geometric multiplicities is the number of independent eigenvectors the matrix has in total. Corollary 5. An $n \times n$ matrix with $n$ distinct eigenvalues is diagonalizable. (Chapter 4 explains why independence is all that is needed.) The converse is false: $I$ has only one eigenvalue and is already diagonal; so is $B$ after a change of basis. Chapter 4 — Diagonalization The main theorem Theorem 6. An $n \times n$ matrix $A$ is diagonalizable if and only if it has $n$ linearly independent eigenvectors. In that case $A = PDP^{-1}$, where the columns of $P$ are the eigenvectors and $D$ is the diagonal matrix of the matching eigenvalues, in the same order. Proof. Write $P = (v1 \cdots vn)$ and $D = \operatorname{diag}(\lambda1, \dots, \lambdan)$. Column $i$ of $AP$ is $Avi$ and column $i$ of $PD$ is $\lambdai vi$. So $$AP = PD \iff Avi = \lambdai vi \text{ for every } i.$$ If there are $n$ independent eigenvectors, $P$ is invertible and $A = PDP^{-1}$. Conversely, if $A = PDP^{-1}$ then $AP = PD$, so the columns of $P$ are eigenvectors, and they are independent because $P$ is invertible. ∎ In the language of Linear Algebra 03: $D$ is the matrix of the same operator in the eigenvector basis. Diagonalizing means finding coordinates in which the map acts on each coordinate separately. Criterion. Combining Theorems 3 and 4: $A$ is diagonalizable over $\mathbb{C}$ if and only if, for every eigenvalue, geometric multiplicity = algebraic multiplicity. It is diagonalizable over $\mathbb{R}$ if in addition all eigenvalues are real. Worked example. For the running example, $$P = \begin{pmatrix} 1 & 1 \\ 1 & -2 \end{pmatrix}, \quad D = \begin{pmatrix} 5 & 0 \\ 0 & 2 \end{pmatrix}, \quad P^{-1} = \frac{1}{3}\begin{pmatrix} 2 & 1 \\ 1 & -1 \end{pmatrix}, \quad A = PDP^{-1}.$$ For $B$, take $P = \begin{pmatrix} 1 & -1 & -1 \\ 1 & 1 & 0 \\ 1 & 0 & 1 \end{pmatrix}$; then $P^{-1}BP = \operatorname{diag}(4, 1, 1)$. > Watch out: The order of the columns of $P$ must match the order of the eigenvalues in $D$. Eigenvectors can be scaled freely (any nonzero multiple is still an eigenvector), so $P$ is never unique — but $D$ is unique up to the order of its entries. A defective matrix and the Jordan form $$C = \begin{pmatrix} 3 & 1 \\ -1 & 1 \end{pmatrix}, \qquad pC(\lambda) = \lambda^2 - 4\lambda + 4 = (\lambda - 2)^2.$$ $C - 2I = \begin{pmatrix} 1 & 1 \\ -1 & -1\end{pmatrix}$ has rank 1, so the eigenspace is only the line spanned by $(1, -1)$. Algebraic multiplicity 2, geometric multiplicity 1: there is no eigenvector basis, and $C$ is not diagonalizable. Such a matrix is called defective. What is the best you can do? Take the eigenvector $v1 = (1, -1)$ and solve $(C - 2I)w = v1$; one solution is $w = (1, 0)$ (a generalised eigenvector). With $P = (v1\ w) = \begin{pmatrix} 1 & 1 \\ -1 & 0\end{pmatrix}$, $$P^{-1}CP = \begin{pmatrix} 2 & 1 \\ 0 & 2 \end{pmatrix}.$$ Theorem 7 (Jordan normal form, statement only). Every square complex matrix is similar to a block diagonal matrix whose blocks are Jordan blocks $$Jk(\lambda) = \begin{pmatrix} \lambda & 1 & & \\ & \lambda & \ddots & \\ & & \ddots & 1 \\ & & & \lambda \end{pmatrix} \quad (k \times k),$$ and the blocks are unique up to their order. For each eigenvalue, the number of blocks equals its geometric multiplicity and the total size of its blocks equals its algebraic multiplicity. A matrix is diagonalizable exactly when every block is $1 \times 1$. The proof takes a full chapter (Axler, Chapter 8); it is planned for a later post in this series. Chapter 5 — Powers and difference equations Powers If $A = PDP^{-1}$ then the inner $P^{-1}P$ pairs cancel: $$A^k = (PDP^{-1})(PDP^{-1})\cdots(PDP^{-1}) = PD^kP^{-1}, \qquad D^k = \operatorname{diag}(\lambda1^k, \dots, \lambdan^k).$$ For the running example: $$A^k = \frac{1}{3}\begin{pmatrix} 2\cdot 5^k + 2^k & 5^k - 2^k \\ 2 \cdot 5^k - 2 \cdot 2^k & 5^k + 2\cdot 2^k \end{pmatrix}.$$ Check with $k = 1$: $\frac{1}{3}\begin{pmatrix} 12 & 3 \\ 6 & 9\end{pmatrix} = A$. With $k = 3$: $\frac{1}{3}\begin{pmatrix} 258 & 117 \\ 234 & 141 \end{pmatrix} = \begin{pmatrix} 86 & 39 \\ 78 & 47 \end{pmatrix}$, which is $A^3$ computed directly. For large $k$ the $5^k$ terms dominate, so $A^k \approx \frac{5^k}{3}\begin{pmatrix} 2 & 1 \\ 2 & 1\end{pmatrix}$: every starting vector gets pulled towards the direction $(1, 1)$. Difference equations A linear difference equation (discrete dynamical system) is $u{k+1} = Auk$, so $uk = A^k u0$. Expand the start in eigenvectors, $u0 = c1 v1 + \dots + cn vn$ (that is, $c = P^{-1}u0$). Each piece evolves on its own: $$uk = c1 \lambda1^k v1 + c2 \lambda2^k v2 + \dots + cn \lambdan^k vn.$$ So the long-run behaviour is read from the eigenvalues: if every $\lvert\lambdai\rvert < 1$ then $uk \to 0$; if some $\lvert\lambdai\rvert > 1$ (with $ci \neq 0$) the solution blows up; the eigenvalue of largest modulus decides the dominant direction. Worked example — Fibonacci numbers $F0 = 0$, $F1 = 1$, $F{k+1} = Fk + F{k-1}$. Put $uk = (F{k+1}, Fk)$. Then $$u{k+1} = \begin{pmatrix} 1 & 1 \\ 1 & 0 \end{pmatrix} uk, \qquad u0 = \begin{pmatrix} 1 \\ 0 \end{pmatrix}.$$ The matrix $F = \begin{pmatrix} 1 & 1 \\ 1 & 0\end{pmatrix}$ has trace 1 and determinant $-1$, so $pF(\lambda) = \lambda^2 - \lambda - 1$ with roots $$\varphi = \frac{1 + \sqrt 5}{2} \approx 1.618034, \qquad \psi = \frac{1 - \sqrt 5}{2} \approx -0.618034.$$ For either root, $v = (\lambda, 1)$ is an eigenvector: $F(\lambda, 1) = (\lambda + 1, \lambda) = (\lambda^2, \lambda)$ because $\lambda^2 = \lambda + 1$. Since $\varphi - \psi = \sqrt5$, the start splits as $u0 = \frac{1}{\sqrt 5}\big((\varphi, 1) - (\psi, 1)\big)$. Hence $uk = \frac{1}{\sqrt5}\big(\varphi^k(\varphi, 1) - \psi^k(\psi, 1)\big)$, and the second component is Binet's formula: $$Fk = \frac{\varphi^k - \psi^k}{\sqrt 5}.$$ Because $\lvert\psi\rvert < 1$, the $\psi^k$ term dies away: $Fk$ is the integer nearest to $\varphi^k/\sqrt5$. For $k = 20$, $\varphi^{20}/\sqrt5 \approx 6765.00003$, and $F{20} = 6765$. The ratio $F{k+1}/Fk \to \varphi$. As a check on the matrix form, $F^{10} = \begin{pmatrix} 89 & 55 \\ 55 & 34 \end{pmatrix} = \begin{pmatrix} F{11} & F{10} \\ F{10} & F9 \end{pmatrix}$. Worked example — a Markov chain A town's weather is either sunny or rainy. If today is sunny, tomorrow is sunny with probability 0.9; if today is rainy, tomorrow is sunny with probability 0.5. With $xk = (\Pr[\text{sunny on day } k], \Pr[\text{rainy on day } k])$, $$x{k+1} = Mxk, \qquad M = \begin{pmatrix} 0.9 & 0.5 \\ 0.1 & 0.5 \end{pmatrix}.$$ Each column of $M$ sums to 1 (a column-stochastic or Markov matrix). Trace $1.4$, determinant $0.45 - 0.05 = 0.4$, so $pM(\lambda) = \lambda^2 - 1.4\lambda + 0.4 = (\lambda - 1)(\lambda - 0.4)$. - $\lambda = 1$: eigenvector $(5, 1)$. Scaled so the entries sum to 1: the steady state $s = (5/6, 1/6)$.- $\lambda = 0.4$: eigenvector $(-1, 1)$. Start on a rainy day, $x0 = (0, 1) = \frac{1}{6}(5, 1) + \frac{5}{6}(-1, 1)$. Then $$xk = \begin{pmatrix} 5/6 \\ 1/6 \end{pmatrix} + (0.4)^k \begin{pmatrix} -5/6 \\ 5/6 \end{pmatrix}.$$ Check: $x1 = (0.5, 0.5)$, $x2 = (0.7, 0.3)$, $x3 = (0.78, 0.22)$, each equal to $M$ times the previous one. After ten days the gap to the steady state is $(0.4)^{10} \cdot \frac56 \approx 0.0000874$; $x{10} \approx (0.83325, 0.16675)$. The rate of convergence is set by the second eigenvalue, 0.4. Why 1 is always an eigenvalue of a Markov matrix: the columns of $M$ sum to 1 means $M^T(1, \dots, 1) = (1, \dots, 1)$, so 1 is an eigenvalue of $M^T$, hence of $M$ (same characteristic polynomial). For a Markov matrix with all entries positive, Perron's theorem adds that the eigenvalue 1 is simple and every other eigenvalue has $\lvert\lambda\rvert < 1$, so every starting distribution converges to the same steady state. Chapter 6 — Complex eigenvalues A real matrix can have a characteristic polynomial with no real roots. Rotation by $90°$, $\begin{pmatrix} 0 & -1 \\ 1 & 0\end{pmatrix}$, has $p(\lambda) = \lambda^2 + 1$, so $\lambda = \pm i$ — no real direction is kept, which is what a rotation should do. Working over $\mathbb{C}$ restores the theory: every $n \times n$ matrix has $n$ complex eigenvalues counted with multiplicity. For a real matrix, non-real eigenvalues come in conjugate pairs: if $Av = \lambda v$ then conjugating gives $A\bar v = \bar\lambda \bar v$. Worked example. $$R = \begin{pmatrix} 1 & -1 \\ 1 & 1 \end{pmatrix} = \sqrt2 \begin{pmatrix} \cos 45° & -\sin 45° \\ \sin 45° & \cos 45° \end{pmatrix}, \qquad pR(\lambda) = \lambda^2 - 2\lambda + 2.$$ The roots are $\lambda = 1 \pm i$. For $\lambda = 1 + i$: $R - (1+i)I = \begin{pmatrix} -i & -1 \\ 1 & -i\end{pmatrix}$, and by the $2 \times 2$ trick $v = (i, 1)$. Check: $Rv = (i - 1, i + 1)$ and $(1 + i)(i, 1) = (i + i^2, 1 + i) = (i - 1, 1 + i)$. The other eigenpair is $1 - i$ with $\bar v = (-i, 1)$. Read the geometry from the polar form $1 + i = \sqrt2\, e^{i\pi/4}$: the modulus $\lvert\lambda\rvert = \sqrt 2$ is the scaling and the argument $45°$ is the rotation angle. Each application of $R$ turns the plane by $45°$ and scales by $\sqrt2$, so iterates spiral outwards; after 8 steps, $R^8 = (\sqrt2)^8 I = 16I$. In general a real $2 \times 2$ matrix with eigenvalues $a \pm bi$ ($b \neq 0$) is similar over $\mathbb{R}$ to $\begin{pmatrix} a & -b \\ b & a\end{pmatrix}$, a rotation combined with a scaling by $\sqrt{a^2 + b^2}$. Theorem 2 still holds with complex eigenvalues: $(1 + i) + (1 - i) = 2 = \operatorname{tr}R$ and $(1+i)(1-i) = 2 = \det R$. Chapter 7 — The Cayley–Hamilton theorem Theorem 8 (Cayley–Hamilton). Every square matrix satisfies its own characteristic polynomial: if $pA(\lambda) = \lambda^n + c{n-1}\lambda^{n-1} + \dots + c0$, then $$pA(A) = A^n + c{n-1}A^{n-1} + \dots + c1 A + c0 I = 0.$$ Proof for diagonalizable $A$. For a polynomial $q$, $q(PDP^{-1}) = P\,q(D)\,P^{-1}$ (apply the power rule term by term), and $q(D) = \operatorname{diag}(q(\lambda1), \dots, q(\lambdan))$. With $q = pA$ every diagonal entry is $pA(\lambdai) = 0$. ∎ The general case follows from the Jordan form, or from a density argument (diagonalizable matrices are dense among complex matrices, and $pA(A)$ depends continuously on $A$); see Axler, Chapter 8, or Hoffman and Kunze, Chapter 6. > Common pitfall: The "proof" $pA(A) = \det(AI - A) = \det(0) = 0$ is wrong. $pA(A)$ is a matrix, obtained by substituting $A$ into a polynomial; $\det(AI - A)$ is a number. The substitution is not allowed inside the determinant. Worked example. For $A = \begin{pmatrix} 4 & 1 \\ 2 & 3\end{pmatrix}$, $pA(\lambda) = \lambda^2 - 7\lambda + 10$. Indeed $$A^2 = \begin{pmatrix} 18 & 7 \\ 14 & 11 \end{pmatrix}, \qquad A^2 - 7A + 10I = \begin{pmatrix} 18 - 28 + 10 & 7 - 7 \\ 14 - 14 & 11 - 21 + 10 \end{pmatrix} = 0.$$ Two uses: - Inverse without elimination. Rearrange: $A(7I - A) = 10I$, so $A^{-1} = \frac{1}{10}(7I - A) = \frac{1}{10}\begin{pmatrix} 3 & -1 \\ -2 & 4 \end{pmatrix}$.- Reducing powers. $A^2 = 7A - 10I$, so every power of $A$ is a combination of $I$ and $A$. For an $n \times n$ matrix, every power is a combination of $I, A, \dots, A^{n-1}$. For $B$ from Chapter 2, $pB(B) = B^3 - 6B^2 + 9B - 4I = 0$. In fact the smaller polynomial $(\lambda - 4)(\lambda - 1)$ already kills $B$: $B^2 - 5B + 4I = 0$. The lowest-degree monic polynomial with $q(A) = 0$ is the minimal polynomial; a matrix is diagonalizable exactly when its minimal polynomial has no repeated roots. Chapter 8 — Systems of differential equations The matrix exponential A linear system of ordinary differential equations with constant coefficients is $$x'(t) = Ax(t), \qquad x(0) = x0,$$ with $x(t) \in \mathbb{R}^n$. In one dimension the answer is $x(t) = e^{at}x0$. The same works for matrices with the matrix exponential $$e^{At} = I + At + \frac{(At)^2}{2!} + \frac{(At)^3}{3!} + \cdots,$$ which converges for every square $A$ and satisfies $\frac{d}{dt}e^{At} = Ae^{At}$. The solution is $x(t) = e^{At}x0$, and it is unique. If $A = PDP^{-1}$, the power rule applies to each term, so $$e^{At} = P e^{Dt} P^{-1}, \qquad e^{Dt} = \operatorname{diag}(e^{\lambda1 t}, \dots, e^{\lambdan t}).$$ Equivalently, writing $x0 = \sum ci vi$: $$x(t) = c1 e^{\lambda1 t} v1 + \dots + cn e^{\lambdan t} vn.$$ This is the continuous twin of the difference-equation formula, with $\lambda^k$ replaced by $e^{\lambda t}$. The system is stable ($x(t) \to 0$ for every start) exactly when every eigenvalue has negative real part. > Watch out: $e^{A + B} = e^A e^B$ only when $AB = BA$. And $e^{At}$ is not the matrix of entry-wise exponentials $e^{a{ij}t}$. Worked example Two quantities decay and leak into each other: $$x1' = -2x1 + x2, \quad x2' = x1 - 2x2, \qquad A = \begin{pmatrix} -2 & 1 \\ 1 & -2 \end{pmatrix}, \quad x(0) = \begin{pmatrix} 1 \\ 0 \end{pmatrix}.$$ Trace $-4$, determinant $3$: $pA(\lambda) = \lambda^2 + 4\lambda + 3 = (\lambda + 1)(\lambda + 3)$. Eigenvectors: $(1, 1)$ for $-1$ and $(1, -1)$ for $-3$. The start is $(1, 0) = \frac12(1,1) + \frac12(1,-1)$, so $$x(t) = \frac12 e^{-t}\begin{pmatrix} 1 \\ 1 \end{pmatrix} + \frac12 e^{-3t}\begin{pmatrix} 1 \\ -1 \end{pmatrix}, \qquad e^{At} = \frac12\begin{pmatrix} e^{-t} + e^{-3t} & e^{-t} - e^{-3t} \\ e^{-t} - e^{-3t} & e^{-t} + e^{-3t} \end{pmatrix}.$$ Reading the answer: the difference $x1 - x2$ (the $(1,-1)$ mode) dies fast, like $e^{-3t}$; the total $x1 + x2$ (the $(1,1)$ mode) dies slowly, like $e^{-t}$. Both eigenvalues are negative, so the system is stable. Differentiating confirms $x' = Ax$ and $x(0) = (1, 0)$. For a defective matrix the Jordan block gives extra polynomial factors: for $C$ from Chapter 4, $e^{Ct}$ contains terms $te^{2t}$ as well as $e^{2t}$. A second-order equation $y'' + a y' + b y = 0$ becomes a first-order system with $x = (y, y')$; Exercise 6 does one. Chapter 9 — Power iteration Characteristic polynomials are for hand calculation only. Their roots are extremely sensitive to rounding in the coefficients (Wilkinson's famous example has roots $1, 2, \dots, 20$, and a change of about $2^{-23}$ in one coefficient turns several of them complex), so numerical software never computes eigenvalues that way. The simplest numerical method is power iteration: 1. Start with a vector $x0$ (random, or anything not orthogonal to the target).2. Repeat: $y = Axk$, then $x{k+1} = y / \lVert y\rVert$ (normalise, to avoid overflow). Why it works. Suppose $A$ is diagonalizable with $\lvert\lambda1\rvert > \lvert\lambda2\rvert \ge \dots$, and $x0 = \sum ci vi$ with $c1 \neq 0$. Then $$A^k x0 = \lambda1^k \left( c1 v1 + c2 \left(\tfrac{\lambda2}{\lambda1}\right)^k v2 + \dots \right),$$ and every term except the first shrinks like $\lvert\lambda2/\lambda1\rvert^k$. The direction converges to $v1$, and the scale factor converges to $\lambda1$. Worked example. MongoDB Course — 10 · Replica Sets — Primary, Secondary, Oplog, Elections
Created2026-06-21|Database MongoDB
A single is a single point of failure. A replica set is a group of processes that maintain copies of the same data and automatically elect a new primary when one fails. Three or more members get you durability, automatic failover, optional read scaling on secondaries, and zero-downtime maintenance. This post covers the architecture, the oplog, election protocol, write-concern interaction with replication, secondary read trade-offs, and the canonical 3-member + arbiter topologies. > Series map: 00 Foundations → … → 09 Transactions → 10 Replica Sets (this post) → 11 Sharding → 12 Change Streams → … → 17 Drivers & Case Studies. Learning Outcome - Explain PRIMARY / SECONDARY / ARBITER roles.- Initiate a replica set and inspect .- Read the oplog and understand replication lag.- Force an election + observe automatic failover.- Configure priorities, hidden members, delayed members.- Pick the right topology for your durability + cost target. Chapter 1 — Why replication Three things at once: 1. Durability — N copies of the data; loss of one server doesn't lose data.2. High availability — automatic failover; clients reconnect to a new primary in seconds.3. Read scaling (optional) — secondaries serve eventual-consistent reads. Replication doesn't scale writes — every write still goes through one primary. For write scaling, you shard (Post 11) on top of replica sets. Chapter 2 — Member roles | Role | Receives writes | Serves reads | Votes in election | Holds data ||------|------------------|---------------|--------------------|-------------|| PRIMARY | yes (only one at a time) | yes | yes | yes || SECONDARY | replicates from primary's oplog | yes (with etc.) | yes | yes || ARBITER | no | no | yes | no — voting only || HIDDEN | no | no (invisible to drivers) | yes | yes (backups, analytics) || DELAYED | no | no | yes | yes (lags primary by N seconds — disaster recovery) | A typical minimal production set: 3 data-bearing members (1 primary + 2 secondaries). Loss of any one keeps a majority alive. Avoid: - Even number of voting members without an arbiter → election can split. Always odd.- Arbiter-only failover safety in 2026 → arbiters can't vote on majority writes; prefer a 3-data-member setup unless cost-constrained. (See "election + write concern" pitfall in Chapter 8.) Chapter 3 — Initiate a replica set (local) Connect to one + initiate: Within a second or two, one member is PRIMARY, the other two are SECONDARY. In Atlas, every cluster is already a replica set — you don't initiate manually. Chapter 4 — Connection string for a replica set The driver:- Reads the seed list (your hosts).- Polls each to discover the full topology and the current primary.- Re-discovers automatically on failover. You only need to list a few seed hosts — the driver finds the rest. The SRV form (Atlas) returns the full member list via DNS, so the URI stays short. Chapter 5 — The oplog The oplog is a capped collection () on every replica-set member that records every write applied. Secondaries tail it and replay it to stay in sync. Each entry: timestamp, operation type (insert/update/delete), namespace, document or update spec. Oplog size matters Default size: 5 % of free disk (with a 50 GB upper cap on most platforms). If a secondary falls behind by more oplog entries than fit, it goes STALE and must do a full resync — slow. Tune via at start, or admin command. Atlas auto-sizes. > Trick: if you regularly run multi-hour ingest jobs while secondaries catch up, increase oplog size. The "1 day of writes fits" rule of thumb prevents most stale-member surprises. Chapter 6 — Replication mechanics + lag 1. Client writes to PRIMARY.2. PRIMARY records the write to its own oplog and applies it.3. Each SECONDARY tails the primary's oplog and applies in order.4. Once a majority of voters have applied the write, it's "majority committed". Replication lag = how far behind the primary a secondary is in oplog time. Inspect: Causes of lag: - Big write spike (secondaries can't keep up).- Slow disk on a secondary.- Network latency (especially across regions).- Long oplog entries (huge updates). Persistent lag > a few seconds = warning. Lag growing unbounded = crisis (eventually goes STALE). Chapter 7 — Elections If the PRIMARY becomes unreachable, voting members hold an election (under the hood: Raft-like protocol Version 1, "PV1"). Steps: 1. A secondary that hasn't heard from the primary for (default 10 s) calls an election.2. Other voting members vote yes if the candidate's oplog is up-to-date enough.3. Majority of votes → new PRIMARY.4. Drivers detect the change via heartbeats; subsequent writes go to the new primary. Typical failover: 10-20 seconds for clients to reconnect; retryable writes (Post 08) hide most of the disruption. Force a manual failover (test) A useful production drill — practise failover under controlled conditions. Chapter 8 — Write concern + replica sets Recap from Post 08 — write concern interacts with replication: | | Meaning ||-----|---------|| 0 | fire-and-forget || 1 | primary acked || | majority of voters acked || N | exactly N members acked | is the production-correct default — guarantees the write survives the primary failing (because at least one surviving voter has it). Arbiter pitfall If you have a 2-data + 1-arbiter set (total 3 voters, majority = 2), arbiters can vote in elections but don't store data. A write reaching only the primary + the arbiter (waiting for the second data member) can be lost in failover. Modern guidance: avoid arbiters in 2026 for any system where data loss isn't acceptable. Use 3 data-bearing members. Chapter 9 — Read preference + secondary reads Recap from Post 08: | Preference | Effect ||------------|--------|| (default) | always primary, freshest || | primary if up, else secondary || | secondary only || | secondary first, fall back to primary || | lowest-latency member | Use secondary reads for: - Reporting / dashboards tolerating seconds of lag.- Scaling read-heavy workloads horizontally.- Region-local reads via . Don't use for: - Read-your-own-writes (RYOW) without causal-consistency session.- Anything where stale-by-seconds matters (orders, balances, leaderboards).
