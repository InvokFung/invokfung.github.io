Chapter 1 — Why state machines

A workflow is a graph of steps with branches, parallelism, error handling, and (sometimes) human approval. Hand-rolled, this turns into a tangle of Lambdas invoking other Lambdas, with retry logic copied in each, error-handling baked into each step, and no central view of "where is this execution right now?".

Step Functions externalises the orchestration:

- The state machine definition is a JSON document — version-controlled, auditable.- Step Functions runs each execution: tracks position, retries, errors, history.- The console shows a visual diagram of every execution — which step succeeded, which failed, what data flowed where.- Each step is small and stateless (your Lambdas or AWS service calls); orchestration logic lives in one place.

Chapter 2 — Workflow types

| Type | Duration | Pricing | Execution history | Use ||------|----------|---------|-------------------|------|| Standard | up to 1 year | per state transition | full history, queryable | long-running, audit-required, occasional || Express | up to 5 min | per execution time | CloudWatch Logs only | high-throughput, short |

Standard suits business workflows (order fulfilment, ETL, approvals). Express suits per-request orchestration (an API call that needs to fan out, gather, return).

Chapter 6 — The Saga pattern

In a distributed system, you can't have ACID across services. The Saga pattern fakes it: every step has a compensating action, and if a later step fails, the workflow runs the prior compensating actions in reverse.

Example: order placement.

If  fails, the workflow:

1. Cancels delivery (n/a, never scheduled).2. Refunds the card.3. Releases the inventory.4. Returns the user a coherent failure response.

In Step Functions, model it as a  block with  that routes to a compensating sub-workflow.

Chapter 7 — Express vs Standard pricing

| Standard | Express ||----------|---------|| USD 0.025 per 1,000 state transitions | USD 1 per 1M executions + GB-second compute time |

A long-running workflow with 50 transitions costs USD 0.00125 per execution on Standard. A 200-ms Express execution at 100 MB costs USD 0.0000004 per execution. Express wins for high-volume; Standard wins for long-running / fewer / audit-required.

Many production systems use both: Standard for the business workflow, Express for inner high-frequency loops.

Chapter 8 — When NOT to use Step Functions

| Scenario | Better fit ||----------|------------|| Single Lambda, no branching | just use Lambda || Pure pub/sub fanout | SNS or EventBridge || Pure queue + worker | SQS + Lambda || Stream processing | Kinesis + Lambda || Simple event chain across AWS services without transformations | EventBridge Pipes (newer, lighter than Step Functions for source → enrich → target) || Always-on long-running daemon | ECS / EC2 |

EventBridge Pipes deserves a special mention: launched 2022, ideal for "read from queue/stream → optional Lambda enrich → write to target". For pure pipelines without branching, Pipes is cheaper and simpler than Step Functions.

Chapter 1 — ConfigMaps and Secrets

Terminology

- ConfigMap — a namespaced API object holding non-confidential key/value data, consumed by Pods as environment variables, command-line arguments, or files.- Projection — the act of a kubelet rendering a ConfigMap or Secret into a Pod's filesystem.- Hot reload — the application noticing a configuration change without being restarted.- Immutable object — a ConfigMap or Secret marked , which can never be updated, only replaced.

Two ways to consume it, with very different behaviour

The propagation delay

Mounted files do not update instantly. The kubelet refreshes projected volumes on its periodic sync, using a locally cached copy of the object. The worst-case delay is therefore roughly the kubelet sync period (, default 1 minute) plus the ConfigMap/Secret cache propagation delay (watch-based by default; the TTL-based strategy defaults to another minute). In practice, budget for changes appearing within about two minutes, not immediately.

Three further caveats:

- Updates are atomic per volume. The kubelet writes a new timestamped directory and swings a symlink, so an application never reads a half-updated set of files. Watch the directory, not the file inode — many file watchers miss the symlink swap.- The application still has to do something. A file changing on disk is not a reload; something must re-read it. Either implement a watcher, or accept a restart.-  is the classic trap. It is used to drop a single file into a directory that already has other content (), and it silently opts you out of updates entirely.

> Common pitfall: "I edited the ConfigMap and nothing happened." Check which of the three consumption forms you used. If it is  or , nothing will happen. Roll the Deployment.

Secrets, and what they actually protect

A Secret looks exactly like a ConfigMap with a different  and a  convenience field.

The blunt truth

A Secret is base64-encoded, not encrypted. Base64 is an encoding, not a cipher;  prints the password, and anyone with  permission in that namespace can do it. By default the value also sits in etcd in plain text, which means an etcd backup, a stolen disk snapshot, or a compromised control-plane node exposes it.

What a Secret actually buys you over a ConfigMap:

- It is a distinct resource kind, so RBAC can be written against it separately (Post 07). This is the real benefit.- Its values are not printed by .- The kubelet stores projected Secret volumes in , so they do not touch the node's disk.- It is only distributed to nodes running a Pod that requests it.

What it does not buy you: encryption, audit of reads by the application, rotation, or safety from anyone who can  into the Pod.

Chapter 3 — Storage

Terminology

- Volume — a directory available to the containers in a Pod, with a lifetime tied to the Pod.  is scratch space that vanishes with the Pod; , ,  and  are read-only data sources.- PersistentVolume (PV) — a cluster-scoped object representing a real piece of storage (an EBS volume, a Ceph RBD image, an NFS export).- PersistentVolumeClaim (PVC) — a namespaced request for storage: size, access mode, class. Pods reference PVCs, never PVs.- StorageClass — a named recipe describing how to provision a PV on demand: which provisioner, which parameters, which reclaim and binding policy.- CSI (Container Storage Interface) — the standard gRPC contract between Kubernetes and a storage vendor's driver.

The indirection exists so that a workload author can ask for "20 GiB, fast, exclusive" without knowing whether the cluster runs on AWS, on-prem Ceph, or a laptop.

Static versus dynamic provisioning

Static: an administrator creates PVs by hand and users claim them. Necessary for pre-existing storage (an NFS export, a restored snapshot). Dynamic: the user creates a PVC naming a StorageClass, and the CSI driver provisions a matching PV automatically. Dynamic is the default in every managed cloud and is what you should use unless you have a specific reason not to.

Access modes — and the mistake everyone makes

| Mode | Short | Meaning ||------|-------|---------|| ReadWriteOnce | RWO | mounted read-write by one node (several Pods on that node may share it) || ReadOnlyMany | ROX | mounted read-only by many nodes || ReadWriteMany | RWX | mounted read-write by many nodes || ReadWriteOncePod | RWOP | mounted read-write by exactly one Pod (GA in Kubernetes 1.29) |

The mistake: assuming RWX is available. It usually is not. Block storage — EBS, GCE PD, Azure Disk, most on-prem SANs — is RWO only, because a block device cannot safely be mounted read-write on two machines at once. RWX requires a file protocol: NFS, EFS, Azure Files, CephFS, Filestore. If your design has three replicas of a Deployment all writing to one shared volume, either budget for a networked filesystem (slower, more expensive, another thing to operate) or redesign so each replica owns its own volume — which is what a StatefulSet gives you.

Note also that RWO is per node, not per Pod. Two Pods of the same Deployment that happen to land on the same node can both write to one RWO volume and corrupt each other. RWOP exists precisely to prevent that.

Reclaim policy

Set on the StorageClass (inherited by dynamically provisioned PVs) or directly on a static PV:

- Delete — deleting the PVC deletes the PV and the underlying disk. The default for dynamic provisioning. Convenient; also how data gets destroyed by a careless .- Retain — the PV survives in  state, the data stays, and an administrator must manually clean up or re-bind. The correct choice for anything you would be upset to lose.- Recycle — deprecated, do not use.

> Watch out: for production databases, either use  or make sure the StorageClass's  behaviour is compensated by real, tested, off-cluster backups. "The PVC was deleted" should not be an unrecoverable event.

volumeBindingMode and the zone-mismatch bug

This setting fixes a failure that is baffling the first time you hit it.

-  — the PV is provisioned as soon as the PVC is created, before any Pod exists. In a multi-zone cluster the provisioner has to guess a zone. If the scheduler later places the Pod in a different zone, the Pod cannot mount the volume and stays  forever with a  event. Zonal block storage cannot cross zones.-  — provisioning is deferred until a Pod that uses the PVC is scheduled. The scheduler picks a node first, considering all its normal constraints, and then the volume is created in that node's zone.

CSI in one paragraph

Every storage integration is now an out-of-tree CSI driver: a controller Deployment that handles create/delete/attach and a node DaemonSet that handles mount/unmount, both speaking a standard gRPC interface. The in-tree cloud provider volume plugins have been migrated to CSI and removed. Practical consequences: driver features arrive on the vendor's schedule rather than Kubernetes releases; snapshots (, ), cloning, expansion (, then edit the PVC's requested size) and topology awareness are all standard CSI capabilities you can rely on if the driver advertises them.

Chapter 5 — DaemonSets, Jobs and CronJobs

DaemonSet

Runs exactly one Pod per node (optionally a filtered subset), and automatically adds a Pod when a node joins the cluster. This is the right shape for anything that is a property of the node rather than of the application: log collectors, metrics exporters (), CNI agents, CSI node plugins, security agents.

CronJob

Creates a Job on a schedule.

matters more than it looks:

- Allow (default) — a run that overruns its interval simply overlaps with the next one. The missed-schedule trap

The CronJob controller does not have perfect memory. When it wakes up, it counts the schedules it missed since it last ran. If it finds more than 100 missed schedules, it gives up entirely, schedules nothing, and records an event saying so — the CronJob then silently never fires again until it is edited or recreated. This happens after a long control-plane outage, after restoring an old cluster backup, or after a CronJob is created with a schedule in the past.

interacts with this: if set, the controller only counts misses within that window, which keeps the count small and avoids the lockout — but it also means a run more than that many seconds late is dropped rather than started. Setting it to a value shorter than the controller's own check interval can cause runs to be missed altogether.

> Watch out: always alert on "expected CronJob has not produced a successful Job in N intervals". Do not alert on the CronJob object being healthy — it looks perfectly healthy while firing nothing at all.

Chapter 7 — Should the database be on Kubernetes at all?

The honest answer is "sometimes", and the reasoning matters more than the verdict.

The case against

- The failure modes are unfamiliar. A node drain, a spot-instance reclaim, a memory limit hit, an eviction under disk pressure, a CNI hiccup — each is routine for a stateless service and each is a potential data event for a database.- You are now operating two hard systems. Kubernetes upgrades every few months; the database has its own upgrade path. The intersection is where the incidents live.- Managed services are genuinely good. RDS, Aurora, Cloud SQL, Atlas and their peers give you backups, PITR, failover, patching and a support contract for a price that is usually less than the engineer-time you would spend replicating them badly.- Storage performance is a layer deeper. Network-attached block storage under a CSI driver under a container runtime has more moving parts and more tail latency than a local NVMe device.

The case for

- You already run Kubernetes for everything else, and the operational uniformity — same deploy pipeline, same secrets, same observability, same RBAC — is worth real money.- On-prem, sovereign or air-gapped requirements rule out managed services entirely.- A mature operator exists for your database. This is the pivotal question. CloudNativePG for Postgres, Strimzi for Kafka, the MongoDB and Percona operators, Vitess for MySQL — these encode failover, backup and upgrade as controllers. Running a database on Kubernetes with a mature operator is a different activity from running one with a hand-written StatefulSet.- Many identical database instances. Per-tenant or per-environment databases are exactly where declarative provisioning pays off.

A decision rule

| Situation | Reasonable call ||-----------|-----------------|| Managed service available, no sovereignty constraint, small team | Use the managed service. || Already deep in Kubernetes, mature operator exists, platform team on call | On Kubernetes, via the operator. || On-prem or air-gapped | On Kubernetes — it is likely the best option available || Small dataset, low QPS, one instance | plain VM or managed; the cluster adds cost without benefit || Hand-written StatefulSet, no operator, no runbook, production data | Do not. |

For a fuller treatment of this exact trade-off in one ecosystem — operator choice, production checklist, cost and compliance — see , which covers the same decision for MongoDB with the concrete numbers and the operator landscape spelled out.

Whatever you choose, the non-negotiables are the same: tested restores (not just backups), storage with a  reclaim policy or an equivalent guard, a PodDisruptionBudget so a node drain cannot take quorum (Post 06), anti-affinity so replicas are not co-located, and monitoring that alerts on replication lag rather than on Pod count.

Chapter 1 — The model

Terminology

- Agent — a call stack, a set of queues and one event loop. A window (with its same-origin iframes), each worker, and each Node  worker are separate agents.- Task (often "macrotask") — a unit of work queued by the host: a timer firing, an input event, a network response, a . Browsers keep several task queues (by task source) and may choose which queue to serve next — this is how input can be prioritised over timers.- Microtask — a smaller unit queued by promise reactions, , and . There is one microtask queue per agent.- Microtask checkpoint — the step that runs microtasks until the queue is empty, including microtasks queued by microtasks.- Rendering opportunity — a moment when the browser can present a new frame, typically aligned with the display refresh (about every 16.7 ms at 60 Hz). Browsers may skip frames or throttle hidden pages.

One turn of the browser loop

1. Pick the oldest task from a task queue the browser chooses, and run it to completion. The call stack empties.2. Perform a microtask checkpoint: run microtasks until none remain.3. If this is a rendering opportunity and there is something to render, update the rendering (Chapter 3).4. Repeat.

Two rules produce nearly every "surprising" order:

- Microtasks run whenever the JavaScript stack becomes empty, not only between tasks. The HTML spec's "clean up after running script" step performs a microtask checkpoint whenever the JavaScript execution context stack becomes empty — after a task, but also after each event listener the browser invokes and after each  callback.- The checkpoint drains the queue completely. A microtask that queues another microtask keeps the loop in step 2. An infinite chain of microtasks freezes the page as surely as  — rendering and input never get a turn.

> Watch out:  is not "run next". HTML clamps the delay to at least 4 ms once timers are nested more than 5 levels deep, browsers throttle timers in background tabs heavily, and a timer is only a task — everything already queued, and the rendering step, can run first.

When the loop decides to render, the HTML standard's update the rendering step runs, per document, in this order (abridged):

Consequences for engineers:

- rAF is the place for visual writes. Code in a rAF callback runs just before style and layout, so the frame shows its result. A  animation drifts against the display's refresh and may run twice or zero times per frame.- A rAF callback that calls rAF schedules for the next frame, not the current one. > Common pitfall: using rAF in a background tab to keep "real-time" work going. Browsers stop or heavily throttle rAF in hidden documents (the HTML spec removes hidden documents from rendering). Chapter 1 — Logic and proof

Analysis is written in a small, precise language. Most mistakes in a first analysis course are not mistakes about numbers; they are mistakes about quantifiers.

Terminology

- Statement — a sentence that is either true or false, e.g. "$7$ is prime".- Implication "$P \Rightarrow Q$" — "if $P$ then $Q$". It is false only when $P$ is true and $Q$ is false.- Converse of $P \Rightarrow Q$ — the statement $Q \Rightarrow P$. It is a different statement and may be false.- Contrapositive of $P \Rightarrow Q$ — the statement $\neg Q \Rightarrow \neg P$. It is logically equivalent to the original.- Universal quantifier $\forall$ — "for all". Existential quantifier $\exists$ — "there exists (at least one)".- Counterexample — one specific object that shows a "for all" statement is false.

Negating quantified statements

The two rules are:

$$\neg\big(\forall x,\ P(x)\big) \iff \exists x,\ \neg P(x), \qquad \neg\big(\exists x,\ P(x)\big) \iff \forall x,\ \neg P(x).$$

To negate a nested statement, move the $\neg$ from left to right, flipping every quantifier it passes, and negate the final condition. The definition of "the sequence $(an)$ converges to $a$" (see Real Analysis 01) is

$$\forall \varepsilon > 0\ \ \exists N \in \mathbb{N}\ \ \forall n \ge N:\ \ \lvert an - a \rvert < \varepsilon.$$

Its negation, "$(an)$ does not converge to $a$", is

$$\exists \varepsilon > 0\ \ \forall N \in \mathbb{N}\ \ \exists n \ge N:\ \ \lvert an - a \rvert \ge \varepsilon.$$

In words: there is one fixed tolerance $\varepsilon$ such that, however far out you go, some later term is still at least $\varepsilon$ away from $a$.

The same mechanical rule applies to continuity (see Real Analysis 02). "$f$ is continuous at $c$" is $\forall \varepsilon > 0\ \exists \delta > 0\ \forall x:\ \lvert x - c\rvert < \delta \Rightarrow \lvert f(x) - f(c)\rvert < \varepsilon$. Its negation is

$$\exists \varepsilon > 0\ \ \forall \delta > 0\ \ \exists x:\ \ \lvert x - c \rvert < \delta \ \text{ and } \ \lvert f(x) - f(c) \rvert \ge \varepsilon.$$

Note that the negation of an implication $A \Rightarrow B$ is "$A$ and not $B$", not another implication.

> Watch out: the order of quantifiers matters. "$\forall x\ \exists y:\ y > x$" (every real number has a larger one) is true in $\mathbb{R}$. "$\exists y\ \forall x:\ y > x$" (one number is larger than all of them) is false. Swapping $\forall$ and $\exists$ changes the meaning completely. In analysis the classic example is uniform continuity (Real Analysis 02), which differs from continuity only by the position of one quantifier.

Three proof patterns

Direct proof. Assume the hypothesis, reach the conclusion by valid steps. Example: if $m$ and $n$ are even, $m + n$ is even. Write $m = 2a$, $n = 2b$; then $m + n = 2(a + b)$.

Contrapositive and contradiction. To prove $P \Rightarrow Q$ you may prove $\neg Q \Rightarrow \neg P$ instead. In a proof by contradiction you assume the statement is false and derive something impossible. Example: if $n^2$ is even, then $n$ is even. Contrapositive: if $n$ is odd, $n = 2k + 1$, then $n^2 = 4k^2 + 4k + 1 = 2(2k^2 + 2k) + 1$ is odd.

Induction. To prove $P(n)$ for all $n \in \mathbb{N} = \{1, 2, 3, \dots\}$, prove the base case $P(1)$ and the inductive step $P(n) \Rightarrow P(n+1)$. This works because of the well-ordering principle: every nonempty subset of $\mathbb{N}$ has a least element (if $P$ failed somewhere, look at the least failure).

Example (Bernoulli's inequality). For every $x \ge -1$ and every $n \in \mathbb{N}$, $(1 + x)^n \ge 1 + nx$.

Proof. For $n = 1$ both sides equal $1 + x$. Suppose $(1+x)^n \ge 1 + nx$. Since $1 + x \ge 0$, multiplying both sides by $1 + x$ keeps the inequality:

$$(1+x)^{n+1} \ge (1 + nx)(1 + x) = 1 + (n+1)x + nx^2 \ge 1 + (n+1)x,$$

because $nx^2 \ge 0$. $\blacksquare$

The hypothesis $x \ge -1$ is used exactly once, to multiply an inequality by a non-negative number. Bernoulli's inequality is the standard tool for showing $r^n \to 0$ when $\lvert r \rvert < 1$ (Real Analysis 01).

The square root of 2 is irrational

Theorem. There is no rational number $r$ with $r^2 = 2$.

Proof. Suppose, for contradiction, that $r = p/q$ with integers $p, q$, $q \ne 0$, and $r^2 = 2$. Cancel common factors, so that $p$ and $q$ are not both even. Then $p^2 = 2q^2$, so $p^2$ is even, and by the contrapositive example above $p$ is even: $p = 2k$. Substituting, $4k^2 = 2q^2$, so $q^2 = 2k^2$ is even, and $q$ is even. Now $p$ and $q$ are both even, contradicting the choice of $p/q$ in lowest terms. $\blacksquare$

This is the first sign that $\mathbb{Q}$ has gaps: the rationals whose square is less than $2$ creep up towards a point that is not there.

Chapter 2 — Ordered fields and absolute value

Terminology

- Field — a set $F$ with two operations $+$ and $\cdot$ satisfying the field axioms below.- Ordered field — a field with a relation $<$ satisfying the order axioms below.- Absolute value — $\lvert x \rvert = x$ if $x \ge 0$ and $\lvert x \rvert = -x$ if $x < 0$.- Distance between $x$ and $y$ — the number $\lvert x - y \rvert$.

The axioms

A field satisfies, for all $x, y, z$:

| Axiom | Addition | Multiplication ||-------|----------|----------------|| Closure | $x + y \in F$ | $xy \in F$ || Associative | $(x+y)+z = x+(y+z)$ | $(xy)z = x(yz)$ || Commutative | $x + y = y + x$ | $xy = yx$ || Identity | $x + 0 = x$ | $1 \cdot x = x$, with $1 \ne 0$ || Inverse | some $-x$ has $x + (-x) = 0$ | if $x \ne 0$, some $x^{-1}$ has $x x^{-1} = 1$ || Distributive | $x(y+z) = xy + xz$ | (links the two operations) |

An ordered field also has a relation $<$ such that:

1. Trichotomy: for all $x, y$ exactly one of $x < y$, $x = y$, $y < x$ holds.2. Transitivity: $x < y$ and $y < z$ imply $x < z$.3. Addition: $x < y$ implies $x + z < y + z$.4. Multiplication: $x < y$ and $0 < z$ imply $xz < yz$.

Everything in high-school algebra follows. For example, $x^2 \ge 0$ for all $x$, and $0 < 1$ (since $1 = 1^2$ and $1 \ne 0$). If $x < y$ and $z < 0$ then $yz < xz$: multiplying by a negative number flips an inequality.

Both $\mathbb{Q}$ and $\mathbb{R}$ are ordered fields. So these axioms cannot be what distinguishes them; Chapter 3 adds the one axiom that does.

The triangle inequality

Three facts about absolute value, all checked by cases on the signs: $\lvert xy \rvert = \lvert x \rvert \lvert y \rvert$; $-\lvert x \rvert \le x \le \lvert x \rvert$; and for $a \ge 0$, $\lvert x \rvert \le a \iff -a \le x \le a$.

Theorem (triangle inequality). For all real $x, y$: $\lvert x + y \rvert \le \lvert x \rvert + \lvert y \rvert$.

Proof. Add $-\lvert x \rvert \le x \le \lvert x \rvert$ and $-\lvert y \rvert \le y \le \lvert y \rvert$:

$$-(\lvert x \rvert + \lvert y \rvert) \le x + y \le \lvert x \rvert + \lvert y \rvert.$$

By the third fact with $a = \lvert x \rvert + \lvert y \rvert$, this says $\lvert x + y \rvert \le \lvert x \rvert + \lvert y \rvert$. $\blacksquare$

Two forms are used constantly:

- Distance form: $\lvert a - b \rvert \le \lvert a - c \rvert + \lvert c - b \rvert$ (put $x = a - c$, $y = c - b$). Going from $a$ to $b$ via $c$ is never shorter.- Reverse triangle inequality: $\big\lvert \lvert x \rvert - \lvert y \rvert \big\rvert \le \lvert x - y \rvert$. (From $\lvert x \rvert = \lvert (x - y) + y \rvert \le \lvert x - y \rvert + \lvert y \rvert$, and the same with $x$ and $y$ swapped.)

> Trick: almost every $\varepsilon$ proof in this course is "add and subtract a middle term, then use the triangle inequality". When you see $\lvert an bn - ab \rvert$, write it as $\lvert an bn - an b + an b - ab \rvert$ and split.

Proving that two numbers are equal

Lemma. Two real numbers $a$ and $b$ are equal if and only if for every $\varepsilon > 0$, $\lvert a - b \rvert < \varepsilon$.

Proof. If $a = b$ then $\lvert a - b \rvert = 0 < \varepsilon$. Conversely, suppose $a \ne b$. Then $\varepsilon0 = \lvert a - b \rvert > 0$, and $\lvert a - b \rvert < \varepsilon0$ is false. $\blacksquare$

This is how analysis proves equalities: not by computing both sides, but by showing their distance is smaller than any positive tolerance.

Chapter 3 — Supremum, infimum and completeness

Terminology

- Upper bound — $b$ is an upper bound of $A \subseteq \mathbb{R}$ if $a \le b$ for every $a \in A$. $A$ is bounded above if it has one.- Lower bound, bounded below — the same with $\ge$. Bounded means bounded above and below.- Supremum (least upper bound) — $s = \sup A$ if (i) $s$ is an upper bound of $A$, and (ii) $s \le b$ for every upper bound $b$ of $A$.- Infimum (greatest lower bound) — $\inf A$, defined the same way with the inequalities reversed.- Maximum — an element of $A$ that is an upper bound of $A$. A set may have a supremum but no maximum.

A supremum is unique when it exists: if $s1$ and $s2$ are both least upper bounds, then $s1 \le s2$ and $s2 \le s1$.

Examples

| Set $A$ | $\sup A$ | Attained (a max)? | $\inf A$ ||---------|----------|-------------------|----------|| $[0, 1]$ | $1$ | yes | $0$ || $(0, 1)$ | $1$ | no | $0$ || $\{1 - 1/n : n \in \mathbb{N}\}$ | $1$ | no | $0$ (a min) || $\{1/n : n \in \mathbb{N}\}$ | $1$ | yes | $0$ (not a min) || $\mathbb{N}$ | none (not bounded above) | — | $1$ |

For $A = \{1 - 1/n\}$: $1$ is an upper bound since $1/n > 0$. If $b < 1$, the Archimedean property (Chapter 4) gives $n$ with $1/n < 1 - b$, so $1 - 1/n > b$ and $b$ is not an upper bound. For example, $b = 0.85$ is beaten by $1 - \tfrac17 = \tfrac67 \approx 0.857$ (and $n = 7$ is the first index that works, since $1 - \tfrac16 \approx 0.833$). Hence $\sup A = 1$, and $1 \notin A$.

The epsilon characterization

Lemma. Let $s$ be an upper bound of $A$. Then $s = \sup A$ if and only if for every $\varepsilon > 0$ there is some $a \in A$ with $s - \varepsilon < a$.

Proof. ($\Rightarrow$) Let $\varepsilon > 0$. Since $s - \varepsilon < s$ and $s$ is the least upper bound, $s - \varepsilon$ is not an upper bound. So some $a \in A$ has $a > s - \varepsilon$.

($\Leftarrow$) Let $b$ be any upper bound with $b < s$. Put $\varepsilon = s - b > 0$. By hypothesis some $a \in A$ has $a > s - \varepsilon = b$, contradicting that $b$ is an upper bound. So every upper bound $b$ satisfies $b \ge s$, and $s = \sup A$. $\blacksquare$

In pictures: nothing in $A$ lies to the right of $s$, but every window $(s - \varepsilon, s]$, however narrow, contains a point of $A$.

The Axiom of Completeness

> Axiom of Completeness (least upper bound property). Every nonempty set of real numbers that is bounded above has a supremum in $\mathbb{R}$.

$\mathbb{R}$ is defined to be an ordered field that satisfies this axiom. (Such a field exists and is unique up to an order-preserving isomorphism; the standard constructions use Dedekind cuts, as in Rudin Chapter 1, or Cauchy sequences of rationals, as in Tao Chapter 5. This course takes the axiom as the starting point, as Abbott does.)

The axiom for infima follows. If $A$ is nonempty and bounded below, then $-A = \{-a : a \in A\}$ is nonempty and bounded above, and $\inf A = -\sup(-A)$.

Why $\mathbb{Q}$ fails the axiom. Let $S = \{r \in \mathbb{Q} : r^2 < 2\}$. It is nonempty ($1 \in S$) and bounded above by $2$. Suppose it had a least upper bound $s$ in $\mathbb{Q}$. The argument in Chapter 4 (existence of $\sqrt{2}$) shows that $s^2 < 2$ and $s^2 > 2$ are both impossible, so $s^2 = 2$; but no rational squares to $2$. So $S$ has no supremum in $\mathbb{Q}$: the rationals have a hole exactly where $\sqrt{2}$ should be. Concretely, $1, 1.4, 1.41, 1.414, \ldots$ are in $S$ (their squares are below $2$; for example $1.414^2 = 1.999396$), while $1.5, 1.42, 1.415, \ldots$ are rational upper bounds ($1.415^2 = 2.002225$). Every rational upper bound can be improved, and the two lists close in on a point that $\mathbb{Q}$ does not contain.

Working with suprema

Two small results, each proved with the lemma above, are used often.

- Shift: for $c \in \mathbb{R}$, $\sup(A + c) = \sup A + c$, where $A + c = \{a + c : a \in A\}$. (If $s = \sup A$, then $s + c$ is an upper bound of $A + c$, and for each $\varepsilon$ some $a > s - \varepsilon$ gives $a + c > (s + c) - \varepsilon$.)- Order: if $A \subseteq B$, $A$ is nonempty and $B$ is bounded above, then $\sup A \le \sup B$. (Every upper bound of $B$ is an upper bound of $A$.)

> Common pitfall: assuming $\sup A \in A$. The supremum of $(0,1)$ is $1$, which is not in the set. Proofs that pick "the largest element of $A$" are wrong unless $A$ is finite or known to have a maximum.

Chapter 4 — First consequences of completeness

The Archimedean property

Theorem (Archimedean property).(i) For every $x \in \mathbb{R}$ there is $n \in \mathbb{N}$ with $n > x$.(ii) For every $y > 0$ there is $n \in \mathbb{N}$ with $1/n < y$.

Proof. (i) Suppose not: then $x$ is an upper bound of $\mathbb{N}$, so by completeness $\alpha = \sup \mathbb{N}$ exists. Then $\alpha - 1$ is not an upper bound, so some $n \in \mathbb{N}$ has $n > \alpha - 1$. But then $n + 1 > \alpha$ and $n + 1 \in \mathbb{N}$, contradicting that $\alpha$ is an upper bound of $\mathbb{N}$.(ii) Apply (i) to $x = 1/y$: some $n > 1/y$, so $1/n < y$. $\blacksquare$

This property looks obvious, yet the proof needs completeness: there are ordered fields (for example suitably ordered fields of rational functions) with "infinitely large" elements, where it fails.

Density of the rationals

Theorem (density of $\mathbb{Q}$). For all real $a < b$ there is a rational $r$ with $a < r < b$.

Proof. By the Archimedean property choose $n \in \mathbb{N}$ with $1/n < b - a$. Let $m$ be the least integer with $m > na$ (it exists by the Archimedean property and well-ordering), so $m - 1 \le na < m$. Then $a < m/n$, and

$$m \le na + 1 < na + n(b - a) = nb,$$

using $1 < n(b - a)$. So $a < m/n < b$. $\blacksquare$

The idea: steps of size $1/n$ are shorter than the interval, so one of the points $m/n$ must land inside.

Corollary. The irrationals are dense too: between any $a < b$ there is an irrational number. (Find a rational $r \ne 0$ with $a/\sqrt{2} < r < b/\sqrt{2}$; then $r\sqrt{2}$ is irrational and lies in $(a, b)$.)

Existence of the square root of 2

Theorem. There is $\alpha \in \mathbb{R}$ with $\alpha^2 = 2$.

Proof sketch. Let $T = \{t \in \mathbb{R} : t^2 < 2\}$. It is nonempty ($1 \in T$) and bounded above by $2$ (if $t > 2$ then $t^2 > 4$). Let $\alpha = \sup T$; note $\alpha \ge 1$. Show that the other two cases of trichotomy are impossible.

Case $\alpha^2 < 2$. For $n \in \mathbb{N}$,

$$\left(\alpha + \tfrac{1}{n}\right)^2 = \alpha^2 + \frac{2\alpha}{n} + \frac{1}{n^2} \le \alpha^2 + \frac{2\alpha + 1}{n}.$$

Choose $n$ with $\frac{1}{n} < \frac{2 - \alpha^2}{2\alpha + 1}$ (Archimedean property). Then $(\alpha + 1/n)^2 < 2$, so $\alpha + 1/n \in T$, contradicting that $\alpha$ is an upper bound.

Case $\alpha^2 > 2$. Now $\left(\alpha - \tfrac{1}{n}\right)^2 > \alpha^2 - \frac{2\alpha}{n}$. Choose $n$ with $\frac{1}{n} < \frac{\alpha^2 - 2}{2\alpha}$; then $(\alpha - 1/n)^2 > 2$, and $\alpha - 1/n > 0$. Any $t \in T$ with $t > \alpha - 1/n > 0$ would have $t^2 > (\alpha - 1/n)^2 > 2$, which is impossible. So $\alpha - 1/n$ is an upper bound of $T$ smaller than $\alpha$ — a contradiction.

So $\alpha^2 = 2$. $\blacksquare$

The same argument, with $\mathbb{Q}$ in place of $\mathbb{R}$, is the proof that $\{r \in \mathbb{Q} : r^2 < 2\}$ has no supremum in $\mathbb{Q}$: its supremum would have to square to $2$. With more algebra it gives $n$-th roots of every positive real.

The Nested Interval Property

Theorem (Nested Interval Property). For each $n \in \mathbb{N}$ let $In = [an, bn]$ be a closed bounded interval, with $I1 \supseteq I2 \supseteq I3 \supseteq \cdots$. Then $\bigcap{n=1}^\infty In \ne \emptyset$.

Proof. Nesting means $a1 \le a2 \le \cdots$ and $\cdots \le b2 \le b1$, and $an \le bm$ for all $n, m$ (with $k = \max(n,m)$: $an \le ak \le bk \le bm$). So the set $A = \{an : n \in \mathbb{N}\}$ is nonempty and bounded above by every $bm$. Let $x = \sup A$. Then $an \le x$ for all $n$ (upper bound) and $x \le bm$ for all $m$ (each $bm$ is an upper bound and $x$ is the least). So $x \in In$ for every $n$. $\blacksquare$

If in addition the lengths $bn - an$ shrink to $0$, the intersection is exactly one point.

> Watch out: both hypotheses are needed. The open intervals $(0, 1/n)$ are nested but their intersection is empty (any $x > 0$ is excluded once $1/n < x$). The closed but unbounded intervals $[n, \infty)$ are nested with empty intersection too. And in $\mathbb{Q}$ the property fails: intervals of rationals closing in on $\sqrt{2}$ have no common rational point.

Together with the Archimedean property, the Nested Interval Property is equivalent to the Axiom of Completeness. It is the version used in bisection arguments (Bolzano–Weierstrass in Real Analysis 01, the Intermediate Value Theorem in Real Analysis 02).

Chapter 5 — Countable and uncountable sets

Completeness makes $\mathbb{R}$ enormously larger than $\mathbb{Q}$, even though both are dense. Cardinality makes "larger" precise.

Terminology

- Function $f : A \to B$ — a rule assigning to each $a \in A$ one element $f(a) \in B$.- One-to-one (injective) — $f(a1) = f(a2)$ implies $a1 = a2$.- Onto (surjective) — every $b \in B$ equals $f(a)$ for some $a$.- Bijection — one-to-one and onto. $A$ and $B$ have the same cardinality, written $A \sim B$, if a bijection $A \to B$ exists.- Countable — $A \sim \mathbb{N}$ (an infinite list $a1, a2, a3, \dots$ with every element appearing exactly once). Uncountable — infinite and not countable.

The rationals are countable

First, $\mathbb{Z}$ is countable: the list $0, 1, -1, 2, -2, 3, -3, \dots$ is the bijection $f : \mathbb{N} \to \mathbb{Z}$ with $f(n) = (n-1)/2$ for odd $n$ and $f(n) = -n/2$ for even $n$.

Theorem. $\mathbb{Q}$ is countable.

Proof. For each $n \in \mathbb{N}$ let $An$ be the set of rationals that can be written as $\pm p/q$ in lowest terms with integers $p \ge 0$, $q \ge 1$ and $p + q = n$. For example $A1 = \{0\}$, $A2 = \{1, -1\}$, $A3 = \{1/2, -1/2, 2, -2\}$. Each $An$ is finite, the $An$ are disjoint, and every rational lies in exactly one of them. List $A1$, then $A2$, then $A3$, and so on. This list contains every rational exactly once, so it is a bijection with $\mathbb{N}$. $\blacksquare$

The reals are uncountable

Theorem (Cantor, 1874; diagonal argument 1891). The interval $(0, 1)$, and hence $\mathbb{R}$, is uncountable.

Proof. Every $x \in (0,1)$ has a decimal expansion $x = 0.d1 d2 d3 \ldots$. It is unique if expansions ending in an infinite string of $9$s are excluded (so $0.4999\ldots$ is written $0.5000\ldots$). Suppose $f : \mathbb{N} \to (0,1)$ were onto, and write

$$\begin{aligned}f(1) &= 0.\,a{11}\, a{12}\, a{13}\, a{14} \ldots \\f(2) &= 0.\,a{21}\, a{22}\, a{23}\, a{24} \ldots \\f(3) &= 0.\,a{31}\, a{32}\, a{33}\, a{34} \ldots \\&\ \ \vdots\end{aligned}$$

Define $x = 0.b1 b2 b3 \ldots$ by $bn = 2$ if $a{nn} \ne 2$ and $bn = 3$ if $a{nn} = 2$. This $x$ lies in $(0,1)$, its expansion has no $9$s (so it is the unique allowed one), and it differs from $f(n)$ in the $n$-th digit for every $n$. So $x \ne f(n)$ for all $n$, and $f$ is not onto. $\blacksquare$

Since $(0,1) \sim \mathbb{R}$ (for example via $x \mapsto \tan(\pi x - \pi/2)$), $\mathbb{R}$ is uncountable. Consequences:

- The irrationals $\mathbb{R} \setminus \mathbb{Q}$ are uncountable (if they were countable, $\mathbb{R}$ would be a union of two countable sets, which is countable).- Almost all real numbers are irrational, even though the rationals are dense. Density is about where points are; cardinality is about how many.

> Common pitfall: "the diagonal number might equal some $f(n)$ with a different expansion". That is exactly why the proof uses the digits $2$ and $3$ only and excludes trailing $9$s: the number $x$ has only one decimal expansion, so differing in a digit really means being a different number.

The Cantor set

Start with $C0 = [0,1]$. Remove the open middle third to get $C1 = [0, \tfrac13] \cup [\tfrac23, 1]$. Remove the open middle third of each piece to get $C2$, a union of $4$ intervals of length $\tfrac19$. In general $Cn$ is a union of $2^n$ closed intervals of length $3^{-n}$. The Cantor set is $C = \bigcap{n=0}^\infty Cn$.

- Length removed: at step $k$ you remove $2^{k-1}$ intervals of length $3^{-k}$, so the total is $\sum{k=1}^\infty 2^{k-1}/3^k = 1$. The Cantor set has "length zero".- Many points survive: $0$, $1$, $\tfrac13$, $\tfrac23$ and every endpoint stay forever. So does $\tfrac14$, which is never an endpoint: in base $3$, $\tfrac14 = 0.020202\ldots3$, since $\sum{k=1}^\infty 2/9^k = 2/8 = 1/4$.- Uncountable: $x \in C$ exactly when $x$ has a base-$3$ expansion using only the digits $0$ and $2$. Replacing each $2$ by $1$ and reading the result in base $2$ maps $C$ onto $[0,1]$, so $C$ is uncountable.

The Cantor set is the standard example of a set that is "small" in length but "large" in cardinality. It returns in Real Analysis 02 as a closed, compact set that contains no interval.

Practice Exercises

1. Write the negation of: "for every $M > 0$ there is $N \in \mathbb{N}$ such that for all $n \ge N$, $an > M$" (the definition of $an \to \infty$).

<details><summary>Solution</summary>

"There is $M > 0$ such that for every $N \in \mathbb{N}$ there is $n \ge N$ with $an \le M$." In words: there is a level $M$ at or below which infinitely many terms stay.

</details>

2. Prove by induction that $1 + 2 + \cdots + n = \frac{n(n+1)}{2}$ for all $n \in \mathbb{N}$.

<details><summary>Solution</summary>

Base: $1 = \frac{1 \cdot 2}{2}$. Step: if $1 + \cdots + n = \frac{n(n+1)}{2}$, then $1 + \cdots + n + (n + 1) = \frac{n(n+1)}{2} + (n+1) = \frac{(n+1)(n+2)}{2}$, which is the formula for $n + 1$.

</details>

3. Prove that $\sqrt{3}$ is irrational.

<details><summary>Solution</summary>

First, if $3$ divides $n^2$ then $3$ divides $n$: otherwise $n = 3k \pm 1$ and $n^2 = 9k^2 \pm 6k + 1$ leaves remainder $1$ on division by $3$. Now suppose $\sqrt{3} = p/q$ in lowest terms. Then $p^2 = 3q^2$, so $3$ divides $p$; write $p = 3k$. Then $9k^2 = 3q^2$, so $q^2 = 3k^2$ and $3$ divides $q$. Both divisible by $3$ contradicts lowest terms.

</details>

4. Find $\sup A$ and $\inf A$ for $A = \left\{ \frac{n}{n+1} : n \in \mathbb{N} \right\}$ and prove your answer for the supremum.

<details><summary>Solution</summary>

$\inf A = \frac12$ (the minimum, at $n = 1$, since $\frac{n}{n+1} = 1 - \frac{1}{n+1}$ increases with $n$). $\sup A = 1$: it is an upper bound since $\frac{n}{n+1} < 1$. Given $\varepsilon > 0$, choose $n$ with $\frac{1}{n+1} < \varepsilon$ (Archimedean); then $\frac{n}{n+1} = 1 - \frac{1}{n+1} > 1 - \varepsilon$. By the $\varepsilon$-characterization, $\sup A = 1$. It is not attained.

</details>

5. Let $A, B$ be nonempty and bounded above, and $A + B = \{a + b : a \in A, b \in B\}$. Prove $\sup(A + B) = \sup A + \sup B$.

<details><summary>Solution</summary>

Let $s = \sup A$, $t = \sup B$. For $a \in A$, $b \in B$: $a + b \le s + t$, so $s + t$ is an upper bound. Given $\varepsilon > 0$, pick $a > s - \varepsilon/2$ and $b > t - \varepsilon/2$; then $a + b > (s + t) - \varepsilon$. By the $\varepsilon$-characterization, $\sup(A + B) = s + t$.

</details>

6. Show that the intervals $In = (0, 1/n]$ are nested but have empty intersection. Which hypothesis of the Nested Interval Property fails?

<details><summary>Solution</summary>

$1/(n+1) < 1/n$ gives $I{n+1} \subseteq In$. If $x \le 0$, $x \notin I1$. If $x > 0$, choose $n$ with $1/n < x$ (Archimedean); then $x \notin In$. So the intersection is empty. The intervals are not closed (the left endpoint $0$ is missing).

</details>

7. Show that the set of all finite subsets of $\mathbb{N}$ is countable, but the set $\mathcal{P}(\mathbb{N})$ of all subsets of $\mathbb{N}$ is not.

<details><summary>Solution</summary>

Finite subsets: for each $n$, the subsets of $\{1, \dots, n\}$ form a finite collection ($2^n$ sets), and every finite subset of $\mathbb{N}$ belongs to one of these collections. List the first collection, then the new sets of the second, and so on; this lists every finite subset exactly once. All subsets: suppose $f : \mathbb{N} \to \mathcal{P}(\mathbb{N})$ were onto. Let $B = \{n : n \notin f(n)\}$. If $B = f(m)$, then $m \in B \iff m \notin f(m) = B$, a contradiction. (This is Cantor's theorem, the same diagonal idea.)

</details>

Chapter 2 — The V8 pipeline

V8 has one interpreter and three compilers. Each tier trades compile time for code quality:

| Tier | Kind | Shipped | Input → output | Why it exists ||---|---|---|---|---|| Ignition | Interpreter | V8 5.9 / Chrome 59 (with TurboFan) | Source → bytecode, then executes it | Fast start, small memory, collects type feedback || Sparkplug | Baseline (non-optimising) compiler | Chrome 91 | Bytecode → machine code in one linear pass, no IR | Removes interpreter dispatch cost almost for free || Maglev | Mid-tier optimising compiler | Chrome 117 | Bytecode + feedback → SSA/CFG IR → machine code | Good code quickly: about 10× slower to compile than Sparkplug, about 10× faster than TurboFan (V8 team's figure) || TurboFan | Top-tier optimising compiler | V8 5.9 | Bytecode + feedback → heavily optimised machine code | Peak speed for truly hot code; its JavaScript backend now runs on the CFG-based Turboshaft IR |

Parsing: most functions are parsed twice

Full parsing is expensive, and most functions in a large bundle never run. V8 therefore pre-parses inner functions: it checks syntax and records which variables they capture, but builds no AST and no bytecode. The full parse and bytecode generation happen on the first call ("lazy compilation"). A function that is called immediately pays twice, so V8 uses heuristics — for example a function expression wrapped in parentheses () is compiled eagerly.

Consequences:

- Startup cost is dominated by how much code is parsed, not how much exists. Code splitting and lazy  help because unparsed code costs nothing.- Compiled bytecode can be cached. Chrome caches it for scripts it sees repeatedly; Node offers a module compile cache (, added in v22.1.0) that persists it to disk between runs, useful for CLIs.

The bracketed numbers after each operation are feedback slots. Every property access, call and arithmetic operation records what it saw — which object shapes, whether the operands were small integers or doubles — into the function's feedback vector. Everything the optimising tiers do is built on this record. Code that never ran has no feedback, and the optimisers cannot specialise it.

Tiering up and OSR

V8 counts how much a function runs (invocations and loop iterations, weighted by bytecode size) and promotes it when budgets run out. The exact thresholds are internal heuristics that change between releases; do not design around numbers.

A long-running loop inside a function that is called only once would never tier up by call count, so V8 performs on-stack replacement (OSR): it compiles an optimised version while the loop is running and jumps into it mid-loop.

Speculation is the whole trick

It emits a cheap check (a guard) followed by a fast path — a load at a fixed offset, an integer add. If the guard fails at run time, the optimised code cannot continue; it deoptimizes (Chapter 5). Chapter 4 — Inline caches and polymorphism

An inline cache (IC) is the feedback slot of one property access or call site. It remembers which maps it has seen and, for each, where the property lives.

| IC state | Maps seen | What the fast path does | Optimisable? ||---|---|---|---|| Uninitialised | 0 | Nothing yet; the access has not run | No feedback, the optimiser inserts a deopt point || Monomorphic | 1 | One map check, then a load at a known offset | Best case || Polymorphic | 2–4 | A short chain of map checks | Yes, slightly slower per extra map || Megamorphic | more than 4 | Gives up per-site caching; uses a global stub cache (hash table) | TurboFan cannot inline the access |

Smis and heap numbers

V8 represents small integers as Smis — tagged values stored directly in the pointer, with no allocation. Chapter 7 — The Orinoco garbage collector

Terminology

- Generational hypothesis — most objects die young. A GC that collects young objects often and cheaply wins.- Young generation — where new objects are allocated. In V8 it is split into a nursery and an intermediate generation.- Old generation — objects that survived two young collections.- Scavenge (minor GC) — copying collection of the young generation.- Mark-Compact (major GC) — marking live objects in the whole heap, sweeping dead ones, compacting fragmented pages.- Write barrier — a small piece of code the engine runs on every pointer store into the heap, so concurrent or incremental marking does not miss new references, and old-to-young pointers are remembered.- Stop-the-world pause — time the main thread spends in GC instead of running JavaScript.

Young generation: the scavenger

New objects go into the nursery with bump-pointer allocation (very cheap). When the young space fills, a scavenge copies live objects out: survivors of their first scavenge become intermediate; survivors of a second are promoted to the old generation. The young generation uses a semi-space design, so half of it is always empty to receive the copies. Cost is proportional to the number of live objects, not the garbage — dying young is nearly free.

The scavenger runs in parallel on helper threads; the V8 team measured a 20–50% reduction in main-thread young-generation GC time from parallel scavenging.

Node exposes the size knob:  (MiB). The Node docs note that the young generation is three times the semi-space size, so +1 MiB of semi-space adds 3 MiB of heap. Raising it can cut scavenges for allocation-heavy servers; benchmark before and after.

Old generation: concurrent mark-compact

- Marking finds everything reachable from the roots (stack, globals, handles). V8 does most of it concurrently on background threads while JavaScript runs, plus incremental steps on the main thread. Write barriers keep it correct while your code mutates the heap.- Sweeping frees dead objects' memory into free lists, concurrently.- Compaction moves objects out of fragmented pages, in parallel, during a pause.- Large objects (above a size threshold) live in a separate large-object space and are never moved.- Idle-time GC: the browser tells V8 when a frame finished early, and V8 uses the idle slice for GC work.

Concurrent marking and sweeping reduced pause times in heavy WebGL games by up to 50%, per the V8 team.

In Chrome, Blink's C++ DOM objects are managed by Oilpan () and traced together with the JavaScript heap, so a cycle between a DOM node and a JavaScript closure is still collectable.

Chapter 1 — The problem Kubernetes solves (and when you do not need it)

Terminology

- Orchestrator — a system that decides which container runs where, restarts it when it dies, and keeps its identity on the network stable while the underlying process moves.- Desired state — a declaration of what the cluster should look like, stored in the API server. Actual state — what is really running, as reported by the nodes.- Reconciliation — the continuous work of shrinking the gap between the two.- Controller — a process whose entire job is one reconciliation loop for one kind of object.- Node — a machine that runs workloads. Control plane — the components that store desired state and drive reconciliation.

What breaks at fleet scale

Compose (Post 02) works beautifully on a single host and stops working the moment you need any of the following:

| Need | Single host with Compose | Kubernetes ||------|--------------------------|------------|| Survive a host dying | you notice, you fix it | scheduler places replacements on surviving nodes || Run 40 replicas across 6 machines | write your own placement | scheduler does bin-packing || Roll out a new version with no downtime | scripted, bespoke, fragile | built-in rolling update with health gating || Stable address for a moving process | hardcode IPs or add Consul | Service + cluster DNS || Express "3 of these, always" | none | a single declarative object |

The common thread is convergence. Every one of those is "keep reality matching a description", which is exactly the loop Kubernetes implements once and reuses for everything.

When you do not need Kubernetes

This deserves to be said plainly, because the cost of Kubernetes is real: a control plane to run or pay for, a YAML surface area to learn, an upgrade treadmill roughly every four months, and an on-call rotation that now has to understand a distributed system underneath the application.

Do not reach for Kubernetes when:

- You run one or two services on one or two machines and a few minutes of downtime is acceptable. Compose plus a systemd unit and a restart policy is genuinely simpler and genuinely reliable.- Your workload is bursty and stateless — a managed serverless or PaaS runtime (Cloud Run, Fargate, App Runner, Fly, Render) removes the entire operational tier.- You have no platform owner. Kubernetes without someone responsible for it degrades into an unpatched cluster running a version nobody dares upgrade.- The team is three engineers shipping a product. The orchestration you save is smaller than the orchestration you acquire.

Reach for Kubernetes when you have many services, more than one team deploying, an existing cluster to piggyback on, an on-prem or sovereign requirement, or a genuine need for the ecosystem (operators, service mesh, policy engines) built on its API.

> Watch out: "we might need to scale later" is not a reason to adopt Kubernetes today. Migrating a containerised app onto Kubernetes later is a bounded, well-trodden project. Running a cluster you do not need for two years is not.

Chapter 5 — Pods, ReplicaSets and Deployments

Why the Pod, not the container

A Pod is one or more containers that are scheduled together, share a network namespace and an IP address, can share volumes, and live and die as a unit. It is the smallest thing Kubernetes schedules.

The reason for the extra layer is that some containers are genuinely useless alone. A log shipper that tails  must be on the same filesystem as the app. A proxy that terminates mTLS for the app must be on the same network stack as the app. Making the group the schedulable unit means those helpers can be separate images with separate lifecycles and still be guaranteed co-location.

What is shared

- Network namespace — every container in the Pod sees the same interfaces and the same IP. They reach each other over , and they must not bind the same port. This is the most common Pod authoring bug: two containers both listening on 8080.- IPC namespace and hostname.- Volumes — declared at Pod level, mounted independently in each container.

Not shared by default: the filesystem (each container keeps its own image root) and the PID namespace (opt in with ).

Init containers

Init containers run to completion, in order, before any app container starts. If one fails, the kubelet restarts it (subject to the Pod restart policy) and the app containers never start.

Use them for schema migrations, waiting on a dependency, fetching config into a shared volume, or setting kernel parameters in a privileged container so the app container needs no privileges.

Sidecars — including the native kind

Historically a "sidecar" was just a second entry in , and it had two well-known defects: it could start after the app container needed it, and in a Job it would keep running forever after the main container exited, so the Job never completed.

Kubernetes solved this by giving init containers a , which turns them into native sidecars: they start in init order (so before the app), they keep running alongside it, and they are terminated automatically after the app containers exit. The feature was alpha in 1.28, beta and on by default in 1.29, and graduated to stable in Kubernetes 1.33.

> Trick: if a Job of yours has ever hung at "1 of 2 containers still running", the native sidecar is the fix. On clusters older than 1.29, fall back to having the main container write a sentinel file that the sidecar watches for and exits on.

You almost never write a bare Pod

A Pod on its own is not rescheduled if its node dies. Write a Deployment, StatefulSet, DaemonSet, or Job — all of which manage Pods for you. Bare Pods are for debugging ().

ReplicaSet

A ReplicaSet has exactly one job: ensure N Pods matching this selector exist. It counts, and it creates or deletes to close the gap. You rarely write one directly.

Deployment

A Deployment manages ReplicaSets to provide versioned, controlled rollouts. Change the Pod template and the Deployment controller creates a new ReplicaSet, scales it up while scaling the old one down, and keeps the old one around at zero replicas so you can roll back.

Pods are mortal and their IPs are ephemeral. A Service is a stable virtual IP plus a DNS name in front of a label-selected set of Pods.

How kube-proxy implements it

A Service IP is not owned by any interface — nothing is listening on it. kube-proxy watches Services and EndpointSlices and programs the node's networking so that packets addressed to the virtual IP are rewritten to a real Pod IP:

- iptables mode (long-standing default) — NAT rules with probabilistic jumps. Simple and robust, but rule count grows with Service × endpoint count, so very large clusters see slow reprogramming.- IPVS mode — kernel load balancing with hash tables: better at scale, real scheduling algorithms.- nftables mode — the modern replacement for the iptables backend, fixing its scaling behaviour; the direction of travel.- eBPF datapaths (Cilium and friends) can replace kube-proxy entirely.

The decision is made per connection, in the kernel, on the client's node — no hop through a central box. It is also L4 only, so long-lived HTTP/2 or gRPC connections pin to one backend and will not rebalance. For L7 balancing you need an Ingress, a Gateway, or a mesh (Post 07).

Chapter 7 — Kafka topics + partitioning

For Mongo source events:

- One topic per collection (default) — easy.- Topic key = document  → events for the same doc land in the same partition → preserved order per doc.

For Debezium Postgres source:

- One topic per table.- Key = primary key → ordered per row.

Partition count = expected throughput. Default 6-12 partitions per topic for medium throughput. Don't go to 100 unless you have parallel consumers to match.

Retention: 7 days default. For replay scenarios, 30 days. For Event Sourcing (Post 21), forever (compact topic or off-cluster archive).

Chapter 8 — Schema Registry + Avro / JSON Schema

Without a registry, every consumer must parse JSON heuristically + handle schema changes manually.

With Confluent Schema Registry (or Apicurio, Karapace):

- Producers register schemas.- Consumers fetch schema by ID embedded in each message.- Compatibility rules enforced (backward, forward, full).

Format choice: Avro (binary, compact, strong typing) for high-volume; JSON Schema (human-readable, debuggable) for moderate. Avro is the Kafka native; JSON Schema gaining ground.

Connectors support both. Configure once; downstream consumers get type safety + evolution rules for free.

Chapter 9 — Deduplication + ordering — same rules as outbox

Kafka delivers at-least-once (default). Consumers must be idempotent.

Patterns:

- Key by business ID → idempotent upserts at the sink.- Optimistic versioning — sink rejects events with .- Tombstone records for deletes (key = ID, value = null) — compaction-friendly.

Ordering:

- Within a partition: guaranteed.- Across partitions: not guaranteed.- Key your events so all events for one entity land in one partition.
