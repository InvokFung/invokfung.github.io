Chapter 5 — Copy semantics The compiler generates a copy constructor and copy assignment operator by default. They do member-wise copy. For most classes this is fine. For classes that own raw memory, you must define them. The default member-wise copy would have copied the pointer — both objects would point to the same memory, and the second destructor would double-free. Classic bug. Chapter 6 — Move semantics (C++11+) Moving = transferring ownership of resources without copying. Crucial for performance when you want a new object to take over what an old one had. When does move happen?- Returning a local from a function.- cast.- Passing a temporary (rvalue) to a constructor. > Trick: if you implement copy + dtor by hand, also implement move. Otherwise the compiler won't generate move automatically, and your class falls back to copies in performance-critical places. The Rule of Five If you write any of: destructor, copy ctor, copy assign, move ctor, move assign — you should write (or / ) all five. The Rule of Zero If your class only owns members that already handle their own copy/move/destruction (smart pointers, standard containers), write none of the five. Let the compiler default everything. This is the modern way. Reach for explicit Rule-of-Five only when wrapping a C library or hand-managing memory.
