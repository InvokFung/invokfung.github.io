MongoDB has had multi-document ACID transactions since 4.0 (replica sets) and 4.2 (sharded clusters). Chapter 7 ??When NOT to use transactions Transactions are powerful + tempting, but expensive. Cheaper alternatives: Single-document atomicity (free) The whole update is atomic. Chapter 1 ??The mental shift SQL: design schema first, query later.MongoDB: start from the queries you want to run, design schema to make them efficient. Two principles: 1. Chapter 2 ??Embed vs reference Embed (sub-document or array) Pros:- One document fetch returns the whole thing.- Atomic writes across the whole document.- No joins.
