Chapter 4 — Point-in-Time Recovery (PITR) Snapshots give you "the state as of snapshot time". PITR lets you restore to any second within a retention window — recover from "we accidentally dropped this collection 22 minutes ago". Atlas Atlas continuous backup ships PITR by default on dedicated tiers. Restore via UI: pick a point in time, choose target (new cluster, in-place, or download). Retention configurable (typical: 7-30 days continuous + monthly snapshots for longer retention). Self-hosted Use Percona Backup for MongoDB (PBM) or MongoDB Cloud Manager for PITR. Configure base snapshot + oplog archive to S3 / GCS / Azure Blob. Chapter 5 — Restore drills A backup is meaningless if you've never tested it. Schedule: - Monthly: pick a random recent backup; restore to a temporary cluster; verify a small sanity-check query returns expected data. Record RTO (time taken).- Quarterly: full PITR drill — restore a DB to a specific past second.- Annually: tabletop disaster scenario (region down). Walk through your runbook. Track: - RTO (Recovery Time Objective) — how long restore takes.- RPO (Recovery Point Objective) — how much data you'd lose (depends on backup frequency + oplog window). MongoDB Course — 13 · Security — Auth, RBAC, TLS, KMS, CSFLE, Queryable Encryption

A leaky MongoDB is one of the worst possible operational mistakes — open instances on the public internet are ransomwared within hours. Chapter 6 — Encryption at rest Self-hosted (Enterprise / Atlas): - WiredTiger native encryption — AES-256 with keys from KMIP, Vault, Azure Key Vault, GCP KMS, AWS KMS, or a local keyfile.- Atlas: enabled by default with customer-managed keys (CMK) optional on dedicated tiers. Backups, snapshots, oplog files are all encrypted on disk. Encryption at rest protects against disk theft. It does NOT protect against a logged-in attacker (they have the cluster's own decryption key, transparently). For that, you need field-level encryption (next). Chapter 7 — Client-Side Field-Level Encryption (CSFLE) Sensitive fields are encrypted by the driver before they leave the application. The server only ever sees ciphertext. Algorithm matters: - Deterministic — same plaintext → same ciphertext. Allows equality lookups ().- Random — same plaintext → different ciphertext each time. Hides distribution + frequency but no equality lookups. The driver intercepts queries + writes, encrypts/decrypts as needed. Server, admins, backups, replicas all see ciphertext only. Key Management: data keys are encrypted by a master key held in your KMS (AWS KMS, Azure Key Vault, GCP KMS, KMIP). The key vault collection stores encrypted data keys; the master key never leaves the KMS. Constraints with CSFLE: - Only equality queries on deterministically-encrypted fields.- No range / sort / aggregation on encrypted fields.- For "range queries on encrypted data" → use Queryable Encryption. Chapter 8 — Queryable Encryption (GA in 7.0) Queryable Encryption extends field-level encryption to support equality + range + prefix queries on encrypted data — without ever decrypting on the server. Use cases: - PII fields needing search (email lookup for password reset).- Salaries, balances, ages — range queries while keeping plaintext invisible to DBAs.- Compliance (HIPAA, GDPR) — data is encrypted to ops staff but still queryable to apps with the right key. Caveats: slower than unencrypted queries; some index types unsupported; key management complexity. Plan carefully. Atlas: Queryable Encryption is supported on dedicated tiers + recent Mongo versions. Chapter 9 — Audit log The audit log records authentication + authorization + operations. Self-hosted (Enterprise): Atlas: audit logs available on dedicated tiers; shipped to S3, splunk, etc. Standard ops to audit: privileged role grants, user creation, collection drops, failed logins, schema changes. Created2026-06-26|Programming 3D
Post-processing is the cinematic polish — bloom on bright highlights, depth of field on out-of-focus regions, ambient occlusion in crevices, anti-aliasing on jagged edges. Three.js does it via the EffectComposer pipeline: render the main scene into a texture, then pass that texture through one or more screen-space passes that read in / write out. Chapter 1 — Why postprocess The raw render is "physically correct" but rarely cinematic. Each is a full-screen pass. Each costs ms. Use sparingly on mobile (Post 08). A scene that hits 144 fps on a gaming laptop can collapse to 8 fps on a three-year-old Android. Chapter 1 — Pixel ratio (the biggest free win) A modern phone may report — meaning a 400×800 logical viewport renders at 1200×2400 actual pixels. MongoDB has had multi-document ACID transactions since 4.0 (replica sets) and 4.2 (sharded clusters). They look like SQL transactions (), behave like SQL transactions (snapshot isolation), and carry SQL-like costs (locking, latency, contention). Chapter 1 — Why transactions in MongoDB Single-document updates are already atomic in MongoDB — that's true for any update operator on one document, no transaction needed.
