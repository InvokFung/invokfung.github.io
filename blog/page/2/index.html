Dev Essentials — 17 · How LLMs Work in Practice — Tokens, Context, Sampling and Embeddings
Created2026-09-11|Dev Essentials
A large language model (LLM) reads text as tokens and predicts the next token, again and again. That one idea explains most of the surprises developers meet: why a prompt costs what it costs, why a long chat "forgets" how it started, why the same question gets two different answers, and why a model can state a false fact with full confidence. This post builds the mental model step by step: tokens, the transformer, training, the context window, sampling and embeddings. Then it covers hallucinations and three API features you will meet everywhere. It opens Part D, and the next two posts build on it. The ideas apply to every vendor; the runnable examples use Python, NumPy, and the Anthropic Python SDK. > Series map: 01 Text Encoding → … → 16 CI/CD → 17 How LLMs Work (this post) → 18 Coding with AI Agents → … → 24 Desk Health. Part D · AI tools. Learning Outcome - Explain what a token is, why tokens are not words, and why code and non-English text often cost more.- Train a toy BPE tokenizer, and count real tokens with Anthropic's token-counting endpoint.- Describe next-token prediction and attention at an intuition level.- Name the training stages: pretraining, instruction tuning, and preference training (RLHF, AI feedback).- Explain the context window, what fills it, and what happens when a request is too big.- Use temperature, top-k and top-p correctly, and know which current models still accept them.- Turn text into embeddings and compare them with cosine similarity.- Explain why hallucinations happen, and reduce them.- Recognise prompt caching, tool use and extended thinking in an API. Chapter 1 — Tokens and tokenizers Setup You need Python 3.10 or newer (the 1.x SDK requires it) and, for the API examples, a key from the Anthropic Console. Terminology | Term | Meaning ||------|---------|| Token | One chunk of text from the model's fixed list: a word, part of a word, a space plus a word, a symbol, or a byte. || Vocabulary | The fixed list of all tokens a model knows. Each token has an integer ID. || Tokenizer | The program that turns text into token IDs and back. It is fixed before training. || BPE | Byte Pair Encoding: build a vocabulary by merging the most frequent neighbouring pieces, over and over. | Tokens are not words The model never sees letters or words. It sees a list of integers. A common word may be one token; a rare word may be three or four. Spaces, punctuation and line breaks use tokens too. A rule of thumb from Anthropic's models page (vendor spec, September 2026): on the tokenizer Claude has used since Claude Opus 4.7, 1M tokens is roughly 555k English words, or 2.5M Unicode characters. Earlier models fit about 750k words in 1M tokens. So the same text gives a different count on a different model. Tokens matter because almost every limit uses them: price (per million input and output tokens), the context window (Chapter 4), (the cap on what the model writes) and rate limits. BPE in one example Byte Pair Encoding was brought into neural machine translation by Sennrich, Haddow and Birch (ACL 2016) to handle rare words as sequences of smaller units. Training: split every word into characters, count every neighbouring pair, merge the most frequent pair, repeat. Tokenizing: replay the merges in the same order. Many modern tokenizers run the same idea on UTF-8 bytes, so any text can be encoded (see Dev Essentials 01 · Text Encoding). Output: is common, so it becomes one token. never appeared, so it breaks into known pieces plus single letters. Common text becomes few tokens. Rare text becomes many. Why code and non-English text often cost more Merges are learned from the tokenizer's training data. Whatever is common there gets long tokens. - Non-English text. Petrov et al. (NeurIPS 2023) tokenized the same text translated into many languages and found lengths that differ by up to 15 times in some cases (independent measurement). A Chinese character is also 3 bytes in UTF-8, so a byte-level tokenizer starts from more pieces.- Code. The Codex paper (Chen et al., 2021) found the GPT-3 text tokenizer "not very effective for representing code", with whitespace the largest waste. Adding tokens for runs of spaces cut code token counts by about 30% (vendor research paper). Measure your own data instead of trusting a rule of thumb. Anthropic's token-counting endpoint is free (rate-limited by usage tier) and returns an estimate for the exact model you name: A higher means that kind of text is packed more tightly. Each count includes a few tokens of message framing, which is why the samples repeat 20 times. For scale, the docs show a tiny request (system "You are a scientist", message "Hello, Claude") counting as on . > Trick: count with both model IDs before you switch models. Anthropic's docs say Claude 4.7 and later models use a newer tokenizer that produces about 30% more tokens for the same text (vendor spec). Budgets and cost estimates move with it. Chapter 2 — Next-token prediction and the transformer Every LLM answer comes from the same loop: 1. Turn the prompt into token IDs.2. Run them through the network. It returns one score (a logit) per vocabulary token.3. Turn the scores into probabilities and pick one token (Chapter 5).4. Append it and repeat. Stop at an end token, a stop sequence or . Attention, at intuition level Almost every modern LLM is a transformer, from "Attention Is All You Need" (Vaswani et al., 2017). Its key part is self-attention: for each token, the model decides how much each earlier token matters right now. In "The animal didn't cross the street because it was tired", attention lets "it" pull in information from "animal". Each token makes a query (what am I looking for?), a key (what do I contain?) and a value (what do I pass on?): $$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{dk}}\right)V$$ For text generation, a causal mask stops each token from looking at later tokens. Real models stack many such layers, each with several attention "heads". What this means for you: - Output is written one token at a time, which is why APIs offer streaming. On Anthropic's current price list, output tokens cost five times as much as input tokens.- The model cannot go back. An early wrong token shapes everything after it. Reasoning before answering helps (Chapter 8).- Long inputs cost more compute. The paper lists self-attention cost per layer as $O(n^2 \cdot d)$ for sequence length $n$. Pretraining. The model learns to predict the next token over a very large text collection. It picks up grammar, facts, code patterns and reasoning habits, but does not reliably follow instructions yet.2. Instruction tuning. Fine-tuning on demonstrations: a request, then a good response.3. Preference training. InstructGPT (Ouyang et al., 2022) describes classic RLHF: supervised fine-tuning on labeller demonstrations, then a reward model trained on rankings of model outputs, then reinforcement learning against it. Constitutional AI (Bai et al., 2022) replaces much human labelling for harmlessness: the model critiques and revises its own answers against written principles, and a preference model trained on AI comparisons gives the reward (RLAIF). In practice: - Knowledge has a cutoff. Anthropic lists a "reliable knowledge cutoff" per model (vendor spec): for example Feb 2025 for Claude Haiku 4.5 and Jun 2026 for Claude Opus 5.5.- The model knows nothing about your private code or data. You supply it through context: prompts, files, retrieved documents (post 19), tool results (post 18). Chapter 4 — The context window The context window is everything the model can read while writing a response, including the response itself. Anthropic's docs call it the model's "working memory". It counts the system prompt, every message (including tool results, images and documents), tool definitions, and this turn's output including any thinking. The API is stateless. The model does not remember your last request, so a chat app resends the whole history every turn. Turn 10 pays for turns 1 to 9 again (Exercise 4 does the maths). Sizes change often. As of September 2026 (vendor spec), current Claude Opus, Sonnet and Fable models have a 1M-token window and up to 128k output tokens per request; Claude Haiku 4.5 has 200k and 64k. Check your API's docs. > Watch out: bigger is not automatically better. Anthropic's docs describe context rot: as the token count grows, accuracy and recall degrade. Choose what goes in with care. Ways to stay inside the window: trim the oldest turns; summarise them (Anthropic's server-side version is called "compaction"); retrieve only the relevant chunks (post 19); or start a fresh session from a short written summary (post 18). Temperature $T$ divides the logits first: $$pi = \frac{e^{zi / T}}{\sumj e^{zj / T}}$$ $T < 1$ sharpens the distribution, $T > 1$ flattens it, and as $T$ approaches 0 sampling approaches greedy decoding (always the top token). Why the same prompt gives different answers: above temperature 0 every token is a random draw, and one different early token changes everything after it. Even at 0, Anthropic's API reference says results will not be fully deterministic. Chapter 7 — Why hallucinations happen and how to reduce them A hallucination is fluent, confident text that is false or not supported by the given sources. Causes: - The goal is a plausible next token, not a true statement. A made-up citation can look very plausible.- Training and tests reward guessing. Kalai et al. (2025, "Why Language Models Hallucinate") argue that training and evaluation reward guessing over admitting uncertainty, like an exam with no penalty for wrong answers.- Missing knowledge: after the cutoff, private, or rare.- Missing or buried context: not in the prompt, or lost in a very long one. Fixes. Chapter 1 — The polymer physics that predicts printing behaviour Almost everything a filament does on the machine follows from two thermal transitions and one question about molecular order. Terminology - Glass transition temperature (Tg) — the temperature range over which an amorphous polymer (or the amorphous fraction of a semi-crystalline one) changes from a rigid, glassy solid into a soft, rubbery one. It is not a phase change with latent heat; it is a change in molecular mobility. Tg is a range, and the number a datasheet reports depends on the measurement method (DSC, DMA) and the heating rate.- Melting temperature (Tm) — the temperature at which crystalline regions melt. Only semi-crystalline polymers have a true Tm. Purely amorphous polymers soften progressively and have no sharp melting point.- Amorphous polymer — chains arranged with no long-range order, frozen in a tangle. Examples used in printing: ABS, ASA, PC, PETG (largely amorphous by design), most photopolymer resins after cure.- Semi-crystalline polymer — contains ordered crystalline domains embedded in amorphous regions. Examples: PLA (slow-crystallising, usually printed nearly amorphous), the nylons (PA6, PA12), PP, PEEK.- Heat deflection temperature (HDT) — the temperature at which a standard test bar deflects a specified amount under a specified load. A load-dependent engineering figure, not a material constant; always quoted with its stress level (commonly 0.45 MPa or 1.8 MPa).- Crystallinity — the mass fraction of the polymer that is in ordered crystalline domains. It changes with cooling rate and with annealing, and it drives stiffness, chemical resistance, opacity and shrinkage. Why Tg, not Tm, sets the service temperature A printed part carries load through solid polymer. Above Tg the amorphous fraction becomes rubbery: modulus drops by orders of magnitude, and a part that was rigid at room temperature will sag, creep and lose dimensional stability long before anything melts. This is why a PLA phone mount fails in a car parked in the sun even though PLA does not melt until far higher: the interior of a closed car in direct sun readily reaches the low end of PLA's Tg range. Three consequences worth internalising: 1. Compare service temperature against Tg, with margin. Treat Tg as the ceiling, and derate further if the part is loaded — polymers creep faster as they approach Tg (Post 07).2. Tm is a printing parameter, not a service parameter. It tells you roughly where the extruder must operate. It tells you nothing useful about whether a bracket survives on an engine bay.3. HDT is closer to what you want but still not it. HDT is measured at a specific stress on a specific bar geometry, in a solid moulded specimen — not a 3-perimeter, 15 %-infill print with anisotropic layer bonding. > Watch out: the Tg values circulating in the hobby community for a given material vary by 10–20 °C between sources, because different grades, different additives and different measurement methods genuinely give different numbers. Use them as a family ranking (PLA < PETG < ABS/ASA < PC), and use the specific spool's technical datasheet for anything that matters. Chapter 3 — Warping, shrinkage and the enclosure question Warping is not a mystery and it is not a bed-adhesion problem in origin — bed adhesion is only where the symptom appears. The physics Every polymer contracts as it cools. In a printed part, that contraction happens unevenly in time: the layer being deposited is at nozzle temperature, the layer below is somewhere between, and the first layer has been sitting on a heated plate for an hour. Each new layer solidifies and then tries to contract while bonded to a layer beneath that has already finished contracting and will not move. The result is a stress field locked into the part, tensile in the newer material, and it grows with every layer. That locked-in stress has to go somewhere. It is relieved by: - Curling — the free edges of the part lift, which is geometrically the cheapest way to relieve it. Corners lift first because they have two free directions.- Delamination — a layer interface splits, usually on a tall thin part or at a stress raiser.- Bed release — the whole part peels off the plate. Two independent quantities drive the magnitude: the total contraction from nozzle to room temperature (roughly the coefficient of thermal expansion times the temperature drop, plus any crystallisation shrinkage) and the temperature gradient through the part while printing. Why ABS needs an enclosure and PLA does not Run the comparison: - PLA is printed around 200 °C and, being effectively amorphous as printed, contracts modestly. Its Tg is around 55–65 °C, so the part becomes rigid at a temperature only a little above the bed, meaning the stress-accumulating window is short and the accumulated stress is small. An enclosure adds nothing and can hurt: it raises the temperature around the heatsink and hotend, promoting heat creep and jams.- ABS is printed around 250 °C, has a Tg around 100–110 °C, and contracts substantially. The part is above Tg — mobile, able to relax stress rather than store it — over a much larger part of its cooling path. An enclosure holds the chamber high enough that the part stays in that mobile, relaxing regime for longer, and it removes the gradients caused by room draughts. That is the mechanism: the enclosure is a stress-relief oven, not a heater for the plastic. Consequences that follow directly: | Symptom | Mechanism | Fix in order of leverage ||---|---|---|| Corners lift on a large flat ABS part | high contraction plus draught-driven gradients | enclosure; raise chamber temperature; brim; reduce part footprint or split the part || Part releases mid-print, PLA | adhesion, not warp | clean the plate (IPA, then soap and water for oils); first-layer squish (Post 01) || Tall PC part delaminates near the top | chamber cools with height; interface bonding falls | enclosure with an actively warm chamber; raise nozzle temperature; reduce cooling || Nylon curls despite an enclosure | crystallisation shrinkage plus moisture | dry the filament (Chapter 4) before blaming warp || Fibre-filled version of the same polymer warps less | fibres restrain matrix contraction | expected — this is a genuine benefit of CF/GF grades | > Common pitfall: adding a brim or raft to fight ABS warp. It buys a little and hides the cause. The stress is still in the part; you have merely bonded it harder to the plate, which converts corner lift into internal stress or a delamination crack higher up. Fix the thermal environment. > Trick: you can see the locked-in stress. Print a thin ABS bar without an enclosure, let it cool fully, then cut it lengthwise with a sharp blade. The two halves spring apart. A bar printed in a warm enclosure moves much less. This is a five-minute experiment that makes the whole chapter concrete. Chapter 4 — Moisture, the invisible variable Which polymers care Hygroscopic means the polymer absorbs water from air into its bulk, not just onto its surface. In rough order of severity for printing filaments: | Severity | Materials | Practical consequence ||---|---|---|| Extreme | PVA, PA (nylon), PC | unprintable within hours to days of open-air exposure in a humid room || High | TPU, PETG, ASA | visible surface and strength degradation over days to weeks || Moderate | ABS, PLA | degrades over weeks to months; PLA additionally hydrolyses when hot and wet, permanently shortening chains || Low | dried, sealed, unopened spools of anything | the state you want to maintain | The hydrolysis point matters and is often missed: for PLA and the polyesters, water is not just a bubble source. At extrusion temperature, absorbed water chemically cleaves the polymer chains. Drying removes the water but does not undo the chain scission. Wet-then-dried PLA prints acceptably and is measurably weaker than it should be. What wet filament looks and sounds like | Sense | Signature ||---|---|| Sound | intermittent popping, crackling, hissing at the nozzle — steam escaping || Extrusion | visible steam or micro-bubbles; the strand from a hand-purge is foamy or wavy rather than smooth || Surface | rough, matte, pitted; PETG turns hazy and blistered rather than glossy || Stringing | dramatically worse, and unresponsive to retraction tuning || Dimensions | inconsistent extrusion width; unpredictable flow calibration (this contaminates the Post 05 measurements) || Strength | reduced, often severely, especially interlayer || Cross-section | cut a purged strand: voids and bubbles inside the bead | > Common pitfall: tuning retraction for hours to chase stringing that is caused by moisture. Before any retraction tuning session, do the hand-purge test: extrude 100 mm by hand and look and listen. If it pops, dry the spool first and start the tuning session over. Drying Drying is a diffusion process: temperature sets the rate, time lets the water get out of the core of the spool. Getting the temperature wrong in the other direction fuses the spool. Published starting points — again, the spool's own datasheet wins, especially for filled and specialty grades: | Material | Typical drying temperature | Typical time | Note ||---|---|---|---|| PLA | 40–50 °C | 4–8 h | stay well below Tg or the spool welds to itself || PETG | 60–70 °C | 4–8 h | || ABS / ASA | 65–80 °C | 4–6 h | || TPU | 45–55 °C | 4–8 h | soft; low temperature, longer time || PVA | 45–55 °C | 6–12 h | re-wets almost immediately after || Nylon / PA | 70–90 °C | 8–12 h+ | manufacturers commonly specify the upper end || PC | 80–100 °C | 6–12 h | | The universal rule that makes those numbers safe: dry below the material's Tg, with margin, or the spool deforms and the windings fuse. That is why nylon tolerates 80–90 °C and PLA does not — nylon's amorphous fraction is not the load-bearing part of a spool wound from a semi-crystalline polymer, while PLA at 70 °C is above Tg and structurally soft. Equipment, ranked by how well it works: 1. Purpose-built filament dryer — controlled temperature, adequate airflow, can print directly from the box. The right answer if you print hygroscopic materials at all.2. Food dehydrator — cheap, good airflow, often needs the shelves cut out to fit a spool. Verify the actual temperature with a separate thermometer; dial markings on cheap units are frequently wrong by 10 °C or more.3. Convection oven — workable if it can hold a low temperature accurately. Many domestic ovens cannot regulate below 70–80 °C and cycle far above the setpoint. Verify with a thermometer before trusting it with a spool.4. The printer's heated bed with a box over it — a last resort, poorly controlled. Silica gel in a sealed box maintains dryness; it does not dry a wet spool in any reasonable time. Dry first, then store. Storage that actually works - Sealed container (vacuum bag or gasketed box) with indicating desiccant, plus a cheap hygrometer inside so you can see whether the system works. Target the lowest relative humidity you can maintain and hold; single digits is achievable in a good sealed box with fresh desiccant.- Regenerate desiccant on a schedule (bake per its instructions) — spent desiccant looks identical to fresh unless it is the indicating kind.- Dry boxes that feed the printer directly, for nylon, PC, PVA and TPU. For these materials, "dry it before printing" is not enough; a 20-hour print will re-absorb moisture from the room.- Sealed bags on unopened spools are only as good as the desiccant packed with them. A spool that has sat in a warehouse for two years is not automatically dry. Chapter 5 — Abrasives, multi-material adhesion, and soluble supports Abrasive filaments and nozzle wear Carbon fibre, glass fibre, metal-filled, wood-filled, glow-in-the-dark (glass or strontium aluminate particles) and many "sparkle" or "silk-matte" filaments contain hard particles. A standard brass nozzle is soft; those particles cut it. Soluble supports and their own moisture problems - PVA (polyvinyl alcohol) — dissolves in plain water. Compatible with PLA and (with care) PETG. It is the most hygroscopic common filament by a wide margin: it will absorb enough moisture to become unprintable within hours in a humid room, and wet PVA foams, oozes, jams and clogs. Chapter 6 — Properties you set after the print: annealing, post-cure, pigment Annealing Annealing is holding a printed part at an elevated temperature — above Tg but below the melting/softening point — for a period, then cooling it slowly. For a semi-crystalline polymer printed too fast to crystallise (PLA is the archetype), it does three things at once: 1. Increases crystallinity. Chains gain mobility above Tg and organise into crystalline domains. Stiffness, heat resistance and chemical resistance rise. Annealed PLA can retain useful stiffness meaningfully above its as-printed service ceiling — how much depends on the grade, the additives (nucleating agents in "HT" PLA grades are there specifically to make this work) and the schedule.2. Relieves internal stress. The locked-in stress from Chapter 3 relaxes. Good for stability, and it is why the part changes shape.3. Improves interlayer bonding somewhat. Chains interdiffuse across layer interfaces given mobility and time, reducing the Z-direction weakness of Post 07 — reducing, not eliminating. The cost is dimensional change, and it is not small. Crystallisation densifies the polymer, so the part shrinks — and it shrinks anisotropically, because the print's own layer structure and residual stress field are anisotropic. Parts also sag under their own weight if unsupported above Tg. Practical annealing procedure, if you decide the part needs it: 1. Decide first whether it does. Annealing is worth it for heat-exposed and stiffness-critical PLA parts. It is not worth it for anything that has to fit something else, unless you are prepared to re-measure and iterate.2. Support the part fully — bury it in dry sand, salt or plaster, or lay it on a flat plate with nothing overhanging.3. Hold above Tg but below softening: a common starting window for PLA is roughly 80–110 °C. Longer at a lower temperature is safer than shorter at a higher one.4. Cool slowly in the oven. Quenching re-introduces the stress you just removed.5. Measure the same features before and after and record the change as a percentage. That percentage is your machine-plus-material-plus-schedule constant, and you scale the CAD model by it next time. It is not a number anyone can give you — Post 05 gives the measurement discipline. > Watch out: annealing an amorphous polymer (ABS, PETG, PC) does not increase crystallinity, because there is no crystalline phase to grow. It still relieves stress, which can be useful, and it still causes dimensional change. Do not expect the stiffness gain that PLA shows. The critical structural fact: for photopolymer resin, a large share of the part's final mechanical properties is set by post-processing, not by printing. A green part straight out of the vat is under-polymerised, soft, and full of uncured monomer. Those numbers come from specimens cured on the vendor's validated schedule. An under-cured part is dramatically weaker; an over-cured part is more brittle. Post-cure is the variable, and it is yours to control. Colour, pigment and additives The single most under-appreciated fact about filament: colour is not cosmetic. The pigments, fillers and processing aids change the polymer's behaviour. - Thermal behaviour. Pigment loading changes melt viscosity and thermal conductivity. It is normal for two colours from the same vendor and the same product line to want different nozzle temperatures — sometimes by 10 °C or more.- Crystallisation. Some pigments act as nucleating agents. This changes crystallisation rate, which changes shrinkage and warping. Black and white parts of the same nominal material genuinely do not always behave the same.- Abrasion. Metallics, "silk", glitter and glow additives are abrasive. See Chapter 5.- Strength. High filler loading dilutes the polymer matrix. Heavily filled decorative filaments are usually weaker than the plain version of the same material.- Surface finish. Matte finishes come from filler particles that scatter light; they also hide layer lines, which is genuinely useful and is a materials effect, not a slicer effect.- UV behaviour. Carbon black is an effective UV absorber; black parts often outlast light-coloured ones of the same polymer outdoors. This is not a reason to skip ASA for an outdoor part, but it is a real effect. > Trick: when you switch colour within the same product line, re-run a temperature tower and a flow check before assuming your profile transfers. It costs twenty minutes and explains a surprising number of "the printer suddenly got worse" reports. Chapter 7 — Choosing a material, and printing it safely The decision tree Start from the requirement, not the material. Read down until a branch matches. Two meta-rules that outrank the tree: 1. Prototype in PLA regardless of the final material. Iterate the geometry cheaply and fast, then reprint the final version in the material the job needs. Changing material changes dimensions, so re-verify the fit (Post 05) — but do the geometry iteration in the easy material.2. Prefer the easiest material that meets the requirement. Every step up in material difficulty costs enclosure, drying, nozzle hardware, tuning time and failed prints. Only pay that when the requirement demands it. Safety Printing polymers releases ultrafine particles (UFPs) and volatile organic compounds (VOCs). This is measured, published science, not speculation. Peer-reviewed work characterising desktop FDM printers (Azimi et al., Environmental Science & Technology, 2016) found that emission rates and species depend strongly on filament and nozzle temperature: styrene dominates for ABS and HIPS, caprolactam for nylon-based and composite filaments, and lactide for PLA — with ABS emitting substantially more overall than PLA, and lower nozzle temperatures producing lower emission rates. ANSI/CAN/UL 2904 is the standard test method for characterising these emissions, and some printers and filaments are certified against it. The proportionate response: | Situation | Measure ||---|---|| Any printer, any material | do not print in a bedroom or an unventilated occupied room || PLA/PETG in a well-ventilated workshop | adequate room ventilation is a reasonable baseline || ABS/ASA/nylon/PC, or any long print | enclosure with a filter (HEPA for particles plus activated carbon for VOCs — a HEPA filter alone does nothing for VOCs), or vent the enclosure outdoors || Printing near where people sleep or work all day | vent outdoors, or move the printer || Any material, any enclosure | run the fan, and note that an enclosure without filtration concentrates emissions and then releases them when opened | Resin adds a different and more direct hazard class: - Uncured resin is a skin sensitiser. Nitrile gloves, always. Sensitisation is cumulative and can be permanent: people who handled resin carelessly for a year and then developed a reaction do not get to go back.- Eye protection when handling resin or IPA.- Ventilation — resin and IPA vapour both need it.- Never pour uncured resin, resin-contaminated IPA, or water-washable rinse water down a drain. Cure the waste solid under UV or sunlight first, then dispose of it as solid plastic waste, per local rules.- Cure everything, including failed prints, supports, drips and the paper towels. Cured resin is inert; uncured resin is not. Also mechanical and thermal, and easy to forget: hotends run at 200–300 °C, beds at up to 120 °C, and a printer with an unattended thermal runaway is a fire source. Verify that thermal runaway protection is enabled in firmware, keep the machine off carpet and away from anything flammable, and treat a smoke alarm in the print room as mandatory equipment rather than an optional extra. There is one decision in 3D printing that outweighs every slicer setting combined, and it is made in about two seconds by dragging a model around a build plate. Orientation simultaneously determines which direction the part is strong in, which surfaces come out smooth, how much support material is needed, how long the print takes, and how accurate the holes are — and those five objectives conflict with each other, so there is no orientation that wins on all of them. Chapter 1 — Orientation as the master decision Terminology - Build orientation — the rotation of the part relative to the build plate. Three rotational degrees of freedom, and every one of them matters.- Strength axis — the direction in which the part's layers run continuously, and therefore the direction it is strongest in.- Overhang — a downward-facing surface with nothing directly beneath it.- Bridge — an unsupported horizontal span with both ends anchored in solid material.- Support — sacrificial structure printed to hold up overhangs, then removed.- Interface layer — the dense top layers of a support, which form the surface the part rests on.- Z-gap / contact distance — vertical clearance between support top and part underside.- Self-supporting — geometry whose every downward face is shallow enough to print without support.- Scar — the rough surface left where support touched the part. The five conflicting objectives Every orientation is a bet across these: 1. Strength. The service load should run along the layers, not across them (post 00, Chapter 3).2. Surface quality. Vertical walls get layer lines; top faces get skin; downward faces get support scars; sloped faces get stepping.3. Support volume. More overhangs means more sacrificial material, more time, more cleanup, more scars.4. Print time. Roughly, taller means more layers means longer — but a tall thin part also has short layers with long minimum-layer-time waits, so it is not linear.5. Dimensional accuracy. XY features are accurate in a different way than Z features; holes behave completely differently depending on axis; the first layer is squashed. They conflict. The orientation that makes a bracket strongest usually also makes it tallest, slowest, and puts its bolt holes on their sides. Rank the objectives for this specific part before you rotate anything. For a functional bracket, strength and hole accuracy outrank surface finish. For a display model, the reverse. A worked part: the L-bracket Take a concrete part. An L-shaped bracket: two legs, 60 mm and 40 mm, each 4 mm thick and 30 mm wide, with two clearance holes through each leg. In service it is bolted to a wall by the short leg, and a load hangs from the end of the long leg, bending the bracket about the inside corner. Three orientations, all of which someone will suggest: Orientation A — flat on its back. The short leg lies on the plate, the long leg stands vertically. Layers are horizontal planes stacked up the long leg. Orientation B — L-profile flat on the plate. The L profile lies in the plane of the bed and the 30 mm width becomes the build height. Each layer is a complete L outline, 4 mm thick, repeated 30 mm tall. Orientation C — standing on the corner. The bracket balanced at 45°, corner down, both legs rising. | | A — flat on its back | B — L-profile flat | C — on the corner ||---|---|---|---|| Layer direction relative to the service load | tensile stress at the corner runs across layers | tensile stress runs along continuous roads that wrap the corner | stress at roughly 45° to layers || Strength under the design load | worst — a clean interlayer break at the inside corner is the predicted failure | best — the corner is a continuous loop of material every layer | intermediate || Support needed | none | none | yes, under the corner and the underside of both legs || Print time | short — 40 mm tall, big cross-sections | moderate — 30 mm tall, small L cross-sections, many layers of little material | longest — support plus a tall diagonal envelope || Bed footprint | small | large — the whole L profile | small || Hole axis | vertical through the short leg, horizontal through the long leg | horizontal through both legs | diagonal through both || Hole quality | mixed: one good, one egg-shaped | both need teardrop or chamfer treatment, or drilling | worst — diagonal holes are both overhung and stepped || Visible surface quality | good on the outer faces; layer lines up the long leg | layer lines wrap the profile; the two big flat faces are top-skin and bed-face | support scars on the underside of both legs || Adhesion risk | good — a big flat first layer | good — a long thin first layer, watch corner lift | poor — small contact area, needs a brim | The decision. Half of all orientation mistakes are made by people who have not consciously answered that question. Chapter 2 — The anisotropy rule The rule: load should run along layers, never peel them apart. Everything in post 00, Chapter 3 reduces to this. Material along a road is continuous polymer. Material across a layer interface is held together only by the chains that diffused across during the moments the interface was hot. The interface is always the weaker path. The failure modes even look different, which makes diagnosis easy: | | In-plane failure | Interlayer failure ||---|---|---|| Fracture surface | ragged, drawn, fibrous | flat, follows a single layer line, often glassy || Warning before failure | visible yielding, whitening, deformation | usually none — it goes suddenly || Fracture path | wanders through the section | perfectly planar and horizontal | If you snap a printed part and the break is a flat horizontal plane, the part was oriented wrong. That is the whole diagnosis. Three orientations of the same bracket, mechanically Return to the L-bracket. The load bends the long leg about the inside corner. Bending puts the outside of the corner in tension. - Orientation A: the tensile stress at the outer corner is vertical, i.e. perpendicular to the horizontal layers. The load is directly peeling the interfaces apart, one at a time, starting at the outermost fibre where the stress is highest. Failure is a clean horizontal snap at the corner, at a load far below what the material could take.- Orientation B: the tensile stress runs around the L profile, which is exactly the direction the perimeter roads run. Continuous polymer carries the load. The interfaces are loaded in shear rather than tension, and shear is a far more favourable loading for a weld.- Orientation C: the stress is at roughly 45° to the interfaces, giving a mixed mode. Better than A, worse than B, and it costs support material and surface quality on top. Two corrections to the rule It is not "print everything standing up" or "print everything flat". The rule is about the load, not about the part. A hook loaded in its own plane wants that plane flat on the bed; a hook loaded out of its plane wants the opposite. Reason from the load path every time. Walls do more than infill. As post 02 noted, in bending, material far from the neutral axis dominates. A part in the right orientation with four walls and 15 % infill will usually beat the same part in the wrong orientation at 60 % infill. Orientation first, walls second, infill third. It works because the extrudate is laid under tension — the nozzle is moving away from an anchored end, drawing the strand taut — and cools enough to hold its own weight before it sags appreciably. This is the good case, but it is not perfect: - Consistently undersized. Roads following a concave inner curve are compressed on their inner edge, so material bulges into the bore. Add die swell and elastic recovery and vertical holes come out reliably a little small. This is systematic and repeatable, which means it is correctable — post 05 covers the compensation.- Polygonal. The hole is only as round as the mesh's tessellation. A coarsely exported 5 mm hole can be a visible dodecagon.- Seamed. The perimeter loop's start/stop lands somewhere in the bore, leaving a small ridge. Painted seam placement helps. Horizontal holes (axis parallel to the bed) This is the problem case, and the mechanism is worth seeing clearly. Walk up a horizontal cylindrical bore layer by layer. At the widest point of the circle the bore wall is vertical. As you climb toward the crown, the wall angle sweeps continuously from vertical through 45° and on to horizontal at the very top. So the upper part of every horizontal hole is an increasingly severe overhang, and the last stretch before the crown is effectively an unsupported bridge across the bore. The results are consistent: - The top of the bore sags into the hole, so the hole is undersized at the top.- The cross-section becomes egg-shaped or D-shaped rather than circular.- The overhanging surface is rough, so a shaft binds even where the hole is nominally large enough.- The effect worsens with larger diameters (longer unsupported span) and with taller layers. The fixes, in order of preference 1. Reorient so the hole is vertical. Always consider this first. It is free and it is the best result. It is also why hole axes should be part of the orientation decision in Chapter 1, not an afterthought. 2. Teardrop the hole. Replace the top arc of the circle with two straight faces at 45° from vertical, meeting at a point — the classic teardrop profile. Every surface then satisfies the self-supporting criterion and nothing droops. Cost: the hole is no longer a true circle, so it suits clearance holes, cable passes and bolt shanks rather than precision bearing seats. 3. Chamfer the top of the hole. A less intrusive variant: replace only the top of the arc with a short flat roof and two 45° chamfers, giving a hexagon-topped bore. Preserves more of the circular profile than a full teardrop, still self-supporting, and the flat roof is a short, reliable bridge. 4. Print undersize and machine to size. Model the hole a little small, then drill or ream it. This is the accurate answer for anything that must actually be round and on-size, and it is the standard practice for bearing seats and dowel holes. 5. Leave it and rely on bridging. For large holes with a well-tuned bridging profile, the crown can be acceptable. Check the slicer preview to confirm the crown is being treated as a bridge. > Common pitfall: teardropping a hole that a bolt head or a bearing has to sit in. The teardrop's point is above the nominal circle, so the hole is larger than nominal at the top and a press fit will be loose there. Teardrops belong on clearance features, not on fits. Both types are worth having in your repertoire — tree supports are not a strict upgrade. Interface layers The top few layers of a support can be printed denser than the body — the interface. A dense interface gives the part's downward face something continuous to land on, so the underside is smoother. The trade is direct: more interface density and more interface layers means a better underside and a harder removal. Where the machine allows it, an interface printed in a different material solves this outright. Water-soluble PVA or BVOH dissolves away completely. Alternatively, an interface in a material that bonds poorly to the part material — PETG under PLA is the classic pairing, and vice versa — releases cleanly with no dissolution needed. The Z-gap: the parameter that decides everything The Z-gap (contact distance, top contact Z distance) is the vertical clearance left between the top of the support and the part's underside. It is the single parameter that determines whether supports snap off or fuse on. - Too large: the part's first layer over the support has nothing to sit on, and droops badly. You get an ugly underside and, at the extreme, a failed region.- Too small, or zero: the support welds to the part. Removal tears the surface, or is simply not possible without damaging the part. A common starting point is one layer height. The correct value is a material property in practice, because it depends on how aggressively the material bonds to itself — PETG self-bonds far more strongly than PLA and generally needs a larger gap for the same removability. Procedure: find your Z-gap 1. Model or download a small test block with a flat overhanging ledge, and put four copies on the plate.2. Use per-object settings (post 02) to give each copy a different Z-gap: 0, 0.5×, 1.0× and 1.5× layer height.3. Print in the material you care about, with your normal profile.4. Remove the supports from each and judge two things: how hard removal was, and how good the resulting underside is.5. Choose the largest gap that still gives an acceptable underside. Record it in your material profile.6. Repeat per material. Do not carry a PLA value into a PETG profile. There is a matching XY separation parameter controlling horizontal clearance between support and vertical part walls; the same logic applies, and it matters most for supports inside pockets and against tall walls. Support strategy options - Support on build plate only. Supports are generated only where they can reach the plate, so nothing ever touches the model's own surfaces except the underside of true overhangs above the plate. No scars on model faces. It fails whenever an overhang sits above the part itself.- Painted supports (enforcers and blockers). Paint directly on the model where you want support and where you forbid it. Almost always better than adjusting the global angle threshold, which is a blunt instrument that adds support everywhere the threshold catches.- Support blockers as modifier volumes. Drop a box over a region that must stay clean. The scar Supports always leave a mark. The interface never separates perfectly cleanly, so a supported face is rougher than an unsupported one and dimensionally less reliable. Three responses, in order of quality: 1. Design the overhang away (Chapter 6). Best answer.2. Orient so the scar lands on a face nobody sees or measures. Second best.3. Accept it and post-process — knife, file, sanding. Real, but it is manual labour on every copy. Chapter 6 — Support-free design Support is a workaround. The superior answer, wherever the part's function permits, is geometry that does not need it. Chamfers instead of overhangs Under a horizontal ledge, boss or shelf, add a 45° chamfer rather than leaving a square underside. The chamfer is self-supporting, prints cleanly and adds material exactly where a bending stress concentration would otherwise sit. Note the asymmetry with fillets: a fillet under a ledge is not a good substitute, because a fillet's surface becomes tangent to horizontal at its lower end — the worst possible overhang, right where the geometry starts. Chamfer downward-facing transitions; fillet upward-facing ones. Self-supporting geometry throughout Once you have measured your machine's overhang threshold (Chapter 3), design to it. Cones instead of cylinders on downward faces, pyramidal instead of rectangular bosses, sloped instead of flat undersides. On a part designed this way, the support setting is simply "off", and that is worth a great deal of cleanup time over a print run. Sacrificial bridge layers Over a large horizontal internal hole or pocket, a single sacrificial layer of bridging material gives the layers above something to build on. Many slicers can add this automatically for internal features; it can also be modelled deliberately as a thin membrane to be drilled out afterwards. Split the part If a part cannot be made support-free in any single orientation, cut it. Two halves, each oriented for its own loads and each printing support-free, glued or bolted together, will often beat one supported part on strength, surface and time simultaneously. See Chapter 7 for where to cut and how to join. Print in place Sometimes the correct answer to "how do I assemble this" is "don't". Print-in-place hinges, captive nuts, chain links and compliant mechanisms remove assembly entirely. They are clearance problems, and that is the topic of Chapter 7's last section. Put text and detail where the process can print it Embossed text on a top or vertical face prints legibly. Engraved text on a top face prints legibly. Text on a downward face is a support problem and will be a mess. Move it. Chapter 7 — Designing for the process Minimum wall thickness relative to extrusion width A wall is built from an integer number of roads. If your extrusion width is 0.45 mm, then: A wall of 1.0 mm asks for 2.22 roads. Classic perimeter generation lays two roads and dumps the remaining 0.10 mm into gap fill; variable-width extrusion (post 02) instead widens both roads to 0.50 mm, which is better but still a compromise. The rule: design walls as whole multiples of your extrusion width, and treat two roads as the practical structural minimum for anything that carries load or needs to survive handling. Single-road walls exist and are useful for vase-mode parts and light enclosures, but they are not structure. Note the dependency: this rule is tied to your nozzle and profile. If you design a 0.90 mm wall and later print with a 0.6 mm nozzle, the wall becomes an awkward 1.5 roads. Parametrise the wall thickness in CAD (post 06) rather than hard-coding it. Minimum feature size - Nothing narrower than one extrusion width can exist. A 0.3 mm rib on a 0.45 mm profile is simply not printed, or is printed at 0.45 mm and is therefore wrong.- Embossed or engraved detail should be at least two extrusion widths wide and at least two layers deep or tall to be legible. Below that it disappears into the surface texture.- Small holes close up. A 1 mm vertical hole in a 0.4 mm nozzle profile has room for barely one road around it; expect it to be undersized and rough, and plan to drill it. Chamfer the bottom edge Elephant foot (post 01) bulges the bottom edge outward. Slicers offer a compensation setting that shrinks the first layer inward, but the better fix lives in the model: put a small chamfer — typically a few tenths of a millimetre at 45° — on every bottom edge. The chamfer gives the squashed first layer somewhere to bulge into rather than past the nominal footprint. The part still sits flat, the base dimension is preserved, and the fix travels with the model into any slicer, on any printer, forever. This is one of the highest value-per-effort habits in the whole discipline. Text - Cap height of roughly 4–5 mm and above reads reliably; below that, legibility depends heavily on the font and on your extrusion width.- Stroke width should be at least two extrusion widths. Thin serif and script fonts do not survive; a bold sans-serif does.- Relief depth of at least two layers, both for embossed and engraved.- Embossed text generally reads better than engraved on FDM, because engraved text's fine channels get partially filled.- On a vertical face, vertical resolution of the glyph is limited by layer height, so curves and thin horizontals suffer. Thin unsupported pillars A tall, thin pillar is the classic failed feature, and there are three separate reasons: 1. It has no time to cool. Each layer is tiny, so the nozzle returns before the previous layer has solidified, and the pillar turns into a soft blob.2. It has no rigidity. The nozzle's drag and the travel moves knock it around.3. It is unstable. A tall narrow column has a small base and a high aspect ratio. Fixes, in order: taper it (a cone is stronger and cools better than a cylinder); enable minimum layer time or slow down for short layers; print several parts at once so each pillar has time to cool between visits; add a sacrificial cooling tower next to it; or reorient so the pillar lies down. Splitting and joining Where to cut. Choose a plane that (a) lets each half print support-free, (b) puts each half's layers in the right direction for its own loads, (c) does not pass through the region of highest stress, and (d) leaves a joint you can align. Cutting straight through a bending corner puts the joint exactly where the part is trying hardest to break. Alignment features. Never rely on a plain butt joint plus glue for alignment. Add: - Dowel pins — printed pins and matching holes, or bought steel/brass pins in reamed holes (more accurate).- Dovetails or keyed slots — self-aligning and carry shear load without relying on the adhesive.- Lip and groove — a step around the joint that locates the halves and increases bonded area.- A screw plus a heat-set insert — a mechanical joint that can be taken apart again. Too small and the parts fuse into a solid lump; too large and the mechanism is sloppy. Chapter 1 — Who are you, and what may you do? Two questions sit behind every protected request: 1. Authentication (AuthN) — who are you? The user proves an identity, for example with a password plus a code.2. Authorization (AuthZ) — what may you do? The app checks whether this identity may read or change this thing. They fail in different ways. A perfect login does not help if any logged-in user can open that belongs to someone else. That second bug is authorization, and Dev Essentials 12 · OWASP Top 10 shows it as "Broken Access Control". HTTP has a status code for each. means "I do not know who you are" (not logged in, or a bad token). means "I know who you are, and you may not do this". A is also fine for "not yours" when you do not want to reveal that the thing exists. Terminology - Credential — the thing that proves identity: a password, a private key, a code.- Factor — a kind of proof: something you know (password), have (phone, security key), or are (fingerprint). MFA means two or more different kinds.- Session — the server remembers "this browser is logged in as Ada" after the login step.- Token — a string the client sends with each request to show it is logged in. Chapter 2 — Storing passwords Never plain text, never reversible encryption If you store passwords as plain text, one database leak exposes every user — and most users reuse passwords on other sites. Encryption is not the answer either. Encrypted data can be decrypted, so whoever steals the key gets every password back. You want a one-way function: easy to check a guess, impossible to reverse. That is a hash. But not any hash. Why SHA-256 is the wrong hash SHA-256 and MD5 are built to be fast. A modern GPU can compute billions of them per second. If an attacker steals your table of SHA-256 password hashes, they hash every word from a big list of leaked passwords and compare. Password hashing functions are built to be slow and memory-hungry on purpose. One login costs your server a fraction of a second. For an attacker trying billions of guesses, the same cost becomes enormous. Being memory-hard matters too: GPUs have many cores but little memory per core, so a hash that needs many MiB per guess slows them down. Salt and pepper - Salt — a random value, different for every password, stored next to the hash. Two users with the same password get different hashes, and precomputed tables ("rainbow tables") become useless. Modern libraries make and store the salt for you.- Pepper — one secret value shared by all passwords, stored outside the database (a secrets manager or an HSM). OWASP says a pepper "should not be stored along with the generated hash". If only the database leaks, the hashes cannot be cracked without it. A pepper is defence in depth, not a replacement for a slow hash. The algorithms and the current OWASP parameters The OWASP Password Storage Cheat Sheet (checked September 2026) gives this order of preference. Passkeys and WebAuthn TOTP codes can still be phished: a fake site asks for the code and replays it within 30 seconds. Passkeys fix this. A passkey is a key pair created by the user's device or password manager through the WebAuthn browser API. The server stores only the public key.
