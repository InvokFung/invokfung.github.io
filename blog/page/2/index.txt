e:T4366,A language model knows nothing about your own notes. Retrieval-Augmented Generation (RAG) fixes that without any training: when a question arrives, find the few passages of your documents that answer it, put them in the prompt, and ask the model to answer from those passages, with citations. This post builds a complete RAG tool in about 180 lines of Python, one piece per chapter: load Markdown files, chunk them by heading, embed them with a free local model, store the vectors in a NumPy file, retrieve the top matches, and generate a cited answer with the Anthropic Messages API. Then it measures retrieval with a small hand-written test set (hit rate and MRR), improves it with hybrid search and reranking, and covers the ways RAG fails. The running example is "ask questions about your own notes", for instance a blog's posts folder. It builds on the embeddings from post 17.

Learning Outcome

- Explain what RAG is, when it helps, and when something simpler is better.- Chunk Markdown by heading, with size limits and overlap, without breaking on code comments.- Embed chunks, store them as a NumPy matrix, and retrieve the top-k by cosine similarity.- Build a prompt that makes the model cite sources and treat documents as data.- Evaluate retrieval with hit rate@k and MRR on a hand-written question set.- Improve retrieval with BM25 + vectors (reciprocal rank fusion), a cross-encoder reranker, and metadata filters.- Recognise the main failure modes: bad chunks, stale index, prompt injection inside documents.

Chapter 1 — RAG in one picture

Terminology

| Term | Meaning ||------|---------|| Chunk | A small piece of a document, the unit you embed and retrieve. || Index | The stored chunks plus their vectors. || Retrieval | Finding the chunks most related to a question. Top-k = the best k of them. || Grounding | Making the model answer from supplied text instead of its own memory. || BM25 | A classic keyword-matching score, used by search engines for decades. || Reranker | A slower, more accurate model that re-orders a short list of candidates. || Hit rate@k, MRR | Two simple retrieval scores (Chapter 6). |

The name comes from Lewis et al. (NeurIPS 2020), who combined a model's built-in ("parametric") memory with a searchable document index. Today the word covers any system that retrieves text and puts it in the prompt.

Why not just paste everything into the prompt? Sometimes you should. If your documents fit in a few thousand tokens, paste them and use prompt caching (post 17). RAG earns its place when the collection is too big for the context window, or when stuffing it in would be slow, costly, or hurt accuracy (the "context rot" from post 17). It also makes answers checkable: every claim points to a chunk.

When RAG is the wrong tool: questions that need every document at once ("how many posts mention Docker?") need a query or a script, not top-5 retrieval.

Why chunk, and how big

- The embedding model has an input limit. The  model card says input longer than 256 word pieces is truncated. Anything past the limit is silently ignored.- One vector should mean one topic. A vector for a whole long post is a blurry average. A vector for one section is sharp.- Smaller chunks retrieve more precisely but carry less context. Larger chunks carry more context but match less precisely.- Overlap repeats a little text between neighbouring chunks, so a sentence cut at a boundary still appears whole in one of them.

This post uses 800 characters with 150 of overlap. That is a rule of thumb for English prose staying under 256 word pieces. To check a chunk, count its word pieces with .

Chapter 1 — Authentication in layers

Terminology

- Authentication — who is the caller? (a valid session)- Authorisation — may this caller do this to this resource? (ownership, role)- Optimistic check — a cheap check on the presence of a session cookie, without a database or full verification; good for redirects, never enough for data.- Secure check — full session verification plus an authorisation decision, next to the data access.- IDOR — Insecure Direct Object Reference: the caller changes an id and gets someone else's record because only authentication was checked.

Where each check belongs

| Layer | Check | Purpose | Enough on its own? ||---|---|---|---||  | Optimistic (cookie present?) | Redirect logged-out users early; cheap | No: bypassable, and skips any path its matcher excludes || Layout | Avoid auth logic here | A shared layout is not re-rendered on navigation between its children (partial rendering) | No || Page / Server Component | Secure, via the DAL | Decide what UI to render | For that page's reads || Server Action | Secure, inside the action | Actions are public POST endpoints | For that mutation || Route Handler | Secure, inside the handler | Public HTTP endpoint | For that endpoint || Data Access Layer | Secure + authorisation per query | The one place data is read or written | The real boundary |

Chapter 2 — The incidents, and what they teach

CVE-2025-29927: middleware bypass (March 2025)

Next.js used an internal header, , to stop middleware from recursing into itself. The server trusted that header on incoming requests, so an attacker who sent it with the right value made the server skip middleware entirely: authentication redirects, authorisation checks, security headers, everything.

- Severity: critical, CVSS 9.1.- Affected: self-hosted apps using  (including ). Vercel, Netlify, Cloudflare Workers and static exports were not affected (Vercel's routing is decoupled from the Next.js server; exports have no server).- Fixed in: 15.2.3, 14.2.25, and backports 13.5.9 and 12.3.5.- Timeline: reported late February 2025, patched March 17–18, disclosed March 21.- Workaround: strip  at the load balancer or reverse proxy before it reaches Next.js.

Lesson: an app whose only authorisation lived in middleware had none. Apps that re-checked in the DAL lost a redirect, not their data.

Chapter 1 — The mechanics you actually need

Terminology

- Stress (σ) — force per unit area, in pascals (N/m²) or MPa. What the material experiences, independent of the part's size.- Strain (ε) — deformation per unit length, dimensionless. How much the material stretched relative to its original length.- Stiffness (elastic modulus, E) — the slope of stress against strain in the elastic region. How much it deflects under load. A stiff material barely moves.- Strength — the stress at which the material fails, whether by yielding or by fracturing. How much load it takes before something goes wrong. Stiffness and strength are independent properties: a material can be stiff and weak (glass), or compliant and strong (many elastomers).- Yield strength — the stress at which deformation stops being elastic and becomes permanent. Past yield the part is bent, even after the load comes off.- Ultimate tensile strength (UTS) — the maximum stress the material carries before fracture.- Toughness — the energy absorbed before fracture; the area under the stress-strain curve. How much abuse it takes before breaking. A tough material bends, absorbs and survives.- Ductile failure — the material yields, stretches, necks and then tears. It gives warning. PETG, ABS, nylon, TPU.- Brittle failure — the material fractures suddenly at or near its elastic limit, with little permanent deformation and no warning. PLA, standard photopolymer resin, and most fibre-filled composites.- Fatigue — failure from repeated cycles of load well below the static strength. A part that survives a 100 N pull once may fail after 10,000 cycles at 30 N.- Creep — slow, continuous deformation under a constant load over time, without any increase in load. It accelerates dramatically as temperature approaches Tg.- Stress concentration — a local multiplication of stress at a geometric discontinuity (a sharp internal corner, a notch, a hole edge, a sudden change of section).- Neutral axis — in a beam under bending, the surface where the stress is zero; material on one side is in tension, on the other in compression.

The distinction beginners get wrong most often

Stiff ≠ strong ≠ tough. These are three different questions and different materials win each:

| Question | Property | The common filament that wins ||---|---|---|| How much does it bend under load? | stiffness | PLA is the stiffest common filament — genuinely || How much load until it breaks? | strength | depends heavily on direction; PLA is competitive in-plane || Does it survive being dropped or shocked? | toughness | PLA is poor; PETG, ABS, PC and nylon are far better |

This is why PLA feels great on the bench (stiff, holds shape, precise) and disappoints in service (brittle, notch-sensitive, creeps). It is not a bad material. It is a material with a specific and well-known profile.

Creep — the quiet killer

Creep deserves its own treatment because it is the failure mode most often misdiagnosed as "the print was weak".

Polymers are viscoelastic: under sustained load they behave partly like solids and partly like very stiff liquids. Hold a constant load on a printed bracket and it will slowly, continuously deform. Not fail — deform. Over hours, days, months, depending on the material, the stress level and the temperature.

The temperature dependence is the sting. Creep rate rises sharply as the material approaches Tg (Post 04). A PLA part at 20 °C creeps slowly enough to be irrelevant for many uses. The same part at 50 °C — a closed car in summer, a sunlit window sill, a shelf above a radiator, next to a stepper motor — is within striking distance of PLA's Tg of roughly 55–65 °C, and creeps fast enough to be visible in a day.

The canonical failure: a PLA phone mount, wall hook, or shelf bracket that was perfectly fine for weeks and one day is simply drooping. Nothing broke. It flowed.

Design responses, in order of effectiveness:

1. Don't use PLA for a sustained load in a warm place. PETG is a large improvement, ABS/ASA more, PC more again, and a fibre-filled grade of any of them better still.2. Reduce the stress. Creep rate is strongly stress-dependent; halving the stress helps disproportionately. Thicker sections, more perimeters, a shorter moment arm.3. Put the load into compression rather than bending. Compressive creep in a well-supported column is far less troublesome than bending creep in a cantilever.4. Carry the sustained load in metal. A printed body with a steel screw, rod or bracket taking the actual load is a robust pattern.5. Anneal (Post 04) if the part is PLA and must be warm — increased crystallinity meaningfully raises creep resistance. Then re-check the fit, because the dimensions changed.

> Watch out: static strength tests tell you nothing about creep. Hanging a weight on a bracket for thirty seconds and declaring it strong is not a test of a load it will carry for a year. If the part carries a sustained load, the only meaningful test is a sustained one.

Chapter 2 — Anisotropy, honestly

What is actually going on

A moulded part is essentially isotropic: the polymer is a continuous mass and its properties are the same in every direction. A printed part is not. It is a stack of extruded beads bonded to their neighbours, and the bond between beads is not the same as the bulk material.

- In-plane (X/Y), along and across the extrusion direction, load is carried mostly by continuous polymer within beads and by side-to-side welds between adjacent beads laid down while both were hot.- Through-thickness (Z), across layers, load is carried entirely by the interlayer weld: the region where a new bead was deposited onto a layer that had already partly cooled, and the polymer chains had a limited time and a limited temperature at which to diffuse across the interface and entangle.

That diffusion process is the entire mechanism. The strength of the Z direction is the strength of that weld, and the weld is imperfect: it forms in a fraction of a second, at a temperature falling rapidly toward Tg, between two surfaces that also have geometric voids at the bead junctions.

The honest statement of the magnitude: interlayer (Z) strength is substantially lower than in-plane strength for essentially every FDM material and profile. The size of the gap varies enormously — it depends on the polymer, the nozzle temperature, the layer height, the part cooling, the chamber temperature, the layer time, the bead geometry, and whether the part was annealed. Published studies find a wide range of ratios, and any single percentage quoted as a general fact about "3D printing" is not one.

You will see figures like "Z is 50 % of XY" repeated widely. Treat them the way Post 05 taught you to treat "0.05 mm accuracy": as a number for someone's specific machine, material and profile, not as a property of the technology. Measure it on yours. Exercise 2 gives the procedure.

Reducing the gap

| Lever | Effect on interlayer strength | Cost ||---|---|---|| Higher nozzle temperature | strong positive — more time above the diffusion temperature | surface quality, stringing, oozing; bounded by material degradation || Enclosure / warm chamber | strong positive — the previous layer is hotter when the new one lands | equipment; not appropriate for PLA (Post 04) || Less part cooling | positive | overhangs and bridges degrade; a real trade-off || Thicker layers | positive — more bonded area per interface and more retained heat | resolution, surface finish || Wider extrusion / bigger nozzle | positive — larger weld area, fewer voids | resolution, detail || Slower printing | mixed — slower gives more heat per unit length, but a longer layer time means the previous layer is cooler when you return to it | time || Annealing | positive — chains interdiffuse across interfaces given time above Tg | dimensional change (Post 04) || Ironing / higher flow | small positive — reduces interlayer voids | || Orientation | eliminates the problem — put the load in-plane | usually free; occasionally costs support material |

> Watch out: every mitigation in that table trades something away — surface quality, overhang capability, resolution, or time — and none of them removes the weakness. Only orientation does.

The last row is the point of the whole chapter. Every other lever is a partial mitigation with a cost. Orientation makes the weakness irrelevant, and it usually costs nothing but a decision. That is why it heads the next chapter's list.

Chapter 3 — What actually controls strength, in order

Beginners tune this list in roughly reverse order. Here it is correctly ordered by leverage.

1. Orientation — by a wide margin the most important

Rotating the part on the plate can change its breaking load by a factor. Nothing else in the profile comes close.

The rule: never let the primary tensile load path cross a layer boundary. Identify how the part is loaded, identify where the tension is highest, and orient so the layers run along the load, not across it.

Concrete cases:

| Part | Wrong orientation | Right orientation ||---|---|---|| Hook carrying a downward load | printed upright — the bending tension at the root is across layers | printed flat on its side (or standing in the load plane) so layers run along the hook || Bracket with an L-shape | either leg vertical — the corner is a layer interface in tension | flat, with both legs in the layer plane || Threaded boss taking a pull-out load | axis vertical — the thread strips layer by layer | axis horizontal, or use a heat-set insert (Post 06) || Long thin rod under tension | vertical — every layer is a potential fracture plane | horizontal || A gear | either works for tooth bending; hub axis vertical is standard | axis vertical, so tooth loads are in-plane |

Post 03 covers orientation for surface quality and supports. This is the same decision viewed through strength, and when the two conflict, strength usually wins on a functional part.

2. Perimeter (wall) count

Second-largest lever, and much larger than infill. Going from 2 to 4 perimeters typically makes a far bigger difference than going from 20 % to 50 % infill, at a fraction of the material and time cost.

Why: where bending stress actually acts

Most printed parts fail in bending, not pure tension. In a beam under bending:

- The material on the outside of the bend is in tension; on the inside, in compression; and somewhere between them, at the neutral axis, the stress is zero.- Stress varies linearly with distance from the neutral axis. The extreme fibres carry the maximum; material at the neutral axis carries nothing.- Bending stiffness is governed by the second moment of area, which weights material by the square of its distance from the neutral axis. Bending strength is governed by the section modulus, which likewise rewards distance from the axis.

That is the entire argument. Perimeters are the material at the extreme fibres — the material that is doing the work. Infill is the material near the neutral axis, where the stress is small. Adding infill adds mass and print time in the place where it contributes least.

Infill is not useless; it does three real jobs:

1. Supports the top surfaces so they can be printed at all (Post 02).2. Stabilises the perimeters against buckling — a thin shell under compression fails by buckling long before it fails by crushing, and infill braces it.3. Carries compression and shear in a part loaded through its bulk rather than in bending.

But for the common case — a bracket, a hook, a mount, a lever, anything cantilevered — perimeters win decisively.

3. Material

Third. Choosing PETG over PLA for a part that gets knocked, or nylon over PETG for a part that wears, changes the outcome more than any slicer setting except the two above. Post 04's decision tree is the tool. Note that the material choice interacts with orientation: fibre-filled composites are dramatically stiffer in-plane and are usually more brittle across layers, so the anisotropy gets worse, not better.

4. Temperature and cooling

Fourth. Nozzle temperature is the strongest single lever on interlayer strength within a given material (Chapter 2). Reduced part cooling helps interlayer bonding and hurts overhangs. An enclosure helps materials that want one. These are real effects with real trade-offs — but they are refinements on top of the first three decisions, not substitutes for them.

5. Infill density and pattern

Fifth, and well below where beginners put it.

- Density. Beyond roughly 40–50 %, additional infill buys little strength for a lot of time and material; the curve flattens. Below about 15 % the part becomes noticeably soft and top surfaces suffer. For most functional parts, 20–30 % infill with 4–6 perimeters outperforms 50 % infill with 2 perimeters, using less material.- Pattern. Matters more than density in some load cases. Gyroid is isotropic, self-supporting, prints fast and is a strong general default. Cubic and triangular are stiff and good under multi-axis load. Grid creates crossing points where the nozzle collides with previously-laid material. Lines/rectilinear is weak in one direction. Concentric is right under flexible parts.- Special case: a fully solid part (100 % infill) is not automatically the strongest thing you can print. Over-extrusion in a solid part introduces internal stress and can leave voids; and the part still fails at layer interfaces. Solid is heavy, slow and often not better than thick perimeters plus moderate infill.

6. Layer height

Sixth. Thicker layers bond somewhat better and print faster; thinner layers give finer detail and better surface. Its effect on strength is real but small next to the levers above.

> Common pitfall: the reflex "print it at 100 % infill so it's strong". It costs hours and grams, and it usually loses to reorienting the part and adding two perimeters — which costs nothing.

Chapter 4 — Stress concentration and design patterns

The notch effect

A sharp internal corner is a stress concentrator. The local stress at the corner can be several times the nominal stress in the surrounding material, and it rises as the corner radius falls — approaching, in the idealised limit of a perfectly sharp corner, an unbounded value. Real materials do not see infinite stress, but the multiplication is large and real, and it is where cracks start.

Printed parts are unusually vulnerable to this for two reasons:

1. PLA and filled composites are notch-sensitive — brittle materials do not locally yield to blunt the peak, so the concentration translates directly into a crack.2. A layer interface at a sharp internal corner combines a stress raiser with the weakest plane in the part. That combination is the single most common origin of a printed-part fracture.

Fillets: the cheapest strength upgrade available

Adding a fillet to a loaded internal corner costs one CAD feature, a negligible amount of material, and essentially no print time. It reduces the peak stress substantially. There is no other change with that ratio of benefit to cost.

Practical guidance:

- Fillet every loaded internal corner. A radius comparable to the local wall thickness is a reasonable default; larger is better, up to what the geometry allows.- A larger radius is better than a smaller one. The benefit is strongly nonlinear at small radii — going from sharp to a small fillet buys most of the improvement.- Fillet transitions between sections too. A sudden change from thick to thin is a stress raiser even without a corner. Taper it.- Watch the printing rules (Post 06): fillet vertical and top edges freely; chamfer bottom edges.- Do not fillet a corner that needs to mate flush with something. Chamfer that one, or add a relief groove on the mating part.

Design patterns for functional parts

| Pattern | Instead of | Why ||---|---|---|| Ribs | solid bulk | a rib places material away from the neutral axis; you get most of the stiffness for a fraction of the material and time. Rib thickness ≈ 0.5–1× the wall it stands on; rib height ≈ 2–3× thickness; add a draft or taper and a fillet at the root || Gussets (triangular webs) | a bare right-angle joint | carries the bending moment at a corner directly into a stiff triangle. The single most effective addition to an L-bracket || Generous fillets everywhere loaded | sharp internal corners | Chapter 4 above || Load spread over multiple fasteners | one big screw | distributes stress; a single fastener creates a concentrated bearing load in soft plastic that will creep || Washers or a metal backing plate under fastener heads | screw head directly on plastic | prevents the head pulling through and spreads the bearing area || Load path within the layer plane | load path crossing layers | Chapter 3, lever 1 || Compression rather than bending | cantilevers | polymers are far better in compression, and creep less || Increased section depth | increased material | stiffness scales with the cube of depth in bending — making a beam twice as deep makes it eight times as stiff, while making it twice as wide only doubles it, so extra depth is worth four times as much as the same extra width || Metal where load is sustained | plastic carrying it alone | a threaded rod, a steel pin, a bought bracket || Rounded rather than square holes near an edge | square cutouts | corners of square cutouts are stress raisers; radius them || A relief slot at the end of a flexure | a flexure terminating in a corner | terminates the crack path in a rounded feature |

> Trick: the single highest-value five-minute change to almost any printed bracket is: add a gusset, fillet the internal corner, and rotate it so the layers run along the load. Those three together frequently more than double the failure load, and cost no extra material worth mentioning.

| Process | What it changes | Notes and safety ||---|---|---|| Annealing | crystallinity, stiffness, heat resistance, creep resistance, interlayer bonding — and dimensions | Post 04, Chapter 6. Amorphous polymers gain stress relief but not crystallinity || Sanding | surface finish; removes stress-raising surface features | wet-sand to control dust; always wear a respirator with fine plastic dust, and never dry-sand fibre-filled materials without one || Vapour smoothing (ABS/ASA) | glossy sealed surface; improves interlayer strength at the surface by dissolving and re-fusing it; softens sharp detail | acetone is highly flammable and its vapour forms explosive mixtures with air. Gluing, by material

| Material | Adhesive that works | Notes ||---|---|---|| PLA | cyanoacrylate (superglue); two-part epoxy for structural joints | solvent welding is unreliable || PETG | cyanoacrylate; two-part epoxy | solvents are largely ineffective || ABS / ASA | acetone (solvent weld — genuinely fuses the parts), ABS slurry (ABS dissolved in acetone), cyanoacrylate, epoxy | the solvent weld is by far the strongest option and is essentially a repair of the base material || Nylon | notoriously difficult — most adhesives do not bond. Cyanoacrylate with a plastic primer, or specialist polyamide adhesives | design a mechanical joint instead || TPU | flexible cyanoacrylate, polyurethane adhesive, contact cement | rigid glues crack at the joint under flex || PC | cyanoacrylate, epoxy; solvent cements exist but PC is prone to solvent stress-cracking | test on a scrap first |

Universal rules for a glued joint: roughen both faces, degrease with IPA, maximise surface area (a lap joint beats a butt joint), and clamp during cure. A glued joint that relies on end-grain-equivalent contact between two flat printed faces will disappoint; design a scarf, a lap or a tongue.

Chapter 6 — Failure-mode catalogue

Read the fracture surface. It tells you what happened.

| Symptom | What the fracture looks like | Root cause | Fix ||---|---|---|---|| Snapped cleanly along a layer line | flat, matching the layer plane exactly; you can see the bead pattern on the face | tensile load crossed the layer interface | reorient so the load runs in-plane. Then: hotter nozzle, less cooling, thicker layers, enclosure. Consider annealing || Cracked at a sharp internal corner | crack initiates at the corner and runs outward | stress concentration, often compounded by a layer interface at the corner | fillet the corner. Add a gusset. Reorient so the corner is not a layer boundary || Split between perimeters and infill | separation at the shell/infill boundary | insufficient perimeter-to-infill overlap, under-extrusion, or too few perimeters | increase perimeter count; check flow calibration (Post 01); increase infill/perimeter overlap || Stripped a printed thread | thread crests sheared off, often in a layer-wise spiral | printed threads are weak; the crest is layer-bonded plastic | heat-set insert or captive nut (Post 06). If it must be a printed thread: coarser pitch, axis vertical, more engagement length || Screw pulled through the plastic | conical crater under the head | bearing stress under the head exceeded what the polymer takes | washer or metal backing plate; larger head; spread across more fasteners; thicker section || Boss cracked around an insert | radial cracks from the insert outward | boss wall too thin, or the insert forced in cold / too fast / crooked | thicker boss wall; correct pocket dimensions per datasheet; proper installation temperature and slow, straight pressure || Warped over time on the shelf | no fracture; the part simply is not the shape it was | residual stress relaxing, or moisture absorption (nylon), or heat exposure | print with an appropriate thermal environment (Post 04); anneal to relieve stress deliberately; store away from heat || Sagged under a sustained load | no fracture; permanent bend, often at the highest-moment section | creep | Chapter 1. Change material, reduce stress, put the load in compression, or carry it in metal || Failed after long use at a load it once held easily | fracture surface with a smooth region (crack growth) and a rough final region | fatigue | reduce stress amplitude; eliminate stress raisers; a tougher material; more section || Became brittle and chalky outdoors | surface crazing, colour fade, snaps with no warning | UV degradation, plus thermal cycling | ASA. Paint with a UV-stable coating. Never PLA outdoors || Delaminated mid-print or shortly after | horizontal split, often in a tall thin part | thermal gradient plus residual stress; poor interlayer bonding | enclosure; hotter nozzle; less cooling; shorter/wider geometry (Post 04) || Layers separated at an overhang or bridge | localised, at the geometry transition | poor support of the region; excessive cooling variation | supports or reorientation (Post 03); bridging settings || Snapped where a section changed abruptly | fracture right at the step | stress concentration at the section change | taper or fillet the transition || Part dissolved / softened in service | swelling, tackiness, dimensional growth | chemical incompatibility with a solvent, oil or cleaner | check chemical resistance (Post 04); change material or coat it || Loosened at a press fit over time | joint has play that was not there when assembled | polymer stress relaxation — the interference decayed | do not rely on a plastic press fit for a permanent joint; use a fastener, a snap with a positive lock, or adhesive |

> Trick: photograph every fracture surface before you throw the part away, with the load direction noted. A folder of these is the most useful engineering reference you will build, because it is entirely about your machine, your materials and your designs.

Chapter 7 — Testing, and when not to print

Test the part, not a coupon

Standardised tensile coupons (ISO 527, ASTM D638) exist for a reason: they let laboratories compare materials on equal terms. They are the right tool for material comparison and the wrong tool for answering "will my bracket hold".

A coupon tells you about a dogbone specimen printed in one orientation. Your part has a specific geometry, specific stress concentrations, a specific orientation, a specific load path, specific infill, and a specific set of fillets and section changes. Those interactions dominate. Test the actual part, loaded the way it will actually be loaded.

A repeatable comparative test rig

You are not trying to produce absolute engineering data. You are trying to answer "is A better than B on my machine". That requires only repeatability and a controlled comparison — both achievable with cheap equipment.

The minimum viable rig:

1. A fixture that holds the part exactly the same way every time. This is the most important part. Print a jig that clamps the part in one repeatable position. Variation in how the part is held will swamp everything else.2. A way to apply load progressively and measure it. Options in ascending order of cost: a bucket you add water or sand to and then weigh; a luggage scale or fish scale pulled by hand; a hanging digital scale with a peak-hold function; a lever arm with hanging weights; an inexpensive load cell with an amplifier logging to a microcontroller.3. A record. Load at first audible crack, load at failure, where it failed, a photograph of the fracture.

The disciplines that make the results mean something:

- Change exactly one variable at a time. Same spool, same day, same profile except the one thing being tested.- Print all specimens in the same batch, on the same plate where possible, so filament and machine state are shared.- n ≥ 3 per condition. Five is better. Printed parts scatter; a single specimen tells you nothing, exactly as in Post 05.- Report the spread, not just the mean. If A's mean beats B's by less than the within-group spread, you have not shown anything.- Note the temperature. Polymer strength is temperature-dependent, so a test in a cold garage is not comparable to one in a warm room.

Anisotropy test procedure

Print the same simple beam three times in each of three orientations — flat, on-edge, and upright — with everything else identical. Break each in three-point bending in your fixture. The upright specimens fail across layers; the others do not. The ratio of mean failure loads is your anisotropy figure, for that material and profile.

> Common pitfall: comparing A against B when the two batches were printed on different days, from different spools, or with the fixture reassembled in between. Any of those can shift the result by more than the effect you are trying to measure, and the comparison then tells you about the day rather than about the change.

When not to 3D print

This section is the honest one, and it is missing from most 3D printing material because it is not what the audience wants to hear. FDM is a superb process for a specific envelope: one-off or low-volume parts with complex geometry, needed quickly, at low cost, where moderate strength and moderate accuracy suffice. Outside that envelope, something else wins.

| Instead consider | When it wins | Why ||---|---|---|| Buying the part | it exists as a standard component — brackets, hinges, enclosures, knobs, clamps, standoffs, gears, bearings, fasteners | a mass-produced part is stronger, cheaper, and available now. Printing a worse copy of a €3 bracket over six hours is a hobby, not engineering. Search first. || CNC machining | precision, isotropic strength, metal, surface finish | milled aluminium is strong in every direction, dimensionally accurate to a far tighter tolerance, and holds up under heat and sustained load || Injection moulding | quantity — hundreds up, and certainly thousands | per-part cost collapses once tooling is amortised; parts are isotropic and dimensionally consistent. Print the prototype, mould the product || Sheet metal | flat panels, brackets, enclosures, chassis | enormously stiff and strong per gram; cheap; laser-cut and bent quickly. Most bracket-shaped problems are sheet-metal problems || Laser cutting (acrylic, ply, MDF) | flat parts and panels | seconds per part instead of hours, dimensionally excellent in-plane, isotropic || Casting (silicone mould, resin or urethane) | tens of copies of a complex shape | print the master, mould it, cast in a material with better properties than any filament || Woodwork / metalwork | large structures, furniture, anything over a few hundred millimetres | a printed part at that scale is slow, expensive, weak and warped || Extruded profile + fasteners | frames and structures | aluminium extrusion is straight, strong and instant || Hybrid: print + bought parts | almost always | a printed body carrying bought bearings, shafts, fasteners and springs is the strongest, cheapest and fastest answer far more often than a fully printed one |

The productive way to hold this: 3D printing's genuine superpower is geometry, not material. It makes shapes that no other process can make at any price, in a single operation, in an afternoon, with no tooling. Use it for that. When a part's requirement is strength, precision, temperature resistance, or quantity — the things other processes are actually good at — the printer is not the answer, and knowing that is a mark of competence rather than defeat.

Chapter 4 — Partial Prerendering and Cache Components

From "static or dynamic" to "both, per component"

Partial Prerendering (PPR) was introduced as an experiment in Next.js 14 (2023), offered as an incremental opt-in ( per route) in 15, and folded into Cache Components in 16, which removed the  flag. With , PPR is simply how the App Router renders.

The model: at build time Next.js renders every route as far as it can. Everything that is static or cached () becomes the static shell. Every Suspense boundary whose content needs request data or uncached data becomes a dynamic hole. At request time, the shell is sent immediately (it can come from a CDN) and the holes are rendered and streamed into the same response.

Chapter 6 — Node.js vs Edge runtime

The Edge runtime is a restricted, Web-API-only environment (no , no native Node.js modules, no , no  or , no ISR) designed to start fast and run close to users. The Node.js runtime has the full Node.js API and is the default.

By 2026 the balance has moved decisively to Node.js:

-  runs only on Node.js (16.0).- Cache Components requires the Node.js runtime (16.0).- The route segment option  is marked deprecated in the docs (as of 16.3), with the advice to remove it; the error page  says the Node.js runtime needs no replacement.- Next.js 16.3 replaced web streams with native Node.js streams in the App Router rendering layer and reports up to 22% more requests handled under load.

| Concern | Node.js runtime | Edge runtime ||---|---|---|| APIs | Full Node.js | Web APIs subset +  polyfill || npm packages | All | ESM, no native Node.js APIs || ISR / Cache Components | Yes | No || Status in 16 | Default everywhere |  deprecated;  (Edge) deprecated || Where the latency goes | Near your database | Near the user, far from the database |

The latency row is the one people forget: a function at the edge that makes three sequential queries to a database in one region pays the long round trip three times. Rendering next to the data and caching the output at the CDN usually wins.

Chapter 1 — The line

1 · Mirror the pocket

1. Picture the pocket reflected behind the cushion, the same distance on the other side (the mirror pocket).2. The red must go at the mirror pocket. Where that line meets the cushion is the point the red must hit.3. Now it is a normal pot at the mirror pocket: find the ghost ball and aim (post 02).

A red that has just been hit is sliding, and a sliding ball comes off a cushion close to the mirror line (post 07).

> Trick: check the line from the other end. Stand behind the pocket and look at the cushion point: the red should sit on the reflected line.

2 · Find the cushion point by proportion

The mirror rule gives a quick check. The cushion point splits the distance along the cushion in the same ratio as the distances from the cushion:

| | From the cushion | Along the cushion ||-|------------------|-------------------|| red | a = 40 cm | 5 cm to the cushion point || pocket | b = 176 cm | 22 cm from the cushion point |

40 : 176 is the same as 5 : 22. So a red close to the cushion hits it almost straight in front of itself; a red half-way across hits it half-way to the pocket.

3 · Pace: a double is a long pot

This red travels about 2.2 m: up to the cushion, then all the way across. The cushion also takes pace off it.

| White | Power 3 | Power 4 | Power 5 ||-------|---------|---------|---------|| straight behind the red (full ball) | stops short ✗ | ✓ | ✓ || from the left (cut about 35°) | short, and the white went in-off ✗ | ✓ | ✓ || from the right (cut about 50°) | short ✗ | ✓ | ✓ |

(Each ✓ is with the aim fine-tuned; section 4 shows why power 5 needs it.) Power 4 was enough every time; power 3 never was. The thinner you hit the red, the less pace it gets (post 04), so on a cut double lean towards the firmer side.

4 · Firm doubles come off a little short

The same mirror aim at two paces (model):

| Power | Reaches the far cushion | Result ||-------|-------------------------|--------|| 4 | 2 cm from the pocket's centre | ✓ || 5 | 6 cm short of it | ✗ |

At high pace the red comes off the cushion a little short (squarer). At power 5 the aim needed turning about 0.2° to make up for it. So: play doubles at the lowest pace that gets there, and if you must hit hard, aim a touch longer.

Chapter 1 — How the cushion works

1 · Where the cushion meets the ball

The cushion's nose is a little above the middle of the ball, about 64% of its height in the model. So the push from the cushion points slightly down, pressing the ball into the cloth during the hit. The cloth then grips it, and most of the white's spin comes off at the cushion.

This is why, after a cushion, spin effects are smaller than you might expect, and why the angle off the cushion is the thing that changes.

2 · The mirror point, and when it works

To send the white off a cushion to a spot: reflect the spot behind the cushion (the mirror point) and aim at it.

That works when the white is still sliding at the cushion. A white that is already rolling comes off a little flatter and runs on.

| Hit | Where it goes (model, 80 cm to the cushion) ||-----|---------------------------------------------|| 1 · power 3, centre ball (rolling by the cushion) | about 12 cm past the target ✗ || 2 · the same aim, power 4 (still sliding) | within 4 cm ✓ || 3 · power 3, aim about 5 cm shorter along the cushion | on target ✓ |

Two good answers: play it firmer, or keep the slow pace and aim shorter. Choose by where you want the white to stop.

> Trick: reflect the target in the line where the white's centre touches the cushion, half a ball out from the rubber, not in the rubber itself.

3 · Pace and spin bend the line

The same line in at 45°, four hits:

| Hit | Off the cushion at… | Then ||-----|---------------------|------|| slow roll (power 2, a little above centre) | 35° | almost straight || firm roll (power 4, a little above centre) | 39° | straight || stun (power 3, below centre, sliding at the cushion) | 47° | straight: angle in = angle out || screw (power 4, below centre, still spinning back) | 48° | bends away, to 52° |

A rolling white comes off flatter (the slower, the flatter), a stun follows the mirror, and backspin makes it steeper and bends it away.

4 · Straight in and back: the tip sets the distance

Four whites, 60 cm from the cushion, straight in at power 2. Only the tip changes (model):

| Tip | Comes back from the cushion ||-----|-----------------------------|| top (7/10 height) | 117 cm || centre | 56 cm || a little low | 23 cm || low | 8 cm |

A high tip rolls from the start and arrives with the most pace. A low tip spends pace on the cloth while its backspin wears off (post 03), so it arrives slowly and dies near the cushion.

> Trick: to leave the white tight on a cushion (a good safety, post 11), go straight in with a low tip and soft pace.

Chapter 2 — Side at the cushion

5 · Running side and check side

- Running side makes the white run on: it comes off wider (flatter to the cushion) and keeps more pace.- Check side holds it: it comes off narrower (squarer) and slower.

Which is which? Look at the way the white will turn off the cushion. Here it turns right, so right-hand side is running side.

6 · Side matters most when you hit the cushion square

The same side, two lines in (model, power 3, side 0.6 R):

| Line in | Check | Plain | Running | Side changes it by ||---------|-------|-------|---------|--------------------|| 30° (shallow) | 17° | 18° | 14° | 3° || 60° (square-ish) | 62° | 55° | 33° | 29° |

On a shallow line, the white is already sliding along the cushion and side has little to add. Coming in squarer, side changes everything. So when you need side for the angle, come into the cushion squarer.

Chapter 1 — Tokens and tokenizers

Setup

You need Python 3.10 or newer (the  1.x SDK requires it) and, for the API examples, a key from the Anthropic Console.

Terminology

| Term | Meaning ||------|---------|| Token | One chunk of text from the model's fixed list: a word, part of a word, a space plus a word, a symbol, or a byte. || Vocabulary | The fixed list of all tokens a model knows. Each token has an integer ID. || Tokenizer | The program that turns text into token IDs and back. It is fixed before training. || BPE | Byte Pair Encoding: build a vocabulary by merging the most frequent neighbouring pieces, over and over. |

Tokens are not words

The model never sees letters or words. It sees a list of integers. A common word may be one token; a rare word may be three or four. Spaces, punctuation and line breaks use tokens too.

A rule of thumb from Anthropic's models page (vendor spec, September 2026): on the tokenizer Claude has used since Claude Opus 4.7, 1M tokens is roughly 555k English words, or 2.5M Unicode characters. Earlier models fit about 750k words in 1M tokens. So the same text gives a different count on a different model.

Tokens matter because almost every limit uses them: price (per million input and output tokens), the context window (Chapter 4),  (the cap on what the model writes) and rate limits.

BPE in one example

Byte Pair Encoding was brought into neural machine translation by Sennrich, Haddow and Birch (ACL 2016) to handle rare words as sequences of smaller units. Training: split every word into characters, count every neighbouring pair, merge the most frequent pair, repeat. Tokenizing: replay the merges in the same order. Many modern tokenizers run the same idea on UTF-8 bytes, so any text can be encoded (see Dev Essentials 01 · Text Encoding).

Why code and non-English text often cost more

Merges are learned from the tokenizer's training data. Whatever is common there gets long tokens.

- Non-English text. Petrov et al. (NeurIPS 2023) tokenized the same text translated into many languages and found lengths that differ by up to 15 times in some cases (independent measurement). A Chinese character is also 3 bytes in UTF-8, so a byte-level tokenizer starts from more pieces.- Code. The Codex paper (Chen et al., 2021) found the GPT-3 text tokenizer "not very effective for representing code", with whitespace the largest waste. Adding tokens for runs of spaces cut code token counts by about 30% (vendor research paper).

Chapter 2 — Next-token prediction and the transformer

Every LLM answer comes from the same loop:

1. Turn the prompt into token IDs.2. Run them through the network. It returns one score (a logit) per vocabulary token.3. Turn the scores into probabilities and pick one token (Chapter 5).4. Append it and repeat. Stop at an end token, a stop sequence or .

A real LLM looks at all earlier tokens, its probabilities come from billions of learned parameters, and it works on subword tokens. The loop is the same.

Attention, at intuition level

Almost every modern LLM is a transformer, from "Attention Is All You Need" (Vaswani et al., 2017). Its key part is self-attention: for each token, the model decides how much each earlier token matters right now. In "The animal didn't cross the street because it was tired", attention lets "it" pull in information from "animal". Each token makes a query (what am I looking for?), a key (what do I contain?) and a value (what do I pass on?):

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{dk}}\right)V$$

For text generation, a causal mask stops each token from looking at later tokens. Real models stack many such layers, each with several attention "heads".

What this means for you:

- Output is written one token at a time, which is why APIs offer streaming. On Anthropic's current price list, output tokens cost five times as much as input tokens.- The model cannot go back. An early wrong token shapes everything after it. Reasoning before answering helps (Chapter 8).- Long inputs cost more compute. The paper lists self-attention cost per layer as $O(n^2 \cdot d)$ for sequence length $n$.

Chapter 3 — Training stages (high level)

| Term | Meaning ||------|---------|| Pretraining | Next-token prediction on a huge text corpus. Produces a base model. || Instruction tuning (SFT) | Supervised fine-tuning on example requests with good answers. || Reward model | A model trained to score answers, from human rankings. || RLHF / RLAIF | Reinforcement learning from human / AI feedback. |

This is deliberately high level: labs combine and change these steps, and full recipes are not published.

1. Pretraining. The model learns to predict the next token over a very large text collection. It picks up grammar, facts, code patterns and reasoning habits, but does not reliably follow instructions yet.2. Instruction tuning. Fine-tuning on demonstrations: a request, then a good response.3. Preference training. InstructGPT (Ouyang et al., 2022) describes classic RLHF: supervised fine-tuning on labeller demonstrations, then a reward model trained on rankings of model outputs, then reinforcement learning against it. Constitutional AI (Bai et al., 2022) replaces much human labelling for harmlessness: the model critiques and revises its own answers against written principles, and a preference model trained on AI comparisons gives the reward (RLAIF).

In practice:

- Knowledge has a cutoff. Anthropic lists a "reliable knowledge cutoff" per model (vendor spec): for example Feb 2025 for Claude Haiku 4.5 and Jun 2026 for Claude Opus 5.5.- The model knows nothing about your private code or data. You supply it through context: prompts, files, retrieved documents (post 19), tool results (post 18).

Chapter 4 — The context window

The context window is everything the model can read while writing a response, including the response itself. Anthropic's docs call it the model's "working memory". It counts the system prompt, every message (including tool results, images and documents), tool definitions, and this turn's output including any thinking.

The API is stateless. The model does not remember your last request, so a chat app resends the whole history every turn. Turn 10 pays for turns 1 to 9 again (Exercise 4 does the maths).

Sizes change often. As of September 2026 (vendor spec), current Claude Opus, Sonnet and Fable models have a 1M-token window and up to 128k output tokens per request; Claude Haiku 4.5 has 200k and 64k. When a request does not fit, the Anthropic API does this (vendor spec):

| Situation | Result ||-----------|--------|| Input alone is bigger than the window |  ("prompt is too long") || Input fits, but input +  does not (Claude 4.5 and newer) | Accepted; if generation hits the limit it stops with  || Chat apps such as claude.ai | May drop the oldest turns ("first in, first out") |

Other vendors differ, and some truncate silently. Check your API's docs.

> Watch out: bigger is not automatically better. Anthropic's docs describe context rot: as the token count grows, accuracy and recall degrade. Choose what goes in with care.

Chapter 5 — Sampling: temperature, top-k and top-p

Softmax turns logits $zi$ into probabilities. Temperature $T$ divides the logits first:

$$pi = \frac{e^{zi / T}}{\sumj e^{zj / T}}$$

$T < 1$ sharpens the distribution, $T > 1$ flattens it, and as $T$ approaches 0 sampling approaches greedy decoding (always the top token). Watch it with made-up logits for the word after "The cat sat on the":

Output:

Two filters cut the unlikely tail before sampling: top-k keeps the $k$ most likely tokens; top-p (nucleus sampling, Holtzman et al., ICLR 2020) keeps the smallest set of top tokens whose probabilities add up to at least $p$.

Why the same prompt gives different answers: above temperature 0 every token is a random draw, and one different early token changes everything after it. Even at 0, Anthropic's API reference says results will not be fully deterministic.

Chapter 7 — Why hallucinations happen and how to reduce them

A hallucination is fluent, confident text that is false or not supported by the given sources. Causes:

- The goal is a plausible next token, not a true statement. A made-up citation can look very plausible.- Training and tests reward guessing. Kalai et al. (2025, "Why Language Models Hallucinate") argue that training and evaluation reward guessing over admitting uncertainty, like an exam with no penalty for wrong answers.- Missing knowledge: after the cutoff, private, or rare.- Missing or buried context: not in the prompt, or lost in a very long one.

Fixes. The first five follow Anthropic's "Reduce hallucinations" guide and work with any model:

| Technique | How ||-----------|-----|| Allow "I don't know" | "If the documents do not contain the answer, say so." || Ground in sources | Put the documents in the prompt; tell the model to use only them. || Quote first | For long documents, extract word-for-word quotes, then answer from them. || Cite and check | One citation per claim; retract any claim without a supporting quote. || Compare several runs | Answers that disagree across runs are a warning sign. || Verify with tools | Run the code and tests; check official docs for any API or flag you do not know. |

The AI Prompting post covers prompt structure and evaluation in depth; post 18 applies "verify with tools" to coding.
