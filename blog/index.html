AI Prompting (Foundations & Practice)
Created2026-05-15|AI
Prompting is the practice of writing inputs that steer a Large Language Model (LLM) toward useful outputs. It is part interface design, part rhetoric, and part empirical science. This note covers the foundations and the techniques that have been validated by published research, with worked examples you can copy. Learning Outcome - Explain what a prompt is and why model behaviour is sensitive to its phrasing.- Decompose a prompt into its functional parts (instruction, context, examples, format spec).- Apply core techniques: zero-shot, few-shot, chain-of-thought, role conditioning, decomposition, and self-consistency.- Recognise common anti-patterns and explain why they fail.- Design an evaluation harness with a golden set + rubric + A/B framework.- Read a research paper on prompting and judge whether its claims will transfer to your task. Chapter 1 - Foundations Terminology - Prompt ??the full token sequence the model conditions on before generating the next token.- Completion ??the model's generated response.- Token ??sub-word unit (4 characters of English on average). All limits (context window, throughput, billing) are measured in tokens.- Context window ??maximum prompt+completion length the model can attend to.- In-context learning (ICL) ??model adapts its behaviour from examples in the prompt without weight updates. Reported in Language Models are Few-Shot Learners, Brown et al. (2020).- Temperature ??sampling parameter; $0$ is greedy, higher values increase diversity.- Top-p / Top-k ??nucleus / top-k sampling, alternatives to temperature.- System / developer message ??privileged prompt segment used to set persistent behaviour. Mechanism formalised by The Instruction Hierarchy, Wallace et al. (2024). Why prompts matter An LLM is a next-token predictor over a learned distribution $P(tn \mid t1, \dots, t{n-1})$. The prompt is the conditional sequence $t1, \dots, t{n-1}$. Two prompts that read as semantically equivalent to a human can produce very different distributions because the model is sensitive to token-level cues it has learned to associate with answer quality (formality, code-block fences, "Let's think step by step", etc.). This sensitivity has been measured empirically. Lu et al. (2022) showed that simply reordering few-shot examples can swing accuracy on classification benchmarks by tens of percentage points. Sclar et al. (2024) showed that benign formatting changes (newline vs. colon as separator) shift task accuracy by a comparable margin. The practical consequence: prompts are programs. They deserve version control, testing, and review. How the model "reads" a prompt A typical chat-tuned model receives a structured sequence ??for instance OpenAI's ChatML or Anthropic's / turn markers ??where each turn is tagged with a role. The model has been fine-tuned (instruction-tuned + RLHF or DPO) to: 1. Treat the system / developer message as a high-priority constraint.2. Treat user messages as questions or requests.3. Treat its own prior responses as commitments to maintain consistency with. The training procedure was first detailed in InstructGPT, Ouyang et al. (2022) and the Anthropic RLHF paper, Bai et al. (2022). The hierarchy of trust between roles was later sharpened in The Instruction Hierarchy, Wallace et al. (2024). Chapter 2 - Anatomy of a Prompt A well-formed prompt contains, in some combination, six functional parts. Naming them helps you debug what is missing. | Part | Purpose | Example ||------|---------|---------|| Role / persona | Set a frame the model uses to choose vocabulary, depth, formality | "You are a senior database administrator." || Instruction | The actual verb of the request | "Explain why this query is slow." || Context | Domain facts, retrieved documents, prior turns | The SQL query + output || Examples (shots) | Demonstrations of input ??output | A prior worked optimisation || Format spec | Constraint on output shape | "Return JSON matching schema X" || Stop / guardrails | Negative constraints, refusal triggers | "If the query is fine, say only." | A minimal template The order matters less than the presence of each part. The OpenAI prompt-engineering guide (OpenAI 2024) and Anthropic's prompt library both converge on the same six-part skeleton. Chapter 3 - Core Techniques Zero-shot Ask the question directly with no examples. Works when the task is well-represented in the training distribution (translation, summarisation, common QA). Few-shot (in-context learning) Provide $k$ input/output pairs, then the new input. Brown et al. (2020) showed few-shot prompting closes a large fraction of the gap to fine-tuning on many tasks without any gradient updates. Tips:- Order examples easy ??hard (Lu et al., 2022).- Make examples cover the failure modes you observe in zero-shot, not the easy cases.- Keep formatting identical across shots; a stray newline can degrade accuracy (Sclar et al., 2024). Chain-of-Thought (CoT) prompting Ask the model to show its work before committing to an answer. Reported in Chain-of-Thought Prompting Elicits Reasoning in Large Language Models, Wei et al. (2022). Improves arithmetic, symbolic, and commonsense reasoning on large models. Two variants worth knowing:- Zero-shot CoT: append "Let's think step by step." Kojima et al. (2022). Cheap and surprisingly effective.- Self-consistency: sample $n$ chains at temperature $>0$, take the majority vote on the final answer. Wang et al. (2022). Improves arithmetic accuracy further at $n \times$ cost. Role / persona conditioning Setting an expert persona biases vocabulary, depth, and inferred audience. The effect is real but smaller than CoT or few-shot; treat it as fine-tuning of style, not capability. Decomposition Break a hard problem into ordered sub-problems and prompt each separately, chaining outputs. Equivalent to Khot et al. (2023) "Decomposed Prompting" or least-to-most prompting by Zhou et al. (2023). The chain is easier to debug than a single monolithic prompt; you can swap or rerun any step. ReAct (Reasoning + Acting) Interleave reasoning steps with tool calls. Yao et al. (2023). The model alternates between (a reasoning step), (a tool call), and (tool result), until ready to emit an . ReAct is the foundation pattern under most "agent" frameworks (LangChain, LlamaIndex, modern function-calling SDKs). Chapter 4 - Structural Patterns Delimiters Use unambiguous markers around user-supplied or retrieved content. Three formats all work, in roughly equal measure: ... XML tags have the advantage of being self-documenting and survive whitespace normalisation. Anthropic explicitly recommends XML in their prompt-engineering documentation. Markdown structure Models trained on heavy Markdown corpora respond well to headings (), lists, and tables. Use the same conventions in your prompt that you want to see in the output. Numbered constraints Numbered constraints are easier for the model to enumerate against than a paragraph of "and also, make sure to..." Format specifications Three escalating strengths: | Strength | Mechanism | Reliability ||----------|-----------|-------------|| Soft | Natural-language description ("return JSON") | 60-80% || Schema | Provide explicit schema (TypeScript / JSON Schema / Pydantic) | 90% || Hard | Use the provider's structured-output / JSON-mode API | 100% (provider-enforced) | If you need a guaranteed shape, use the provider's structured output. Soft format is convenient but will fail on tail cases. Chapter 5 - Reasoning Boosters Self-consistency Already mentioned. Formally: sample $n$ chains $c1, \dots, cn$ at $T > 0$, extract the final answer $ai$ from each, return $\arg\maxa \sumi \mathbb{1}[ai = a]$. The probability that the majority answer is correct converges to the per-sample accuracy raised to a Condorcet-style power as $n$ grows, when individual samples are conditionally independent given the question. Tree of Thoughts (ToT) Yao et al. (2023). Generalises CoT from a chain to a search tree. The model proposes multiple next-thoughts at each step, a value model scores each, and a search algorithm (BFS/DFS) explores. Helps on combinatorial problems (Game of 24, crosswords) where a single chain commits too early. Reflexion Shinn et al. (2023). After a wrong attempt, the model writes a critique of its own trace; that critique is appended to context for the next attempt. The agent improves across attempts within a single session. Step-Back prompting Zheng et al. (2024). Before answering a specific question, ask the model to first derive the general principle that governs the question. The principle then conditions the specific answer. Improves abstract / multi-step reasoning. Chapter 6 - Common Anti-patterns Vague verbs , , , are unmeasurable. The model has to guess a direction. Replace with a measurable verb: , , . Conflicting constraints The model resolves contradictions arbitrarily. Pick one side of each axis and state it. Leading questions The framing forces the model to defend a premise instead of evaluating it. Prefer: Long irrelevant context Liu et al. (2023) Lost in the Middle showed models degrade on retrieval tasks when relevant information sits in the middle of a long context. Prune aggressively. If you must include long retrieved documents, put the most relevant snippets at the start or the end. Negation-only instructions is weaker than Models follow positive constraints more reliably than negative ones. "Polite filler" adds tokens without affecting behaviour. Strip it. Chapter 7 - Evaluation A prompt is a piece of software, so evaluate it like software. Golden set A small, curated set of representative inputs with hand-graded expected outputs. 30??00 items is enough to detect a 5pp accuracy shift. Rubric Decompose "is the output good?" into yes/no axes. For a summarisation task you might score: - Factual (no hallucinated entities)- Complete (all named main points present)- Concise (within length limit)- Format (parses as JSON)- Refusal (correctly refused when no claim present) Each axis scored 0/1 by a human grader or a separate "judge" model. LLM-as-judge Zheng et al. (2023). A stronger model grades a weaker model's output against a rubric. Cheap, scales, but biased toward outputs that look like the judge's style. Use a different family of model as the judge where possible, and spot-check 10% with a human. A/B framework Track $\Delta$ per axis, not just overall. A change that improves factuality but hurts conciseness is still a regression on the conciseness axis. Statistical sanity With $n=100$ binary outcomes, the 95% confidence interval on accuracy is roughly $\pm 10$pp around the observed rate. Differences smaller than that are noise. Increase $n$ or repeat the run to tighten. Chapter 8 - Tool Use and Structured Output Modern model providers expose two APIs that should replace most prompt-engineering hacks: Function calling / tool use You declare a JSON schema for one or more tools; the model picks one and emits arguments matching the schema. The runtime executes the tool and returns the result, which you append to the conversation and prompt again. The model is fine-tuned to know when to call a tool versus answer directly. This is more reliable than ReAct in raw text because the model emits parsed JSON via the API. Structured output (JSON / Pydantic mode) You supply the full output schema; the provider's decoder constrains generation so the response is guaranteed valid against the schema. Eliminates "the model added a friendly preamble that broke my parser" failures. When NOT to use tools If the task is pure transformation of text the model already has the knowledge for (summarise, translate, classify), tools add latency and cost. Use tools when you need fresh data, deterministic computation, or side effects. Chapter 9 - Putting It Together A production prompt for "extract action items from a meeting transcript" ??combining roles, delimiters, few-shot, format, and a guardrail: This prompt is testable (you have a golden set), debuggable (each rule is a single axis you can score), and safe (the negative examples teach refusal on vague language). No preamble." || Refuses too much | Add an explicit allow-list of permitted topics || Drifts off topic mid-conversation | Re-state the system message every $k$ turns || Slow / expensive | Decompose; use a smaller model for the easy steps | Quick sanity checks before shipping 1. Chapter 8 - Hashing Terminology - Indexing- Perfect Hashing- Minimal Perfect Hashing- Hash Collision- Open Addressing- Closed Addressing- Design of Hash function Introduction of Hashing Hashing is generally [ Indexing ]. If you have learnt what [ index ] is, you may understand it as positioning or classifying objects with duplicated meaning for a smaller size of data and better searching. Steps for Indexing1. Define an array with a specific purpose.2. Define meaning for each index in the array.3. Classify the input and determine the size of the array.4. Map the input to the array. Example of Indexing (Minimal Perfect Hashing)Given A string [foo] = "abacbdef".\Precondition: there will only be alphabets inside the string.\If you want to find how many 'a' occured inside the string, you may use Indexing.1. Define an array for storing the occurrence of letters.2. Each index represents an alphebet.3. There are a total of 26 alphabets as potential input, so the size of array will be 26.4. Similar to the ASCII table, we can take index [0] representing the occurrence of 'a', index [1] representing the occurrence of 'b', and so on...5. Loop over the string and map the character to corresponding index. However, there are still some differences between Hashing and Indexing.\In Hashing, we convert ASCII char to key directly with so that 'a' = 0, 'b' = 1, and so on...\which allows us to map the data easier and faster. Hash function A function f(k) is known as defined with specific formula,\it can be either One-to-one, or Many-to-one,\Under this property,\it can convert a large variable-sized amount of data into a small datum by transforming data into keys. A Hash table arr[ ] is an array that will be created to hold the keys after conversion. A Hash value is usually an integer that may serve as an index to an array. Example of Hash function Hashing Student ID k using Modulo, where h is the function, h(k) is the hash value of k, n is an arbitrary key.$$ h(k) = k \bmod n $$The size of the array will be reduced significantly due to the limited range of the modulus [0 to n-1]. Take k = 5000, n = 5, the function will be$$ h(k) = k \bmod 5 $$In Hash table, the value k will be updated to the index of hash value, arr[h(k)] = k$$ h(5000) = 5000 \bmod 5 = 0 $$arr[0] = 5000, arr[1] = 5081, arr[2] = 5072, arr[3] = 5023, arr[4] = 5014 You may now be thinking of what if the index collides, it should happen frequently as the function is many-to-one. Yes, and therefore, I am going to introduce the solution against collision. Hash Collision Collision occurs when two distinct data own the same hash value.\Collisions are usually unavoidable when a large set of data is mapped into small datum.\It will increase the average cost of lookup operations. Solutions to Hash Collision- Open Addressing- Closed Addressing Load factor represents the length of data in each index,\larger load factor brings lower performance Open Addressing Place the key in other free slot when collisions occured. An index only maps to 1 key.\Theoretical max load factor = 1 Advantages- No size overhead apart from the hash table array- Better memory locality and cache performance. Memory allocation is laid out linearly- Performs better when the number of keys is known in advance and the churn is low.
