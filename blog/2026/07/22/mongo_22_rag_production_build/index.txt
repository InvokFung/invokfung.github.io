<h1 id="Chapter-1-—-Why-MongoDB-for-RAG"><a href="#Chapter-1-—-Why-MongoDB-for-RAG" class="headerlink" title="Chapter 1 — Why MongoDB for RAG"></a>Chapter 1 — Why MongoDB for RAG</h1>
<p>The naïve RAG stack is:</p>
<pre><code class="language-text"><figure class="highlight text"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span></pre></td><td class="code"><pre><code class="text"><span class="line">documents → embedder → vector DB → retrieval → LLM</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Mongo + Atlas Vector Search replaces a separate vector DB:</p>
<ul>
<li>Documents + their embeddings + their metadata live in <strong>one collection</strong> in one database.</li>
<li><strong>Hybrid search</strong> (lexical + vector) is one pipeline (Post 16 Ch 2).</li>
<li><strong>Filter</strong> on metadata (tenant, recency, category) alongside vector search.</li>
<li>Same backup / monitoring / connection-pool patterns as the rest of your Mongo workload.</li>
<li>No data sync between document store + vector store.</li>
</ul>
<p>Trade-off vs Pinecone / Weaviate / pgvector: Atlas Vector Search is HNSW only (no IVF or hybrid index types in 2026); cluster cost scales with index size. For &lt; a few hundred million vectors, Atlas wins on operational simplicity.</p>

<p>Chunking guidelines:</p>
<ul>
<li><strong>800-1200 tokens</strong> per chunk for general documents. Smaller for FAQs (200-400); larger for narrative text (1500-2000).</li>
<li><strong>Overlap</strong> of 10-15 % to preserve context across boundaries.</li>
<li>For code / structured docs, split at structural boundaries (functions, sections).</li>
</ul>
<p>Embedding batch size: OpenAI accepts up to ~2048 inputs per call; tune to your rate limit. Batch dramatically reduces cost + latency.</p>

</ul>

<h1 id="Chapter-8-—-Evaluation"><a href="#Chapter-8-—-Evaluation" class="headerlink" title="Chapter 8 — Evaluation"></a>Chapter 8 — Evaluation</h1>
<p>A small eval set is the difference between &quot;I think it's good&quot; and &quot;I know it's improving&quot;.</p>
<p>Build 50-200 queries with the expected source(s). Run retrieval; measure:</p>
<ul>
<li><strong>Recall@k</strong> — was the right doc in the top-k?</li>
<li><strong>MRR</strong> — mean reciprocal rank of the first correct doc.</li>
<li><strong>End-to-end accuracy</strong> — manually + via LLM-judge on a sample.</li>
</ul>

<h1 id="Chapter-9-—-Observability-cost"><a href="#Chapter-9-—-Observability-cost" class="headerlink" title="Chapter 9 — Observability + cost"></a>Chapter 9 — Observability + cost</h1>
<p>Track per request:</p>
<ul>
<li>Query string + tenant + filters.</li>
<li>Embedding tokens (input length).</li>
<li>Retrieved chunk IDs + scores (for offline replay).</li>
<li>Reranker latency.</li>
<li>LLM input + output tokens.</li>
<li>End-to-end latency.</li>
</ul>
<p>Persist to a <code>traces</code> collection or use LangSmith / Helicone / Langfuse. Use this data to:</p>
<ul>
<li>Identify slow queries.</li>
<li>Estimate per-query cost (embedding tokens × embedding price + LLM tokens × LLM price).</li>
<li>Find queries with low retrieval quality (no high-score matches).</li>
</ul>

<h1 id="Chapter-11-—-Common-pitfalls"><a href="#Chapter-11-—-Common-pitfalls" class="headerlink" title="Chapter 11 — Common pitfalls"></a>Chapter 11 — Common pitfalls</h1>
<table>
<thead>
<tr>
<th>Pitfall</th>
<th>Cause</th>
<th>Fix</th>
</tr>
</thead>
<tbody>
<tr>
<td>Embeddings dimension mismatch</td>
<td>swapped model didn't rebuild index</td>
<td>rebuild index when changing embedder</td>
</tr>
<tr>
<td>Low recall with high <code>limit</code></td>
<td><code>numCandidates</code> too small</td>
<td>raise to 500-1000</td>
</tr>
<tr>
<td>Mixed tenants in results</td>
<td>no filter on metadata</td>
<td>add <code>filter</code> to <code>$vectorSearch</code></td>
</tr>
<tr>
<td>LLM ignores context, hallucinates</td>
<td>weak system prompt</td>
<td>strengthen &quot;USE ONLY context&quot;; refusal instruction; eval</td>
</tr>
<tr>
<td>Latency spikes</td>
<td>reranker on every query</td>
<td>rerank top-20 only; or skip when not needed</td>
</tr>
<tr>
<td>Cost spike</td>
<td>one user spamming</td>
<td>rate-limit + cache identical Qs</td>
</tr>
<tr>
<td>Stale answers after document update</td>
<td>embeddings not updated</td>
<td>change-stream-driven re-embed (Post 12)</td>
</tr>
<tr>
<td>Long context blowing token limit</td>
<td>too many chunks in prompt</td>
<td>smaller <code>top_n</code>; smaller chunks</td>
</tr>
<tr>
<td>Reranker different lang than docs</td>
<td>language mismatch</td>
<td>use multilingual rerank model</td>
</tr>
<tr>
<td>Eval set drift</td>
<td>new feature areas not covered</td>
<td>grow eval set quarterly</td>
</tr>
</tbody>
</table>

<h1 id="Practice-Exercises"><a href="#Practice-Exercises" class="headerlink" title="Practice Exercises"></a>Practice Exercises</h1>
<h2 id="Exercise-1-—-Ingest-a-small-corpus"><a href="#Exercise-1-—-Ingest-a-small-corpus" class="headerlink" title="Exercise 1 — Ingest a small corpus"></a>Exercise 1 — Ingest a small corpus</h2>
<p>Download ~50 markdown docs (your repo's docs / Wikipedia subset). Chunk + embed + insert. Build the vector index.</p>
<h2 id="Exercise-2-—-Vector-only-retrieval"><a href="#Exercise-2-—-Vector-only-retrieval" class="headerlink" title="Exercise 2 — Vector-only retrieval"></a>Exercise 2 — Vector-only retrieval</h2>
<p>Endpoint that takes a query, runs <code>$vectorSearch</code>, returns top-5 chunks + scores. Test 10 questions; rate manually.</p>
<h2 id="Exercise-3-—-Hybrid-retrieval"><a href="#Exercise-3-—-Hybrid-retrieval" class="headerlink" title="Exercise 3 — Hybrid retrieval"></a>Exercise 3 — Hybrid retrieval</h2>
<p>Add lexical (<code>$search</code> text) to the pipeline. Compare top-5 across vector / lexical / hybrid for the same 10 questions.</p>
<h2 id="Exercise-4-—-Reranker"><a href="#Exercise-4-—-Reranker" class="headerlink" title="Exercise 4 — Reranker"></a>Exercise 4 — Reranker</h2>
<p>Add Cohere rerank step after hybrid. Confirm top-1 quality improves on questions where exact keywords matter.</p>
<h2 id="Exercise-5-—-Streaming-endpoint"><a href="#Exercise-5-—-Streaming-endpoint" class="headerlink" title="Exercise 5 — Streaming endpoint"></a>Exercise 5 — Streaming endpoint</h2>
<p>Wire the streaming pipeline into FastAPI SSE. Render in a small HTML page that progressively displays tokens.</p>
<h2 id="Exercise-6-—-Eval-harness"><a href="#Exercise-6-—-Eval-harness" class="headerlink" title="Exercise 6 — Eval harness"></a>Exercise 6 — Eval harness</h2>
<p>Build a 20-question eval set with known gold chunks. Run <code>recall@1 / recall@5 / MRR</code>. Tune <code>numCandidates</code>, chunk size, reranker on/off; track which combination wins.</p>
