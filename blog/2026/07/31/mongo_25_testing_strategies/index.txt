11:Td7ee,<p>Mocking MongoDB lies about behaviour. Real MongoDB in tests gives correctness without the brittleness. <strong>Testcontainers</strong> spins up a throwaway Mongo container per test run; <strong>in-memory</strong> binaries (mongo-memory-server / EphemeralMongo) run a local mongod against <code>/tmp</code> or memory; <strong>fixtures</strong> seed known state; <strong>snapshot tests</strong> lock down query results. <h3 id="Performance"><a href="#Performance" class="headerlink" title="Performance"></a>Performance</h3>
<p>Container start: 5-15 seconds first time (image pull) + 2-5 seconds per restart. <strong>One container per test run</strong> (scope <code>session</code>) is the right default; per-test containers are too slow.</p>
<p>For replica-set features (transactions, change streams), use <code>MongoDbContainer</code> with replica-set mode or compose multiple containers. Recent versions of the npm + Python packages support this directly.</p>

<h1 id="Chapter-12-—-Common-pitfalls"><a href="#Chapter-12-—-Common-pitfalls" class="headerlink" title="Chapter 12 — Common pitfalls"></a>Chapter 12 — Common pitfalls</h1>
<table>
<thead>
<tr>
<th>Pitfall</th>
<th>Cause</th>
<th>Fix</th>
</tr>
</thead>
<tbody>
<tr>
<td>Container takes 30+ seconds to start</td>
<td>first-run image pull</td>
<td>pre-pull in CI cache</td>
</tr>
<tr>
<td>Tests pass locally fail in CI</td>
<td>different Mongo version</td>
<td>pin <code>mongo:8</code> in both</td>
</tr>
<tr>
<td>Replica-set features fail in test</td>
<td>container in standalone mode</td>
<td>use replica-set container or <code>MongoMemoryReplSet</code></td>
</tr>
<tr>
<td>Flaky tests</td>
<td>shared state / shared time</td>
<td>per-test isolation + frozen time</td>
</tr>
<tr>
<td>Test &quot;X&quot; passes alone fails in suite</td>
<td>leaked state from earlier test</td>
<td>better cleanup</td>
</tr>
<tr>
<td>In-memory MongoDB binary download blocked</td>
<td>corporate firewall</td>
<td>mirror the binary; or use Testcontainers</td>
</tr>
<tr>
<td>Slow CI</td>
<td>one container per test instead of per session</td>
<td>scope <code>session</code></td>
</tr>
<tr>
<td>Mocking driver gives false confidence</td>
<td>mocks lie</td>
<td>always use real DB for data-access tests</td>
</tr>
<tr>
<td><code>db.dropDatabase()</code> slow on big seed</td>
<td>unnecessary if you isolate by collection</td>
<td><code>deleteMany({})</code> per collection</td>
</tr>
</tbody>
