<h2 id="Pitfalls"><a href="#Pitfalls" class="headerlink" title="Pitfalls"></a>Pitfalls</h2>
<ul>
<li><code>updateOne / findOneAndUpdate</code> hooks <strong>don't fire <code>save</code> middleware</strong>. Use the <code>updateOne</code> hook explicitly.</li>
<li><code>bulkWrite</code> ops skip hooks unless you opt in.</li>
<li>Throw inside <code>pre</code> to abort the op.</li>
<li><code>post('save')</code> can't reject the operation — for side-effect-only work.</li>
</ul>

<h2 id="Cost"><a href="#Cost" class="headerlink" title="Cost"></a>Cost</h2>
<p><code>populate</code> runs <strong>additional queries</strong> — one per referenced collection, with <code>$in</code> over the gathered IDs. Not server-side <code>$lookup</code> — happens client-side via the driver.</p>
<p>When you have many populates over big lists, prefer:</p>
<ol>
<li><strong>Embedded references</strong> — denormalise the rare fields you always need (Post 07 extended-reference pattern).</li>
<li><strong>Aggregation <code>$lookup</code></strong> — single round-trip server-side.</li>
</ol>
<blockquote>
<p><strong>Trick:</strong> lint for populates inside loops. Each iteration is a fresh round-trip. Always fan out the IDs first, then one <code>User.find({ _id: { $in: ids } })</code>, then map.</p>
</blockquote>

<h1 id="Chapter-11-—-lean-—-the-perf-escape-hatch"><a href="#Chapter-11-—-lean-—-the-perf-escape-hatch" class="headerlink" title="Chapter 11 — .lean() — the perf escape hatch"></a>Chapter 11 — <code>.lean()</code> — the perf escape hatch</h1>
<p>By default Mongoose <code>find</code> returns <strong>Mongoose documents</strong> — heavy objects with getters, virtuals, change tracking, methods.</p>
<p>For read-only queries (API responses, dashboards), use <code>.lean()</code>:</p>
<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-keyword">const</span> users = <span class="hljs-keyword">await</span> <span class="hljs-title class_">User</span>.<span class="hljs-title function_">find</span>({ ... }).<span class="hljs-title function_">lean</span>();    <span class="hljs-comment">// plain JS objects, no overhead</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Faster by 2-10× on big result sets. Loses: virtuals (use <code>mongoose-lean-virtuals</code>), getters, <code>instanceof</code> checks, methods, change tracking.</p>
<p>Rule: <strong>default <code>.lean()</code> on every list endpoint</strong>. Skip it only when you're going to mutate + save.</p>

<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-title class_">UserSchema</span>.<span class="hljs-title function_">index</span>({ <span class="hljs-attr">email</span>: <span class="hljs-number">1</span> }, { <span class="hljs-attr">unique</span>: <span class="hljs-literal">true</span> });</span><br><span class="line"><span class="hljs-title class_">UserSchema</span>.<span class="hljs-title function_">index</span>({ <span class="hljs-attr">createdAt</span>: -<span class="hljs-number">1</span> });</span><br><span class="line"><span class="hljs-title class_">UserSchema</span>.<span class="hljs-title function_">index</span>({ <span class="hljs-attr">name</span>: <span class="hljs-string">&#x27;text&#x27;</span>, <span class="hljs-attr">bio</span>: <span class="hljs-string">&#x27;text&#x27;</span> });</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>On startup, Mongoose calls <code>createIndexes</code> for each model. In production, <strong>disable auto-indexing</strong> + create indexes through migrations:</p>
<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span></pre></td><td class="code"><pre><code class="ts"><span class="line">mongoose.<span class="hljs-title function_">set</span>(<span class="hljs-string">&#x27;autoIndex&#x27;</span>, process.<span class="hljs-property">env</span>.<span class="hljs-property">NODE_ENV</span> !== <span class="hljs-string">&#x27;production&#x27;</span>);</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Auto-indexing blocks reads/writes on first run with a big collection. Always control index builds explicitly in production.</p>

<h1 id="Chapter-14-—-Schema-less-mixed-types"><a href="#Chapter-14-—-Schema-less-mixed-types" class="headerlink" title="Chapter 14 — Schema-less / mixed types"></a>Chapter 14 — Schema-less / mixed types</h1>
<p>When a field genuinely has dynamic shape:</p>
<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-keyword">const</span> <span class="hljs-title class_">Schema</span> = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Schema</span>({</span><br><span class="line">  <span class="hljs-attr">payload</span>: <span class="hljs-title class_">Schema</span>.<span class="hljs-property">Types</span>.<span class="hljs-property">Mixed</span>,</span><br><span class="line">});</span><br><span class="line"> </span><br><span class="line"><span class="hljs-keyword">const</span> doc = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Model</span>({ <span class="hljs-attr">payload</span>: {} });</span><br><span class="line">doc.<span class="hljs-property">payload</span>.<span class="hljs-property">foo</span> = <span class="hljs-string">&#x27;bar&#x27;</span>;</span><br><span class="line">doc.<span class="hljs-title function_">markModified</span>(<span class="hljs-string">&#x27;payload&#x27;</span>);     <span class="hljs-comment">// required! <h1 id="Chapter-15-—-Mongoose-vs-official-driver-Zod"><a href="#Chapter-15-—-Mongoose-vs-official-driver-Zod" class="headerlink" title="Chapter 15 — Mongoose vs official driver + Zod"></a>Chapter 15 — Mongoose vs official driver + Zod</h1>
<table>
<thead>
<tr>
<th>Aspect</th>
<th>Mongoose</th>
<th>Official + Zod</th>
</tr>
</thead>
<tbody>
<tr>
<td>Schema + validation</td>
<td>rich, in-DB-friendly</td>
<td>runtime validation only</td>
</tr>
<tr>
<td>Middleware (hooks)</td>
<td>yes</td>
<td>none built-in (wrap manually)</td>
</tr>
<tr>
<td><code>populate</code></td>
<td>client-side joins free</td>
<td>use <code>$lookup</code> aggregation</td>
</tr>
<tr>
<td>Type safety in TypeScript</td>
<td>inferred but partial</td>
<td>full inference via Zod</td>
</tr>
<tr>
<td>Performance</td>
<td>30-50 % slower than driver</td>
<td>matches driver</td>
</tr>
<tr>
<td>Aggregation</td>
<td>thin wrapper</td>
<td>identical to driver</td>
</tr>
<tr>
<td>Discriminators</td>
<td>nice</td>
<td>manual <code>type</code> field</td>
</tr>
<tr>
<td>Community</td>
<td>huge</td>
<td>thinner</td>
</tr>
</tbody>
</table>
<p>Pick Mongoose for: traditional Express/Node services, teams used to ORM-style codebases, lots of populate use.</p>
<p>Pick official + Zod for: TypeScript-first projects, edge runtimes, services where aggregation is hot path, microservices that want minimal dependencies.</p>
<p>Both run perfectly fine on the same DB. You can mix per service.</p>

<h1 id="Chapter-16-—-Common-pitfalls"><a href="#Chapter-16-—-Common-pitfalls" class="headerlink" title="Chapter 16 — Common pitfalls"></a>Chapter 16 — Common pitfalls</h1>
<table>
<thead>
<tr>
<th>Pitfall</th>
<th>Cause</th>
<th>Fix</th>
</tr>
</thead>
<tbody>
<tr>
<td>Validators not running on update</td>
<td>default: only <code>save</code> runs them</td>
<td><code>runValidators: true</code></td>
</tr>
<tr>
<td><code>populate</code> round-trips per loop iter</td>
<td>N+1 query problem</td>
<td>batch IDs, single <code>$in</code> query</td>
</tr>
<tr>
<td><code>Mixed</code> field changes not saved</td>
<td>Mongoose can't detect nested change</td>
<td><code>doc.markModified('field')</code></td>
</tr>
<tr>
<td>Heavy responses on list endpoints</td>
<td>not using <code>.lean()</code></td>
<td>add <code>.lean()</code></td>
</tr>
<tr>
<td>Production startup slow / blocking</td>
<td><code>autoIndex</code> rebuild on big collection</td>
<td>disable in prod; migrate indexes manually</td>
</tr>
<tr>
<td>Hooks fire twice on same op</td>
<td>both pre('save') + pre('updateOne') registered</td>
<td>pick one per op</td>
</tr>
<tr>
<td><code>findOneAndUpdate</code> returns old doc</td>
<td>default behaviour</td>
<td><code>{ new: true }</code></td>
</tr>
<tr>
<td>Discriminator queries on base also return subtype</td>
<td>by design; filter explicitly if needed</td>
<td><code>Model.find({ kind: 'Click' })</code></td>
</tr>
<tr>
<td>Schema circular ref errors</td>
<td>two schemas reference each other before model registered</td>
<td>declare schemas first, register models after</td>
</tr>
</tbody>
</table>
