<h1 id="Learning-Outcome"><a href="#Learning-Outcome" class="headerlink" title="Learning Outcome"></a>Learning Outcome</h1>
<ul>
<li>Explain the core difference: Bash pipes <em>text</em>, PowerShell pipes <em>objects</em>.</li>
<li>Redirect stdout and stderr correctly, and avoid PowerShell 5.1's encoding traps.</li>
<li>Search text (<code>grep</code> / <code>Select-String</code> / <code>rg</code>), find files (<code>find</code> / <code>Get-ChildItem</code> / <code>fd</code>), and edit in place (<code>sed</code> / <code>-replace</code>).</li>

<li>Use environment variables, exit codes, chaining and quoting correctly in both shells.</li>
<li>Search history, set up aliases and profiles, and use SSH keys, <code>~/.ssh/config</code>, <code>scp</code> and <code>rsync</code>.</li>

<h1 id="Chapter-1-—-Two-shells-two-ideas"><a href="#Chapter-1-—-Two-shells-two-ideas" class="headerlink" title="Chapter 1 — Two shells, two ideas"></a>Chapter 1 — Two shells, two ideas</h1>
<p><strong>Bash</strong> passes plain text between programs. Every tool reads lines and writes lines, and you cut columns out of text with <code>awk</code>, <code>cut</code> or <code>sed</code>. <strong>PowerShell</strong> passes .NET <em>objects</em>. <code>Get-ChildItem</code> sends file objects with properties like <code>Name</code>, <code>Length</code> and <code>LastWriteTime</code>, so you filter by property, not by column position. &quot;Files over 1 MB&quot; in each shell:</p>
<table>
<thead>
<tr>
<th>Bash — parse column 5 of text</th>
<th>PowerShell — filter a property</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>ls -l | awk '$5 &gt; 1000000 {print $9}'</code></td>
<td><code>Get-ChildItem | Where-Object Length -gt 1MB | Select-Object Name</code></td>
</tr>
</tbody>
</table>
<p>On Windows, <strong>Git Bash</strong> comes with Git for Windows: real Bash plus GNU tools (<code>grep</code>, <code>sed</code>, <code>awk</code>, <code>find</code>, <code>ssh</code>…). It shows drives as <code>/c/Users/...</code>; <code>cygpath -w /c/Users</code> converts a path to Windows form. <strong>Windows PowerShell 5.1</strong> is built into Windows. The newer <strong>PowerShell 7</strong> (<code>pwsh</code>) is a separate install and fixes several traps shown below; this post targets 5.1 because it is always there.</p>
<blockquote>
<p><strong>Watch out:</strong> in Windows PowerShell 5.1, <code>ls</code>, <code>cat</code>, <code>sort</code> and <code>curl</code> are <em>aliases</em> for cmdlets (<code>Get-ChildItem</code>, <code>Get-Content</code>, <code>Sort-Object</code>, <code>Invoke-WebRequest</code>). They look like the Unix tools but take different options. <code>Get-Alias curl</code> shows what a name really runs.</p>
</blockquote>

<p>PowerShell has six redirectable streams (1 success, 2 error, 3 warning, 4 verbose, 5 debug, 6 information); <code>*&gt;</code> redirects all of them.</p>
<blockquote>
<p><strong>Common pitfall:</strong> order matters in Bash. <code>cmd &gt; all.txt 2&gt;&amp;1</code> sends both streams to the file. <code>cmd 2&gt;&amp;1 &gt; all.txt</code> sends stderr to the <em>terminal</em>, because <code>2&gt;&amp;1</code> copies where stdout pointed at that moment.</p>
</blockquote>
<blockquote>
<p><strong>Watch out:</strong> Windows PowerShell 5.1 does not write UTF-8 by default. <code>&gt;</code> and <code>Out-File</code> write UTF-16LE; <code>Set-Content</code> and <code>Add-Content</code> write the ANSI code page; <code>-Encoding utf8</code> adds a BOM. See Dev Essentials 01 · Text Encoding for safe patterns.</p>
</blockquote>
<blockquote>
<p><strong>Watch out:</strong> in 5.1, redirecting a <em>native</em> program's stderr (<code>git fetch 2&gt;&amp;1</code>) wraps each stderr line in an <code>ErrorRecord</code>. It prints like an error, and <code>$?</code> becomes <code>False</code>, even when the program succeeded (checked on 5.1.26100). Judge native programs by <code>$LASTEXITCODE</code> (Chapter 9).</p>
</blockquote>

<p>The classic ranking pipeline: pull out a field, sort, count duplicates, sort by count.</p>

<pre><code class="language-powershell"><figure class="highlight powershell"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span></pre></td><td class="code"><pre><code class="powershell"><span class="line">curl.exe <span class="hljs-literal">-sS</span> <span class="hljs-literal">-o</span> NUL <span class="hljs-literal">-w</span> <span class="hljs-string">&#x27;%{http_code}\n&#x27;</span> https://example.com</span><br><span class="line">(<span class="hljs-built_in">Invoke-RestMethod</span> https://api.github.com/repos/python/cpython).stargazers_count</span><br><span class="line"><span class="hljs-built_in">Invoke-RestMethod</span> <span class="hljs-literal">-Method</span> Post <span class="hljs-literal">-Uri</span> https://httpbin.org/post <span class="hljs-literal">-ContentType</span> <span class="hljs-string">&#x27;application/json&#x27;</span> <span class="hljs-literal">-Body</span> <span class="hljs-string">&#x27;{&quot;name&quot;:&quot;Ada&quot;}&#x27;</span></span><br><span class="line"><span class="hljs-built_in">Invoke-WebRequest</span> https://example.com <span class="hljs-literal">-UseBasicParsing</span> | <span class="hljs-built_in">Select-Object</span> StatusCode</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p><code>Invoke-RestMethod</code> parses a JSON reply into objects for you. Since the Windows updates of 9 December 2025, <code>Invoke-WebRequest</code> in 5.1 shows a security prompt when it would parse a page with the old Internet Explorer engine. Microsoft's advice is to add <code>-UseBasicParsing</code>, which also keeps scripts non-interactive.</p>
<blockquote>
<p><strong>Common pitfall:</strong> PowerShell 5.1 strips inner double quotes when it passes arguments to native programs. <code>curl.exe -d '{&quot;name&quot;:&quot;Ada&quot;}'</code> sends <code>{name:Ada}</code> (checked on 5.1). Use <code>Invoke-RestMethod -Body</code>, escape the quotes (<code>'{\&quot;name\&quot;:\&quot;Ada\&quot;}'</code>), or send a file with <code>-d '@body.json'</code>. PowerShell 7.3 changed this behavior.</p>
</blockquote>

<p>Rules that save hours:</p>
<ul>
<li><strong>Prefer single quotes</strong> for regexes, JSON and anything with <code>$</code> in it — in both shells.</li>
<li><strong>Braces are special in PowerShell.</strong> <code>git reset --hard HEAD@{1}</code> breaks in 5.1; write <code>'HEAD@{1}'</code> (see Dev Essentials 03 · Git Rescue Kit).</li>
<li><strong>The stop-parsing token <code>--%</code></strong> passes the rest of the line to a native program almost as-is: <code>icacls X:\VMS --% /grant Dom\HVAdmin:(CI)(OI)F</code>. (Backslash is <em>not</em> an escape in PowerShell, so <code>&quot;C:\new&quot;</code> is just a path.)</li>
</ul>

<h1 id="Chapter-11-—-History-aliases-and-profiles"><a href="#Chapter-11-—-History-aliases-and-profiles" class="headerlink" title="Chapter 11 — History, aliases and profiles"></a>Chapter 11 — History, aliases and profiles</h1>
<p><strong>History search.</strong> In Bash, press <strong>Ctrl+R</strong> and type part of an old command; press Ctrl+R again for older matches. PowerShell's PSReadLine module (bundled with 5.1) uses the same <strong>Ctrl+R</strong>, and <strong>F8</strong> finds history entries that start with what you already typed. To grep old commands: <code>history | grep ssh</code> in Bash. In PowerShell, <code>Get-History</code> only shows the current session; the full saved history lives in <code>%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt</code>, so search it with <code>Select-String -Path (Get-PSReadLineOption).HistorySavePath -Pattern 'ssh'</code>.</p>

<h1 id="Chapter-12-—-SSH-keys-config-copying-files"><a href="#Chapter-12-—-SSH-keys-config-copying-files" class="headerlink" title="Chapter 12 — SSH: keys, config, copying files"></a>Chapter 12 — SSH: keys, config, copying files</h1>
<p><strong>Make a key.</strong> Ed25519 is the type GitHub's docs recommend; they keep RSA 4096 only for old systems that lack Ed25519.</p>
<pre><code class="language-bash"><figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span></pre></td><td class="code"><pre><code class="bash"><span class="line">ssh-keygen -t ed25519 -C <span class="hljs-string">&quot;laptop-2026&quot;</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>

<p><strong>Load it into an agent</strong> so you type the passphrase once:</p>
<pre><code class="language-bash"><figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span></pre></td><td class="code"><pre><code class="bash"><span class="line"><span class="hljs-built_in">eval</span> <span class="hljs-string">&quot;<span class="hljs-subst">$(ssh-agent -s)</span>&quot;</span>                  <span class="hljs-comment"># Git Bash</span></span><br><span class="line">ssh-add ~/.ssh/id_ed25519</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<pre><code class="language-powershell"><figure class="highlight powershell"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span></pre></td><td class="code"><pre><code class="powershell"><span class="line"><span class="hljs-comment"># Windows OpenSSH agent — one-time setup, in PowerShell run as administrator</span></span><br><span class="line"><span class="hljs-built_in">Get-Service</span> <span class="hljs-literal">-Name</span> ssh<span class="hljs-literal">-agent</span> | <span class="hljs-built_in">Set-Service</span> <span class="hljs-literal">-StartupType</span> Manual</span><br><span class="line"><span class="hljs-built_in">Start-Service</span> ssh<span class="hljs-literal">-agent</span></span><br><span class="line">ssh<span class="hljs-literal">-add</span> <span class="hljs-variable">$env:USERPROFILE</span>\.ssh\id_ed25519</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>On Windows there are two <code>ssh</code> programs: Git Bash runs its own <code>/usr/bin/ssh</code>, and PowerShell runs <code>C:\Windows\System32\OpenSSH\ssh.exe</code>. Both read the same <code>~/.ssh</code> folder, but each has its own agent.</p>
<p><strong>Name your servers in <code>~/.ssh/config</code>:</strong></p>
<pre><code class="language-text"><figure class="highlight text"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span></pre></td><td class="code"><pre><code class="text"><span class="line">Host lab</span><br><span class="line">    HostName 203.0.113.10</span><br><span class="line">    User deploy</span><br><span class="line">    Port 2222</span><br><span class="line">    IdentityFile ~/.ssh/id_ed25519</span><br><span class="line">    IdentitiesOnly yes</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>SSH uses the <em>first</em> value it finds for each setting, so put specific hosts at the top and any <code>Host *</code> defaults at the bottom. Now <code>ssh lab</code> replaces <code>ssh -p 2222 -i ~/.ssh/id_ed25519 deploy@203.0.113.10</code>.</p>
<pre><code class="language-bash"><figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span></pre></td><td class="code"><pre><code class="bash"><span class="line">ssh lab <span class="hljs-string">&#x27;df -h&#x27;</span>                                <span class="hljs-comment"># run one command and return</span></span><br><span class="line">scp report.pdf lab:/tmp/ ; scp lab:/var/log/app.log .   <span class="hljs-comment"># copy up; copy down</span></span><br><span class="line">scp -r site lab:/var/www/                      <span class="hljs-comment"># copy a folder</span></span><br><span class="line">rsync -avz --dry-run --delete site/ lab:/var/www/site/   <span class="hljs-comment"># preview a sync, then drop --dry-run</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p><code>rsync</code> copies only what changed. The trailing slash matters: <code>site/</code> means &quot;the contents of site&quot;, <code>site</code> means &quot;the folder itself&quot;. <code>--delete</code> removes files on the target that are gone from the source, so always preview first. Git Bash does not include <code>rsync</code>; use it from Linux, macOS or WSL, or fall back to <code>scp</code>. Test GitHub access with <code>ssh -T git@github.com</code>.</p>
