Dev Essentials — 06 · Regex from Zero to Useful

Created2026-08-20|Updated2026-08-20|Dev Essentials
|Post View:

A regular expression (regex) is a tiny language for describing text patterns: "four digits, a dash, two digits", "a line that starts with date:", "the same word twice in a row". You meet regexes in grep, sed, editors, Python, JavaScript, PowerShell and every log tool. This post builds them up from single characters to lookarounds, shows where the flavors differ, gives recipes you will reuse, and ends with the dark side: a regex that can freeze a server.

Series map: 01 Text Encoding → … → 05 Command Line → 06 Regex (this post) → 07 HTTPS → … → 24 Desk Health. Part B · Everyday skills.

Learning Outcome

  • Read and write patterns with literals, character classes, quantifiers, anchors, groups and alternation.
  • Explain greedy vs lazy matching, backreferences, named groups, and lookahead/lookbehind.
  • Use flags (ignore case, multiline, dot-all, verbose) in Python, JavaScript and PowerShell.
  • Know what changes between POSIX BRE/ERE, PCRE, Python re, JavaScript and .NET.
  • Use Python's re module with raw strings, and apply regexes to logs, dates, frontmatter and file names.
  • Explain why a regex should not fully validate email addresses.
  • Recognize catastrophic backtracking (ReDoS) and fix it.

Chapter 1 — What a regex is, and how to test one

A regex engine walks through the text and tries to match your pattern at each position. Most characters match themselves. A few metacharacters have special jobs: . ^ $ * + ? ( ) [ ] { } | \.

Test patterns before you trust them. Two good ways:

  1. regex101.com — paste a pattern and sample text, pick the flavor (PCRE2, ECMAScript, Python, Golang, Java, .NET, Rust), and it explains every token and shows every match.

Terminology

Term Meaning
Pattern The regex itself, e.g. \d{4}
Match A piece of text the pattern fits
Flavor One engine's dialect (POSIX, PCRE, Python, JavaScript, .NET…)
Metacharacter A character with a special meaning, like . or *
Character class A set of allowed characters, like [a-z]
Quantifier "How many": *, +, ?, {2,5}
Anchor A position, not a character: ^, $, \b
Group Parentheses that bundle part of a pattern and (usually) capture it
Backtracking The engine going back to try another way after a dead end

Chapter 2 — Literals and escaping

cat matches the three letters c, a, t — anywhere, including inside concatenate. To match a metacharacter literally, put a backslash before it: \. is a real dot, \$ a real dollar sign, \( a real parenthesis.

When the text to match comes from a user or a file, never paste it into a pattern raw. Escape it: re.escape(text) in Python, [regex]::Escape($text) in PowerShell. Both turn price (USD) $5.00? into price\ \(USD\)\ \$5\.00\?. JavaScript added RegExp.escape() in ECMAScript 2025; older runtimes such as Node.js 20 do not have it yet.

Chapter 3 — Character classes

Pattern Matches
[aeiou] one vowel
[a-z], [A-Za-z0-9] one character from a range
[^0-9] one character that is not a digit (^ first inside [] means "not")
. any character except newline (unless the dot-all flag is on)
\d / \D a digit / a non-digit
\w / \W a "word" character (letter, digit, underscore) / anything else
\s / \S whitespace (space, tab, newline…) / anything else
[[:digit:]], [[:space:]], [[:alpha:]] POSIX classes, for grep and sed

Inside [], most metacharacters lose their power: [.$] matches a dot or a dollar. Only ], \, ^ (at the start) and - (between two characters) are special there.

Watch out: "digit" is not the same everywhere. In Python (for str patterns) and .NET, \d matches any Unicode decimal digit, including Arabic-Indic ٣٤. In JavaScript, \d is only 0-9. If you mean ASCII digits, write [0-9] or pass re.ASCII in Python.

Chapter 4 — Quantifiers, greedy and lazy

* means 0 or more, + 1 or more, ? 0 or 1 (optional), {3} exactly 3, {2,} 2 or more, {2,5} 2 to 5. A quantifier applies to the thing right before it: ab+ is a then one or more b; (ab)+ repeats ab.

Greedy vs lazy. By default, quantifiers are greedy: they take as much as they can, then give back only if the rest of the pattern fails. Add ? to make them lazy: take as little as possible.

Trick: "anything up to the next X" is best written as [^X]*X. It cannot run past the first X, so it never needs to backtrack.

Chapter 5 — Anchors, boundaries and alternation

Anchor Meaning
^ start of the string (or of each line, in multiline mode)
$ end of the string (or of each line, in multiline mode)
\b word boundary: between a \w and a \W character
\B not a word boundary
\A, \Z (Python) / \A, \z (.NET, PCRE) the very start / the very end of the whole string

\bcat\b matches cat in "the cat sat" but not in "concatenate".

Watch out: in Python and .NET, $ also matches just before a final newline. re.match(r"^\d+$", "123\n") succeeds. To demand "nothing after", use re.fullmatch(r"\d+", s) in Python or \z in .NET. In JavaScript, $ (without the m flag) means the true end.

Alternation | means "or", and it has the lowest priority of all operators. ^cat|dog$ means "cat at the start" or "dog at the end":

Wrap alternatives in a group when they belong together: ^(?:cat|dog)$.

Chapter 6 — Groups, backreferences and named groups

Parentheses do two jobs: they group (so a quantifier or | applies to the whole part) and they capture (so you can read the matched text later).

  • (?:...) groups without capturing. Use it when you only need grouping — it keeps group numbers tidy and findall output simple.
  • A backreference \1 matches the same text that group 1 matched. Find doubled words:

Named groups make long patterns readable. The syntax differs by flavor:

Define Backreference in pattern In replacement
Python (?P<year>\d{4}) (?P=year) \g<year>
JavaScript (?<year>\d{4}) \k<year> $<year>
.NET / PowerShell (?<year>\d{4}) \k<year> ${year}
PCRE (grep -P) (?<year>\d{4}) or (?P<year>…) \k<year> —

In Python, re.search(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})", s) gives a match where m["y"] is '2026' and m.groupdict() is {'y': '2026', 'm': '09', 'd': '24'}. In PowerShell:

Common pitfall: in PowerShell, write the replacement in single quotes. In double quotes, PowerShell expands $1 or ${d} as its own variables first — '2026-09-24' -replace '(\d{4})-(\d{2})-(\d{2})', "$3/$2/$1" returns //.

Chapter 7 — Lookahead and lookbehind

Lookarounds check what is next to the current position without consuming it. They match a position, like \b does.

Syntax Name Meaning
X(?=Y) lookahead X, only if followed by Y
X(?!Y) negative lookahead X, only if not followed by Y
(?<=Y)X lookbehind X, only if preceded by Y
(?<!Y)X negative lookbehind X, only if not preceded by Y

The middle one reads: "at a position that is not a word boundary, where a multiple of three digits follows up to the end of the number, insert a comma".

Watch out: Python's lookbehind must be fixed width. (?<=\$\s*)\d+ raises look-behind requires fixed-width pattern. JavaScript and .NET accept variable-length lookbehind. POSIX grep/sed have no lookarounds at all — use grep -P or another tool.

Chapter 9 — Flavors: what changes where

Feature POSIX BRE (grep, sed) POSIX ERE (grep -E, sed -E) PCRE (grep -P) Python re JavaScript .NET (PowerShell)
+ ? ( ) { } and alternation special only with a backslash: \+, \?, \(…\) (GNU) yes yes yes yes yes
\d no — use [0-9] no — use [0-9] yes yes (Unicode) yes (ASCII) yes (Unicode)
Named groups no no yes (?P<n>…) (?<n>…) (?<n>…)
Lookbehind no no yes fixed width only yes yes
Atomic groups / possessive no no both both (3.11+) neither atomic only
Group in replacement \1 \1 — \1, \g<n> $1, $<n> $1, ${n}

The classic trap is \d in grep:

Newer GNU grep (3.8 and later) also prints a warning about the "stray" backslash. In Git Bash, grep -P may need a UTF-8 locale: LC_ALL=en_US.UTF-8 grep -P ... (see Dev Essentials 05 · Command Line).

Python needs raw strings. In a normal string, "\n" is a newline and "\b" is a backspace character, so the regex engine never sees the backslash. Write r"\b\d+\b". The re docs themselves recommend raw string notation for patterns.

Chapter 10 — Python's re in practice

Function Returns
re.search(p, s) first match anywhere, or None
re.match(p, s) a match only at the start of s, or None
re.fullmatch(p, s) a match only if the whole s matches
re.findall(p, s) list of matched strings — or of groups, if the pattern has groups
re.finditer(p, s) iterator of match objects (positions, named groups)
re.sub(p, repl, s) new string with replacements; repl can be a function
re.split(p, s) list of pieces between matches
re.compile(p) reusable pattern object with the same methods

Common pitfall: findall with capturing groups returns the groups, not the whole match. re.findall(r"(\d{4})-(\d{2})", "2026-09") gives [('2026', '09')]. Use (?:...) for groups you do not need, or finditer and m.group(0).

Chapter 12 — Don't fully validate email with a regex

Real email syntax (RFC 5322) allows quoted local parts, comments and other rare forms, so a "complete" regex is huge, hard to read and still does not tell you whether the mailbox exists. The HTML standard itself does not follow RFC 5322 for <input type="email">: it calls its own simpler rule a "willful violation" of that RFC, because the RFC grammar is too strict in some places and too loose in others to be practical.

A sensible approach:

  1. Do a light sanity check: one @, no spaces, a dot in the domain part.
  2. Send a confirmation email. Only a click on the link proves the address works.

This check rejects some legal but odd addresses (such as user@localhost) and accepts some that bounce. That is fine: its only job is to catch typos early.

Chapter 13 — Catastrophic backtracking and ReDoS

Most engines (Python, JavaScript, .NET, PCRE, Java) are backtracking engines. When part of a pattern fails, they go back and try the other ways the earlier parts could have matched. Usually there are only a few ways. But nested or overlapping quantifiers create an exponential number of ways, and on text that almost matches, the engine tries them all.

The textbook case is (a+)+$ against aaaa…ab. The inner and outer + can split the as in about 2ⁿ ways, and the final b makes every split fail. A timing on one Windows 11 laptop with Python 3.11.9 (one run each — an informal measurement, not a benchmark; your numbers will differ, the doubling will not):

n (number of as) 18 20 22 24
Time 0.012 s 0.055 s 0.221 s 0.802 s

Every 2 extra characters cost about 4 times more. Extrapolating, 40 characters would take more than ten hours. That is ReDoS (regular expression denial of service): one short, crafted input keeps a CPU core busy. OWASP lists typical "evil" shapes: (a+)+, ([a-zA-Z]+)*, (a|aa)+, (a|a?)+. Real-life versions look innocent, like ^(\w+\s?)*$ for "words separated by spaces" — in the same test, 22 letters plus a ! took 0.25 s.

This is not theory. On 2 July 2019, one Cloudflare WAF rule with a badly backtracking regex (the part .*(?:.*=.*)) exhausted CPUs across Cloudflare's network and caused about 27 minutes of downtime.

Fixes, from best to last resort

1. Rewrite the pattern so each character can be matched only one way.

Evil Safe Why
(a+)+$ a+$ the nesting added nothing
^(\d+)*$ ^\d*$ same language, one way to split
^(\w+\s?)*$ ^(?:\w+\s)*\w*$ each repeat must end with a space, so splits are fixed

On 100,000 characters, the rewritten ^(?:\w+\s)*\w*$ finished in about 1 ms in the same test. It also gave the same yes/no answer as the original on every test string tried ("hello world", "hello world", "hello world ", "", " lead", "x!").

2. Forbid backtracking into a part with an atomic group (?>...) or a possessive quantifier (*+, ++, ?+). Once matched, the engine will not try other splits. Python supports both since 3.11; PCRE and Java support both; .NET supports atomic groups only; JavaScript supports neither.

3. Use a linear-time engine for untrusted patterns or input. Google's RE2, Go's regexp and Rust's regex crate guarantee time linear in the input size (Rust documents O(m × n) for pattern size m and text size n). The price: no backreferences and no lookarounds. .NET 7 and later offer RegexOptions.NonBacktracking with the same kind of guarantee; Windows PowerShell 5.1 runs on .NET Framework and does not have it. After its outage, Cloudflare planned to move to RE2 or the Rust engine for exactly this reason.

4. Limit the damage. Cap input length before matching. In .NET, pass a timeout — the default is infinite:

Python's built-in re has no timeout, so rewrite the pattern or run risky matching in a separate process you can stop.

Exercise 4 — Frontmatter title, CRLF-safe

Get the title from "---\r\ntitle: Regex from Zero to Useful\r\ndate: 2026-09-24 10:30:00\r\n---\r\nBody text\r\n" without a trailing \r.

Solution

The lazy (.+?) stops as early as it can, and \s*$ swallows the \r before the line end. The naive ^title: (.+)$ returns 'Regex from Zero to Useful\r'.

Exercise 5 — Defuse a slow pattern

^(\d+)*$ is used to check "only digits". Time it on "1" * 24 + "x", then rewrite it.

Solution

^\d*$ accepts exactly the same strings, with one way to match each. Better still for this job: re.fullmatch(r"[0-9]+", s) — ASCII digits only, at least one, and nothing after (not even a newline).

Exercise 6 — CSS hex colors

In "color: #fff; bg: #1a2b3c; bad: #ffff; also #ABCDEF; nope #12345678.", match 3- or 6-digit hex colors only.

Solution

The \b at the end stops #ffff and #12345678 from matching a shorter prefix.

Need Pattern
Any digit / word char / space \d \w \s (ASCII only: [0-9], or re.ASCII)
One of / none of [abc] / [^abc]
Repeat * + ? {n} {n,m} — add ? for lazy
Anything up to X [^X]*X
Start / end / word edge ^ $ \b (whole string: fullmatch, \A…\z)
Group / no capture / or (...) / (?:...) / a|b
Same text again \1, (?P=name) (Python), \k<name>
Named group (?P<n>...) Python, (?<n>...) JS/.NET/PCRE
Replacement refs Python \1 \g<n> · JS $1 $<n> · .NET $1 ${n} · sed \1
Followed / not followed by (?=...) / (?!...)
Preceded / not preceded by (?<=...) / (?<!...)
Flags (?i) ignore case, (?m) multiline, (?s) dot-all, (?x) verbose
Escape user text re.escape, [regex]::Escape, RegExp.escape (ES2025)
Stop runaway backtracking rewrite, (?>...), a++, RE2/Rust/Go, .NET timeout
