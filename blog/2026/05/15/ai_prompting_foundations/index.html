AI Prompting (Foundations & Practice)

Created2026-05-15|Updated2026-05-15|AI
|Post View:

Prompting is the practice of writing inputs that steer a Large Language Model (LLM) toward useful outputs. It is part interface design, part rhetoric, and part empirical science. This note covers the foundations and the techniques that have been validated by published research, with worked examples you can copy.

Learning Outcome

  • Explain what a prompt is and why model behaviour is sensitive to its phrasing.
  • Decompose a prompt into its functional parts (instruction, context, examples, format spec).
  • Apply core techniques: zero-shot, few-shot, chain-of-thought, role conditioning, decomposition, and self-consistency.
  • Recognise common anti-patterns and explain why they fail.
  • Design an evaluation harness with a golden set + rubric + A/B framework.
  • Read a research paper on prompting and judge whether its claims will transfer to your task.

Chapter 1 - Foundations

Terminology

  • Prompt — the full token sequence the model conditions on before generating the next token.
  • Completion — the model's generated response.
  • Token — sub-word unit (~4 characters of English on average). All limits (context window, throughput, billing) are measured in tokens.
  • Context window — maximum prompt+completion length the model can attend to.
  • In-context learning (ICL) — model adapts its behaviour from examples in the prompt without weight updates. Reported in Language Models are Few-Shot Learners, Brown et al. (2020).
  • Temperature — sampling parameter; 000 is greedy, higher values increase diversity.
  • Top-p / Top-k — nucleus / top-k sampling, alternatives to temperature.
  • System / developer message — privileged prompt segment used to set persistent behaviour. Mechanism formalised by The Instruction Hierarchy, Wallace et al. (2024).

Why prompts matter

An LLM is a next-token predictor over a learned distribution P(tn∣t1,…,tn−1)P(t_n \mid t_1, \dots, t_{n-1})P(tn​∣t1​,…,tn−1​). The prompt is the conditional sequence t1,…,tn−1t_1, \dots, t_{n-1}t1​,…,tn−1​. Two prompts that read as semantically equivalent to a human can produce very different distributions because the model is sensitive to token-level cues it has learned to associate with answer quality (formality, code-block fences, "Let's think step by step", etc.).

This sensitivity has been measured empirically. Lu et al. (2022) showed that simply reordering few-shot examples can swing accuracy on classification benchmarks by tens of percentage points. Sclar et al. (2024) showed that benign formatting changes (newline vs. colon as separator) shift task accuracy by a comparable margin.

The practical consequence: prompts are programs. They deserve version control, testing, and review.

How the model "reads" a prompt

A typical chat-tuned model receives a structured sequence — for instance OpenAI's ChatML or Anthropic's Human:/Assistant: turn markers — where each turn is tagged with a role. The model has been fine-tuned (instruction-tuned + RLHF or DPO) to:

  1. Treat the system / developer message as a high-priority constraint.
  2. Treat user messages as questions or requests.
  3. Treat its own prior responses as commitments to maintain consistency with.

The training procedure was first detailed in InstructGPT, Ouyang et al. (2022) and the Anthropic RLHF paper, Bai et al. (2022). The hierarchy of trust between roles was later sharpened in The Instruction Hierarchy, Wallace et al. (2024).

Chapter 2 - Anatomy of a Prompt

A well-formed prompt contains, in some combination, six functional parts. Naming them helps you debug what is missing.

Part Purpose Example
Role / persona Set a frame the model uses to choose vocabulary, depth, formality "You are a senior database administrator."
Instruction The actual verb of the request "Explain why this query is slow."
Context Domain facts, retrieved documents, prior turns The SQL query + EXPLAIN ANALYZE output
Examples (shots) Demonstrations of input → output A prior worked optimisation
Format spec Constraint on output shape "Return JSON matching schema X"
Stop / guardrails Negative constraints, refusal triggers "If the query is fine, say OK only."

Chapter 3 - Core Techniques

Zero-shot

Ask the question directly with no examples. Works when the task is well-represented in the training distribution (translation, summarisation, common QA).

Few-shot (in-context learning)

Provide kkk input/output pairs, then the new input. Brown et al. (2020) showed few-shot prompting closes a large fraction of the gap to fine-tuning on many tasks without any gradient updates.

Tips:

  • Order examples easy → hard (Lu et al., 2022).
  • Make examples cover the failure modes you observe in zero-shot, not the easy cases.
  • Keep formatting identical across shots; a stray newline can degrade accuracy (Sclar et al., 2024).

Chain-of-Thought (CoT) prompting

Ask the model to show its work before committing to an answer. Reported in Chain-of-Thought Prompting Elicits Reasoning in Large Language Models, Wei et al. (2022). Improves arithmetic, symbolic, and commonsense reasoning on large models.

Two variants worth knowing:

  • Zero-shot CoT: append "Let's think step by step." Kojima et al. (2022). Cheap and surprisingly effective.
  • Self-consistency: sample nnn chains at temperature >0>0>0, take the majority vote on the final answer. Wang et al. (2022). Improves arithmetic accuracy further at n×n \timesn× cost.

Role / persona conditioning

Setting an expert persona biases vocabulary, depth, and inferred audience. The effect is real but smaller than CoT or few-shot; treat it as fine-tuning of style, not capability.

Decomposition

Break a hard problem into ordered sub-problems and prompt each separately, chaining outputs. Equivalent to Khot et al. (2023) "Decomposed Prompting" or least-to-most prompting by Zhou et al. (2023).

The chain is easier to debug than a single monolithic prompt; you can swap or rerun any step.

ReAct (Reasoning + Acting)

Interleave reasoning steps with tool calls. Yao et al. (2023). The model alternates between Thought: (a reasoning step), Action: (a tool call), and Observation: (tool result), until ready to emit an Answer:.

ReAct is the foundation pattern under most "agent" frameworks (LangChain, LlamaIndex, modern function-calling SDKs).

Chapter 4 - Structural Patterns

Delimiters

Use unambiguous markers around user-supplied or retrieved content. Three formats all work, in roughly equal measure:

XML tags have the advantage of being self-documenting and survive whitespace normalisation. Anthropic explicitly recommends XML in their prompt-engineering documentation.

Markdown structure

Models trained on heavy Markdown corpora respond well to headings (## Step 1), lists, and tables. Use the same conventions in your prompt that you want to see in the output.

Numbered constraints

Numbered constraints are easier for the model to enumerate against than a paragraph of "and also, make sure to..."

Format specifications

Three escalating strengths:

Strength Mechanism Reliability
Soft Natural-language description ("return JSON") ~60-80%
Schema Provide explicit schema (TypeScript / JSON Schema / Pydantic) ~90%
Hard Use the provider's structured-output / JSON-mode API ~100% (provider-enforced)

If you need a guaranteed shape, use the provider's structured output. Soft format is convenient but will fail on tail cases.

Chapter 5 - Reasoning Boosters

Self-consistency

Already mentioned. Formally: sample nnn chains c1,…,cnc_1, \dots, c_nc1​,…,cn​ at T>0T > 0T>0, extract the final answer aia_iai​ from each, return arg⁡max⁡a∑i1[ai=a]\arg\max_a \sum_i \mathbb{1}[a_i = a]argmaxa​∑i​1[ai​=a]. The probability that the majority answer is correct converges to the per-sample accuracy raised to a Condorcet-style power as nnn grows, when individual samples are conditionally independent given the question.

Tree of Thoughts (ToT)

Yao et al. (2023). Generalises CoT from a chain to a search tree. The model proposes multiple next-thoughts at each step, a value model scores each, and a search algorithm (BFS/DFS) explores. Helps on combinatorial problems (Game of 24, crosswords) where a single chain commits too early.

Reflexion

Shinn et al. (2023). After a wrong attempt, the model writes a critique of its own trace; that critique is appended to context for the next attempt. The agent improves across attempts within a single session.

Step-Back prompting

Zheng et al. (2024). Before answering a specific question, ask the model to first derive the general principle that governs the question. The principle then conditions the specific answer. Improves abstract / multi-step reasoning.

Chapter 6 - Common Anti-patterns

Vague verbs

improve, optimise, make better, enhance are unmeasurable. The model has to guess a direction. Replace with a measurable verb: shorten to 100 words, rewrite at a 10th-grade reading level, remove all passive voice.

Conflicting constraints

The model resolves contradictions arbitrarily. Pick one side of each axis and state it.

Leading questions

The framing forces the model to defend a premise instead of evaluating it. Prefer:

Long irrelevant context

Liu et al. (2023) Lost in the Middle showed models degrade on retrieval tasks when relevant information sits in the middle of a long context. Prune aggressively. If you must include long retrieved documents, put the most relevant snippets at the start or the end.

Negation-only instructions

Do not list more than 3 items. is weaker than List exactly 3 items. Models follow positive constraints more reliably than negative ones.

"Polite filler"

Please, if you could, kindly attempt to consider... adds tokens without affecting behaviour. Strip it.

Chapter 7 - Evaluation

A prompt is a piece of software, so evaluate it like software.

Golden set

A small, curated set of representative inputs with hand-graded expected outputs. 30–100 items is enough to detect a 5pp accuracy shift.

Rubric

Decompose "is the output good?" into yes/no axes. For a summarisation task you might score:

  • Factual (no hallucinated entities)
  • Complete (all named main points present)
  • Concise (within length limit)
  • Format (parses as JSON)
  • Refusal (correctly refused when no claim present)

Each axis scored 0/1 by a human grader or a separate "judge" model.

LLM-as-judge

Zheng et al. (2023). A stronger model grades a weaker model's output against a rubric. Cheap, scales, but biased toward outputs that look like the judge's style. Use a different family of model as the judge where possible, and spot-check 10% with a human.

A/B framework

Track Δ\DeltaΔ per axis, not just overall. A change that improves factuality but hurts conciseness is still a regression on the conciseness axis.

Statistical sanity

With n=100n=100n=100 binary outcomes, the 95% confidence interval on accuracy is roughly ±10\pm 10±10pp around the observed rate. Differences smaller than that are noise. Increase nnn or repeat the run to tighten.

Chapter 8 - Tool Use and Structured Output

Modern model providers expose two APIs that should replace most prompt-engineering hacks:

Function calling / tool use

You declare a JSON schema for one or more tools; the model picks one and emits arguments matching the schema. The runtime executes the tool and returns the result, which you append to the conversation and prompt again.

The model is fine-tuned to know when to call a tool versus answer directly. This is more reliable than ReAct in raw text because the model emits parsed JSON via the API.

Structured output (JSON / Pydantic mode)

You supply the full output schema; the provider's decoder constrains generation so the response is guaranteed valid against the schema. Eliminates "the model added a friendly preamble that broke my parser" failures.

When NOT to use tools

If the task is pure transformation of text the model already has the knowledge for (summarise, translate, classify), tools add latency and cost. Use tools when you need fresh data, deterministic computation, or side effects.

Goal First thing to try
Wrong answer on math Append "Let's think step by step."
Output not parseable Switch to provider's structured-output API

Inconsistent answers across runs Self-consistency, n=5n=5n=5, majority vote

Drifts off topic mid-conversation Re-state the system message every kkk turns
Slow / expensive Decompose; use a smaller model for the easy steps

Quick sanity checks before shipping

  1. Does the prompt have all six anatomy parts (role, instruction, context, examples, format, stop)?
  2. Is there a golden set of ≥ 30 items with rubric scores?
  3. Have you tested the failure modes, not just the happy path?
  4. Are you using structured output for any machine-parsed response?
  5. Have you token-counted the prompt under realistic context lengths?
  6. Have you versioned the prompt in git with a short rationale per change?
