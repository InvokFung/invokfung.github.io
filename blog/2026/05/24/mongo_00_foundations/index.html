MongoDB Course — 00 · Foundations, Document Model, Install, Tools

Created2026-05-24|Updated2026-05-24|Database > MongoDB
|Post View:

MongoDB is the most popular general-purpose document database. It stores JSON-like documents (BSON on disk), scales horizontally via sharding, and trades the rigid schema + joins of relational databases for flexible schemas, fast denormalised reads, and rich nested queries. This 18-post course covers it from "what is a document" through CRUD, indexes, aggregation, schema design, connection pools, transactions, replication, sharding, security, backups, performance, Atlas, drivers, and modelling case studies. Post 00 grounds the rest in the mental model + tooling every project reuses.

Series map: 00 Foundations (this post) → 01 CRUD → 02 Query Operators → 03 Indexes → 04 Query Optimization → 05 Aggregation Basics → 06 Aggregation Advanced → 07 Schema Design → 08 Connection Pool & Concurrency → 09 Transactions → 10 Replica Sets → 11 Sharding → 12 Change Streams → 13 Security → 14 Backup & Ops → 15 Performance Deep → 16 Atlas Search + Vector + Triggers → 17 Drivers & Modelling Case Studies.

Learning Outcome

  • Explain the document model and how it differs from relational.
  • Define database, collection, document, field, BSON.
  • Install MongoDB locally and connect with mongosh.
  • Connect to a free MongoDB Atlas cluster.
  • Use Compass (GUI) and the official driver landscape.
  • Recognise when MongoDB is the right (or wrong) tool.

Chapter 1 — What MongoDB is

Terminology

  • MongoDB — distributed document database; open-source core + commercial Atlas service.
  • Document — a BSON object: ordered key-value pairs, nested arrays + sub-documents. Conceptually a JSON object with extra types (ObjectId, Date, Binary, Decimal128).
  • Collection — a group of documents (analogous to a SQL table; no enforced schema by default).
  • Database — a group of collections.
  • BSON — Binary JSON, the on-disk + on-wire format. Adds types JSON lacks (ObjectId, Date, Binary, etc.) and length-prefixes for fast traversal.
  • _id — every document has one. Auto-generated ObjectId (12 bytes: timestamp + machine + pid + counter) unless you supply your own.
  • Replica set — a group of mongod processes that maintain the same data; provides HA + read scaling.
  • Sharded cluster — multiple replica sets partitioned by a shard key; provides horizontal write scaling.

Document example

One document holds the user, their tags array, and a nested address — no joins, no separate tables.

Chapter 2 — Document vs relational mental model

Relational MongoDB
Database Database
Table Collection
Row Document
Column Field
Primary key _id
Foreign key Reference (manual or $lookup)
Join $lookup aggregation stage
Schema enforced by DDL Optional schema validation ($jsonSchema)
Transactions Multi-document transactions (since 4.0)
Index Index (B-tree, hashed, text, geo, vector)

The shift in thinking:

  • Relational: normalise first, denormalise for performance.
  • Document: denormalise first (embed related data) for read locality; reference only when reuse + size dictate.

Post 07 (Schema Design) covers this decision deeply.

When MongoDB fits

  • Document-shaped data (catalogue items, user profiles, content items).
  • High write throughput with sharding.
  • Flexible / evolving schema (early product, multi-tenant SaaS with per-tenant variation).
  • Geographic + full-text + vector queries on the same data.
  • Real-time change streams.

When MongoDB doesn't fit (consider alternatives)

  • Heavy multi-row ACID transactions → Postgres / CockroachDB.
  • Complex relational reporting + ad-hoc joins → relational + warehouse.
  • Pure key-value at giant scale → Redis / DynamoDB.
  • Strict tabular columnar analytics → ClickHouse / BigQuery.

Chapter 3 — Versions in 2026

MongoDB ships major versions yearly; current as of 2026 is 8.x. LTS-friendly defaults:

Version Notable
4.0 (2018) multi-document transactions
4.2 sharded transactions, wildcard indexes
5.0 resharding, time-series collections, window functions
6.0 queryable encryption (preview), Atlas Vector Search foundations
7.0 queryable encryption GA, large change-stream events
8.0+ continued perf + TSL-era features

For new projects in 2026, target 8.x (latest GA). Atlas Free Tier runs the current version automatically.

Chapter 6 — Compass (the GUI)

MongoDB Compass is the official desktop client. Useful for:

  • Schema discovery — sample documents + auto-detect field types + distributions.
  • Visual query builder.
  • Aggregation pipeline editor with stage-by-stage preview.
  • Performance tab — explain + index hints.
  • Connection-string + Atlas integration.

Beginners learn faster with Compass open beside mongosh. Compass writes the same commands mongosh does — copy and paste between them.

Chapter 7 — Drivers (official languages)

Language Package Notes
Node.js mongodb (official), mongoose (ODM) most popular; Mongoose adds schemas + middleware
Python pymongo (sync), motor (async) both maintained by MongoDB Inc.
Java / Kotlin mongodb-driver-sync / mongodb-driver-reactivestreams enterprise default
C# / .NET MongoDB.Driver first-class LINQ support
Go mongo-go-driver popular for backend services
Rust mongodb (official) async via tokio
PHP, Ruby, Swift, Scala, Perl official drivers maintained

A connection string is identical across drivers; idioms differ. Post 17 contrasts the major drivers + Mongoose vs Prisma trade-offs.

Chapter 10 — Conventions used in this course

  • Examples use mongosh syntax (db.collection.method(...)); the Node driver uses collection.method(...) with the same arguments — easy mental swap.
  • All _ids shown as ObjectId("...") are illustrative; real ones are 24-character hex strings.
