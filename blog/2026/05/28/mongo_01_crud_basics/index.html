MongoDB Course — 01 · CRUD Basics — Insert, Find, Update, Delete, Bulk

Created2026-05-28|Updated2026-05-28|Database > MongoDB
|Post View:

CRUD — Create, Read, Update, Delete — is the daily 95 % of MongoDB. This post covers every standard operation (insertOne / insertMany / findOne / find / updateOne / updateMany / replaceOne / deleteOne / deleteMany / bulkWrite), all the update operators ($set / $inc / $push / $pull / $addToSet / $rename / $unset / $mul / $min / $max / $pop), the upsert pattern, and the write-concern + return-value behaviour you need to know to use them safely.

Series map: 00 Foundations → 01 CRUD (this post) → 02 Query Operators → 03 Indexes → 04 Query Optimization → 05 Aggregation Basics → … → 17 Drivers & Case Studies.

Learning Outcome

  • Insert single and many documents; understand _id generation.
  • Read with findOne, find (cursor), projection, sort, skip, limit.
  • Update with $set, $inc, $push, $pull, $addToSet, $rename, $unset, $mul, $min, $max, $pop.
  • Use replaceOne vs updateOne correctly.
  • Use upsert to "insert or update".
  • Delete safely with deleteOne / deleteMany.
  • Use bulkWrite for batched mixed operations.
  • Understand write concern (w, j, wtimeout) and return values.

Projection — pick fields

  • 1 = include; 0 = exclude.
  • Cannot mix include + exclude in one projection except to exclude _id.
  • Default returns the whole document.

Sort, limit, skip

Chained on the cursor. Order applied during the server-side query.

Watch out: .skip(N) walks N documents before discarding — costs O(N). For pagination beyond a few hundred rows, prefer range pagination (find({ at: { $lt: lastSeenAt } })) — covered in Post 02.

countDocuments + estimatedDocumentCount

For "how many total" use estimatedDocumentCount (instant). For "how many match X" use countDocuments.

Chapter 5 — Upsert (insert-or-update)

If the filter matches a document → updates it. If no match → inserts a new document combining the filter fields + update fields.

Use cases: idempotent upserts from a job; "first-seen / last-seen" tracking; counters per key.

Counter-per-key idiom:

Increments the counter; creates the document with count: 1 if the key didn't exist.

Trick: when upserting on a unique field, ensure there's a unique index on that field. Otherwise two simultaneous upserts can race and produce two documents.

Chapter 6 — updateOne vs updateMany vs replaceOne

Operation Filter matches What it changes
updateOne first match only applies update operators
updateMany all matches applies update operators
replaceOne first match only replaces the entire document (except _id)
findOneAndUpdate first match applies operators + returns the doc (before or after)
findOneAndReplace first match replaces + returns
findOneAndDelete first match deletes + returns

replaceOne is dangerous if you forget to include existing fields — they vanish. Prefer updateOne + $set unless you really mean "wipe and re-create".

returnDocument: 'after' returns the post-update version — common for atomic counters.

Chapter 7 — Delete

Returns:

There is no built-in undo. For safety:

  • Use a "soft delete" pattern: $set: { deleted_at: new Date() } instead of physical delete.
  • Or move to an "archive" collection first.
  • Backups (Post 14) save you when those fail.

These are irreversible. Use only in scripts you trust.

Watch out: deleteMany({}) with the empty filter deletes everything in the collection. The shell prompts for confirmation; drivers don't. Always pass a real filter.

Chapter 8 — Bulk writes

bulkWrite batches mixed operations into one network round-trip — much faster than N separate calls.

ordered: true (default) — stop on first error. ordered: false — try all, report errors together.

Use for: data migrations, batch sync from another system, periodic clean-ups.

Driver-specific batching limits

  • Single bulk op limited to 1000 operations / 16 MB BSON payload (server defaults). Larger batches split server-side automatically.
  • For huge loads, chunk into batches of ~500-1000 yourself for memory predictability.

Chapter 9 — Write concern (w, j, wtimeout)

Every write has a write concern controlling how durable the acknowledgement is.

Field Meaning
w: 0 fire-and-forget — no ack
w: 1 primary acked the write (default for single-node)
w: "majority" majority of replica-set voters acked (default in replica sets)
w: N exactly N members acked
j: true ack only after write is journaled to disk
wtimeout: ms give up waiting for w after this many ms

Trade-off: stricter concern = safer + slower. w: "majority", j: true is the production-correct default; the driver and Atlas pick it for you in replica sets.

Read concern (preview — full in Post 08)

Read concern When
local default — read from local memory; may see uncommitted-on-majority writes
majority read only data acked by majority — survives elections
linearizable strongest consistency; slow
snapshot inside transactions

Chapter 10 — Common pitfalls

Symptom Cause Fix
replaceOne wiped half the fields passed new doc without old fields use updateOne + $set
Upsert created two duplicates under load no unique index on filter add unique index on the filter field
find({}) slow on big collection full collection scan add an index (Post 03); use a filter
find({ tags: ["a", "b"] }) matches nothing [a,b] looks like exact-array match, not contains-both use $all: { tags: { $all: ["a","b"] } }
Updates silently no-op filter doesn't match print result.matchedCount and modifiedCount
Deleted production accidentally deleteMany({}) typo always pass a real filter; consider soft-delete
$push on huge array → slow / bloated doc unbounded array growth cap with $slice; or move to a child collection

Cheat-sheet

What How
Insert one db.c.insertOne(doc)
Insert many db.c.insertMany([docs], { ordered: false })
Find first db.c.findOne(filter)
Find all db.c.find(filter).toArray()
Project find(filter, { name: 1, _id: 0 })
Sort / limit / skip .sort({ field: -1 }).limit(N).skip(M)
Cursor stream for await (const d of cursor)
Set fields { $set: { f: v } }
Remove field { $unset: { f: "" } }
Increment { $inc: { n: 1 } }
Append array { $push: { arr: x } } or { $each: [...] }
Append unique { $addToSet: { arr: x } }
Remove array elements { $pull: { arr: x } }
Pop first/last { $pop: { arr: -1 } } / { arr: 1 }
Update positional "arr.$" after match condition
Update by filter $[<id>] + arrayFilters
Upsert third arg { upsert: true }
Replace entire doc replaceOne
Atomic return findOneAndUpdate({}, {}, { returnDocument: 'after' })
Soft delete $set: { deleted_at: new Date() }
Bulk bulkWrite([ops], { ordered: false })
Write concern { w: "majority", j: true, wtimeout: 5000 }
