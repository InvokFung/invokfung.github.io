<h1 id="Chapter-5-—-Upsert-insert-or-update"><a href="#Chapter-5-—-Upsert-insert-or-update" class="headerlink" title="Chapter 5 — Upsert (insert-or-update)"></a>Chapter 5 — Upsert (insert-or-update)</h1>
<pre><code class="language-js"><figure class="highlight js"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span></pre></td><td class="code"><pre><code class="js"><span class="line">db.<span class="hljs-property">users</span>.<span class="hljs-title function_">updateOne</span>(</span><br><span class="line">  { <span class="hljs-attr">email</span>: <span class="hljs-string">&quot;new@x&quot;</span> },</span><br><span class="line">  { <span class="hljs-attr">$set</span>: { <span class="hljs-attr">name</span>: <span class="hljs-string">&quot;New User&quot;</span>, <span class="hljs-attr">created_at</span>: <span class="hljs-keyword">new</span> <span class="hljs-title class_">Date</span>() } },</span><br><span class="line">  { <span class="hljs-attr">upsert</span>: <span class="hljs-literal">true</span> }</span><br><span class="line">)</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>If the filter matches a document → updates it. If no match → inserts a new document combining the filter fields + update fields.</p>
<p>Use cases: idempotent upserts from a job; &quot;first-seen / last-seen&quot; tracking; counters per key.</p>
<p>Counter-per-key idiom:</p>
<pre><code class="language-js"><figure class="highlight js"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span></pre></td><td class="code"><pre><code class="js"><span class="line">db.<span class="hljs-property">metrics</span>.<span class="hljs-title function_">updateOne</span>(</span><br><span class="line">  { <span class="hljs-attr">day</span>: <span class="hljs-string">&quot;2026-05-24&quot;</span>, <span class="hljs-attr">event</span>: <span class="hljs-string">&quot;signup&quot;</span> },</span><br><span class="line">  { <span class="hljs-attr">$inc</span>: { <span class="hljs-attr">count</span>: <span class="hljs-number">1</span> } },</span><br><span class="line">  { <span class="hljs-attr">upsert</span>: <span class="hljs-literal">true</span> }</span><br><span class="line">)</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Increments the counter; creates the document with <code>count: 1</code> if the key didn't exist.</p>
<blockquote>
<p><strong>Trick:</strong> when upserting on a unique field, ensure there's a unique <strong>index</strong> on that field. Otherwise two simultaneous upserts can race and produce two documents.</p>
</blockquote>

<h1 id="Chapter-9-—-Write-concern-w-j-wtimeout"><a href="#Chapter-9-—-Write-concern-w-j-wtimeout" class="headerlink" title="Chapter 9 — Write concern (w, j, wtimeout)"></a>Chapter 9 — Write concern (w, j, wtimeout)</h1>
<p>Every write has a <strong>write concern</strong> controlling how durable the acknowledgement is.</p>
<pre><code class="language-js"><figure class="highlight js"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span></pre></td><td class="code"><pre><code class="js"><span class="line">db.<span class="hljs-property">users</span>.<span class="hljs-title function_">insertOne</span>(</span><br><span class="line">  { <span class="hljs-attr">name</span>: <span class="hljs-string">&quot;Frank&quot;</span> },</span><br><span class="line">  { <span class="hljs-attr">writeConcern</span>: { <span class="hljs-attr">w</span>: <span class="hljs-string">&quot;majority&quot;</span>, <span class="hljs-attr">j</span>: <span class="hljs-literal">true</span>, <span class="hljs-attr">wtimeout</span>: <span class="hljs-number">5000</span> } }</span><br><span class="line">)</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<table>
<thead>
<tr>
<th>Field</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>w: 0</code></td>
<td>fire-and-forget — no ack</td>
</tr>
<tr>
<td><code>w: 1</code></td>
<td>primary acked the write (default for single-node)</td>
</tr>
<tr>
<td><code>w: &quot;majority&quot;</code></td>
<td>majority of replica-set voters acked (default in replica sets)</td>
</tr>
<tr>
<td><code>w: N</code></td>
<td>exactly N members acked</td>
</tr>
<tr>
<td><code>j: true</code></td>
<td>ack only after write is journaled to disk</td>
</tr>
<tr>
<td><code>wtimeout: ms</code></td>
<td>give up waiting for <code>w</code> after this many ms</td>
</tr>
</tbody>
</table>
<p>Trade-off: stricter concern = safer + slower. <code>w: &quot;majority&quot;, j: true</code> is the production-correct default; the driver and Atlas pick it for you in replica sets.</p>

<h1 id="Chapter-10-—-Common-pitfalls"><a href="#Chapter-10-—-Common-pitfalls" class="headerlink" title="Chapter 10 — Common pitfalls"></a>Chapter 10 — Common pitfalls</h1>
<table>
<thead>
<tr>
<th>Symptom</th>
<th>Cause</th>
<th>Fix</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>replaceOne</code> wiped half the fields</td>
<td>passed new doc without old fields</td>
<td>use <code>updateOne</code> + <code>$set</code></td>
</tr>
<tr>
<td>Upsert created two duplicates under load</td>
<td>no unique index on filter</td>
<td>add unique index on the filter field</td>
</tr>
<tr>
<td><code>find({})</code> slow on big collection</td>
<td>full collection scan</td>
<td>add an index (Post 03); use a filter</td>
</tr>
<tr>
<td><code>find({ tags: [&quot;a&quot;, &quot;b&quot;] })</code> matches nothing</td>
<td><code>[a,b]</code> looks like exact-array match, not contains-both</td>
<td>use <code>$all</code>: <code>{ tags: { $all: [&quot;a&quot;,&quot;b&quot;] } }</code></td>
</tr>
<tr>
<td>Updates silently no-op</td>
<td>filter doesn't match</td>
<td>print <code>result.matchedCount</code> and <code>modifiedCount</code></td>
</tr>
<tr>
<td>Deleted production accidentally</td>
<td><code>deleteMany({})</code> typo</td>
<td>always pass a real filter; consider soft-delete</td>
</tr>
<tr>
<td><code>$push</code> on huge array → slow / bloated doc</td>
<td>unbounded array growth</td>
<td>cap with <code>$slice</code>; or move to a child collection</td>
</tr>
</tbody>
</table>

<h2 id="Exercise-4-—-Daily-counter-via-upsert"><a href="#Exercise-4-—-Daily-counter-via-upsert" class="headerlink" title="Exercise 4 — Daily counter via upsert"></a>Exercise 4 — Daily counter via upsert</h2>
<p>Build a function <code>bump(day, event)</code> that increments a per-day-per-event counter using upsert. Call it 100 times concurrently from a Node script.</p>
<h2 id="Exercise-5-—-Bulk-migration"><a href="#Exercise-5-—-Bulk-migration" class="headerlink" title="Exercise 5 — Bulk migration"></a>Exercise 5 — Bulk migration</h2>
<p>Use <code>bulkWrite</code> with <code>ordered: false</code> to: insert 5 new users, increment <code>visits</code> by 1 for everyone over 30, delete users marked <code>inactive: true</code>, in one call.</p>
<h2 id="Exercise-6-—-Soft-delete"><a href="#Exercise-6-—-Soft-delete" class="headerlink" title="Exercise 6 — Soft delete"></a>Exercise 6 — Soft delete</h2>
<p>Replace your <code>deleteOne</code> calls in any past exercise with <code>$set: { deleted_at: new Date() }</code>. Then write a query that excludes soft-deleted docs.</p>
