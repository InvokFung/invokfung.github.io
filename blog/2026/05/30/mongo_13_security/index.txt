<h1 id="Learning-Outcome"><a href="#Learning-Outcome" class="headerlink" title="Learning Outcome"></a>Learning Outcome</h1>
<ul>
<li>Enable authentication + create roles + users with least privilege.</li>
<li>Use TLS in transit + encryption at rest.</li>
<li>Apply network isolation (Atlas private endpoint / VPC peering / IP allowlist).</li>
<li>Use Client-Side Field-Level Encryption for sensitive fields.</li>
<li>Use Queryable Encryption when encrypted data must still be searchable.</li>
<li>Audit access via the audit log.</li>
<li>Apply the production-hardening checklist.</li>

<h2 id="Principle-of-least-privilege"><a href="#Principle-of-least-privilege" class="headerlink" title="Principle of least privilege"></a>Principle of least privilege</h2>
<p>For a typical service:</p>
<ul>
<li>One <strong>read-write</strong> role on its own collections.</li>
<li>One <strong>read-only</strong> role on shared / reference collections.</li>
<li>No access elsewhere.</li>
</ul>
<p>Even for an admin user, prefer <code>dbOwner</code> on the relevant DB rather than <code>root</code>.</p>

<h1 id="Chapter-4-TLS-in-transit"><a href="#Chapter-4-TLS-in-transit" class="headerlink" title="Chapter 4 ??TLS in transit"></a>Chapter 4 ??TLS in transit</h1>
<p>Every wire connection should be TLS-encrypted. Self-hosted:</p>
<pre><code class="language-yaml"><figure class="highlight yaml"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span></pre></td><td class="code"><pre><code class="yaml"><span class="line"><span class="hljs-attr">net:</span></span><br><span class="line">  <span class="hljs-attr">tls:</span></span><br><span class="line">    <span class="hljs-attr">mode:</span> <span class="hljs-string">requireTLS</span></span><br><span class="line">    <span class="hljs-attr">certificateKeyFile:</span> <span class="hljs-string">/etc/ssl/mongo.pem</span></span><br><span class="line">    <span class="hljs-attr">CAFile:</span> <span class="hljs-string">/etc/ssl/ca.pem</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Client connection string:</p>
<pre><code class="language-text"><figure class="highlight text"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span></pre></td><td class="code"><pre><code class="text"><span class="line">mongodb+srv://...?tls=true</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Atlas: TLS is mandatory + the cert is auto-managed. Connections without TLS are refused.</p>
<p>Disable plaintext / require TLS even for localhost ??accidental cleartext on a shared host is a real risk.</p>
<hr>
<h1 id="Chapter-5-Network-isolation"><a href="#Chapter-5-Network-isolation" class="headerlink" title="Chapter 5 ??Network isolation"></a>Chapter 5 ??Network isolation</h1>
<p>Layer your defences:</p>
<ol>
<li><strong>Atlas Private Endpoint</strong> (AWS PrivateLink / Azure Private Link / GCP Private Service Connect) ??traffic stays on the cloud backbone; cluster has no public IP.</li>
<li><strong>VPC Peering</strong> ??your VPC talks to the Atlas VPC over private addresses.</li>
<li><strong>IP allowlist</strong> ??restrict which IPs can connect (a fallback, not a primary defence).</li>
<li><strong>Self-hosted</strong> ??bind <code>mongod</code> to private interface only (<code>bindIp: 127.0.0.1,10.0.0.10</code>); never <code>0.0.0.0</code> on public-internet hosts.</li>
<li><strong>Firewall / Security Group</strong> ??only your app subnets reach port 27017.</li>
</ol>
<p>The infamous &quot;unsecured Mongo on the internet&quot; stories are always: default bind + no auth + no firewall. Avoid all three.</p>
<hr>
<h1 id="Chapter-6-Encryption-at-rest"><a href="#Chapter-6-Encryption-at-rest" class="headerlink" title="Chapter 6 ??Encryption at rest"></a>Chapter 6 ??Encryption at rest</h1>
<p>Self-hosted (Enterprise / Atlas):</p>
<ul>
<li>WiredTiger native encryption ??AES-256 with keys from KMIP, Vault, Azure Key Vault, GCP KMS, AWS KMS, or a local keyfile.</li>
<li>Atlas: enabled by default with customer-managed keys (CMK) optional on dedicated tiers.</li>
</ul>
<p>Backups, snapshots, oplog files are all encrypted on disk.</p>
<p>Encryption at rest protects against <strong>disk theft</strong>. It does NOT protect against a logged-in attacker (they have the cluster's own decryption key, transparently). For that, you need field-level encryption (next).</p>
<hr>
<h1 id="Chapter-7-Client-Side-Field-Level-Encryption-CSFLE"><a href="#Chapter-7-Client-Side-Field-Level-Encryption-CSFLE" class="headerlink" title="Chapter 7 ??Client-Side Field-Level Encryption (CSFLE)"></a>Chapter 7 ??Client-Side Field-Level Encryption (CSFLE)</h1>
<p><strong>Sensitive fields are encrypted by the driver before they leave the application.</strong> The server only ever sees ciphertext.</p>

<p>Algorithm matters:</p>
<ul>
<li><strong>Deterministic</strong> ??same plaintext ??same ciphertext. Allows <strong>equality lookups</strong> (<code>find({ email: &quot;x&quot; })</code>).</li>
<li><strong>Random</strong> ??same plaintext ??different ciphertext each time. <strong>Hides distribution + frequency</strong> but no equality lookups.</li>
</ul>
<p>The driver intercepts queries + writes, encrypts/decrypts as needed. Server, admins, backups, replicas all see ciphertext only.</p>
<p><strong>Key Management</strong>: data keys are encrypted by a <strong>master key</strong> held in your KMS (AWS KMS, Azure Key Vault, GCP KMS, KMIP). The key vault collection stores encrypted data keys; the master key never leaves the KMS.</p>
<p>Constraints with CSFLE:</p>
<ul>
<li>Only equality queries on deterministically-encrypted fields.</li>
<li>No range / sort / aggregation on encrypted fields.</li>
<li>For &quot;range queries on encrypted data&quot; ??use Queryable Encryption.</li>
</ul>
<hr>

<p>Atlas: Queryable Encryption is supported on dedicated tiers + recent Mongo versions.</p>

<h1 id="Chapter-10-Secrets-management"><a href="#Chapter-10-Secrets-management" class="headerlink" title="Chapter 10 ??Secrets management"></a>Chapter 10 ??Secrets management</h1>
<p>Never:</p>
<ul>
<li>Commit connection strings with passwords to git.</li>
<li>Hardcode passwords in config files in the image.</li>
<li>Print connection strings in logs.</li>
</ul>
<p>Use:</p>
<ul>
<li><strong>HashiCorp Vault</strong>, <strong>AWS Secrets Manager</strong>, <strong>Azure Key Vault</strong>, <strong>GCP Secret Manager</strong>.</li>
<li>Kubernetes: <code>Secret</code> resources mounted as env vars or files.</li>
<li>For AWS workloads ??IAM auth to Atlas ??no password to manage.</li>
</ul>
<p>Rotate secrets quarterly. Automate via your secrets manager's rotation hooks.</p>

<h1 id="Chapter-11-Production-hardening-checklist"><a href="#Chapter-11-Production-hardening-checklist" class="headerlink" title="Chapter 11 ??Production-hardening checklist"></a>Chapter 11 ??Production-hardening checklist</h1>
<ul>
<li>[ ] Auth enabled (<code>authorization: enabled</code> or Atlas).</li>
<li>[ ] No <code>root</code> for application users; least-privilege custom roles.</li>
<li>[ ] TLS in transit (Atlas: default; self-hosted: <code>requireTLS</code>).</li>
<li>[ ] No public IPs / no <code>bindIp: 0.0.0.0</code> on internet-facing hosts.</li>
<li>[ ] Atlas: private endpoint OR VPC peering; IP allowlist as backup.</li>
<li>[ ] Encryption at rest enabled (default in Atlas).</li>
<li>[ ] CSFLE / Queryable Encryption for highly sensitive fields.</li>
<li>[ ] Secrets in a secrets manager, not in env / repo.</li>
<li>[ ] Audit log capturing privileged ops + failed logins.</li>
<li>[ ] Routine backups (Post 14) tested with restore drills.</li>
<li>[ ] MFA on Atlas accounts; SSO for org access.</li>
<li>[ ] Quarterly review of users, roles, IP allowlists, network rules.</li>
<li>[ ] Version current; security patches applied within agreed SLA.</li>
</ul>
