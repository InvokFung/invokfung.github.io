In a codebase with two hundred components and forty composables, the questions change: which inputs should a composable accept, who stops its watchers, how does a deeply nested component get a typed service without prop drilling, what exactly does <code>defineProps</code> compile to, and how do you type a generic table component so that its slot props know the row type. This post answers those questions with the reactivity model from Post 00 as the foundation. It covers composable design (refs and getters as inputs, <code>toValue</code>, cleanup, shared state), typed <code>provide</code>/<code>inject</code>, every <code>&lt;script setup&gt;</code> macro including reactive props destructure and <code>defineModel</code>, generic components, <code>useTemplateRef</code>, and async components with <code>Suspense</code> and lazy hydration. <h1 id="Learning-Outcome"><a href="#Learning-Outcome" class="headerlink" title="Learning Outcome"></a>Learning Outcome</h1>
<ul>
<li>Write composables that accept refs, getters or plain values through <code>MaybeRefOrGetter</code> and <code>toValue()</code>, and explain why the read must happen inside an effect.</li>
<li>Decide what a composable returns (refs, readonly refs, functions) so that callers can destructure it safely.</li>
<li>Attach cleanup with <code>onScopeDispose</code> and build a shared, reference-counted composable with a detached <code>effectScope</code>.</li>
<li>Type <code>provide</code>/<code>inject</code> with <code>InjectionKey</code>, expose read-only state plus mutation functions, and fail loudly on a missing provider.</li>
<li>Explain what each <code>&lt;script setup&gt;</code> macro compiles to: <code>defineProps</code> (with destructure), <code>defineEmits</code>, <code>defineModel</code>, <code>defineSlots</code>, <code>defineExpose</code>, <code>defineOptions</code>.</li>
<li>Build a generic component with the <code>generic</code> attribute and typed slots.</li>
<li>Use <code>useTemplateRef</code> for element and component refs.</li>
<li>Configure <code>defineAsyncComponent</code>, <code>Suspense</code> and the 3.5 lazy hydration strategies, and know which parts are still experimental.</li>

<h1 id="Chapter-1-—-What-a-composable-is"><a href="#Chapter-1-—-What-a-composable-is" class="headerlink" title="Chapter 1 — What a composable is"></a>Chapter 1 — What a composable is</h1>
<h2 id="Terminology"><a href="#Terminology" class="headerlink" title="Terminology"></a>Terminology</h2>
<ul>
<li><strong>Composable</strong> — a function that uses Composition API features to encapsulate <strong>stateful</strong> logic. By convention named <code>useX</code>. A pure helper (<code>formatPrice</code>) is not a composable.</li>
<li><strong>Setup context</strong> — the synchronous window in which Vue knows the &quot;current instance&quot;: <code>setup()</code> or <code>&lt;script setup&gt;</code>. Lifecycle hooks, <code>inject()</code> and automatic effect collection depend on it.</li>
<li><strong><code>MaybeRef&lt;T&gt;</code></strong> — <code>T | Ref&lt;T&gt; | ShallowRef&lt;T&gt; | WritableComputedRef&lt;T&gt;</code>.</li>
<li><strong><code>MaybeRefOrGetter&lt;T&gt;</code></strong> — <code>MaybeRef&lt;T&gt; | ComputedRef&lt;T&gt; | (() =&gt; T)</code>. The type for &quot;any reactive or plain input&quot;.</li>
<li><strong><code>toValue(x)</code></strong> (3.3+) — normalises a <code>MaybeRefOrGetter</code>: calls a getter, unwraps a ref, returns anything else as-is.</li>
<li><strong><code>InjectionKey&lt;T&gt;</code></strong> — a typed <code>Symbol</code> used as a <code>provide</code>/<code>inject</code> key.</li>
<li><strong>Compiler macro</strong> — a function like <code>defineProps</code> that exists only at compile time inside <code>&lt;script setup&gt;</code>. It needs no import and cannot be called at run time.</li>
</ul>
<h2 id="The-contract"><a href="#The-contract" class="headerlink" title="The contract"></a>The contract</h2>
<p>A composable called inside <code>setup</code> gets three things for free:</p>
<ol>
<li>Every <code>computed</code>, <code>watch</code> and <code>watchEffect</code> it creates is collected by the component's effect scope and stopped on unmount (Post 00, Chapter 7).</li>
<li>Lifecycle hooks it registers (<code>onMounted</code>, <code>onUnmounted</code>) attach to the calling component.</li>
<li><code>inject()</code> resolves against the calling component's ancestors.</li>
</ol>
<p>All three depend on the <strong>current instance</strong>, which Vue sets while <code>setup</code> runs synchronously. That gives the first rule: <strong>call composables synchronously at the top of <code>setup</code></strong>, not in event handlers, <code>setTimeout</code> callbacks or after an arbitrary <code>await</code>.</p>
<p><code>&lt;script setup&gt;</code> softens the <code>await</code> part. The compiler wraps each top-level <code>await</code> so the instance is restored afterwards. This source:</p>

<h2 id="Global-state-module-scope-vs-provide"><a href="#Global-state-module-scope-vs-provide" class="headerlink" title="Global state: module scope vs provide"></a>Global state: module scope vs provide</h2>
<p>A <code>ref</code> at module scope is fine in a client-only SPA, but in SSR it is shared by every request on the server (Post 00, Chapter 8). Per-user state goes through <code>app.provide</code>, Pinia or Nuxt's <code>useState</code>; module scope holds only constants and truly global caches.</p>

<h2 id="Defaults-and-factories"><a href="#Defaults-and-factories" class="headerlink" title="Defaults and factories"></a>Defaults and factories</h2>
<p><code>inject(ThemeKey, 'light')</code> gives a plain default. <code>inject(LoggerKey, () =&gt; new ConsoleLogger(), true)</code> treats the default as a <strong>factory</strong> (third argument), so the expensive object is built only when no provider exists; without <code>true</code>, a function default is returned as-is, not called.</p>
<h2 id="Where-injection-works"><a href="#Where-injection-works" class="headerlink" title="Where injection works"></a>Where injection works</h2>
<ul>
<li>Inside <code>setup</code> / <code>&lt;script setup&gt;</code> of a descendant, including after a <code>&lt;script setup&gt;</code> top-level <code>await</code> (Chapter 1).</li>
<li><code>app.provide(key, value)</code> makes a value available to every component in the app, and to <code>app.runWithContext(fn)</code> (3.3+), which router guards and plugins use to call <code>inject()</code> outside components.</li>
<li><code>hasInjectionContext()</code> (3.3+) returns whether <code>inject()</code> can be called right now without a warning. Libraries use it to support both component and non-component callers; <code>useRoute()</code> in Vue Router is the example the Vue type definitions give.</li>
</ul>
<blockquote>
<p><strong>Watch out:</strong> a component can <code>inject</code> from ancestors only. A sibling or a component in another subtree cannot see the value, and Teleport does not change this: injection follows the component tree, not the DOM.</p>
</blockquote>

<h2 id="defineProps-and-reactive-destructure-35"><a href="#defineProps-and-reactive-destructure-35" class="headerlink" title="defineProps and reactive destructure (3.5)"></a><code>defineProps</code> and reactive destructure (3.5)</h2>
<p>Since 3.5, destructuring <code>defineProps()</code> is stable and enabled by default, with native default values:</p>
<pre><code class="language-vue"><figure class="highlight vue"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span></pre></td><td class="code"><pre><code class="vue"><span class="line">&lt;script setup lang=<span class="hljs-string">&quot;ts&quot;</span>&gt;</span><br><span class="line"><span class="hljs-keyword">import</span> { computed, watch } from <span class="hljs-string">&#x27;vue&#x27;</span></span><br><span class="line">const { <span class="hljs-built_in">count</span> = <span class="hljs-number">0</span>, label } = defineProps&lt;{ <span class="hljs-built_in">count</span>?: <span class="hljs-built_in">number</span>; label: string }&gt;()</span><br><span class="line">const double = computed(<span class="hljs-function"><span class="hljs-params">()</span> =&gt;</span> <span class="hljs-built_in">count</span> * <span class="hljs-number">2</span>)</span><br><span class="line">watch(<span class="hljs-function"><span class="hljs-params">()</span> =&gt;</span> <span class="hljs-built_in">count</span>, (v) =&gt; <span class="hljs-built_in">console</span>.<span class="hljs-built_in">log</span>(v))</span><br><span class="line">&lt;/script&gt;</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>The compiler rewrites every use of a destructured name into a property read on the props proxy. The relevant part of the 3.5 output:</p>
<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-attr">props</span>: {</span><br><span class="line">  <span class="hljs-attr">count</span>: { <span class="hljs-attr">type</span>: <span class="hljs-title class_">Number</span>, <span class="hljs-attr">required</span>: <span class="hljs-literal">false</span>, <span class="hljs-attr">default</span>: <span class="hljs-number">0</span> },</span><br><span class="line">  <span class="hljs-attr">label</span>: { <span class="hljs-attr">type</span>: <span class="hljs-title class_">String</span>, <span class="hljs-attr">required</span>: <span class="hljs-literal">true</span> }</span><br><span class="line">},</span><br><span class="line"><span class="hljs-title function_">setup</span>(<span class="hljs-params"><span class="hljs-attr">__props</span>: <span class="hljs-built_in">any</span></span>) {</span><br><span class="line">  <span class="hljs-keyword">const</span> double = <span class="hljs-title function_">computed</span>(<span class="hljs-function">() =&gt;</span> __props.<span class="hljs-property">count</span> * <span class="hljs-number">2</span>)</span><br><span class="line">  <span class="hljs-title function_">watch</span>(<span class="hljs-function">() =&gt;</span> __props.<span class="hljs-property">count</span>, <span class="hljs-function">(<span class="hljs-params">v</span>) =&gt;</span> <span class="hljs-variable language_">console</span>.<span class="hljs-title function_">log</span>(v))</span><br><span class="line">}</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>So <code>count</code> is not a local variable at run time; it is <code>__props.count</code>, read inside the <code>computed</code> getter and tracked. Two consequences:</p>
<ul>
<li>Passing the name itself to <code>watch(count, …)</code> would pass a number. The compiler rejects it: <code>&quot;count&quot; is a destructured prop and should not be passed directly to watch(). Pass a getter () =&gt; count instead.</code></li>
<li>Passing it to a composable passes a snapshot. Use <code>useThing(() =&gt; count)</code>; with <code>MaybeRefOrGetter</code> inputs (Chapter 2) this is free.</li>
</ul>
<p><code>withDefaults(defineProps&lt;…&gt;(), { … })</code> still works and remains the way to declare defaults without destructuring.</p>

<h2 id="defineEmits"><a href="#defineEmits" class="headerlink" title="defineEmits"></a><code>defineEmits</code></h2>
<p>The 3.3+ named-tuple syntax is the most readable typed form:</p>
<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-keyword">const</span> emit = defineEmits&lt;{</span><br><span class="line">  <span class="hljs-attr">select</span>: [<span class="hljs-attr">item</span>: <span class="hljs-title class_">Row</span>]</span><br><span class="line">  <span class="hljs-string">&#x27;update:page&#x27;</span>: [<span class="hljs-attr">page</span>: <span class="hljs-built_in">number</span>]</span><br><span class="line">}&gt;()</span><br><span class="line"><span class="hljs-title function_">emit</span>(<span class="hljs-string">&#x27;select&#x27;</span>, row)</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>It compiles to <code>emits: [&quot;select&quot;, &quot;update:page&quot;]</code>. Declaring emits is not only for types: an event listener for a declared event is removed from <code>$attrs</code>, so it does not fall through to the root element as a native listener.</p>
<h2 id="defineModel-stable-since-34"><a href="#defineModel-stable-since-34" class="headerlink" title="defineModel (stable since 3.4)"></a><code>defineModel</code> (stable since 3.4)</h2>
<p><code>defineModel</code> declares a prop and its update event in one line and returns a ref that reads the prop and emits on write:</p>
<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-keyword">const</span> model = defineModel&lt;<span class="hljs-built_in">string</span>&gt;({ <span class="hljs-attr">required</span>: <span class="hljs-literal">true</span> })          <span class="hljs-comment">// v-model</span></span><br><span class="line"><span class="hljs-keyword">const</span> [title, titleModifiers] = defineModel&lt;<span class="hljs-built_in">string</span>, <span class="hljs-string">&#x27;trim&#x27;</span>&gt;(<span class="hljs-string">&#x27;title&#x27;</span>)   <span class="hljs-comment">// v-model:title with modifiers</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>The 3.5 compiler turns this into a <code>modelValue</code> prop, a <code>modelModifiers</code> prop, a <code>title</code> prop, a <code>titleModifiers</code> prop, the events <code>update:modelValue</code> and <code>update:title</code>, and two <code>useModel(__props, …)</code> calls. Modifiers can be applied in a <code>set</code> transformer:</p>
<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-keyword">const</span> [value, modifiers] = defineModel&lt;<span class="hljs-built_in">string</span>, <span class="hljs-string">&#x27;uppercase&#x27;</span>&gt;({</span><br><span class="line">  <span class="hljs-title function_">set</span>(<span class="hljs-params">v</span>) {</span><br><span class="line">    <span class="hljs-keyword">return</span> modifiers.<span class="hljs-property">uppercase</span> ? v.<span class="hljs-title function_">toUpperCase</span>() : v</span><br><span class="line">  }</span><br><span class="line">})</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<blockquote>
<p><strong>Watch out:</strong> a <code>default</code> on <code>defineModel</code> is used when the parent does not bind <code>v-model</code>. The child then works as local state while the parent's own value (if it has one but did not bind it) stays different. The Vue docs warn about this desynchronisation. Give a default only to models that are genuinely optional.</p>
</blockquote>

<h2 id="Typing-refs-to-generic-or-exposed-components"><a href="#Typing-refs-to-generic-or-exposed-components" class="headerlink" title="Typing refs to generic or exposed components"></a>Typing refs to generic or exposed components</h2>
<p><code>InstanceType&lt;typeof Comp&gt;</code> does not work for generic components, because their default export is a function type. The <code>vue-component-type-helpers</code> package (from the Vue language tools) provides <code>ComponentExposed&lt;typeof Comp&gt;</code> for exactly this.</p>
<blockquote>
<p><strong>Trick:</strong> type-based <code>defineProps</code> generates runtime options only from types it can resolve; a union of object shapes becomes <code>type: Object</code> or <code>null</code>, so runtime validation is weaker than the type. Keep prop interfaces local or in a <code>.ts</code> file imported by relative path — the SFC compiler resolves imported types itself (3.3+), but complex conditional or mapped types from third-party packages can fail to resolve and stop the build.</p>
</blockquote>

<p>Why it replaced the old pattern of a <code>ref(null)</code> whose variable name matched the <code>ref</code> attribute:</p>
<ul>
<li>The ref name is a string, so it can be dynamic (<code>:ref=&quot;</code>row-${id}<code>&quot;</code>) and can come from a composable that does not own the template.</li>

<pre><code class="language-ts"><figure class="highlight ts"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span><br><span class="line">10</span><br><span class="line">11</span></pre></td><td class="code"><pre><code class="ts"><span class="line"><span class="hljs-keyword">const</span> <span class="hljs-title class_">Chart</span> = <span class="hljs-title function_">defineAsyncComponent</span>({</span><br><span class="line">  <span class="hljs-attr">loader</span>: <span class="hljs-function">() =&gt;</span> <span class="hljs-keyword">import</span>(<span class="hljs-string">&#x27;./Chart.vue&#x27;</span>),</span><br><span class="line">  <span class="hljs-attr">loadingComponent</span>: <span class="hljs-title class_">ChartSkeleton</span>,</span><br><span class="line">  <span class="hljs-attr">delay</span>: <span class="hljs-number">200</span>,              <span class="hljs-comment">// default: show the loading component only after 200 ms</span></span><br><span class="line">  <span class="hljs-attr">errorComponent</span>: <span class="hljs-title class_">ChartError</span>,</span><br><span class="line">  <span class="hljs-attr">timeout</span>: <span class="hljs-number">10_000</span>,         <span class="hljs-comment">// default: no timeout</span></span><br><span class="line">  <span class="hljs-title function_">onError</span>(<span class="hljs-params">error, retry, fail, attempts</span>) {</span><br><span class="line">    attempts &lt;= <span class="hljs-number">3</span> ? <span class="hljs-title function_">retry</span>() : <span class="hljs-title function_">fail</span>()</span><br><span class="line">  }</span><br><span class="line">})</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>The loader becomes a separate chunk. The 200 ms <code>delay</code> exists so fast loads do not flash a skeleton. If the async component is inside a <code>&lt;Suspense&gt;</code>, it is controlled by that boundary by default (<code>suspensible: true</code>) and its own loading, error, delay and timeout options are ignored.</p>
<h2 id="Suspense-still-experimental"><a href="#Suspense-still-experimental" class="headerlink" title="Suspense (still experimental)"></a><code>Suspense</code> (still experimental)</h2>
<p><code>&lt;Suspense&gt;</code> waits for async dependencies in its subtree — components with an <code>async setup()</code> (including any <code>&lt;script setup&gt;</code> with a top-level <code>await</code>) and suspensible async components — and shows its <code>#fallback</code> slot until all resolve:</p>
<pre><code class="language-vue"><figure class="highlight vue"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span></pre></td><td class="code"><pre><code class="vue"><span class="line"><span class="hljs-tag">&lt;<span class="hljs-name">Suspense</span> <span class="hljs-attr">timeout</span>=<span class="hljs-string">&quot;300&quot;</span> @<span class="hljs-attr">resolve</span>=<span class="hljs-string">&quot;onReady&quot;</span>&gt;</span></span><br><span class="line">  <span class="hljs-tag">&lt;<span class="hljs-name">Dashboard</span> /&gt;</span>                 <span class="hljs-comment">&lt;!-- has top-level await in &lt;script setup&gt; --&gt;</span></span><br><span class="line">  <span class="hljs-tag">&lt;<span class="hljs-name">template</span> #<span class="hljs-attr">fallback</span>&gt;</span><span class="hljs-tag">&lt;<span class="hljs-name">Spinner</span> /&gt;</span><span class="hljs-tag">&lt;/<span class="hljs-name">template</span>&gt;</span></span><br><span class="line"><span class="hljs-tag">&lt;/<span class="hljs-name">Suspense</span>&gt;</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<ul>
<li>On the first render, the fallback shows until everything resolves. On later changes, Suspense keeps showing the <strong>previous</strong> content until the new branch resolves, and only switches to the fallback after <code>timeout</code> ms.</li>
<li>Events: <code>pending</code>, <code>resolve</code>, <code>fallback</code>.</li>
<li>Errors in async setup are not handled by Suspense. Catch them with <code>onErrorCaptured</code> in a parent or with the app-level <code>errorHandler</code>.</li>
<li>Nested <code>&lt;Suspense&gt;</code> boundaries need the <code>suspensible</code> prop (3.3+) on the inner one to join the parent's resolution.</li>
</ul>
<p>The Vue docs still mark <code>&lt;Suspense&gt;</code> as experimental, with an API that may change. Nuxt relies on it for every page, which is a practical sign that it is dependable, but in a plain Vue app keep its use to route-level boundaries.</p>

<h2 id="Exercise-2-—-Who-stops-the-watcher"><a href="#Exercise-2-—-Who-stops-the-watcher" class="headerlink" title="Exercise 2 — Who stops the watcher?"></a>Exercise 2 — Who stops the watcher?</h2>
<p>A composable is called from a Pinia setup store instead of a component. Its <code>watch</code> never stops, and its <code>onUnmounted</code> logs a warning. Explain both, and fix the composable.</p>
<details>
<summary>Solution</summary>
<p>There is no component instance, so <code>onUnmounted</code> has nothing to attach to (warning). </details>
