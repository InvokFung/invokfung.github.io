Three.js Course — 09 · Custom Shaders — GLSL & TSL Node Material

Created2026-05-18|Updated2026-05-18|Programming > 3D
|Post View:

The built-in materials cover ~90 % of what most scenes need. The other 10 % requires writing shader code — for stylised looks (cel-shading, hatching, toon outline), procedural effects (animated water, dissolves, holograms), data visualisation (heat maps, vector fields), or anything else outside the PBR / Phong / Lambert envelope. Three.js offers three paths: ShaderMaterial (classical GLSL), RawShaderMaterial (no Three.js boilerplate at all), and the modern TSL NodeMaterial (compose JS nodes that compile to GLSL or WGSL automatically). This post covers all three, plus onBeforeCompile for patching built-in shaders without rewriting them.

Learning Outcome

  • Read and write simple GLSL vertex + fragment shaders.
  • Pass data via attributes, uniforms, varyings.
  • Use ShaderMaterial with built-in Three.js uniforms.
  • Patch the built-in materials via material.onBeforeCompile.
  • Compose TSL NodeMaterials in pure JavaScript (cross-target GLSL + WGSL).
  • Pick the right path for your project (GLSL when porting, TSL for new work).

Chapter 1 — Shader essentials

A shader is a small program the GPU runs. The classical pipeline has two:

  • Vertex shader — runs once per vertex; outputs gl_Position (clip space).
  • Fragment (pixel) shader — runs once per pixel; outputs gl_FragColor (in GLSL) / @location(0) (WGSL).

Data flows:

Storage Source Per Read in
Attribute BufferGeometry vertex vertex shader
Uniform JavaScript draw call both
Varying vertex shader vertex, interpolated to fragment fragment shader

Chapter 2 — The minimal ShaderMaterial

Key automatic globals ShaderMaterial injects for you:

  • projectionMatrix, modelViewMatrix, viewMatrix, normalMatrix — camera math.
  • position, normal, uv — attributes.
  • cameraPosition — uniform.

For RawShaderMaterial, none of these are injected; you declare every attribute + uniform manually. Useful for advanced custom pipelines; usually overkill.

Chapter 3 — GLSL crash course

GLSL ES 3.00 (WebGL2) syntax:

Types:

Type Notes
float, int, bool scalars
vec2, vec3, vec4 float vectors
mat3, mat4 matrices
sampler2D, samplerCube texture handles

Built-in math: sin, cos, mix(a, b, t), smoothstep(a, b, x), clamp(x, lo, hi), step(edge, x), length, normalize, dot, cross, texture(sampler, uv).

Coordinate spaces:

Space What Useful for
Local (model) the geometry's own coords wave deformations
World after model matrix global noise, world-space effects
View (camera) after view matrix fog, depth
Clip after projection the final gl_Position
NDC clip ÷ w screen-space effects

Chapter 4 — Patching the built-in materials with onBeforeCompile

You usually don't want to rewrite PBR from scratch. To inject just one tweak into a MeshStandardMaterial:

You inject GLSL snippets at named #include points in Three.js's shader source (begin_vertex, output_fragment, dithering_fragment, etc.). Read the relevant file in three/src/renderers/shaders/ShaderChunk/ to find the right hook.

This pattern keeps PBR lighting, shadows, env maps — all the heavy stuff — while you customise one part. Far simpler than rewriting a full standard material.

Chapter 5 — TSL (Three.js Shading Language) — the modern path

Three.js introduced TSL as stable in r184. You compose shaders in JavaScript using nodes that compile to GLSL (for WebGL2) or WGSL (for WebGPU) automatically.

Advantages:

  • One material source works on both backends.
  • Type-safe in TypeScript.
  • Composable — assign nodes to material properties; the renderer wires them up.
  • Easier to read than long GLSL strings.

time, uv(), positionLocal, cameraPosition etc. are built-in nodes. Mathematical operations (add, mul, sin, mix, smoothstep) chain naturally.

Material classes

TSL material Replaces
MeshBasicNodeMaterial MeshBasicMaterial
MeshLambertNodeMaterial MeshLambertMaterial
MeshPhongNodeMaterial MeshPhongMaterial
MeshStandardNodeMaterial MeshStandardMaterial
MeshPhysicalNodeMaterial MeshPhysicalMaterial
NodeMaterial ShaderMaterial (full custom)

You can assign nodes to colorNode, emissiveNode, roughnessNode, metalnessNode, positionNode, normalNode, opacityNode, etc.

Why this matters

In 2026, WebGPU is in every browser. WebGL2 isn't dying for years yet, but new performance + compute features land on WebGPU only. Writing TSL means your shaders work on both today, and gain WebGPU benefits transparently.

Three.js docs: legacy ShaderMaterial is still supported; new node features (compute, advanced effects) are TSL-only.

Chapter 7 — Compute shaders (WebGPU only)

WebGPU enables compute shaders — work that runs on the GPU outside the render pass. Use cases: particle simulation, GPU pathfinding, image processing, ML inference.

Chapter 8 — Tooling + workflow

Tool What
Spector.js inspect every shader compilation + uniform per frame
gl-shader-output render a shader output to test in isolation
vite-plugin-glsl import .glsl files directly: import vert from './shader.vert'
shadertoy.com online GLSL playground; great for prototyping fragment shaders
Compute Toys (computetoys.com) WGSL / WebGPU playground
shaderchunk files live in three/src/renderers/shaders/ShaderChunk/ — read them for shader-patching

Workflow:

  1. Prototype the fragment shader idea on Shadertoy or a flat plane.
  2. Port to ShaderMaterial / NodeMaterial.
  3. Add the uniforms wired from JS.
  4. Test in Spector.js for compilation issues.

Chapter 9 — Picking GLSL vs TSL

Situation Pick
New project in 2026 TSL — cross-platform, future-proof
Porting from existing GLSL ShaderMaterial — preserves your code
Patching one detail in a standard material onBeforeCompile — keep PBR, add a tweak
Need compute shaders TSL + WebGPU
Targeting only WebGL2 + you know GLSL well ShaderMaterial is fine
Maximum portability TSL (compiles to both backends)

In practice, established Three.js shops in 2026 are gradually porting hero materials to TSL while keeping legacy ShaderMaterial code where it works.

Practice Exercises

Exercise 1 — Animated wave plane

PlaneGeometry(4, 4, 64, 64). ShaderMaterial that displaces vertices with sin(uv.x * 10 + uTime). Drive uTime from the loop.

Exercise 2 — Procedural gradient

Fragment shader that colours pixels by vUv.y interpolated between two colours.

Exercise 3 — Fresnel rim

Add a fresnel rim to a MeshStandardMaterial via onBeforeCompile. Visible bright edges from glancing angles.

Exercise 4 — TSL port

Convert Exercise 1 to a MeshStandardNodeMaterial using TSL positionNode. Run with WebGPURenderer. Confirm visually identical.

Exercise 5 — Dissolve

A model that dissolves over 2 seconds — animate a dissolve uniform from 0 to 1; discard fragments above a noise-texture threshold. Bonus: glow at the dissolve edge.

Exercise 6 — Toon outline

Duplicate a model: original with MeshToonMaterial, second with inverted hull + black BackSide. Should look cel-shaded with a clean outline.

Built-in uniforms projectionMatrix, modelViewMatrix, position, normal, uv (ShaderMaterial only)
Uniform update material.uniforms.uTime.value = t (no needsUpdate needed)
Patch built-in material.onBeforeCompile = (shader) => { ... }
Inject GLSL shader.vertexShader.replace('#include <begin_vertex>', ...)
TSL material new MeshStandardNodeMaterial(); assign colorNode, positionNode, etc.
TSL built-ins time, uv(), positionLocal, normalLocal, cameraPosition, mix, sin, smoothstep
Cross-target TSL compiles to GLSL (WebGL2) + WGSL (WebGPU)

Outline inverted hull, BackSide, black, depthWrite false
