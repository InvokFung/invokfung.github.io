11:Tabba,<p>The built-in materials cover ~90 % of what most scenes need. The other 10 % requires writing shader code — for stylised looks (cel-shading, hatching, toon outline), procedural effects (animated water, dissolves, holograms), data visualisation (heat maps, vector fields), or anything else outside the PBR / Phong / Lambert envelope. Three.js offers three paths: <strong><code>ShaderMaterial</code></strong> (classical GLSL), <strong><code>RawShaderMaterial</code></strong> (no Three.js boilerplate at all), and the modern <strong>TSL NodeMaterial</strong> (compose JS nodes that compile to GLSL <strong>or</strong> WGSL automatically). This post covers all three, plus <code>onBeforeCompile</code> for patching built-in shaders without rewriting them.</p>

<h1 id="Chapter-1-—-Shader-essentials"><a href="#Chapter-1-—-Shader-essentials" class="headerlink" title="Chapter 1 — Shader essentials"></a>Chapter 1 — Shader essentials</h1>
<p>A shader is a small program the GPU runs. The classical pipeline has two:</p>
<ul>
<li><strong>Vertex shader</strong> — runs once per vertex; outputs <code>gl_Position</code> (clip space).</li>
<li><strong>Fragment (pixel) shader</strong> — runs once per pixel; outputs <code>gl_FragColor</code> (in GLSL) / <code>@location(0)</code> (WGSL).</li>
</ul>

<h2 id="Why-this-matters"><a href="#Why-this-matters" class="headerlink" title="Why this matters"></a>Why this matters</h2>
<p>In 2026, WebGPU is in every browser. WebGL2 isn't dying for years yet, but new performance + compute features land on WebGPU only. Writing TSL means your shaders work on both today, and gain WebGPU benefits transparently.</p>
<p>Three.js docs: legacy <code>ShaderMaterial</code> is still supported; new node features (compute, advanced effects) are TSL-only.</p>

<h1 id="Chapter-7-—-Compute-shaders-WebGPU-only"><a href="#Chapter-7-—-Compute-shaders-WebGPU-only" class="headerlink" title="Chapter 7 — Compute shaders (WebGPU only)"></a>Chapter 7 — Compute shaders (WebGPU only)</h1>
<p>WebGPU enables compute shaders — work that runs on the GPU outside the render pass. Use cases: particle simulation, GPU pathfinding, image processing, ML inference.</p>
<p>TSL exposes compute via <code>computeNode</code>:</p>

<p>This is advanced territory; the API is stabilising in 2026. For most projects, you won't need compute shaders for years.</p>

<h1 id="Chapter-9-—-Picking-GLSL-vs-TSL"><a href="#Chapter-9-—-Picking-GLSL-vs-TSL" class="headerlink" title="Chapter 9 — Picking GLSL vs TSL"></a>Chapter 9 — Picking GLSL vs TSL</h1>
<table>
<thead>
<tr>
<th>Situation</th>
<th>Pick</th>
</tr>
</thead>
<tbody>
<tr>
<td>New project in 2026</td>
<td><strong>TSL</strong> — cross-platform, future-proof</td>
</tr>
<tr>
<td>Porting from existing GLSL</td>
<td><strong>ShaderMaterial</strong> — preserves your code</td>
</tr>
<tr>
<td>Patching one detail in a standard material</td>
<td><strong><code>onBeforeCompile</code></strong> — keep PBR, add a tweak</td>
</tr>
<tr>
<td>Need compute shaders</td>
<td><strong>TSL</strong> + WebGPU</td>
</tr>
<tr>
<td>Targeting only WebGL2 + you know GLSL well</td>
<td><strong>ShaderMaterial</strong> is fine</td>
</tr>
<tr>
<td>Maximum portability</td>
<td><strong>TSL</strong> (compiles to both backends)</td>
</tr>
</tbody>
</table>
<p>In practice, established Three.js shops in 2026 are gradually porting hero materials to TSL while keeping legacy ShaderMaterial code where it works.</p>

<h2 id="Exercise-1-—-Animated-wave-plane"><a href="#Exercise-1-—-Animated-wave-plane" class="headerlink" title="Exercise 1 — Animated wave plane"></a>Exercise 1 — Animated wave plane</h2>
<p><code>PlaneGeometry(4, 4, 64, 64)</code>. ShaderMaterial that displaces vertices with <code>sin(uv.x * 10 + uTime)</code>. Drive <code>uTime</code> from the loop.</p>
<h2 id="Exercise-2-—-Procedural-gradient"><a href="#Exercise-2-—-Procedural-gradient" class="headerlink" title="Exercise 2 — Procedural gradient"></a>Exercise 2 — Procedural gradient</h2>
<p>Fragment shader that colours pixels by <code>vUv.y</code> interpolated between two colours.</p>
<h2 id="Exercise-3-—-Fresnel-rim"><a href="#Exercise-3-—-Fresnel-rim" class="headerlink" title="Exercise 3 — Fresnel rim"></a>Exercise 3 — Fresnel rim</h2>
<p>Add a fresnel rim to a <code>MeshStandardMaterial</code> via <code>onBeforeCompile</code>. Visible bright edges from glancing angles.</p>
<h2 id="Exercise-4-—-TSL-port"><a href="#Exercise-4-—-TSL-port" class="headerlink" title="Exercise 4 — TSL port"></a>Exercise 4 — TSL port</h2>
<p>Convert Exercise 1 to a <code>MeshStandardNodeMaterial</code> using TSL <code>positionNode</code>. Run with <code>WebGPURenderer</code>. Confirm visually identical.</p>
<h2 id="Exercise-5-—-Dissolve"><a href="#Exercise-5-—-Dissolve" class="headerlink" title="Exercise 5 — Dissolve"></a>Exercise 5 — Dissolve</h2>
<p>A model that dissolves over 2 seconds — animate a dissolve uniform from 0 to 1; discard fragments above a noise-texture threshold. Bonus: glow at the dissolve edge.</p>
<h2 id="Exercise-6-—-Toon-outline"><a href="#Exercise-6-—-Toon-outline" class="headerlink" title="Exercise 6 — Toon outline"></a>Exercise 6 — Toon outline</h2>
<p>Duplicate a model: original with <code>MeshToonMaterial</code>, second with inverted hull + black <code>BackSide</code>. Should look cel-shaded with a clean outline.</p>

<td><code>material.onBeforeCompile = (shader) =&gt; { ... }</code></td>
</tr>

<td><code>shader.vertexShader.replace('#include &lt;begin_vertex&gt;', ...)</code></td>

<td><code>time, uv(), positionLocal, normalLocal, cameraPosition, mix, sin, smoothstep</code></td>

<td>TSL compiles to GLSL (WebGL2) + WGSL (WebGPU)</td>
</tr>

<td>Dissolve</td>

</tr>

</tr>

<td>Fresnel</td>

<td>Import .glsl files</td>
<td><code>vite-plugin-glsl</code></td>
</tr>
<tr>
<td>Compute</td>
