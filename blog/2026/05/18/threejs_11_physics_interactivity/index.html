Three.js Course — 11 · Physics & Interactivity — Rapier, Raycaster, Gizmos

Created2026-05-18|Updated2026-05-18|Programming > 3D
|Post View:

Three.js does not include a physics engine — meshes don't collide, fall, or push each other by themselves. For physics + collisions you add a separate library; the modern default in 2026 is Rapier (Rust + WASM, fast, deterministic). For interaction (click / drag / hover), Three.js provides Raycaster and several controls (TransformControls, DragControls, PointerLockControls). This post covers wiring physics into a Three.js scene, the standard raycast patterns, and the gizmos you need for editor-like apps.

Learning Outcome

  • Install and initialise the Rapier physics world.
  • Sync rigid bodies with Three.js meshes each frame.
  • Use colliders (box, ball, capsule, trimesh, heightfield).
  • Pick objects by raycasting from screen-space pointer.
  • Use TransformControls for in-editor gizmos.
  • Use DragControls for click-drag-on-plane interactions.

Chapter 1 — Pick a physics engine

Choices in 2026:

Engine Backend Notes
Rapier Rust → WASM modern default — fast, deterministic, actively developed
Cannon-es TypeScript older; legacy projects
Ammo.js C++ Bullet → emscripten mature, heavy, advanced features (cloth, soft body)
Havok (commercial) game-engine grade

For new work, Rapier. For legacy with existing Cannon code, stay there.

Install

The -compat build is a single CJS-compatible file — easier to bundle in Vite without WASM-loader plugins.

Chapter 3 — Bodies and colliders

A rigid body is the physical object (with mass, velocity, position). A collider is its shape for collision detection. Bodies can have one or more colliders.

Body types:

  • Dynamic — moves with physics.
  • Fixed (static) — never moves, infinite mass; for floors, walls.
  • Kinematic position-based — moves by setting position; collides with dynamics; doesn't react to forces. For characters/platforms.
  • Kinematic velocity-based — moves by setting velocity; same idea as above.

Collider shapes:

Shape Constructor
Box cuboid(hx, hy, hz)
Sphere ball(r)
Capsule capsule(halfHeight, r)
Cylinder cylinder(halfHeight, r)
Cone cone(halfHeight, r)
Trimesh (any 3D mesh) trimesh(vertices, indices)
Heightfield (terrain) heightfield(rows, cols, heights, scale)
Convex hull convexHull(points)

Trick: never use trimesh for dynamic bodies — only for static terrain. For moving objects, use a primitive (box / capsule) or convex hull. Trimesh-trimesh collisions are 10-100× slower than primitive-primitive.

Chapter 5 — Forces, impulses, joints

Joints connect bodies:

Joint What
Fixed rigidly attached
Revolute hinge (one axis rotation)
Prismatic slider (one axis translation)
Spherical ball joint (3-axis rotation)
Generic configurable

Joints enable: doors, hinges, ragdoll characters, vehicles (4 prismatic wheel joints), chains, ropes (sequential spherical joints).

Chapter 6 — Character controllers

For an FPS / third-person character, dynamic body + capsule collider is technically correct but feels squishy. The standard pattern: kinematic character controller that you move manually and Rapier resolves against the world.

Combine with PointerLockControls for mouse-look + WASD inputs. Real character controllers usually add: jump (vertical impulse on grounded check), gravity (manual vy -= 9.81 * dt), and ground-test raycasts.

Chapter 10 — UI overlay patterns

For mixed 2D UI + 3D scene:

Pattern Use
HTML overlay (absolute-positioned <div> on top of <canvas>) text labels, modals, control panels
CSS2DRenderer / CSS3DRenderer DOM nodes attached to 3D positions, projected each frame
Sprites + canvas textures UI elements that live entirely in the 3D scene
Drei <Html> (in R3F, Post 12) declarative HTML attached to a 3D position

HTML overlay is simplest. CSS2DRenderer is right when labels need to follow 3D objects (think Google Earth pins).

Practice Exercises

Exercise 1 — Rapier hello world

Initialise Rapier. Drop 10 cubes onto a floor. Confirm they stack.

Exercise 2 — Click to spawn

Click anywhere on the canvas → spawn a sphere at the raycast hit on the floor. Add physics body + collider.

Exercise 3 — Character controller

Implement Chapter 6. Capsule + kinematic character + WASD + jump. Walk over a few box obstacles.

Exercise 4 — TransformControls editor

Load any model. Add TransformControls. Hotkeys G / R / S switch modes. Drag the gizmo handles.

Exercise 5 — BVH raycast on a heavy mesh

Load a 100k+ triangle model (Sketchfab statue). Implement Raycaster picking with and without three-mesh-bvh. Measure the difference.

Exercise 6 — Physics raycast (line of sight)

Place an "enemy" cube. Each frame, cast a ray from enemy to player. If a wall is in between (Rapier castRay returns a non-player collider first), enemy can't see player. Visualise the ray as a line.

Cheat-sheet

What How
Default engine Rapier (@dimforge/rapier3d-compat)
Init await RAPIER.init()
World new RAPIER.World({ x: 0, y: -9.81, z: 0 })
Step world.step() each frame (or fixed-step accumulator)
Dynamic body RAPIER.RigidBodyDesc.dynamic().setTranslation(x, y, z)
Static body RAPIER.RigidBodyDesc.fixed()
Box collider RAPIER.ColliderDesc.cuboid(hx, hy, hz)
Trimesh collider static only
Sync mesh mesh.position.set(t.x, t.y, t.z); mesh.quaternion.set(r.x,...)
Impulse body.applyImpulse({...}, true)
Joint world.createImpulseJoint(JointData.revolute(...), a, b, true)
Character controller world.createCharacterController(offset)
Raycaster raycaster.setFromCamera(ndc, camera) + intersectObjects(...)
Faster raycast three-mesh-bvh library
Physics ray world.castRay(ray, maxToi, true)
Gizmo TransformControls (translate/rotate/scale)
Drag in plane DragControls
Pickable per-instance hit.instanceId
HTML over 3D absolute-position div, or CSS2DRenderer
