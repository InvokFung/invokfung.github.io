Three.js Course — 05 · Asset Pipeline — glTF, Draco, KTX2, Meshopt

Created2026-05-18|Updated2026-05-18|Programming > 3D
|Post View:

Hand-built geometry (Post 01) is great for primitives; real production work loads 3D models authored in Blender, Maya, Houdini, ZBrush, Substance, or exported from CAD. The standard interchange format for the web is glTF 2.0 ("the JPEG of 3D"). This post covers loading glTF, the three compression layers that should be on every production model (Draco for geometry, KTX2 for textures, Meshopt as a Draco alternative), the gltf-transform CLI that automates the whole pipeline, and the scene-graph traversal patterns that come up every project.

Series map: 00 Foundations → 01 Geometry & Materials → 02 Cameras & Controls → 03 Lighting & Shadows → 04 Textures & PBR → 05 Asset Pipeline (this post) → 06 Animation → 07 Instancing & Batching → 08 Low-End Perf → 09 Shaders → 10 Post-Processing → 11 Physics → 12 R3F → 13 AI 3D.

Learning Outcome

  • Load .glb / .gltf models with GLTFLoader.
  • Configure Draco + KTX2 + Meshopt decoders correctly.
  • Run a full optimisation pass with the gltf-transform CLI.
  • Traverse the loaded scene graph to wire shadows, materials, picking.
  • Pick between embedded .glb and separate .gltf + assets.
  • Avoid the common pitfalls (wrong colour space, broken animations, missing draco decoder).

Chapter 1 — glTF in one paragraph

glTF 2.0 (Khronos, 2017) is the standard 3D delivery format for the web. It's a JSON file (*.gltf) describing scene graph + materials, plus binary buffers for geometry/textures. A .glb is the same data packed into a single binary file. Materials follow the metallic-roughness PBR model. Extensions add advanced features (KHR_draco_mesh_compression, KHR_texture_basisu, EXT_meshopt_compression, KHR_materials_clearcoat, etc.).

Why glTF over alternatives:

  • Designed for web/real-time (compact, GPU-friendly buffers).
  • Comprehensive material support that maps onto Three.js MeshStandardMaterial / MeshPhysicalMaterial exactly.
  • Animations, skins, morph targets all standardised.
  • First-class exporters from every major DCC (Blender, Maya, 3ds Max, Houdini, Cinema 4D, Substance, ZBrush).

.glb (binary, single file) is the right default unless you have a specific reason to split.

Chapter 3 — The three compressions you should enable

A typical 5 MB glTF can shrink to 500 KB with the right compression — and load 5× faster.

Layer What it compresses Decoder bytes Ratio
Draco mesh geometry ~250 KB (lazy loaded) up to 10×
Meshopt mesh geometry + animations + morph targets tiny (no separate decoder) similar to Draco, sometimes better
KTX2 / Basis textures (GPU + disk) ~700 KB transcoder ~10× GPU memory

You'll usually pick either Draco or Meshopt for geometry (not both), plus KTX2 for textures.

Draco vs Meshopt

Draco Meshopt
Compression very good comparable
Decode speed slower (CPU-heavy) faster
Animations / morph targets dropped preserved
Bundle cost ~250 KB decoder (lazy) tiny
Status mature modern, recommended for animated models

For static models, either works. For models with skinned animation or morph targets, prefer Meshopt so the animation data survives compression.

Chapter 7 — Embedded vs split glTF

Layout When
.glb (everything in one binary) default — one HTTP request, no path mistakes
.gltf + .bin + textures separately when textures change independently or shared across models
.gltf with data-URIs (textures base64-inlined) rare — bloats parse

For the web, .glb is the right default 99 % of the time.

Chapter 8 — Common pitfalls

Symptom Cause Fix
Model loads but is invisible scale mismatch (model in mm; scene in m) export at correct unit; or gltf.scene.scale.setScalar(0.001)
Materials wrong colour colour space mishandled (rare with glTFLoader; common if you bypass it) trust GLTFLoader; don't post-process colour textures
Animations not playing forgot to attach to AnimationMixer Post 06
Console: "no DRACOLoader instance" model uses Draco compression but decoder not configured add DRACOLoader
Textures black on iOS Safari < 26 KTX2 not supported in older Safari ship JPG fallback or accept Safari 26+ baseline
Wrong winding / inside-out left-handed exporter (rare); material.side = DoubleSide to test
Massive bundle on first load decoders pulled into main bundle use dynamic import to lazy-load decoders only when needed

Practice Exercises

Exercise 1 — Load + add

Download DamagedHelmet.glb from Khronos sample assets. Load with GLTFLoader. Add lighting + an HDR environment. Should look photorealistic.

Exercise 2 — Wire shadows on a loaded model

After load, traverse and castShadow / receiveShadow = true on every mesh. Add a ground plane that receives. Verify shadows render.

Exercise 3 — Optimise with gltf-transform

Take a 5+ MB glTF (search Sketchfab). Run gltf-transform inspect. Apply gltf-transform optimize. Compare sizes + load times. Confirm visually identical.

Exercise 4 — All three compressions

Apply Draco (or Meshopt) + KTX2 (UASTC for normal map, ETC1S for colour). Configure all three loaders in Three.js. Confirm renderer.info.memory.textures is way down.

Exercise 5 — Lazy decoders

Refactor your loader setup so DRACOLoader and KTX2Loader are dynamically imported. Confirm the initial bundle (npm run build) shrinks substantially.

Cheat-sheet

What How
Format default .glb (binary, single file)
Loader new GLTFLoader().setDRACOLoader(...).setKTX2Loader(...).setMeshoptDecoder(...)
Draco decoder path three/examples/jsm/libs/draco/
Basis transcoder path three/examples/jsm/libs/basis/
Optimise CLI gltf-transform optimize in.glb out.glb
Geometry compression Draco (static) or Meshopt (animated)
Texture compression KTX2 UASTC (hero) + ETC1S (secondary)
Add to scene scene.add(gltf.scene)
Find by name gltf.scene.getObjectByName('foo')
Wire shadows traverse + castShadow / receiveShadow = true
Get animations gltf.animations (Post 06)
Preserve textures when swapping material copy all map references explicitly
Lazy decoder dynamic import() of GLTFLoader + DRACOLoader
Sample models Khronos glTF-Sample-Assets repo
