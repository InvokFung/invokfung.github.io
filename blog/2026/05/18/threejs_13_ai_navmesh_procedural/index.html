Three.js Course — 13 · AI-Assisted 3D, NavMesh Pathfinding, Procedural

Created2026-05-18|Updated2026-05-18|Programming > 3D
|Post View:

The final base post covers the territory that "barely existed" when the prior posts' patterns were stabilising and is now front-of-mind: AI-generated 3D assets (text-to-3D and image-to-3D in seconds), NavMesh + pathfinding for AI-driven characters, Gaussian Splatting for photoreal scanned environments, and the procedural generation techniques (noise, L-systems, wave-function collapse) that complement or replace authored assets. None of these are exclusive to Three.js, but they all show up in production Three.js pipelines today.

Series map: 00 Foundations → 01 Geometry & Materials → 02 Cameras & Controls → 03 Lighting & Shadows → 04 Textures & PBR → 05 Asset Pipeline → 06 Animation → 07 Instancing & Batching → 08 Low-End Perf → 09 Shaders → 10 Post-Processing → 11 Physics → 12 R3F → 13 AI 3D + NavMesh + Procedural (this post — final in the base series).

Learning Outcome

  • Use AI tools (Meshy, Tripo, Luma Genie, TripoSR, Hunyuan3D, CSM) to generate 3D models from text or images.
  • Clean up + optimise AI-generated meshes for production.
  • Generate a NavMesh from your scene with recast-navigation-js.
  • Pathfind across a NavMesh with Detour.
  • Display Gaussian Splatting captures in Three.js.
  • Generate procedural terrain with Perlin / Simplex noise.
  • Recognise where each technique fits in a pipeline.

Chapter 1 — Text-to-3D + image-to-3D (the 2026 landscape)

In 2026, a usable 3D model from a text prompt or single reference image takes about a minute and costs a few cents. None of these tools fully replace a 3D artist for hero work, but they're production-ready for backgrounds, props, prototypes, and indie / mid-tier projects.

Tool Inputs Outputs Notes
Meshy text, image textured glTF / FBX / USDZ; auto-rig; 500+ animation presets most-complete pipeline; web + API
Tripo text, image textured glTF fast; web + API; cheaper than Meshy
Luma Genie text glTF strong geometric reasoning; web
TripoSR single image mesh in < 0.5 s on an A100 open-source (Stability AI + Tripo); self-hostable
Hunyuan3D (Tencent) text, image high-quality textured mesh open-source, top-tier quality
CSM (Common Sense Machines) concept art / character sheet proportion-faithful character mesh designer-friendly
Spline AI text scenes within Spline (Three.js compatible export) designer tool with AI assist
Rodin text high quality newer, gaining traction

Workflow for AI-generated mesh → Three.js

  1. Generate at the tool's UI. Iterate on prompt + reference images until happy.
  2. Download glTF.
  3. Clean up in Blender — fix the inevitable issues:
    • Floating / disconnected geometry → merge by distance.
    • Hyper-dense topology → decimate.
    • Wrong scale / orientation → fix root transform.
    • Inverted normals → recalculate.
    • Texture seams or bake noise → repaint patches.
  4. Optimise with gltf-transform optimize (Post 05).
  5. Drop into your Three.js scene with GLTFLoader.

Trick: AI-generated meshes look right at "hero camera" angles and wrong from close-up. Always test from your actual camera. For backgrounds it doesn't matter; for player-inspected props, plan to clean up.

Production readiness in 2026

  • Prototype quality is trivial — minutes from prompt to scene.
  • Production quality still needs human review for: hero characters, branded assets, anything inspected closely, manufacturing geometry, anything with text on it (still flaky in 2026).
  • Round-trip test always — export from AI tool, import into your engine, render at production camera, before committing.

Chapter 2 — API integration

For automated pipelines (user-generated content sites, game asset farms, procedural batches):

Tripo, Luma, Hunyuan have similar REST + polling APIs. TripoSR runs entirely on your own GPU — no external API.

Self-hosting TripoSR

Requires a CUDA GPU (A100 ideal, RTX 3060 / 4070 viable). ~0.5-3 seconds per mesh. Self-host when you need privacy, batch volume, or zero per-call cost.

Chapter 3 — NavMesh + pathfinding

For AI-driven characters that need to walk around obstacles, NavMesh (Navigation Mesh) is the standard. A NavMesh is a polygon graph of the walkable surface; pathfinding queries return a sequence of polygons + a straight path inside them.

The canonical library for JS is recast-navigation-js — a WASM port of the C++ Recast (NavMesh construction) + Detour (pathfinding) libraries used in Unreal, Unity, and most game engines.

Chapter 4 — Procedural generation

When you can't or don't want to author every prop, generate procedurally.

Perlin / Simplex noise (the workhorse)

Layering noise at multiple frequencies + amplitudes (fractal Brownian motion) gives natural-looking terrain.

L-systems for plants / fractals

Useful for plants, branches, trees.

Wave Function Collapse (WFC)

Generate tile-based maps from a small example. Libraries: wavefunctioncollapse (npm). Use for dungeons, city blocks, decorative patterns.

Voronoi / Delaunay

Cell partitioning — useful for procedural ground textures, cracked surfaces, cell-shaded foliage clumps. Library: d3-delaunay.

Marching cubes

Convert a 3D scalar field (e.g., from noise) into a triangle mesh — generates caves, blob shapes, organic terrain. Three.js has MarchingCubes in addons.

Trick: "looks too perfect / too repetitive" is the procedural-generation tell. Layer multiple techniques (noise + WFC + hand-placed accents). Add small artist-authored variation on top to break uniformity.

Chapter 5 — Gaussian Splatting (3DGS)

Gaussian Splatting (2023) is a new way to represent and render 3D scenes — a cloud of millions of view-dependent ellipsoids ("splats") rather than a triangle mesh. Captured from photos with tools like Luma AI, Polycam, PostShot. Renders extremely fast even on mobile.

Status in 2026:

  • Three.js doesn't yet ship a built-in 3DGS renderer.
  • Use @mkkellogg/gaussian-splats-3d or luma-web to render .splat / .ply files in a Three.js scene.

Use cases: virtual scans of real places, e-commerce showroom captures, AR scene reconstruction. Limitations: editing is hard (no triangle mesh to nudge); animation harder still.

Chapter 6 — Pipeline integration

Putting it all together — a realistic mixed pipeline for a game / interactive experience:

Three.js (or R3F) sits in the middle, integrating all of it through GLTFLoader, custom loaders, NavMesh queries, and the patterns from posts 00-12.

Chapter 7 — Ethical + legal notes

AI-generated 3D models:

  • Licensing of training data is contested. Most commercial tools (Meshy, Tripo, Luma) claim model output is yours to use; check current ToS.
  • Open-source models (TripoSR, Hunyuan3D) have permissive licences for output but may have non-commercial training-data caveats.
  • Brand / IP prompts ("a Star Wars X-wing") will produce IP-infringing outputs; you carry the legal risk, not the tool.
  • Disclose AI-generated content where required by platform rules (App Store, Steam, etc.).
  • Workflow auditability — log prompts + tool + version per asset for future review.

NavMesh + procedural generation aren't ethically loaded; standard library licensing applies (most are MIT / Apache-2.0).

Gaussian Splat captures of real places — same as photography: respect private property, get model releases for people, follow GDPR / local rules for identifiable people.

Practice Exercises

Exercise 1 — Generate + import

Generate a model on Meshy (free tier) of "a stylised mushroom". Download glTF. Load into a Three.js scene. Add Environment + OrbitControls. Note quality and what you'd need to fix.

Exercise 2 — Optimise the AI mesh

Run gltf-transform inspect then optimize. Compare file size + draw calls + visual quality.

Exercise 3 — NavMesh on a room

Build a simple "room" scene: floor + several walls + a couple of obstacles. Generate a NavMesh via recast-navigation-js. Visualise it (the NavMesh has a .getDebugTriangles() method or similar).

Exercise 4 — Click-to-walk

Click anywhere on the floor → pathfind from character position to click target → move character along the path.

Exercise 5 — Procedural terrain

Generate a 100×100 terrain with layered Simplex noise. Add an LOD swap for distant chunks. Tile with a grass texture (Post 04).

Exercise 6 — Gaussian Splat viewer

Find a free .splat file on luma.com/featured or download one. Display it in a Three.js scene via @mkkellogg/gaussian-splats-3d. Add OrbitControls.

Exercise 7 — Full mini-pipeline

Build a 30-second prototype scene: AI-generated mushroom forest (5 species via Meshy/Tripo), procedural noise terrain, recast-navigation crowd of 20 agents wandering between waypoints, R3F + Drei + Rapier for the engine, deployed on Vercel. Note the friction at each step.
