Three.js Course — 12 · React Three Fiber + Drei Ecosystem

Created2026-05-18|Updated2026-05-18|Programming > 3D
|Post View:

In 2026, most React shops doing 3D use React Three Fiber (R3F) instead of vanilla Three.js. R3F is a thin renderer that maps Three.js objects to JSX — every <mesh>, <group>, <perspectiveCamera> you'd write imperatively becomes a React component. Around it has grown the pmndrs ecosystem: drei (a giant helper library), @react-three/postprocessing, @react-three/rapier, @react-three/xr, plus utilities for state (zustand), animation (framer-motion-3d), and more. This post covers all the essentials so you can port the previous 11 posts' patterns into React.

Series map: 00 Foundations → 01 Geometry & Materials → 02 Cameras & Controls → 03 Lighting & Shadows → 04 Textures & PBR → 05 Asset Pipeline → 06 Animation → 07 Instancing & Batching → 08 Low-End Perf → 09 Shaders → 10 Post-Processing → 11 Physics → 12 R3F + Drei (this post) → 13 AI 3D.

Learning Outcome

  • Set up a Vite + React + R3F project.
  • Build scenes declaratively with <Canvas>, <mesh>, <directionalLight> etc.
  • Use the core hooks: useFrame, useThree, useLoader.
  • Use drei helpers (OrbitControls, Environment, Sky, Stage, Html, Instances, Preload, ContactShadows, ...).
  • Add physics with @react-three/rapier.
  • Add post-processing with @react-three/postprocessing.
  • Profile with r3f-perf.
  • Avoid the standard R3F performance traps.

Chapter 1 — Why R3F

The same scene, two ways:

Same output. R3F wins when:

  • The scene composition is data-driven (mapping over an array of items → list of meshes).
  • You want React idioms: state, effects, suspense, context, hooks, refs.
  • You're already on React for the rest of the app.

R3F doesn't make Three.js faster; it makes the codebase more maintainable for React teams.

Chapter 2 — Setup

JSX naming convention

Lowercase tag = a Three.js class. <mesh> → THREE.Mesh, <boxGeometry> → THREE.BoxGeometry, <directionalLight> → THREE.DirectionalLight.

Property style:

  • Constructor args → args={[...]}.
  • Object properties (vectors, colours) → flat strings/arrays: position={[0, 1, 0]}.
  • Sub-properties via dash notation: rotation-x={Math.PI / 2}, material-color="red".

Chapter 3 — The core hooks

useFrame — per-frame logic

useFrame runs outside React's render cycle — directly inside the render loop. Mutate refs; never call setState here unless you really want a React re-render (almost always a bug).

useThree — access the renderer / scene / camera

For reading: fine. For modifying: prefer refs.

useLoader — async asset loading with Suspense

Drei provides nicer wrappers: useGLTF, useTexture, useFBX, etc.

Chapter 4 — Drei (the helper library)

@react-three/drei ships dozens of components that bundle common patterns. The headline ones:

Controls

<OrbitControls />, <MapControls />, <TrackballControls />, <PointerLockControls />, <FirstPersonControls />, <FlyControls />, <TransformControls object={ref} />, <DragControls items={...} />.

Cameras / staging

<PerspectiveCamera makeDefault />, <OrthographicCamera makeDefault />, <Stage /> (auto-light + ground + camera framing for product viewers), <CameraShake />, <CameraControls /> (better OrbitControls).

Environment / lighting

<Environment preset="sunset" /> — one-line IBL with a built-in HDR.
<Sky distance={450000} sunPosition={[0, 1, 0]} /> — procedural sky.
<Stars />, <Cloud />, <Sparkles />.

Shadows

<ContactShadows position={[0, 0, 0]} opacity={0.4} blur={2.5} far={4} /> — soft fake shadow under an object.
<AccumulativeShadows> + <RandomizedLight> — high-quality baked-look shadows.

Loaders

useGLTF('/model.glb'), useTexture('/diffuse.jpg'), useFBX, useKTX2, useVideoTexture.

Geometry / Mesh helpers

<Box />, <Sphere />, <Plane />, <Torus /> (lighter syntax than <mesh><boxGeometry/></mesh>).
<Instances> + <Instance /> — declarative InstancedMesh.
<Merged> — declarative geometry merge.

Text / HTML

<Text>Hello</Text> — high-quality SDF text.
<Html> — DOM nodes attached to a 3D position.
<Center> — centre child object on origin.

Performance

<Preload all /> — preload textures + models before fade-in.
<AdaptiveDpr pixelated /> — auto-downgrade pixel ratio under load.
<AdaptiveEvents /> — pause pointer events under load.
<BakeShadows /> — bake shadows on first render then freeze.

Misc

<Bounds> + <useBounds()> — zoom to fit children.
<Outlines /> — toon-style outline.
<MeshReflectorMaterial> — reflective floor.
<MeshDistortMaterial> — distorted blob material.

Read the full list at the drei docs.

Chapter 5 — State management with Zustand

For app-level state (selected object, settings, scores), use Zustand. It plays well with R3F because mutations don't force the canvas to re-render.

Chapter 6 — Physics with @react-three/rapier

Each <RigidBody> wraps its children in a Rapier body. Collider shape is auto-derived from the child mesh; override with explicit <CuboidCollider /> / <BallCollider />.

<Physics updateLoop="independent" /> runs physics in its own rAF, invalidating the canvas only when bodies are moving — significant battery savings for idle scenes.

Chapter 8 — Performance traps

R3F is fast when used correctly; slow when used like React. Key rules:

  1. Never call setState in useFrame — causes a React re-render every frame. Mutate refs instead.
  2. Don't create objects inline in render — <mesh material={new MeshStandardMaterial({...})} /> allocates per render. Memoize with useMemo:
  3. Use Drei's <Instances> for many similar objects:
  4. Suspense + <Preload all /> to avoid pop-in.
  5. frameloop="demand" if the scene isn't constantly animating.
  6. Use Zustand selectors so components only re-render when their slice changes.
  7. <AdaptiveDpr /> for automatic quality scaling under load.

Practice Exercises

Exercise 1 — Rebuild Post 00 cube in R3F

A spinning cube in <Canvas> with OrbitControls + Environment.

Exercise 2 — Drei tour

Use <Stage>, <ContactShadows>, <Float>, <Environment preset="sunset">. Drop a Sketchfab model in.

Exercise 3 — Drei <Instances>

10,000 small cubes scattered randomly using <Instances> + <Instance>. Confirm draw calls stay low via <Perf>.

Exercise 4 — Physics

Wrap a stack of 20 cubes in <RigidBody> over a fixed floor with <Physics>. Click a cube → apply an upward impulse (via the body ref).

Exercise 5 — Post-processing

Add <EffectComposer> with Bloom + Vignette + SMAA. Compare visually with/without.

Exercise 6 — Optimise with the traps

Build a scene that violates trap 1-3 (setState in useFrame, inline materials, no instancing). Measure FPS in Perf. Refactor to fix all three. Measure again.

Cheat-sheet

What How
Canvas <Canvas camera={{ position, fov }} dpr={[1, 2]} shadows>
Mesh <mesh position={[x, y, z]}><boxGeometry /><meshStandardMaterial color="red" /></mesh>
Per-frame useFrame((state, dt) => { ref.current.rotation.y += dt })
Access scene const { gl, scene, camera } = useThree()
Load asset useLoader(GLTFLoader, url) or useGLTF(url)
Controls <OrbitControls /> from drei
Environment <Environment preset="sunset" />
Shadows fake <ContactShadows />
Many instances <Instances> + <Instance />
Physics <Physics><RigidBody>{...}</RigidBody></Physics>
Post <EffectComposer><Bloom /></EffectComposer>
Profile <Perf position="top-left" /> from r3f-perf
State Zustand + selectors
On-demand render frameloop="demand"
Adaptive quality <AdaptiveDpr pixelated /> + <AdaptiveEvents />
Preload <Preload all />
Don't setState in useFrame; allocate objects inline
