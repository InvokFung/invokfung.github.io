Three.js Course — 10 · Post-Processing, Tone Mapping, Color Management

Created2026-05-18|Updated2026-05-18|Programming > 3D
|Post View:

Post-processing is the cinematic polish — bloom on bright highlights, depth of field on out-of-focus regions, ambient occlusion in crevices, anti-aliasing on jagged edges. Three.js does it via the EffectComposer pipeline: render the main scene into a texture, then pass that texture through one or more screen-space passes that read in / write out. This post covers EffectComposer, the standard passes, anti-aliasing options, tone mapping, the colour management pipeline, and the postprocessing library (pmndrs/postprocessing) that ships better-quality effects than the built-ins.

Learning Outcome

  • Build an EffectComposer with RenderPass + one or more effect passes.
  • Use the standard passes: Bloom, SSAO, DOF, Outline, FXAA / SMAA / TAA.
  • Pick a tone-mapping operator (ACES, Filmic, Neutral, Cineon, Reinhard).
  • Understand the linear → tone-map → sRGB pipeline.
  • Use pmndrs/postprocessing for higher-quality effects with better performance.
  • Be disciplined about postprocess cost on mobile.

Chapter 1 — Why postprocess

The raw render is "physically correct" but rarely cinematic. Postprocess passes simulate camera and human-vision effects:

  • Bloom — bright pixels bleed into surrounding area; mimics camera lens glare.
  • Depth of field (DOF) — pixels at the focus distance are sharp; others blurred.
  • Screen-space ambient occlusion (SSAO) — darken creases the global lighting missed.
  • Outline — highlight selected objects with a coloured edge.
  • God rays / volumetric light — visible shafts of light through atmosphere.
  • Motion blur — fast objects smear.
  • Anti-aliasing — smooth jagged edges (geometry AA in WebGL is limited).
  • Tone mapping — squash HDR values into the displayable 0-1 range.
  • Colour grading — LUT / curve adjustments for a chosen mood.

Each is a full-screen pass. Each costs ms. Use sparingly on mobile (Post 08).

Chapter 2 — EffectComposer basics

Key points:

  • composer.render() replaces renderer.render(scene, camera).
  • RenderPass draws the scene into a render target.
  • Each subsequent pass reads the previous target and writes a new one.
  • OutputPass must be last — it applies tone mapping + sRGB. Otherwise colours look wrong.

Chapter 3 — Common passes

UnrealBloomPass

threshold is the brightness above which pixels bloom. radius is the blur falloff. strength is the bloom intensity. Defaults: strength ~0.6, radius ~0.4, threshold ~0.8.

For physically-correct rendering (since r155, default), bright emissives need values > 1.0 to bloom. Try material.emissive.set(0xffaa55) + material.emissiveIntensity = 3.

SSAOPass

Approximate ambient occlusion in screen space. Darkens corners.

Expensive. Often the baked AO map (Post 04) is a better answer for static scenes.

OutlinePass

Highlight selected objects with an outline.

Common pattern: raycast on hover → set outline.selectedObjects = [hit.object].

BokehPass (depth of field)

Tweak focus to the distance of your subject; smaller aperture = sharper.

Chapter 4 — Anti-aliasing

WebGL hardware multisample anti-aliasing (MSAA) is enabled by setting antialias: true on the renderer. MSAA does not work when EffectComposer is used because the render target it allocates by default is single-sample.

Three options:

Pass Cost Quality
FXAA (FastApproximateAntiAliasing) very cheap OK; blurs everything slightly
SMAA (Subpixel Morphological) medium better than FXAA
TAA (Temporal AA) medium-high; needs jittered camera best static quality; ghosting on motion
MSAA in composer high; depends on hardware support best raw quality

Chapter 5 — Tone mapping

Real-world brightness has a huge dynamic range (sun = 1.6 billion lux, candle = 1 lux). Monitors display 0-1. Tone mapping is the squashing function that maps HDR scene values into displayable range.

Options:

Operator Style
NoToneMapping linear clip; blown-out highlights — usually wrong
LinearToneMapping tiny boost; simple
ReinhardToneMapping classic; mid-tones favoured
CineonToneMapping film-stock emulation
ACESFilmicToneMapping industry standard cinematic look; default recommendation
AgXToneMapping (newer) Filmic's modern successor; very natural skin / sky
NeutralToneMapping (since r166) Khronos PBR Neutral — preserves albedo colour for product viz

ACES is the safe modern default. For product viewers / e-commerce, Neutral preserves base colours better.

toneMappingExposure is the equivalent of camera ISO. Increase to brighten the scene; decrease to darken.

Trick: when adopting ACESFilmic, your existing materials may look darker/less saturated. Don't fight it — the result is more cinematic and physically plausible. Adjust light intensities, not albedo values.

Chapter 6 — The pmndrs/postprocessing library

Built by the pmndrs collective (same as react-three-fiber). Cleaner API, single-pass effect chains (one big shader rather than many small passes — much faster), better-quality effects.

Effects are composed into one big GPU pass, not chained per-pass — typically 2-4× faster than Three.js's built-in EffectComposer.

R3F has @react-three/postprocessing which wraps the same library declaratively (Post 12).

Effects shipped

SMAAEffect, FXAAEffect, BloomEffect, SelectiveBloomEffect, BokehEffect, DepthOfFieldEffect, SSAOEffect (with better quality than the built-in), OutlineEffect, ChromaticAberrationEffect, GodRaysEffect, LensDistortionEffect, NoiseEffect, VignetteEffect, ToneMappingEffect, BrightnessContrastEffect, HueSaturationEffect, LUT3DEffect, ScanlineEffect, plus custom support.

For new projects, pmndrs/postprocessing is the recommended choice over the built-in EffectComposer.

For textures (Post 04):

  • Colour textures (albedo, emissive): tex.colorSpace = THREE.SRGBColorSpace.
  • Data textures (normal, roughness): tex.colorSpace = THREE.NoColorSpace.

Get any of this wrong and the scene looks washed out, oversaturated, or weirdly dark.

Chapter 8 — LUT colour grading

For a specific "look" (warm filmic, cold thriller, vintage), apply a 3D look-up table (LUT) at the end of the pipeline.

Free LUTs: RocketStock 35 free LUTs, IWLTBAP.

pmndrs/postprocessing ships LUT3DEffect with the same idea.

Chapter 9 — Performance discipline (recap from Post 08)

Desktop Mobile
Postprocess passes 3-5 OK 0-1
Bloom yes sparingly
SSAO yes bake AO instead
DOF yes skip
AA TAA / SMAA / MSAA FXAA only
Tone map in OutputPass or renderer same
LUT yes yes (cheap, single texture lookup)

The single most expensive common pass is SSAO at full resolution. The cheapest is a LUT.

For mobile, the typical stack is RenderPass → FXAAShader → OutputPass and nothing more.

Practice Exercises

Exercise 1 — Bloom on emissives

A scene with one matte sphere + one emissive sphere (emissive: 0xff8844, emissiveIntensity: 5). Add UnrealBloomPass. Confirm the emissive glows; matte doesn't.

Exercise 2 — Outline on hover

OrbitControls scene with 5 objects. Raycast on hover → outline.selectedObjects = [hit.object]. Outline appears.

Exercise 3 — Tone-mapping comparison

Same scene 4× side by side: NoToneMapping, Reinhard, ACESFilmic, Neutral. Note the colour and contrast differences.

Exercise 4 — pmndrs/postprocessing port

Convert your bloom + FXAA pipeline from three/addons/postprocessing to pmndrs/postprocessing in a single EffectPass. Measure framerate before/after.

Exercise 5 — Colour grading

Find a free .cube LUT online; load + apply via LUTPass. Try several LUTs to see the mood shifts.

Exercise 6 — Mobile-strip-down

Take any of the above; create a mobile fallback path with no postprocess at all (just renderer.render). Switch automatically via navigator.userAgent.
