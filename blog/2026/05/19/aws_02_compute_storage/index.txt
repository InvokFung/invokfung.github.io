<h1 id="Chapter-1-—-EC2-in-200-words"><a href="#Chapter-1-—-EC2-in-200-words" class="headerlink" title="Chapter 1 — EC2 in 200 words"></a>Chapter 1 — EC2 in 200 words</h1>
<p>An <strong>EC2 instance</strong> is a virtual machine running on AWS's hypervisor. You pick an <strong>AMI</strong> (the OS image), an <strong>instance type</strong> (CPU/RAM/network spec), a <strong>subnet</strong> (decides which AZ and whether public or private), one or more <strong>security groups</strong>, an optional <strong>key pair</strong> for SSH, and <strong>EBS</strong> volumes for storage. AWS bills per-second (1-minute minimum) for most types.</p>

<tr>
<td>SSM Session Manager</td>
<td><strong>no</strong></td>
<td><strong>no</strong></td>
<td>CloudTrail + Session logs</td>
<td><strong>production</strong></td>
</tr>
</tbody>
</table>
<p>SSM tunnels the shell through AWS APIs — no public IP, no open SSH port, every session logged. Setup:</p>
<ol>
<li>Attach the IAM role with the <code>AmazonSSMManagedInstanceCore</code> managed policy.</li>
<li>The SSM Agent is pre-installed on Amazon Linux 2/2023 and Ubuntu 20.04+.</li>
<li>Connect: <code>aws ssm start-session --target i-...</code>.</li>
</ol>
<p>Closing port 22 to the world eliminates the entire brute-force attack surface in one configuration change.</p>

<h1 id="Chapter-5-—-EBS-block-storage-for-EC2"><a href="#Chapter-5-—-EBS-block-storage-for-EC2" class="headerlink" title="Chapter 5 — EBS (block storage for EC2)"></a>Chapter 5 — EBS (block storage for EC2)</h1>
<p>An EBS volume is a network-attached block device. It survives instance stop/terminate <strong>unless</strong> you tick &quot;Delete on termination = yes&quot; at launch (default for the root volume; default off for additional volumes).</p>
<table>
<thead>
<tr>
<th>Type</th>
<th>Underlying</th>
<th>When</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>gp3</strong></td>
<td>SSD, balanced</td>
<td>default — most workloads</td>
</tr>
<tr>
<td><strong>gp2</strong></td>
<td>SSD, older balanced</td>
<td>use gp3 instead</td>
</tr>
<tr>
<td><strong>io2 / io2 Block Express</strong></td>
<td>SSD, high IOPS</td>
<td>production OLTP, demanding DB</td>
</tr>
<tr>
<td><strong>st1</strong></td>
<td>HDD, throughput</td>
<td>big sequential workloads, data lakes</td>
</tr>
<tr>
<td><strong>sc1</strong></td>
<td>HDD, cold</td>
<td>archive, infrequent access</td>
</tr>
</tbody>
</table>
<h2 id="Snapshots"><a href="#Snapshots" class="headerlink" title="Snapshots"></a>Snapshots</h2>
<p>A snapshot is an <strong>incremental backup</strong> of a volume, stored in S3 (AWS-managed). Snapshots are billed per GB-month (≈ USD 0.05) and are cheap.</p>
<pre><code class="language-bash"><figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span></pre></td><td class="code"><pre><code class="bash"><span class="line">aws ec2 create-snapshot --volume-id vol-XXXXXXXX \</span><br><span class="line">  --description <span class="hljs-string">&quot;nightly db snapshot&quot;</span></span><br><span class="line"> </span><br><span class="line">aws ec2 create-volume --snapshot-id snap-XXXXXXXX \</span><br><span class="line">  --availability-zone ap-east-1a --volume-type gp3</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Use <strong>Data Lifecycle Manager (DLM)</strong> to schedule snapshot creation and retention automatically.</p>
<h2 id="Common-EBS-mistakes"><a href="#Common-EBS-mistakes" class="headerlink" title="Common EBS mistakes"></a>Common EBS mistakes</h2>
<ol>
<li><strong>Orphaned volumes after instance terminate</strong> — easy to leave hundreds of GB billed forever. Run <code>aws ec2 describe-volumes --filters Name=status,Values=available</code> monthly.</li>
<li><strong>gp2 when gp3 is cheaper and faster</strong> — migrate with <code>modify-volume</code>.</li>
<li><strong>Forgetting that EBS is AZ-local</strong> — to move data to another AZ, snapshot + restore.</li>
</ol>

<h1 id="Chapter-6-—-Instance-store-the-ephemeral-cousin"><a href="#Chapter-6-—-Instance-store-the-ephemeral-cousin" class="headerlink" title="Chapter 6 — Instance store (the ephemeral cousin)"></a>Chapter 6 — Instance store (the ephemeral cousin)</h1>
<p>Some instance types (<code>i</code>, <code>r5d</code>, <code>c5d</code>) include physical NVMe SSDs directly on the host. Massive IOPS and bandwidth, <strong>no network hop</strong> — perfect for caches, scratch, and shard-local data on databases like Cassandra. Catch: <strong>all data is lost on instance stop or terminate</strong>. Treat as ephemeral.</p>
<hr>
<h1 id="Chapter-7-—-S3-object-storage"><a href="#Chapter-7-—-S3-object-storage" class="headerlink" title="Chapter 7 — S3 (object storage)"></a>Chapter 7 — S3 (object storage)</h1>
<p>S3 stores <strong>objects</strong> (files) inside <strong>buckets</strong> (containers). Each object is accessed by its key path (<code>s3://bucket-name/folder/file.png</code>). S3 is:</p>
<ul>
<li>Regional (each bucket lives in one region).</li>
<li>99.999999999% (11 nines) durability — replicated across ≥ 3 AZs by default.</li>
<li>99.99% availability for Standard tier.</li>
<li>Practically unlimited size (objects up to 5 TB; multipart upload for &gt; 5 GB).</li>
<li>Billed per GB-month + per-request + per-GB egress (within region: free; cross-region or internet: per-GB).</li>
</ul>
<h2 id="Bucket-naming"><a href="#Bucket-naming" class="headerlink" title="Bucket naming"></a>Bucket naming</h2>
<p>Bucket names are <strong>global</strong> across all AWS accounts (a leftover from when S3 used the bucket as a hostname). Make them long and unique: <code>mycorp-prod-images-2026</code>.</p>

<h1 id="Chapter-9-—-S3-security"><a href="#Chapter-9-—-S3-security" class="headerlink" title="Chapter 9 — S3 security"></a>Chapter 9 — S3 security</h1>
<p>S3 used to have a reputation for accidental data leaks. AWS responded with <strong>Block Public Access</strong>, on by default for new buckets — preventing public ACLs and policies entirely.</p>
<h2 id="Access-control-mechanisms"><a href="#Access-control-mechanisms" class="headerlink" title="Access control mechanisms"></a>Access control mechanisms</h2>
<table>
<thead>
<tr>
<th>Mechanism</th>
<th>When</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>IAM policies</strong></td>
<td>per-user / per-role permission to S3 actions</td>
</tr>
<tr>
<td><strong>Bucket policies</strong></td>
<td>resource-level policy attached to the bucket</td>
</tr>
<tr>
<td><strong>Block Public Access</strong></td>
<td>meta-control: blocks any policy/ACL that opens to the public</td>
</tr>
<tr>
<td><strong>Object Ownership / ACLs disabled</strong></td>
<td>the modern default (2023+); ignore ACLs entirely</td>
</tr>
<tr>
<td><strong>Pre-signed URLs</strong></td>
<td>time-limited HTTPS link generated by your code, allows direct access</td>
</tr>
<tr>
<td><strong>VPC endpoint policy</strong></td>
<td>restrict which buckets can be reached from your VPC</td>
</tr>
</tbody>
</table>

<p>S3 encrypts at rest by default (SSE-S3 with AES-256). For tighter control, use <strong>SSE-KMS</strong> with a Customer Managed Key (Post 07).</p>

<h1 id="Chapter-10-—-S3-in-real-architectures"><a href="#Chapter-10-—-S3-in-real-architectures" class="headerlink" title="Chapter 10 — S3 in real architectures"></a>Chapter 10 — S3 in real architectures</h1>
<p>Common patterns you'll see everywhere:</p>
<ol>
<li><strong>Static website hosting</strong> — bucket holds HTML/JS/CSS, fronted by CloudFront (CDN). The &quot;no servers&quot; website.</li>
<li><strong>Log archive</strong> — application + ALB + CloudFront → S3 for long-term query via Athena.</li>
<li><strong>Data lake</strong> — Parquet files in S3, queried by Athena / Redshift Spectrum / EMR.</li>
<li><strong>Backup tier</strong> — RDS snapshots, EBS snapshots, EC2 AMIs all live in S3 internally.</li>
<li><strong>Inter-service exchange</strong> — service A drops file in S3, S3 event triggers Lambda or SQS for service B (covered in Post 05).</li>
<li><strong>Code artifacts</strong> — Lambda zip packages, container layers, Terraform state files.</li>
</ol>

<h1 id="Practice-Exercises"><a href="#Practice-Exercises" class="headerlink" title="Practice Exercises"></a>Practice Exercises</h1>
<h2 id="Exercise-1-—-Launch-with-SSM-only"><a href="#Exercise-1-—-Launch-with-SSM-only" class="headerlink" title="Exercise 1 — Launch with SSM only"></a>Exercise 1 — Launch with SSM only</h2>
<p>In the VPC you built in Post 01, launch a <code>t3.micro</code> Amazon Linux 2023 instance:</p>
<ul>
<li>in a <strong>private</strong> subnet,</li>
<li>with <strong>no security-group inbound rules</strong>,</li>
<li>attached to an IAM role with <code>AmazonSSMManagedInstanceCore</code>.</li>
</ul>
<p>Connect via <code>aws ssm start-session --target i-...</code> and verify <code>curl https://example.com</code> works (proves NAT egress) but <code>ssh</code> from your laptop fails (no port 22 open).</p>
<h2 id="Exercise-2-—-gp3-snapshot"><a href="#Exercise-2-—-gp3-snapshot" class="headerlink" title="Exercise 2 — gp3 + snapshot"></a>Exercise 2 — gp3 + snapshot</h2>
<p>Attach a 10 GB gp3 volume to the instance. Format and mount it at <code>/data</code>. Write a file. Take a snapshot. Detach + delete the volume. Restore from snapshot into a new volume in <strong>a different AZ</strong>. Verify the file is still there.</p>
<h2 id="Exercise-3-—-Static-site-bucket"><a href="#Exercise-3-—-Static-site-bucket" class="headerlink" title="Exercise 3 — Static site bucket"></a>Exercise 3 — Static site bucket</h2>
<p>Create a bucket. Enable static website hosting. Upload <code>index.html</code> + <code>error.html</code>. Make the website index URL work without making the bucket itself public — use a bucket policy that allows only <code>s3:GetObject</code> on the website objects.</p>
<h2 id="Exercise-4-—-Lifecycle-policy"><a href="#Exercise-4-—-Lifecycle-policy" class="headerlink" title="Exercise 4 — Lifecycle policy"></a>Exercise 4 — Lifecycle policy</h2>
<p>For the bucket from Exercise 3, add a lifecycle rule:</p>
<ul>
<li>transition objects to Standard-IA after 30 days,</li>
<li>transition to Glacier Deep Archive after 180 days,</li>
<li>expire (delete) versions older than 365 days.</li>
</ul>
<h2 id="Exercise-5-—-Pre-signed-URL"><a href="#Exercise-5-—-Pre-signed-URL" class="headerlink" title="Exercise 5 — Pre-signed URL"></a>Exercise 5 — Pre-signed URL</h2>
<p>Generate a pre-signed URL for a private object that expires in 60 seconds. Confirm it works immediately, fails after the minute.</p>
