Python Course — 05 · Files, Paths, and Exception Handling

Created2026-05-22|Updated2026-05-21|Programming
|Post View:

Reading from and writing to files — and handling the things that go wrong in the process — is what turns a script into a useful tool. This post covers Python's open() function, the with context manager, the modern pathlib API, exception handling, and how to define your own exceptions. It closes the base Python course; future posts extend into stdlib deep-dives, typing, async, and packaging.

Series map: 00 Setup → 01 Syntax → 02 Data Structures → 03 Functions & Modules → 04 OOP → 05 Files & Exceptions (this post) → (future: stdlib, typing, async, packaging, testing).

Learning Outcome

  • Open, read, and write text and binary files.
  • Use the with statement (context manager) — and understand why it matters.
  • Use pathlib.Path for cross-platform path manipulation.
  • Read structured formats: csv, json.
  • Handle exceptions with try/except/else/finally.
  • Raise built-in and custom exceptions.
  • Avoid the classic "catch everything" anti-pattern.

Why with?

The with block is a context manager: the file is guaranteed to be closed when the block exits. Always use it for files.

Where I got stuck: an early script of mine kept thousands of files open until the OS refused new ones. The fix was 5 characters: wrap the open(...) in a with. I never forgot again.

Chapter 2 — Encoding

Always pass encoding="utf-8" when opening text files. Without it, Python uses the OS default (cp1252 on Windows, utf-8 on macOS/Linux) → cross-platform bugs.

Chapter 5 — Exceptions: what they are

An exception is an error event that interrupts normal flow. Python signals problems by raising exceptions.

If unhandled, the exception propagates up the call stack and (eventually) crashes the program with a traceback.

Chapter 6 — Handling exceptions

Parts:

  • try: — code that might fail.
  • except XError: — handle a specific exception.
  • except (A, B) as e: — multiple types + bind to name.
  • else: — runs if try completed without exception.
  • finally: — always runs (cleanup).

Catching too much

A bare except: catches everything, including KeyboardInterrupt (Ctrl+C) and SystemExit. You will eventually trap a signal you wanted to receive.

Rule of thumb: catch the narrowest exception type that addresses the failure. If you don't know the type, run the code, see the traceback, then catch that type.

Chapter 7 — Raising exceptions

Use built-in exceptions when they fit:

Exception Use when
ValueError A value is wrong type/range
TypeError An argument has wrong type
KeyError / IndexError Missing dict key / out-of-range index
FileNotFoundError File not found
RuntimeError Generic runtime issue
NotImplementedError Method must be overridden

Chapter 9 — Context managers (your own)

You've used with open(...). You can write your own context manager — useful for resource setup/teardown (DB connections, locks, temp directories).

The block runs at the yield. Whatever's before/after runs as setup/teardown — even on exceptions thanks to the try/finally.
