C++ Course — 02 · Pointers, Arrays, Memory, and RAII

Created2026-05-22|Updated2026-05-21|Programming
|Post View:

This is the post that makes C++ either click or terrify. Pointers, raw arrays, new/delete, and the RAII idiom together define what makes C++ different from Java, Python, or C#. Get through this chapter and you understand why every modern C++ guide says "prefer references and smart pointers" — because you'll have felt the sharp corners of doing it the raw way.

Series map: 00 Setup → 01 Syntax & Types → 02 Pointers & Memory (this post) → 03 Classes & OOP → 04 Templates & STL → 05 Modern C++ → (future).

Learning Outcome

  • Understand what a pointer is and how it differs from a reference.
  • Use & (address-of) and * (dereference) operators.
  • Use C-style arrays — and know when not to.
  • Allocate + free heap memory with new / delete.
  • Recognise and avoid: dangling pointers, double-free, memory leaks, buffer overruns.
  • Understand the RAII (Resource Acquisition Is Initialization) idiom.
  • See why smart pointers (Post 05) are the modern fix.

Chapter 1 — What a pointer is

Terminology

  • Pointer — a variable whose value is the memory address of another variable.
  • Dereference — read the value at the address (*p).
  • Null pointer — a pointer that points to "nothing"; comparisons against nullptr test this.
  • Dangling pointer — a pointer to memory that's been freed or gone out of scope. Reading it = undefined behaviour.

Declaration and dereference

Read int* as "pointer to int". The * after the type is part of the type. The * before the variable name is the dereference operator.

Null pointer

Always initialise pointers. Either give them a real address or nullptr.

Where I got stuck: my first month of C++ I declared int* p; and immediately did *p = 5;. Garbage address → memory access violation → crash. Always either initialise from a real variable's &, set to nullptr, or use new.

Chapter 2 — Pointer vs reference

Pointer (int*) Reference (int&)
Must initialise No (but should) Yes
Can be null Yes (nullptr) No
Can be reassigned to point elsewhere Yes No (fixed at init)
Syntax to access *p to read, p->m for members Just r
Use in function param when Optional, may be null Always present

Rule of thumb: use references when the argument is always present; use pointers when "no argument" is meaningful or the binding might change.

Chapter 3 — C-style arrays

C-style arrays decay to pointers when passed to functions:

This is the classic C foot-gun. The array's size is lost; you must pass it separately. Forget once → buffer overrun → security CVE.

Modern fix: use std::array or std::vector

Both know their size, support range-for, and refuse to decay. Use these in 100% of new code. Save C arrays for embedded / no-std contexts.

Mismatch is undefined behaviour: new[] ↔ delete[], new ↔ delete. Don't cross them.

What goes wrong

These three bugs — double-free, leak, dangling — define why manual memory management is the hardest part of C++.

Trick: in modern C++ you rarely write new and delete directly. You use smart pointers (std::unique_ptr, std::shared_ptr — Post 05) and let the type system free things automatically. This chapter is here so you understand what the smart pointers are doing for you.

Chapter 5 — Stack vs heap

Memory area Allocation Lifetime Speed When
Stack Automatic on function entry Until function returns Very fast (microseconds) Small, fixed-size, function-scoped
Heap Manual (new) / smart pointer Until you free it Slower (allocator overhead) Large, dynamic, or longer-lived

Stack size is limited (~1–8 MB usually). Huge arrays must go on the heap.

Chapter 7 — RAII (the C++ idiom)

Resource Acquisition Is Initialisation = tie a resource's lifetime to an object. The constructor acquires, the destructor releases. When the object goes out of scope, cleanup is automatic.

Why it matters

std::ifstream is an RAII wrapper around a file handle. The destructor closes the file no matter how the function returns (normal, early return, exception thrown).

The pattern in your own classes

Trick: every C++ class that owns a raw resource (memory, file, lock, socket) should follow the Rule of Three / Five / Zero:

  • If you write a custom destructor, you probably also need copy constructor + copy assignment.
  • C++11 adds move constructor + move assignment (Five total).
  • If you can avoid all five by using smart pointers and containers (the Rule of Zero) — do.
