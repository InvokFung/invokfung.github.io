<h1 id="Chapter-1-—-What-C-is-and-isnt"><a href="#Chapter-1-—-What-C-is-and-isnt" class="headerlink" title="Chapter 1 — What C++ is (and isn't)"></a>Chapter 1 — What C++ is (and isn't)</h1>
<h2 id="Terminology"><a href="#Terminology" class="headerlink" title="Terminology"></a>Terminology</h2>
<ul>
<li><strong>Compiler</strong> — translates <code>.cpp</code> source into machine code (object files).</li>
<li><strong>Linker</strong> — combines object files + libraries into a runnable executable.</li>
<li><strong>Standard library (STL/<code>std::</code>)</strong> — the language's built-in collections, algorithms, I/O.</li>
<li><strong>Header file (<code>.h</code> / <code>.hpp</code>)</strong> — declarations imported by other files via <code>#include</code>.</li>
<li><strong>Source file (<code>.cpp</code>)</strong> — implementations + the <code>main()</code> function.</li>
<li><strong>Standard</strong> — the language version: C++11, C++14, C++17, C++20, C++23. Newer = more features.</li>
</ul>
<h2 id="C-vs-Python-one-paragraph"><a href="#C-vs-Python-one-paragraph" class="headerlink" title="C++ vs Python (one paragraph)"></a>C++ vs Python (one paragraph)</h2>
<p>Python is interpreted, dynamically typed, garbage-collected, and slow. C++ is compiled, statically typed, manually memory-managed (with smart-pointer helpers), and fast. Python code reads cleanly with little ceremony; C++ code can be more verbose but exposes what's happening at the machine level. <strong>Use C++</strong> when you need raw speed, low memory footprint, hardware access, or you're building infrastructure that other languages will call into.</p>
<blockquote>
<p><em>Trick:</em> don't pick a language; pick a problem. Most real engineers use both — Python for orchestration and analysis, C++ (or Rust) for the hot inner loop.</p>
</blockquote>

<h2 id="Compile-flags-worth-knowing"><a href="#Compile-flags-worth-knowing" class="headerlink" title="Compile flags worth knowing"></a>Compile flags worth knowing</h2>
<pre><code class="language-bash"><figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span></pre></td><td class="code"><pre><code class="bash"><span class="line">g++ -std=c++20 -Wall -Wextra -O2 hello.cpp -o hello</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<table>
<thead>
<tr>
<th>Flag</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>-std=c++20</code></td>
<td>Use C++20 standard (use <code>c++23</code> if your compiler supports it).</td>
</tr>
<tr>
<td><code>-Wall</code></td>
<td>Most warnings on.</td>
</tr>
<tr>
<td><code>-Wextra</code></td>
<td>Extra warnings (off by default but recommended).</td>
</tr>
<tr>
<td><code>-O2</code></td>
<td>Optimisation level 2 (release builds). For debugging use <code>-O0 -g</code>.</td>
</tr>
<tr>
<td><code>-g</code></td>
<td>Embed debug info for <code>gdb</code> / <code>lldb</code>.</td>
</tr>
</tbody>
</table>
<blockquote>
<p><em>Trick:</em> always compile with <code>-Wall -Wextra</code> from day 1. Warnings catch 80% of beginner bugs before they crash at runtime.</p>
</blockquote>

<h2 id="pragma-once"><a href="#pragma-once" class="headerlink" title="#pragma once"></a><code>#pragma once</code></h2>
<p>A modern shorthand for include guards. It tells the compiler to include this header at most once per translation unit. Older style:</p>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-meta">#<span class="hljs-keyword">ifndef</span> GREETER_H</span></span><br><span class="line"><span class="hljs-meta">#<span class="hljs-keyword">define</span> GREETER_H</span></span><br><span class="line"><span class="hljs-comment">// ... header content ...</span></span><br><span class="line"><span class="hljs-meta">#<span class="hljs-keyword">endif</span></span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Use <code>#pragma once</code> — it's universally supported by g++, clang++, and MSVC.</p>
