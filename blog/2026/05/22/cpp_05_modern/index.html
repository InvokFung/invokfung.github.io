C++ Course — 05 · Modern C++ (smart pointers, move, lambdas, auto, constexpr)

Created2026-05-22|Updated2026-05-21|Programming
|Post View:

C++11 and later releases (C++14, C++17, C++20, C++23) transformed the language. The pre-2011 "C with classes" idioms are still legal — but writing them today is like writing PHP from 2003 in 2026. This post is the final base post and covers the modern C++ feature set every working engineer should know: smart pointers, move semantics in practice, auto, range-based for, lambdas in depth, constexpr, and a glimpse of C++20 concepts and modules.

Series map: 00 Setup → 01 Syntax & Types → 02 Pointers & Memory → 03 Classes & OOP → 04 Templates & STL → 05 Modern C++ (this post) → (future: concurrency · ranges · coroutines · modules deep dive · advanced templates).

Learning Outcome

  • Use std::unique_ptr and std::shared_ptr instead of raw new/delete.
  • Apply move semantics deliberately (when and why to call std::move).
  • Use auto, decltype, and decltype(auto).
  • Write expressive lambdas with capture by value / reference / [=] / [&].
  • Use constexpr for compile-time computation.
  • Use C++17 features: std::optional, std::variant, structured bindings, if constexpr.
  • Glimpse C++20 concepts + modules.

Chapter 1 — Smart pointers

std::unique_ptr — sole ownership

unique_ptr is move-only — there's exactly one owner at a time:

Use unique_ptr for almost all heap-allocated objects. Costs nothing at runtime vs a raw pointer.

std::shared_ptr — shared ownership (reference count)

Use when you genuinely have multiple owners — usually in observer-style or graph structures. Has reference-counting overhead, so prefer unique_ptr when one owner is enough.

std::weak_ptr — non-owning observer

Use to break reference cycles in shared_ptr graphs, or to observe without prolonging life.

Rule: never write new or delete in new code. If you find yourself reaching for them, your design needs a smart pointer or a container.

Chapter 2 — Move semantics in practice

A move transfers a resource's ownership instead of copying it.

The compiler optimises returns automatically (NRVO + implicit move). You don't have to do anything for the common case.

When to call std::move explicitly

Use std::move when:

  • You're passing a local variable to a sink (container, constructor) and won't use it afterward.
  • You're transferring ownership in an assignment or parameter.

Don't move const objects — moving requires modifying the source. The compiler silently falls back to copy.

Pass-by-value + move idiom

The parameter name is constructed (one copy or move depending on the caller). Then std::move transfers into name_ with zero extra allocation. Modern idiomatic style.

decltype(expr) gives you the type of an expression without evaluating it:

decltype(auto) (C++14) preserves references / cv-qualifiers in return type deduction.

Chapter 4 — Lambdas in depth

Captures

Capture Meaning
[ ] no capture
[x] capture x by value (copy)
[&x] capture x by reference
[=] capture all used variables by value
[&] capture all used variables by reference
[=, &x] all by value, but x by reference
[this] capture this (so this->member works)
[x = expr] (C++14) init-capture

mutable

By default, value-captured variables are const inside the lambda. mutable removes that.

Trick: prefer [&] only inside short scopes — capturing by reference outside the captured variable's lifetime = dangling. For lambdas that escape (stored, returned, passed to async), capture by value.

Chapter 5 — constexpr (compile-time computation)

If all arguments are compile-time constants, the call is evaluated by the compiler. Otherwise it runs at runtime.

consteval (C++20) — only compile-time

constexpr containers (C++20)

std::vector, std::string are now constexpr-friendly inside constexpr functions. Compile-time lookup tables become trivial.

Chapter 8 — C++20 modules (glimpse)

Headers are an artefact of 1970s linker design. Modules replace them with proper compile units:

Benefits: ~10× faster compile times, no preprocessor leakage, clean dependency graph.

Tooling still maturing in 2026; most projects still use headers + #include. Worth knowing exists; adopt when your build chain is ready.

Cheat-sheet

What How
Owning ptr (one) std::make_unique<T>(args)
Owning ptr (shared) std::make_shared<T>(args)
Non-owning observer std::weak_ptr<T>
Move std::move(x) — transfers ownership
Deduce type auto, decltype(expr)
Lambda [capture](args) -> ret { body }
Mutable lambda []() mutable { ... }
Compile-time constexpr (or consteval for strict)
Optional std::optional<T>; value_or(default)
Variant std::variant<A, B, C>; std::visit(f, v)
Structured binding auto [a, b] = pair;
Compile-time if if constexpr (cond) { ... }
Concept (C++20) template <std::integral T>
Module (C++20) export module name; / import name;
Rule of Zero use smart pointers + containers; declare nothing
