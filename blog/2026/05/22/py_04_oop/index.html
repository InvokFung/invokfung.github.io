Python Course — 04 · Object-Oriented Python (classes, inheritance, dataclasses)

Created2026-05-22|Updated2026-05-21|Programming
|Post View:

Object-oriented programming organises code around data + the operations on it. Python's OOP is lightweight (no private keyword, no compile-time type checking) yet flexible enough for everything from 10-line scripts to massive frameworks. This post covers classes, instances, inheritance, dunder methods, properties, and the modern @dataclass decorator.

Series map: 00 Setup → 01 Syntax → 02 Data Structures → 03 Functions & Modules → 04 OOP (this post) → 05 Files & Exceptions → (future).

Learning Outcome

  • Define classes with __init__, methods, and instance attributes.
  • Use inheritance and the super() mechanism.
  • Override dunder methods (__repr__, __eq__, __len__, etc.).
  • Use @property for computed attributes.
  • Use @classmethod and @staticmethod.
  • Write classes with @dataclass (the modern shortcut).
  • Understand composition over inheritance.

Chapter 1 — Class basics

Terminology

  • Class — a template that defines attributes and methods.
  • Instance — an object created from a class.
  • Attribute — data stored on an instance (or class).
  • Method — a function defined inside a class.
  • self — the conventional first parameter of every instance method, automatically bound to the instance.

Minimal class

__init__ is the constructor — called automatically when you do Dog(...). The first parameter self is the freshly-created instance.

Trick: you don't pass self when calling d.bark() — Python passes it for you. Inside the class definition, every method that operates on instance data needs self as the first parameter.

Chapter 3 — Inheritance

super() — calling the parent

Multiple inheritance exists (class C(A, B):) and uses the MRO (method resolution order). Keep it simple — use single inheritance unless you have a strong reason.

Chapter 4 — Dunder methods

"Dunder" = "double underscore". These are how Python hooks into your class for built-in operations.

Dunder Triggered by Returns
__init__(self, ...) Cls(...) nothing (initialises)
__repr__(self) repr(obj), REPL display str (developer view)
__str__(self) str(obj), print(obj) str (user view)
__eq__(self, other) obj == other bool
__lt__(self, other) obj < other bool
__len__(self) len(obj) int
__getitem__(self, k) obj[k] item
__contains__(self, x) x in obj bool
__iter__(self) for x in obj iterator
__add__(self, other) obj + other result
__call__(self, ...) obj(...) result

Chapter 5 — Properties (computed attributes)

@property lets you expose calculated values as if they were attributes, and add validation/setters later without breaking callers.

Chapter 6 — classmethod and staticmethod

  • @classmethod — gets the class as cls. Used for alternative constructors.
  • @staticmethod — gets nothing. Used for utility functions that belong with the class logically.

Chapter 7 — @dataclass (the modern shortcut)

Most classes are just "bags of attributes" with __init__, __repr__, and __eq__. The @dataclass decorator generates all of that for you.

That's it. No boilerplate.

Options

  • frozen=True — immutable (hashable, usable as dict keys).
  • slots=True (3.10+) — faster + uses less memory.
  • order=True — generates <, <=, >, >=.

Default values

Trick: @dataclass should be your default class style. Reach for plain class only when you need custom __init__ logic.

Chapter 8 — Composition over inheritance

A common OOP design rule: when you can use containment instead of inheritance, do.

Inheritance creates a tight, often-unwanted coupling. Composition keeps pieces interchangeable.
