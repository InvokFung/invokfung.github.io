C++ Course — 03 · Classes, Constructors, Inheritance, and Polymorphism

Created2026-05-22|Updated2026-05-21|Programming
|Post View:

C++ classes are how you bundle data + behaviour and enforce invariants. Unlike Python, C++ enforces access control at compile time (private/protected/public), supports multiple inheritance, distinguishes static and dynamic dispatch with virtual, and gives the compiler enough information to inline method calls aggressively. This post covers the OOP essentials.

Series map: 00 Setup → 01 Syntax & Types → 02 Pointers & Memory → 03 Classes & OOP (this post) → 04 Templates & STL → 05 Modern C++ → (future).

Learning Outcome

  • Define class / struct with constructors, destructors, member functions.
  • Use access specifiers public, private, protected.
  • Implement copy + move constructors and assignment (Rule of Five).
  • Use inheritance + virtual functions for runtime polymorphism.
  • Use override, final, and abstract classes (pure virtual).
  • Apply the Rule of Zero: design classes that need no explicit copy/move/destructor.

Chapter 1 — class vs struct

class and struct are nearly identical — they differ only in default access: class defaults to private, struct to public. Convention:

  • Use struct for plain data aggregates (no invariants).
  • Use class when you have invariants to enforce or non-trivial behaviour.

Chapter 2 — Constructors and the initialiser list

The : name_(...), age_(...) syntax is the member initialiser list. It runs before the body — and is the only way to initialise:

  • const members,
  • reference members,
  • base classes,
  • members with no default constructor.

Always prefer the initialiser list over assignments inside the body.

Default constructor

If you declare any constructor, the compiler stops generating the default. Add = default if you want both your custom one and a default.

Explicit

Mark single-argument constructors explicit to prevent surprise conversions. Standard advice.

Chapter 3 — Destructor

The destructor runs automatically when the object's lifetime ends:

  • For stack objects: end of scope.
  • For heap objects: when you call delete.
  • For class members: after the enclosing object's destructor body runs.

In modern code, most classes don't need an explicit destructor — the Rule of Zero (Chapter 7).

Chapter 4 — Member functions and const

Mark methods const whenever they don't mutate. Lets callers use the class with const references — better safety, more places usable.

this pointer

Inside a member function, this is a pointer to the current object.

Chapter 5 — Copy semantics

The compiler generates a copy constructor and copy assignment operator by default. They do member-wise copy. For most classes this is fine. For classes that own raw memory, you must define them.

The default member-wise copy would have copied the pointer — both objects would point to the same memory, and the second destructor would double-free. Classic bug.

Chapter 6 — Move semantics (C++11+)

Moving = transferring ownership of resources without copying. Crucial for performance when you want a new object to take over what an old one had.

When does move happen?

  • Returning a local from a function.
  • std::move(x) cast.
  • Passing a temporary (rvalue) to a constructor.

Trick: if you implement copy + dtor by hand, also implement move. Otherwise the compiler won't generate move automatically, and your class falls back to copies in performance-critical places.

The Rule of Five

If you write any of: destructor, copy ctor, copy assign, move ctor, move assign — you should write (or = default / = delete) all five.

The Rule of Zero

If your class only owns members that already handle their own copy/move/destruction (smart pointers, standard containers), write none of the five. Let the compiler default everything.

This is the modern way. Reach for explicit Rule-of-Five only when wrapping a C library or hand-managing memory.

Chapter 7 — Inheritance

Key parts:

  • class Dog : public Animal — public inheritance (the usual kind).
  • virtual — enables runtime dispatch through base-class pointers/references.
  • = 0 — pure virtual; makes Animal abstract (cannot be instantiated).
  • override — checks at compile time that you're actually overriding. Use it on every override.
  • virtual ~Animal() = default; — always virtual-destructor your polymorphic bases, or delete through a base pointer leaks the derived part.

Polymorphism in action

The vector holds Animal* (via unique_ptr), but each speak() dispatches to the correct derived class via the virtual table.

final

Use final when you intend to lock down the hierarchy. Documents intent + lets compiler de-virtualise calls.

Chapter 8 — Access specifiers

Keyword Inside the class In derived classes Outside
public yes yes yes
protected yes yes no
private yes no no

Default to private for data members. Expose access via methods (getters/setters with validation). This lets you change the representation later without breaking callers.

friend

Use sparingly. Tight coupling.

Chapter 9 — Operator overloading (briefly)

C++ lets you overload most operators. Overload sparingly — only when the semantics are obvious (math types, smart-pointer-like wrappers, iterator types).

Exercise 3 — Rule of Zero

Write a class Inventory that holds std::vector<std::string> items. Add methods to add, list, and count items. Do not write a destructor, copy ctor, or assignment operator — Rule of Zero.

Exercise 4 — Rule of Five for a Buffer

Implement Chapter 5+6 Buffer with constructor, destructor, copy ctor, copy assign, move ctor, move assign. Test that copy works (independent buffers) and move leaves the source empty.

Exercise 5 — Operator overload

Cheat-sheet

What How
Default access of class private
Default access of struct public
Initialiser list : a_(x), b_(y) {}
Const method T foo() const;
Default ctor (gen) MyClass() = default;
Block conversion explicit MyClass(int);
Inherit class D : public B
Pure virtual virtual void f() = 0;
Mark override void f() override;
Mark final void f() final; or class D final
Virtual destructor required for polymorphic base
Rule of Five dtor + 2 copy + 2 move
Rule of Zero write none — use members that manage themselves
Move construct T(T&& o) noexcept
Self-assign check if (this == &other) return *this;
Spaceship op auto operator<=>(const T&) const = default;
