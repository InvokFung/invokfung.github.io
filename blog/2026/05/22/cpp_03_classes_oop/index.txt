11:Tb722,<p>C++ classes are how you bundle data + behaviour and enforce invariants. Unlike Python, C++ enforces access control at compile time (<code>private</code>/<code>protected</code>/<code>public</code>), supports multiple inheritance, distinguishes static and dynamic dispatch with <code>virtual</code>, and gives the compiler enough information to inline method calls aggressively. This post covers the OOP essentials.</p>

<h1 id="Learning-Outcome"><a href="#Learning-Outcome" class="headerlink" title="Learning Outcome"></a>Learning Outcome</h1>
<ul>
<li>Define <code>class</code> / <code>struct</code> with constructors, destructors, member functions.</li>
<li>Use access specifiers <code>public</code>, <code>private</code>, <code>protected</code>.</li>
<li>Implement copy + move constructors and assignment (Rule of Five).</li>
<li>Use inheritance + <code>virtual</code> functions for runtime polymorphism.</li>
<li>Use <code>override</code>, <code>final</code>, and abstract classes (pure virtual).</li>
<li>Apply <strong>the Rule of Zero</strong>: design classes that need no explicit copy/move/destructor.</li>
</ul>

<p><code>class</code> and <code>struct</code> are nearly identical — they differ only in <strong>default access</strong>: <code>class</code> defaults to <code>private</code>, <code>struct</code> to <code>public</code>. Convention:</p>
<ul>
<li>Use <code>struct</code> for plain data aggregates (no invariants).</li>
<li>Use <code>class</code> when you have invariants to enforce or non-trivial behaviour.</li>
</ul>

<h1 id="Chapter-2-—-Constructors-and-the-initialiser-list"><a href="#Chapter-2-—-Constructors-and-the-initialiser-list" class="headerlink" title="Chapter 2 — Constructors and the initialiser list"></a>Chapter 2 — Constructors and the initialiser list</h1>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span><br><span class="line">10</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Person</span> {</span><br><span class="line">    std::string name_;</span><br><span class="line">    <span class="hljs-type">int</span>         age_;</span><br><span class="line"><span class="hljs-keyword">public</span>:</span><br><span class="line">    <span class="hljs-built_in">Person</span>(std::string name, <span class="hljs-type">int</span> age)</span><br><span class="line">        : <span class="hljs-built_in">name_</span>(std::<span class="hljs-built_in">move</span>(name)),     <span class="hljs-comment">// initialiser list</span></span><br><span class="line">          <span class="hljs-built_in">age_</span>(age)</span><br><span class="line">    {}</span><br><span class="line">};</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>The <code>: name_(...), age_(...)</code> syntax is the <strong>member initialiser list</strong>. It runs <em>before</em> the body — and is the only way to initialise:</p>
<ul>
<li><code>const</code> members,</li>
<li>reference members,</li>
<li>base classes,</li>
<li>members with no default constructor.</li>
</ul>
<p>Always prefer the initialiser list over assignments inside the body.</p>
<h2 id="Default-constructor"><a href="#Default-constructor" class="headerlink" title="Default constructor"></a>Default constructor</h2>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Counter</span> {</span><br><span class="line">    <span class="hljs-type">int</span> n_;</span><br><span class="line"><span class="hljs-keyword">public</span>:</span><br><span class="line">    <span class="hljs-built_in">Counter</span>() : <span class="hljs-built_in">n_</span>(<span class="hljs-number">0</span>) {}          <span class="hljs-comment">// explicit default</span></span><br><span class="line">    <span class="hljs-comment">// OR: Counter() = default;   // ask compiler to generate one</span></span><br><span class="line">};</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>If you declare any constructor, the compiler <strong>stops generating</strong> the default. Add <code>= default</code> if you want both your custom one and a default.</p>
<h2 id="Explicit"><a href="#Explicit" class="headerlink" title="Explicit"></a>Explicit</h2>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Wrapper</span> {</span><br><span class="line"><span class="hljs-keyword">public</span>:</span><br><span class="line">    <span class="hljs-function"><span class="hljs-keyword">explicit</span> <span class="hljs-title">Wrapper</span><span class="hljs-params">(<span class="hljs-type">int</span> x)</span> </span>{}    <span class="hljs-comment">// explicit blocks implicit conversion</span></span><br><span class="line">};</span><br><span class="line"> </span><br><span class="line"><span class="hljs-function">Wrapper <span class="hljs-title">w1</span><span class="hljs-params">(<span class="hljs-number">5</span>)</span></span>;                    <span class="hljs-comment">// OK</span></span><br><span class="line">Wrapper w2 = <span class="hljs-number">5</span>;                   <span class="hljs-comment">// ERROR if explicit</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Mark single-argument constructors <code>explicit</code> to prevent surprise conversions. Standard advice.</p>

<h1 id="Chapter-3-—-Destructor"><a href="#Chapter-3-—-Destructor" class="headerlink" title="Chapter 3 — Destructor"></a>Chapter 3 — Destructor</h1>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Buffer</span> {</span><br><span class="line">    <span class="hljs-type">int</span>* data_;</span><br><span class="line"><span class="hljs-keyword">public</span>:</span><br><span class="line">    <span class="hljs-built_in">Buffer</span>(<span class="hljs-type">int</span> n) : <span class="hljs-built_in">data_</span>(<span class="hljs-keyword">new</span> <span class="hljs-type">int</span>[n]{}) {}</span><br><span class="line">    ~<span class="hljs-built_in">Buffer</span>() { <span class="hljs-keyword">delete</span>[] data_; }     <span class="hljs-comment">// destructor</span></span><br><span class="line">};</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>The destructor runs automatically when the object's lifetime ends:</p>
<ul>
<li>For stack objects: end of scope.</li>
<li>For heap objects: when you call <code>delete</code>.</li>
<li>For class members: after the enclosing object's destructor body runs.</li>
</ul>
<p>In modern code, <strong>most classes don't need an explicit destructor</strong> — the Rule of Zero (Chapter 7).</p>

<p>Mark methods <code>const</code> whenever they don't mutate. Lets callers use the class with <code>const</code> references — better safety, more places usable.</p>

<p>Inside a member function, <code>this</code> is a pointer to the current object.</p>

<h1 id="Chapter-5-—-Copy-semantics"><a href="#Chapter-5-—-Copy-semantics" class="headerlink" title="Chapter 5 — Copy semantics"></a>Chapter 5 — Copy semantics</h1>
<p>The compiler generates a <strong>copy constructor</strong> and <strong>copy assignment operator</strong> by default. They do member-wise copy. For most classes this is fine. For classes that own raw memory, you must define them.</p>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span><br><span class="line">10</span><br><span class="line">11</span><br><span class="line">12</span><br><span class="line">13</span><br><span class="line">14</span><br><span class="line">15</span><br><span class="line">16</span><br><span class="line">17</span><br><span class="line">18</span><br><span class="line">19</span><br><span class="line">20</span><br><span class="line">21</span><br><span class="line">22</span><br><span class="line">23</span><br><span class="line">24</span><br><span class="line">25</span><br><span class="line">26</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Buffer</span> {</span><br><span class="line">    <span class="hljs-type">int</span>* data_;</span><br><span class="line">    <span class="hljs-type">int</span>  size_;</span><br><span class="line"><span class="hljs-keyword">public</span>:</span><br><span class="line">    <span class="hljs-built_in">Buffer</span>(<span class="hljs-type">int</span> n) : <span class="hljs-built_in">data_</span>(<span class="hljs-keyword">new</span> <span class="hljs-type">int</span>[n]{}), <span class="hljs-built_in">size_</span>(n) {}</span><br><span class="line">    ~<span class="hljs-built_in">Buffer</span>() { <span class="hljs-keyword">delete</span>[] data_; }</span><br><span class="line"> </span><br><span class="line">    <span class="hljs-comment">// copy constructor</span></span><br><span class="line">    <span class="hljs-built_in">Buffer</span>(<span class="hljs-type">const</span> Buffer&amp; <p>The default member-wise copy would have copied the <strong>pointer</strong> — both objects would point to the same memory, and the second destructor would double-free. Classic bug.</p>

<h1 id="Chapter-6-—-Move-semantics-C11"><a href="#Chapter-6-—-Move-semantics-C11" class="headerlink" title="Chapter 6 — Move semantics (C++11+)"></a>Chapter 6 — Move semantics (C++11+)</h1>
<p>Moving = transferring ownership of resources without copying. Crucial for performance when you want a new object to take over what an old one had.</p>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span><br><span class="line">10</span><br><span class="line">11</span><br><span class="line">12</span><br><span class="line">13</span><br><span class="line">14</span><br><span class="line">15</span><br><span class="line">16</span><br><span class="line">17</span><br><span class="line">18</span><br><span class="line">19</span><br><span class="line">20</span><br><span class="line">21</span><br><span class="line">22</span><br><span class="line">23</span><br><span class="line">24</span><br><span class="line">25</span><br><span class="line">26</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Buffer</span> {</span><br><span class="line">    <span class="hljs-type">int</span>* data_;</span><br><span class="line">    <span class="hljs-type">int</span>  size_;</span><br><span class="line"><span class="hljs-keyword">public</span>:</span><br><span class="line">    <span class="hljs-comment">// ... <p>When does move happen?</p>
<ul>
<li>Returning a local from a function.</li>
<li><code>std::move(x)</code> cast.</li>
<li>Passing a temporary (rvalue) to a constructor.</li>
</ul>
<blockquote>
<p><em>Trick:</em> if you implement copy + dtor by hand, also implement move. Otherwise the compiler won't generate move automatically, and your class falls back to copies in performance-critical places.</p>
</blockquote>
<h2 id="The-Rule-of-Five"><a href="#The-Rule-of-Five" class="headerlink" title="The Rule of Five"></a>The Rule of Five</h2>
<p>If you write <strong>any</strong> of: destructor, copy ctor, copy assign, move ctor, move assign — you should write (or <code>= default</code> / <code>= delete</code>) <strong>all five</strong>.</p>
<h2 id="The-Rule-of-Zero"><a href="#The-Rule-of-Zero" class="headerlink" title="The Rule of Zero"></a>The Rule of Zero</h2>
<p>If your class only owns members that already handle their own copy/move/destruction (smart pointers, standard containers), <strong>write none of the five</strong>. Let the compiler default everything.</p>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span></pre></td><td class="code"><pre><code class="cpp"><span class="line"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Buffer_zero</span> {</span><br><span class="line">    std::vector&lt;<span class="hljs-type">int</span>&gt; data_;       <span class="hljs-comment">// std::vector handles itself</span></span><br><span class="line"><span class="hljs-keyword">public</span>:</span><br><span class="line">    <span class="hljs-built_in">Buffer_zero</span>(<span class="hljs-type">int</span> n) : <span class="hljs-built_in">data_</span>(n) {}</span><br><span class="line">    <span class="hljs-comment">// no destructor, no copy/move declarations — all generated correctly</span></span><br><span class="line">};</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>This is the modern way. Reach for explicit Rule-of-Five only when wrapping a C library or hand-managing memory.</p>

<p>Key parts:</p>
<ul>
<li><code>class Dog : public Animal</code> — public inheritance (the usual kind).</li>
<li><code>virtual</code> — enables runtime dispatch through base-class pointers/references.</li>
<li><code>= 0</code> — pure virtual; makes <code>Animal</code> abstract (cannot be instantiated).</li>
<li><code>override</code> — checks at compile time that you're actually overriding. Use it on every override.</li>
<li><code>virtual ~Animal() = default;</code> — <strong>always virtual-destructor your polymorphic bases</strong>, or <code>delete</code> through a base pointer leaks the derived part.</li>
</ul>
<h2 id="Polymorphism-in-action"><a href="#Polymorphism-in-action" class="headerlink" title="Polymorphism in action"></a>Polymorphism in action</h2>
<pre><code class="language-cpp"><figure class="highlight cpp"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span></pre></td><td class="code"><pre><code class="cpp"><span class="line">std::vector&lt;std::unique_ptr&lt;Animal&gt;&gt; zoo;</span><br><span class="line">zoo.<span class="hljs-built_in">push_back</span>(std::<span class="hljs-built_in">make_unique</span>&lt;Dog&gt;(<span class="hljs-string">&quot;Rex&quot;</span>));</span><br><span class="line">zoo.<span class="hljs-built_in">push_back</span>(std::<span class="hljs-built_in">make_unique</span>&lt;Cat&gt;(<span class="hljs-string">&quot;Mochi&quot;</span>));</span><br><span class="line"> </span><br><span class="line"><span class="hljs-keyword">for</span> (<span class="hljs-type">const</span> <span class="hljs-keyword">auto</span>&amp; a : zoo) {</span><br><span class="line">    std::cout &lt;&lt; a-&gt;<span class="hljs-built_in">speak</span>() &lt;&lt; <span class="hljs-string">&quot;\n&quot;</span>;    <span class="hljs-comment">// calls Dog or Cat version</span></span><br><span class="line">}</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
