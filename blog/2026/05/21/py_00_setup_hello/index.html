Python Course — 00 · Setup, REPL, and Hello World

Created2026-05-21|Updated2026-05-21|Programming
|Post View:

Python is the most popular first programming language in the world right now — for good reasons: clean syntax, batteries-included standard library, huge ecosystem, and you can be productive in an afternoon. This post is the first step of a step-by-step course written like a university lecture series. Each post adds one well-scoped layer; by Post 05 you'll be comfortable with files, exceptions, and modules. Future posts extend into stdlib, async, typing, and beyond.

Series map: 00 Setup (this post) → 01 Syntax → 02 Data Structures → 03 Functions & Modules → 04 OOP → 05 Files & Exceptions → (future) stdlib · async · typing · packaging.

Learning Outcome

  • Install Python 3 on Windows / macOS / Linux.
  • Run the REPL (interactive interpreter) and a script file.
  • Understand the difference between interpreter, script, and REPL.
  • Write and run "Hello, World" + an interactive greeting program.
  • Set up a basic project folder + venv (virtual environment).

Chapter 1 — What Python is (and isn't)

Terminology

  • Interpreter — the program (python or python3) that reads and executes Python code line by line.
  • REPL — Read-Eval-Print Loop: an interactive shell where each line you type is executed immediately.
  • Script — a .py file containing Python code, run with python script.py.
  • Module — a .py file imported by another file.
  • Package — a directory of modules with an __init__.py.
  • PEP — Python Enhancement Proposal. The language's design documents. PEP 8 is the style guide everyone follows.

Python vs other languages (one paragraph)

Python is interpreted (no compile step), dynamically typed (you don't declare types, though you can hint them), and garbage-collected (no manual memory management). The trade-off vs C++/Rust: Python is 10–100× slower in raw computation but 5–10× faster to write. For data work, web back-ends, scripts, automation, and ML, the slowness almost never matters.

Trick: don't compare languages by speed in isolation. Compare by time-to-correct-program. Python wins almost every "write something useful by Friday" race.

Shebang (Linux / macOS only)

Add #!/usr/bin/env python3 as the first line of a script, then chmod +x hello.py, and run with ./hello.py. The OS reads the shebang to know which interpreter to use.

Chapter 5 — Virtual environments (venv)

Each Python project should have its own isolated package list. This prevents "global pip install" chaos.

After activation, your shell prompt usually shows (.venv) as a prefix. Any pip install only affects this venv, not the system Python.

Where I got stuck: I skipped venvs for a year. Then one project needed requests==2.20 and another needed requests==2.28. Mass-upgrading broke the older project. The fix took an hour; the fix would have taken 0 hours with venvs. Always use a venv.

Chapter 6 — Editor / IDE choice

Tool Notes
VS Code + Python extension Free, fast, huge ecosystem. Recommended for beginners.
PyCharm Community Heavier, more "IDE feel", excellent refactoring.
Jupyter Notebook / Lab Notebooks for data work. Use pip install jupyterlab.
Neovim / Vim + plugins For terminal lovers. Slow to set up well.
IDLE Ships with Python. Fine for first hour, then upgrade.

Pick one. Don't tool-shop for weeks — pick VS Code if undecided.

Cheat-sheet

What How
Run REPL python or python3
Run script python script.py
Check version python --version
Create venv python -m venv .venv
Activate venv (Win) .venv\Scripts\Activate.ps1
Activate venv (Unix) source .venv/bin/activate
Install package pip install <name>
Freeze deps pip freeze > requirements.txt
Restore deps pip install -r requirements.txt
Exit REPL exit() or Ctrl+D (Unix) / Ctrl+Z + Enter (Win)
