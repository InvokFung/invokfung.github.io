MongoDB Course — 05 · Aggregation Basics — Pipeline, $match, $group, $project, $lookup

Created2026-06-08|Updated2026-06-08|Database > MongoDB
|Post View:

The aggregation framework is MongoDB's "everything beyond CRUD" engine. A pipeline is a sequence of stages, each transforming the stream of documents flowing through it — filter, group, project, sort, join, unwind, compute. This post covers the core stages every project uses: $match, $project, $addFields, $group, $sort, $limit, $skip, $count, $unwind, $lookup. Post 06 follows with advanced stages ($facet, $bucket, $graphLookup, $merge, window functions).

Series map: 00 Foundations → 01 CRUD → 02 Query Operators → 03 Indexes → 04 Query Optimization → 05 Aggregation Basics (this post) → 06 Aggregation Advanced → … → 17 Drivers & Case Studies.

Learning Outcome

  • Write an aggregation pipeline composed of stages.
  • Use $match early to leverage indexes.
  • Group + reduce with $group and accumulators ($sum, $avg, $first, $last, $push, $addToSet, $min, $max).
  • Reshape with $project, $addFields, $set, $unset.
  • Sort, limit, skip, count results.
  • Flatten arrays with $unwind.
  • Join collections with $lookup (left outer join).

Chapter 1 — Pipeline basics

A pipeline is an array of stage objects. Each stage takes the previous stage's output documents as input and emits its own. Order matters.

Mental model:

Field references

Inside aggregation stages, prefix field names with $ to reference document values:

A double-dollar $$variable references a named variable (NOW, ROOT, CURRENT, or pipeline-defined).

Chapter 2 — $match — filter

Same syntax as find filter:

Always put $match as early as possible in the pipeline. When $match is the first stage, MongoDB can use indexes to skip non-matching documents entirely. Later in the pipeline it can't.

The query planner sometimes pushes $match up automatically, but don't rely on it — write the pipeline correctly.

Chapter 3 — $project, $addFields, $set, $unset — reshape

$project — include + transform

Excludes everything not mentioned (except for computed fields). For mostly-keep-but-tweak, prefer $addFields.

$addFields / $set — add or override fields

Doesn't remove other fields.

$unset — remove fields

Chapter 4 — $group — reduce / aggregate

$group collapses input documents into one document per group key.

_id is the group key. It can be:

  • a field reference: _id: "$user_id"
  • a compound: _id: { user: "$user_id", month: { $dateTrunc: { date: "$at", unit: "month" } } }
  • a literal: _id: null (collapse to a single global aggregate)

Accumulators

Accumulator What
$sum: <expr> sum (use $sum: 1 for count)
$avg: <expr> average
$min, $max min, max
$first, $last first / last value (requires sort first to be meaningful)
$push: <expr> accumulate into array
$addToSet: <expr> accumulate into deduplicated array
$mergeObjects merge sub-documents
$stdDevPop, $stdDevSamp standard deviation
$accumulator custom (JS-defined, slower)

Chapter 5 — $sort, $limit, $skip, $count

$sort followed by $limit is optimised — the server only keeps the top-N in memory instead of sorting everything.

$count returns a single document { matching_count: N }. For aggregations, this is cleaner than countDocuments.

Trick: for sort + limit to be efficient over big collections, the sort field needs an index. Otherwise the entire input is sorted in memory (subject to the 100 MB stage memory limit; pass { allowDiskUse: true } to spill).

Chapter 6 — $unwind — flatten arrays

$unwind deconstructs an array, emitting one document per element.

Options

preserveNullAndEmptyArrays: true keeps documents where the array is missing or empty (otherwise dropped).

Use case: per-item revenue

$unwind followed by $group is the canonical pattern for "compute totals across array elements".

Chapter 7 — $lookup — left outer join

Result includes a user field — an array of matching documents (or empty). Unwind to flatten when you expect one match.

Pipeline form — more powerful

The pipeline form lets you filter/sort/limit the joined documents — far more efficient than fetching all then dropping.

Performance

  • $lookup is not free — for every input doc, it queries the foreign collection.
  • The foreign-collection field (the foreignField) should be indexed.
  • Avoid $lookup in hot user-facing paths; prefer embedded documents (Post 07).
  • Acceptable for reporting / dashboards where latency is less critical.

$lookup limits

  • Result document size capped at 16 MB (the BSON doc limit).
  • For huge joins, consider denormalisation or pre-aggregation into a materialised view ($merge, Post 06).

Chapter 10 — Performance + indexing for aggregations

  • The first $match and the first $sort (if both at the top) can use indexes.
  • $lookup's foreignField should be indexed.
  • Large $group results consume memory; pass { allowDiskUse: true } for big aggregations.
  • Avoid expensive transformations before $match reduces the dataset.
  • Use .explain("executionStats") on aggregations (Post 04).

Aggregation result size cap: 16 MB per document. For huge outputs, write to a collection with $out / $merge and query separately.

Trick: $count is faster than $group: { _id: null, c: { $sum: 1 } }. The dedicated stage is optimised internally.

Chapter 11 — Common pitfalls

Symptom Cause Fix
Aggregation slow $match not first always start with $match
$lookup very slow no index on foreignField add it
OOM / "Sort exceeded memory limit" big $sort without index index the sort field; or allowDiskUse: true
$group reduces too much wrong _id shape check group key includes the dimensions you need
Result doc > 16 MB trying to fit everything in one row $out / $merge to a collection
Field references missing $ $group: { _id: "user_id" } instead of "$user_id" always prefix with $
$unwind produces too many rows unwinding before reducing filter first, unwind later, group again
null joined docs after $lookup + $unwind dropping no-match docs preserveNullAndEmptyArrays: true

Cheat-sheet

What How
Run db.c.aggregate([ stages ])
Always $match first to use indexes
Filter $match: { ... } (find-style filter)
Reshape $project, $addFields, $set, $unset
Group $group: { _id, accumulators }
Accumulators $sum, $avg, $min, $max, $first, $last, $push, $addToSet
Sort / limit / skip $sort: { f: -1 }, $limit: N, $skip: N
Count $count: "name"
Flatten array $unwind: "$arr" (preserve empty with options)
Join $lookup: { from, localField, foreignField, as }
Pipeline join $lookup: { from, let, pipeline, as }
Write back $out (replace) / $merge (upsert)
Memory 100 MB per stage; { allowDiskUse: true } to spill
Field ref "$field"
Whole doc "$$ROOT"
Variables "$$NOW", "$$CURRENT", custom via let
Explain db.c.aggregate([...]).explain("executionStats")
