<h1 id="Chapter-7-—-expr-in-match-—-cross-field-predicates"><a href="#Chapter-7-—-expr-in-match-—-cross-field-predicates" class="headerlink" title="Chapter 7 — $expr in $match — cross-field predicates"></a>Chapter 7 — <code>$expr</code> in <code>$match</code> — cross-field predicates</h1>
<p><code>$expr</code> lets aggregation operators appear inside a query filter:</p>
<pre><code class="language-js"><figure class="highlight js"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span></pre></td><td class="code"><pre><code class="js"><span class="line">{ <span class="hljs-attr">$match</span>: {</span><br><span class="line">  <span class="hljs-attr">$expr</span>: { <span class="hljs-attr">$gt</span>: [<span class="hljs-string">&quot;$total&quot;</span>, { <span class="hljs-attr">$multiply</span>: [<span class="hljs-number">10</span>, { <span class="hljs-attr">$size</span>: <span class="hljs-string">&quot;$items&quot;</span> }] }] }</span><br><span class="line">}}</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Cross-field predicates that <code>find</code> can't express directly — without leaving the aggregation framework.</p>
<p>Also useful inside <code>$lookup</code> pipeline form:</p>
<pre><code class="language-js"><figure class="highlight js"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span></pre></td><td class="code"><pre><code class="js"><span class="line">{ <span class="hljs-attr">$lookup</span>: {</span><br><span class="line">  <span class="hljs-attr">from</span>: <span class="hljs-string">&quot;comments&quot;</span>,</span><br><span class="line">  <span class="hljs-attr">let</span>: { <span class="hljs-attr">post_id</span>: <span class="hljs-string">&quot;$_id&quot;</span> },</span><br><span class="line">  <span class="hljs-attr">pipeline</span>: [</span><br><span class="line">    { <span class="hljs-attr">$match</span>: { <span class="hljs-attr">$expr</span>: { <span class="hljs-attr">$eq</span>: [<span class="hljs-string">&quot;$post&quot;</span>, <span class="hljs-string">&quot;$$post_id&quot;</span>] } } }</span><br><span class="line">  ],</span><br><span class="line">  <span class="hljs-attr">as</span>: <span class="hljs-string">&quot;comments&quot;</span></span><br><span class="line">}}</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<hr>
<h1 id="Chapter-8-—-function-—-server-side-JavaScript"><a href="#Chapter-8-—-function-—-server-side-JavaScript" class="headerlink" title="Chapter 8 — $function — server-side JavaScript"></a>Chapter 8 — <code>$function</code> — server-side JavaScript</h1>
<p>Last resort when no operator combination expresses the logic:</p>
<pre><code class="language-js"><figure class="highlight js"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span><br><span class="line">10</span></pre></td><td class="code"><pre><code class="js"><span class="line">{ <span class="hljs-attr">$project</span>: {</span><br><span class="line">  <span class="hljs-attr">custom</span>: {</span><br><span class="line">    <span class="hljs-attr">$function</span>: {</span><br><span class="line">      <span class="hljs-attr">body</span>: <span class="hljs-keyword">function</span> (<span class="hljs-params">a, b</span>) { <span class="hljs-keyword">return</span> a * <span class="hljs-number">2</span> + <span class="hljs-title class_">Math</span>.<span class="hljs-title function_">log</span>(b); },</span><br><span class="line">      <span class="hljs-attr">args</span>: [<span class="hljs-string">&quot;$x&quot;</span>, <span class="hljs-string">&quot;$y&quot;</span>],</span><br><span class="line">      <span class="hljs-attr">lang</span>: <span class="hljs-string">&quot;js&quot;</span></span><br><span class="line">    }</span><br><span class="line">  }</span><br><span class="line">}}</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Limits:</p>
<ul>
<li>Far slower than native operators.</li>
<li>Disabled by default in some Atlas tiers.</li>
<li>Sandboxed but still a security consideration in shared environments.</li>
</ul>
<p>Use only when truly necessary. Native operators almost always exist for everyday math.</p>
<p><code>$accumulator</code> is the equivalent for custom <code>$group</code> reductions — same caveats.</p>
<hr>
<h1 id="Chapter-9-—-allowDiskUse-and-memory"><a href="#Chapter-9-—-allowDiskUse-and-memory" class="headerlink" title="Chapter 9 — allowDiskUse and memory"></a>Chapter 9 — <code>allowDiskUse</code> and memory</h1>
<p>By default each pipeline stage is limited to 100 MB of memory. Exceeding it returns an error.</p>
<pre><code class="language-js"><figure class="highlight js"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span></pre></td><td class="code"><pre><code class="js"><span class="line">db.<span class="hljs-property">orders</span>.<span class="hljs-title function_">aggregate</span>(pipeline, { <span class="hljs-attr">allowDiskUse</span>: <span class="hljs-literal">true</span> })</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Spills to disk → slower but allowed. Drivers expose this as an option.</p>
<p>Stages that often need it: <code>$sort</code> over big inputs without index support, big <code>$group</code>, <code>$lookup</code> returning many docs.</p>
<p>Production tip: <strong>fix the index design first</strong>. <code>allowDiskUse: true</code> masks a missing index — the query works but stays slow.</p>

<h1 id="Chapter-11-—-Patterns-anti-patterns"><a href="#Chapter-11-—-Patterns-anti-patterns" class="headerlink" title="Chapter 11 — Patterns + anti-patterns"></a>Chapter 11 — Patterns + anti-patterns</h1>
<table>
<thead>
<tr>
<th>Pattern</th>
<th>Use</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>$match</code> → <code>$group</code> → <code>$sort</code> → <code>$limit</code></td>
<td>most reports</td>
</tr>
<tr>
<td><code>$facet</code></td>
<td>one round-trip for dashboard with many widgets</td>
</tr>
<tr>
<td><code>$bucket(Auto)</code></td>
<td>histograms / distribution charts</td>
</tr>
<tr>
<td><code>$graphLookup</code></td>
<td>trees + graphs up to small depth</td>
</tr>
<tr>
<td><code>$lookup</code> (pipeline form)</td>
<td>filtered + sorted + limited joins</td>
</tr>
<tr>
<td><code>$merge</code> to a summary collection</td>
<td>precomputed reports, run nightly</td>
</tr>
<tr>
<td><code>$setWindowFields</code></td>
<td>rolling / ranking</td>
</tr>
<tr>
<td><code>$densify</code> + <code>$fill</code></td>
<td>gap-fill before charting</td>
</tr>
</tbody>
</table>
<p>Anti-patterns:</p>
<ul>
<li><code>$group</code> followed by another <code>$group</code> on the same key (combine accumulators in one).</li>
<li>Large <code>$lookup</code> followed by <code>$unwind</code> followed by <code>$group</code> (data shape problem; consider denormalising).</li>
<li><code>$function</code> for trivial math (use native operators).</li>
<li><code>$graphLookup</code> with no <code>maxDepth</code> over a cyclic graph (infinite work).</li>
</ul>
<hr>
<h1 id="Chapter-12-—-Indexes-for-advanced-aggregations"><a href="#Chapter-12-—-Indexes-for-advanced-aggregations" class="headerlink" title="Chapter 12 — Indexes for advanced aggregations"></a>Chapter 12 — Indexes for advanced aggregations</h1>
<ul>
<li><code>$facet</code> doesn't push <code>$match</code> into its sub-pipelines for index use — put a <code>$match</code> <strong>before</strong> the <code>$facet</code>.</li>
<li><code>$lookup</code> <code>foreignField</code> must be indexed.</li>
<li><code>$graphLookup</code> <code>connectToField</code> must be indexed.</li>
<li><code>$merge</code> <code>on</code> fields must be indexed unique.</li>
<li><code>$out</code> recreates the target collection — original indexes are lost. <code>$merge</code> preserves them.</li>
</ul>
