MongoDB Course — 06 · Aggregation Advanced — $facet, $bucket, $graphLookup, Window Functions, $merge

Created2026-06-10|Updated2026-06-10|Database > MongoDB
|Post View:

The aggregation basics from Post 05 cover ~80 % of real pipelines. The remaining 20 % needs the advanced stages: $facet (parallel sub-pipelines on the same input), $bucket / $bucketAuto (histograms), $graphLookup (recursive joins for trees + graphs), $merge (incremental materialised views), $setWindowFields (rolling sums, ranks, leads/lags, percentiles), $densify + $fill (gap-fill time series), $expr in $match, and $function (server-side JS). This post covers all of them with worked examples.

Series map: 00 Foundations → 01 CRUD → 02 Query Operators → 03 Indexes → 04 Query Optimization → 05 Aggregation Basics → 06 Aggregation Advanced (this post) → 07 Schema Design → … → 17 Drivers & Case Studies.

Learning Outcome

  • Run multiple sub-pipelines in parallel with $facet.
  • Build histograms with $bucket and $bucketAuto.
  • Walk hierarchies with $graphLookup.
  • Build incremental materialised views with $merge.
  • Compute rolling sums, ranks, lead/lag with $setWindowFields.
  • Fill missing time-series rows with $densify + $fill.
  • Use $function for custom JS only when the operator library can't.
  • Pass { allowDiskUse: true } for huge aggregations.

Chapter 2 — $bucket and $bucketAuto — histograms

$bucket — manual boundaries

Documents get assigned to the bucket whose range contains the groupBy value ([boundary[i], boundary[i+1]) — half-open). Documents outside all ranges go to default.

$bucketAuto — automatic equal-sized buckets

Server chooses boundaries so each bucket holds roughly the same number of documents — handy when distribution is unknown.

Chapter 3 — $graphLookup — recursive join

For hierarchies (employees → managers → CEO; categories → sub-categories; comment threads):

Use cases:

  • Org charts (find all reports).
  • Comment threads (find all descendants of a post).
  • Category trees (find all sub-categories).
  • Graph traversal up to N hops (set maxDepth).

Performance

$graphLookup can explode in size and time. Always:

  • Set maxDepth to bound traversal.
  • Index connectToField (foreign side).
  • Filter with restrictSearchWithMatch to skip whole sub-trees.

For really large hierarchies, denormalise via the materialised-path or array-of-ancestors patterns (Post 07).

Chapter 4 — $merge — incremental materialised view

$merge writes pipeline output into a target collection with upsert / merge semantics. Use for incremental refresh of pre-computed reports.

Schedule the pipeline via a cron job / Atlas Trigger / change-stream-driven Lambda — every run brings the daily summary up to date without rebuilding from scratch.

$out vs $merge

$out $merge
Mode replace entire collection upsert / merge per doc
Indexes preserved no (collection recreated) yes
Sharded target not supported supported
Cross-DB yes (recent) yes
Use full rebuild incremental update

For modern pipelines, prefer $merge — preserves indexes + supports sharding.

Chapter 5 — $setWindowFields — window functions (5.0+)

Window functions compute values over a sliding window of related rows without collapsing them (unlike $group).

Window types:

  • documents: [-2, 0] — last 2 rows + current.
  • documents: ["unbounded", "current"] — all rows up to and including current.
  • range: [-86400, 0], unit: "second" — time-based window.

Common window operators

  • $sum, $avg, $min, $max, $count, $first, $last (as accumulators)
  • $rank, $denseRank, $documentNumber
  • $shift (offset within partition — lead/lag)
  • $derivative, $integral
  • $expMovingAvg

Use cases

  • Running totals (cumulative revenue).
  • Rolling averages (last 7-day moving average).
  • Rank within group (top product per category by rank).
  • Pct-of-total per row.
  • Lead / lag for change detection.

Trick: before window functions (5.0), every such query needed $lookup self-joins or app-side computation. They're the single biggest aggregation upgrade of the last few years.

Chapter 6 — $densify + $fill — gap-fill time series

Time-series data often has gaps (no rows for days with zero events). $densify inserts placeholder documents at regular intervals; $fill fills missing field values from neighbours or with constants.

Charts that need a complete date axis (line chart with zero-revenue gaps shown as zero, not skipped) use this.

Chapter 8 — $function — server-side JavaScript

Last resort when no operator combination expresses the logic:

Limits:

  • Far slower than native operators.
  • Disabled by default in some Atlas tiers.
  • Sandboxed but still a security consideration in shared environments.

Use only when truly necessary. Native operators almost always exist for everyday math.

$accumulator is the equivalent for custom $group reductions — same caveats.

Chapter 9 — allowDiskUse and memory

By default each pipeline stage is limited to 100 MB of memory. Exceeding it returns an error.

Spills to disk → slower but allowed. Drivers expose this as an option.

Stages that often need it: $sort over big inputs without index support, big $group, $lookup returning many docs.

Production tip: fix the index design first. allowDiskUse: true masks a missing index — the query works but stays slow.

Chapter 11 — Patterns + anti-patterns

Pattern Use
$match → $group → $sort → $limit most reports
$facet one round-trip for dashboard with many widgets
$bucket(Auto) histograms / distribution charts
$graphLookup trees + graphs up to small depth
$lookup (pipeline form) filtered + sorted + limited joins
$merge to a summary collection precomputed reports, run nightly
$setWindowFields rolling / ranking
$densify + $fill gap-fill before charting

Anti-patterns:

  • $group followed by another $group on the same key (combine accumulators in one).
  • Large $lookup followed by $unwind followed by $group (data shape problem; consider denormalising).
  • $function for trivial math (use native operators).
  • $graphLookup with no maxDepth over a cyclic graph (infinite work).

Chapter 12 — Indexes for advanced aggregations

  • $facet doesn't push $match into its sub-pipelines for index use — put a $match before the $facet.
  • $lookup foreignField must be indexed.
  • $graphLookup connectToField must be indexed.
  • $merge on fields must be indexed unique.
  • $out recreates the target collection — original indexes are lost. $merge preserves them.

Recursive join $graphLookup: { from, startWith, connectFromField, connectToField, maxDepth, as }
Materialised view $merge: { into, on, whenMatched, whenNotMatched }
Replace collection $out: "name" (full rebuild)
Window function $setWindowFields: { partitionBy, sortBy, output: { f: { acc, window } } }
Window types documents: [-N, 0] / range: [...] / "unbounded"
Ranks $rank, $denseRank, $documentNumber
Lead / lag $shift: { output, by, default }
Time-series gap fill $densify + $fill
