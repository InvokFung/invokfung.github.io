<h2 id="Tokens-are-not-words"><a href="#Tokens-are-not-words" class="headerlink" title="Tokens are not words"></a>Tokens are not words</h2>
<p>The model never sees letters or words. It sees a list of integers. A common word may be one token; a rare word may be three or four. Spaces, punctuation and line breaks use tokens too.</p>
<p>A rule of thumb from Anthropic's models page (vendor spec, September 2026): on the tokenizer Claude has used since Claude Opus 4.7, <strong>1M tokens is roughly 555k English words, or 2.5M Unicode characters</strong>. Earlier models fit about 750k words in 1M tokens. So the same text gives a different count on a different model.</p>
<p>Tokens matter because almost every limit uses them: <strong>price</strong> (per million input and output tokens), <strong>the context window</strong> (Chapter 4), <strong><code>max_tokens</code></strong> (the cap on what the model writes) and <strong>rate limits</strong>.</p>
<h2 id="BPE-in-one-example"><a href="#BPE-in-one-example" class="headerlink" title="BPE in one example"></a>BPE in one example</h2>
<p>Byte Pair Encoding was brought into neural machine translation by Sennrich, Haddow and Birch (ACL 2016) to handle rare words as sequences of smaller units. Training: split every word into characters, count every neighbouring pair, merge the most frequent pair, repeat. Tokenizing: replay the merges in the same order. Many modern tokenizers run the same idea on UTF-8 <strong>bytes</strong>, so any text can be encoded (see Dev Essentials 01 · Text Encoding).</p>

<h2 id="Why-code-and-non-English-text-often-cost-more"><a href="#Why-code-and-non-English-text-often-cost-more" class="headerlink" title="Why code and non-English text often cost more"></a>Why code and non-English text often cost more</h2>
<p>Merges are learned from the tokenizer's training data. Whatever is common there gets long tokens.</p>
<ul>
<li><strong>Non-English text.</strong> Petrov et al. (NeurIPS 2023) tokenized the same text translated into many languages and found lengths that differ <strong>by up to 15 times in some cases</strong> (independent measurement). A Chinese character is also 3 bytes in UTF-8, so a byte-level tokenizer starts from more pieces.</li>
<li><strong>Code.</strong> The Codex paper (Chen et al., 2021) found the GPT-3 text tokenizer &quot;not very effective for representing code&quot;, with whitespace the largest waste. Adding tokens for runs of spaces cut code token counts by <strong>about 30%</strong> (vendor research paper).</li>
</ul>

<h1 id="Chapter-2-—-Next-token-prediction-and-the-transformer"><a href="#Chapter-2-—-Next-token-prediction-and-the-transformer" class="headerlink" title="Chapter 2 — Next-token prediction and the transformer"></a>Chapter 2 — Next-token prediction and the transformer</h1>
<p>Every LLM answer comes from the same loop:</p>
<ol>
<li>Turn the prompt into token IDs.</li>
<li>Run them through the network. It returns one score (a <strong>logit</strong>) per vocabulary token.</li>
<li>Turn the scores into probabilities and pick one token (Chapter 5).</li>
<li>Append it and repeat. Stop at an end token, a stop sequence or <code>max_tokens</code>.</li>
</ol>

<h2 id="Attention-at-intuition-level"><a href="#Attention-at-intuition-level" class="headerlink" title="Attention, at intuition level"></a>Attention, at intuition level</h2>
<p>Almost every modern LLM is a <strong>transformer</strong>, from &quot;Attention Is All You Need&quot; (Vaswani et al., 2017). Its key part is <strong>self-attention</strong>: for each token, the model decides how much each earlier token matters right now. In &quot;The animal didn't cross the street because <strong>it</strong> was tired&quot;, attention lets &quot;it&quot; pull in information from &quot;animal&quot;. Each token makes a <strong>query</strong> (what am I looking for?), a <strong>key</strong> (what do I contain?) and a <strong>value</strong> (what do I pass on?):</p>

<p>For text generation, a <strong>causal mask</strong> stops each token from looking at later tokens. Real models stack many such layers, each with several attention &quot;heads&quot;.</p>
<p>What this means for you:</p>
<ul>
<li><strong>Output is written one token at a time</strong>, which is why APIs offer streaming. On Anthropic's current price list, output tokens cost five times as much as input tokens.</li>
<li><strong>The model cannot go back.</strong> An early wrong token shapes everything after it. Reasoning before answering helps (Chapter 8).</li>
<li><strong>Long inputs cost more compute.</strong> The paper lists self-attention cost per layer as <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>O</mi><mo stretchy="false">(</mo><msup><mi>n</mi><mn>2</mn></msup><mo>⋅</mo><mi>d</mi><mo stretchy="false">)</mo></mrow><annotation encoding="application/x-tex">O(n^2 \cdot d)</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:1.0641em;vertical-align:-0.25em;"></span><span class="mord mathnormal" style="margin-right:0.02778em;">O</span><span class="mopen">(</span><span class="mord"><span class="mord mathnormal">n</span><span class="msupsub"><span class="vlist-t"><span class="vlist-r"><span class="vlist" style="height:0.8141em;"><span style="top:-3.063em;margin-right:0.05em;"><span class="pstrut" style="height:2.7em;"></span><span class="sizing reset-size6 size3 mtight"><span class="mord mtight">2</span></span></span></span></span></span></span></span><span class="mspace" style="margin-right:0.2222em;"></span><span class="mbin">⋅</span><span class="mspace" style="margin-right:0.2222em;"></span></span><span class="base"><span class="strut" style="height:1em;vertical-align:-0.25em;"></span><span class="mord mathnormal">d</span><span class="mclose">)</span></span></span></span> for sequence length <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>n</mi></mrow><annotation encoding="application/x-tex">n</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.4306em;"></span><span class="mord mathnormal">n</span></span></span></span>.</li>

<tr>

<td>Supervised fine-tuning on example requests with good answers.</td>

<p>This is deliberately high level: labs combine and change these steps, and full recipes are not published.</p>
<ol>
<li><strong>Pretraining.</strong> The model learns to predict the next token over a very large text collection. It picks up grammar, facts, code patterns and reasoning habits, but does not reliably follow instructions yet.</li>
<li><strong>Instruction tuning.</strong> Fine-tuning on demonstrations: a request, then a good response.</li>
<li><strong>Preference training.</strong> InstructGPT (Ouyang et al., 2022) describes classic RLHF: supervised fine-tuning on labeller demonstrations, then a reward model trained on <strong>rankings</strong> of model outputs, then reinforcement learning against it. Constitutional AI (Bai et al., 2022) replaces much human labelling for harmlessness: the model critiques and revises its own answers against written principles, and a preference model trained on AI comparisons gives the reward (RLAIF).</li>
</ol>
<p>In practice:</p>
<ul>
<li><strong>Knowledge has a cutoff.</strong> Anthropic lists a &quot;reliable knowledge cutoff&quot; per model (vendor spec): for example Feb 2025 for Claude Haiku 4.5 and Jun 2026 for Claude Opus 5.5.</li>
<li><strong>The model knows nothing about your private code or data.</strong> You supply it through context: prompts, files, retrieved documents (post 19), tool results (post 18).</li>
</ul>

<h1 id="Chapter-4-—-The-context-window"><a href="#Chapter-4-—-The-context-window" class="headerlink" title="Chapter 4 — The context window"></a>Chapter 4 — The context window</h1>
<p>The <strong>context window</strong> is everything the model can read while writing a response, including the response itself. Anthropic's docs call it the model's &quot;working memory&quot;. It counts the system prompt, every message (including tool results, images and documents), tool definitions, and this turn's output including any thinking.</p>
<p><strong>The API is stateless.</strong> The model does not remember your last request, so a chat app resends the whole history every turn. Turn 10 pays for turns 1 to 9 again (Exercise 4 does the maths).</p>
<p>Sizes change often. As of September 2026 (vendor spec), current Claude Opus, Sonnet and Fable models have a <strong>1M-token</strong> window and up to 128k output tokens per request; Claude Haiku 4.5 has <strong>200k</strong> and 64k. When a request does not fit, the Anthropic API does this (vendor spec):</p>

<thead>
<tr>

<th>Result</th>
</tr>
</thead>

<tr>
<td>Input alone is bigger than the window</td>
<td><code>400 invalid_request_error</code> (&quot;prompt is too long&quot;)</td>
</tr>

<h1 id="Chapter-7-—-Why-hallucinations-happen-and-how-to-reduce-them"><a href="#Chapter-7-—-Why-hallucinations-happen-and-how-to-reduce-them" class="headerlink" title="Chapter 7 — Why hallucinations happen and how to reduce them"></a>Chapter 7 — Why hallucinations happen and how to reduce them</h1>
<p>A <strong>hallucination</strong> is fluent, confident text that is false or not supported by the given sources. Causes:</p>
<ul>
<li><strong>The goal is a plausible next token, not a true statement.</strong> A made-up citation can look very plausible.</li>
<li><strong>Training and tests reward guessing.</strong> Kalai et al. (2025, &quot;Why Language Models Hallucinate&quot;) argue that training and evaluation reward guessing over admitting uncertainty, like an exam with no penalty for wrong answers.</li>
<li><strong>Missing knowledge:</strong> after the cutoff, private, or rare.</li>
<li><strong>Missing or buried context:</strong> not in the prompt, or lost in a very long one.</li>
</ul>
<p>Fixes. The first five follow Anthropic's &quot;Reduce hallucinations&quot; guide and work with any model:</p>
<table>
<thead>
<tr>
<th>Technique</th>
<th>How</th>
</tr>
</thead>
<tbody>
<tr>
<td>Allow &quot;I don't know&quot;</td>
<td>&quot;If the documents do not contain the answer, say so.&quot;</td>
</tr>
<tr>
<td>Ground in sources</td>
<td>Put the documents in the prompt; tell the model to use only them.</td>
</tr>
<tr>
<td>Quote first</td>
<td>For long documents, extract word-for-word quotes, then answer from them.</td>
</tr>
<tr>
<td>Cite and check</td>
<td>One citation per claim; retract any claim without a supporting quote.</td>
</tr>
<tr>
<td>Compare several runs</td>
<td>Answers that disagree across runs are a warning sign.</td>
</tr>
<tr>
<td>Verify with tools</td>
<td>Run the code and tests; check official docs for any API or flag you do not know.</td>
</tr>
</tbody>
</table>

<h1 id="Chapter-8-—-Prompt-caching-tool-use-and-extended-thinking"><a href="#Chapter-8-—-Prompt-caching-tool-use-and-extended-thinking" class="headerlink" title="Chapter 8 — Prompt caching, tool use and extended thinking"></a>Chapter 8 — Prompt caching, tool use and extended thinking</h1>
<h2 id="Prompt-caching"><a href="#Prompt-caching" class="headerlink" title="Prompt caching"></a>Prompt caching</h2>
<p>Much of a request repeats: system prompt, tool list, a long document. <strong>Prompt caching</strong> stores the processed prefix and reuses it (the general idea is in Dev Essentials 13 · Caching). Other providers have similar features; Anthropic's details (vendor spec, September 2026):</p>
<ul>
<li>The match is on the exact <strong>prefix</strong>, in the order <code>tools</code> → <code>system</code> → <code>messages</code>. One changed byte invalidates everything after it, so put stable content first.</li>
<li>A cache entry lives <strong>5 minutes</strong> by default, refreshed on each use; a 1-hour option exists.</li>
<li>A 5-minute cache write costs 1.25× the base input price; a cache read costs 0.1× on most models.</li>
<li>The minimum cacheable prefix is 512 to 4,096 tokens depending on the model (512 on Claude Opus 5.5).</li>
</ul>
<p>Mark the end of the stable part with <code>cache_control</code>, then check <code>response.usage.cache_read_input_tokens</code> on the next call:</p>

<h2 id="Extended-thinking-reasoning"><a href="#Extended-thinking-reasoning" class="headerlink" title="Extended thinking (reasoning)"></a>Extended thinking (reasoning)</h2>
<p>Since the model cannot go back and fix tokens, it helps to let it reason <strong>before</strong> the final answer. On the Anthropic API (vendor spec, September 2026):</p>
<ul>
<li>Current models use <strong>adaptive thinking</strong>: the model decides how much to think; you steer depth with <code>output_config={&quot;effort&quot;: ...}</code> (<code>low</code>, <code>medium</code>, <code>high</code>, <code>xhigh</code>, <code>max</code>).</li>
<li>On Claude Opus 5.5 thinking is always on, and the default effort is <code>medium</code>.</li>
<li>Thinking tokens are billed as output, and count toward <code>max_tokens</code> and the context window.</li>
<li>Thinking text is omitted by default; <code>display: &quot;summarized&quot;</code> returns a readable summary.</li>
