<h1 id="Chapter-4-—-A03-Software-Supply-Chain-Failures"><a href="#Chapter-4-—-A03-Software-Supply-Chain-Failures" class="headerlink" title="Chapter 4 — A03 Software Supply Chain Failures"></a>Chapter 4 — A03 Software Supply Chain Failures</h1>
<p><strong>What it is.</strong> Your app is mostly other people's code: packages, base images, build tools, CI actions. This category covers known-vulnerable dependencies (the 2021 idea) and also attacks on the chain itself: typosquatted package names, hijacked maintainer accounts, poisoned build pipelines.</p>
<p>A tiny vulnerable example is a <code>requirements.txt</code> that says only <code>fastapi</code> and <code>requests</code>: no versions, no hashes, so every install trusts whatever is newest. The fix is to list direct dependencies in <code>requirements.in</code>, then pin exact versions with hashes and audit them:</p>
<pre><code class="language-bash"><figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span></pre></td><td class="code"><pre><code class="bash"><span class="line">pip install pip-tools pip-audit</span><br><span class="line">pip-compile --generate-hashes requirements.in -o requirements.txt   <span class="hljs-comment"># pins + sha256 hashes</span></span><br><span class="line">pip install --require-hashes -r requirements.txt                   <span class="hljs-comment"># refuses anything else</span></span><br><span class="line">pip-audit -r requirements.txt                                      <span class="hljs-comment"># checks known CVEs</span></span><br><span class="line">npm ci &amp;&amp; npm audit                                                <span class="hljs-comment"># the JavaScript side</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p>Add a short list of trusted package sources, audits in CI, and an SBOM (a list of every component). Dev Essentials 09 · Versions &amp; Dependencies covers this in depth.</p>

<h1 id="Chapter-5-—-A04-Cryptographic-Failures"><a href="#Chapter-5-—-A04-Cryptographic-Failures" class="headerlink" title="Chapter 5 — A04 Cryptographic Failures"></a>Chapter 5 — A04 Cryptographic Failures</h1>
<p><strong>What it is.</strong> Sensitive data is exposed because crypto is missing, weak or misused: plain HTTP, passwords stored with MD5, home-made encryption, secrets in source code, or &quot;random&quot; tokens from a predictable generator.</p>
<pre><code class="language-python"><figure class="highlight python"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span></pre></td><td class="code"><pre><code class="python"><span class="line"><span class="hljs-comment"># a04_tokens.py</span></span><br><span class="line"><span class="hljs-keyword">import</span> random, secrets</span><br><span class="line"> </span><br><span class="line">reset_code_bad = <span class="hljs-string">&quot;&quot;</span>.join(random.choice(<span class="hljs-string">&quot;0123456789&quot;</span>) <span class="hljs-keyword">for</span> _ <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(<span class="hljs-number">6</span>))  <span class="hljs-comment"># VULNERABLE</span></span><br><span class="line">reset_token = secrets.token_urlsafe(<span class="hljs-number">32</span>)                                    <span class="hljs-comment"># FIXED</span></span><br><span class="line"><span class="hljs-built_in">print</span>(reset_code_bad, reset_token)</span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p><code>random</code> is a Mersenne Twister. It is fine for games and simulations, but its output can be predicted after enough samples, and six digits is only a million choices. <code>secrets</code> uses the operating system's secure generator, and 32 bytes is 256 bits.</p>
<p><strong>The fix.</strong> TLS everywhere (Dev Essentials 07 · HTTPS). Argon2id for passwords (Dev Essentials 11 · Auth). <code>secrets</code> for tokens. Vetted libraries and modes (for example AES-GCM from the <code>cryptography</code> package), never your own cipher. Keys in a secrets manager, not in Git.</p>

<ol>

<h2 id="Cross-site-scripting-XSS"><a href="#Cross-site-scripting-XSS" class="headerlink" title="Cross-site scripting (XSS)"></a>Cross-site scripting (XSS)</h2>
<p>XSS is injection into HTML. If user input reaches the page unescaped, its <code>&lt;script&gt;</code> runs in other users' browsers, with their session.</p>
<pre><code class="language-python"><figure class="highlight python"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br><span class="line">5</span><br><span class="line">6</span><br><span class="line">7</span><br><span class="line">8</span><br><span class="line">9</span><br><span class="line">10</span><br><span class="line">11</span><br><span class="line">12</span><br><span class="line">13</span><br><span class="line">14</span><br><span class="line">15</span><br><span class="line">16</span><br><span class="line">17</span></pre></td><td class="code"><pre><code class="python"><span class="line"><span class="hljs-comment"># a05_xss.py — Cross-site scripting and its fix</span></span><br><span class="line"><span class="hljs-keyword">import</span> html</span><br><span class="line"><span class="hljs-keyword">from</span> fastapi <span class="hljs-keyword">import</span> FastAPI</span><br><span class="line"><span class="hljs-keyword">from</span> fastapi.responses <span class="hljs-keyword">import</span> HTMLResponse</span><br><span class="line"> </span><br><span class="line">app = FastAPI()</span><br><span class="line">CSP = <span class="hljs-string">&quot;default-src &#x27;self&#x27;; <p>Open <code>http://localhost:8000/v1/hello?name=&lt;script&gt;alert(1)&lt;/script&gt;</code> in a browser and the alert pops up. On <code>/v2/hello</code> the same input shows as text, because it arrives as <code>&amp;lt;script&amp;gt;…</code>.</p>
<p>In the browser, the same rule applies to JavaScript:</p>
<pre><code class="language-javascript"><figure class="highlight javascript"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span></pre></td><td class="code"><pre><code class="javascript"><span class="line"><span class="hljs-keyword">const</span> name = <span class="hljs-keyword">new</span> <span class="hljs-title class_">URLSearchParams</span>(location.<span class="hljs-property">search</span>).<span class="hljs-title function_">get</span>(<span class="hljs-string">&quot;name&quot;</span>);</span><br><span class="line"><span class="hljs-variable language_">document</span>.<span class="hljs-title function_">querySelector</span>(<span class="hljs-string">&quot;#greet&quot;</span>).<span class="hljs-property">innerHTML</span> = <span class="hljs-string">`Hello <span class="hljs-subst">${name}</span>`</span>;   <span class="hljs-comment">// VULNERABLE</span></span><br><span class="line"><span class="hljs-variable language_">document</span>.<span class="hljs-title function_">querySelector</span>(<span class="hljs-string">&quot;#greet&quot;</span>).<span class="hljs-property">textContent</span> = <span class="hljs-string">`Hello <span class="hljs-subst">${name}</span>`</span>; <span class="hljs-comment">// FIXED: always text</span></span><br><span class="line"> </span></code></pre></td></tr></table></figure></code></pre>
<p><strong>The fix.</strong> Escape output for its context (HTML body, attribute, URL, JavaScript). Template engines such as Jinja2 do this when autoescaping is on, and React does it unless you use <code>dangerouslySetInnerHTML</code>. Then add a <strong>Content Security Policy</strong> as a second wall: without <code>'unsafe-inline'</code>, the browser refuses inline scripts even if one slips through. The OWASP CSP Cheat Sheet is clear that CSP &quot;should not be relied upon as the only defensive mechanism against XSS&quot;.</p>
<blockquote>
<p><strong>Common pitfall:</strong> &quot;sanitising&quot; input on the way in with a home-made regex. Escape on the way <strong>out</strong>, in the right context. If you truly must accept user HTML, use a maintained sanitizer library.</p>
</blockquote>

<h1 id="Chapter-8-—-A07-Authentication-Failures"><a href="#Chapter-8-—-A07-Authentication-Failures" class="headerlink" title="Chapter 8 — A07 Authentication Failures"></a>Chapter 8 — A07 Authentication Failures</h1>
<p><strong>What it is.</strong> Weak login and session handling: no rate limit (credential stuffing works), weak or breached passwords allowed, messages that reveal which usernames exist, session IDs that survive logout or are not renewed at login, no MFA for sensitive accounts. A typical vulnerable login returns &quot;No such user&quot; for one case and &quot;Wrong password&quot; for the other, compares plain-text passwords with <code>==</code>, and lets a script retry forever.</p>
<p><strong>The fix.</strong> Everything in Dev Essentials 11 · Auth: Argon2id hashes, one generic error message, rate limits, NIST SP 800-63B-4 password rules, MFA or passkeys, and fresh session IDs with safe cookie flags. That post ends with a complete FastAPI login you can reuse.</p>
<hr>
<h1 id="Chapter-9-—-A08-Software-or-Data-Integrity-Failures"><a href="#Chapter-9-—-A08-Software-or-Data-Integrity-Failures" class="headerlink" title="Chapter 9 — A08 Software or Data Integrity Failures"></a>Chapter 9 — A08 Software or Data Integrity Failures</h1>
<p><strong>What it is.</strong> The app trusts code or data without checking it was not changed: auto-updates without signatures, CI pipelines anyone can edit, scripts from a CDN without integrity checks, and <strong>insecure deserialization</strong> — turning attacker-controlled bytes back into live objects.</p>
<p>Python's <code>pickle</code> is the classic case. The official docs warn: &quot;The pickle module is not secure. Only unpickle data you trust.&quot; Loading a pickle can run arbitrary code, so <code>pickle.loads(base64.b64decode(request.cookies[&quot;prefs&quot;]))</code> is a remote code execution bug. The fix: store plain data as JSON, and sign it with HMAC so any change is detected.</p>

<h1 id="Chapter-10-—-A09-Security-Logging-Alerting-Failures"><a href="#Chapter-10-—-A09-Security-Logging-Alerting-Failures" class="headerlink" title="Chapter 10 — A09 Security Logging &amp; Alerting Failures"></a>Chapter 10 — A09 Security Logging &amp; Alerting Failures</h1>
<p><strong>What it is.</strong> Attacks happen and nobody notices. Failed logins are not logged, logs have no user or IP, nobody gets alerted, or the logs themselves leak passwords and can be forged.</p>

<p>The bad version writes the password to the log and lets a newline in the username fake a second log line. The good version writes one JSON object per line (JSON escapes the newline), never logs secrets, and raises an alert after 10 failures from one IP in 5 minutes.</p>
<p><strong>The fix.</strong> Log security events (logins, access denials, admin actions) with who, what, when and where. Never log passwords, tokens or full card numbers. Ship logs to a central, append-only store. Most important for 2025: turn logs into <strong>alerts</strong> that a person actually receives, with a playbook for what to do.</p>

<p><strong>What it is.</strong> New in 2025. The app does not plan for errors: it <strong>fails open</strong> (grants access when a check crashes), leaks stack traces, or leaves half-finished work behind. <p><code>curl -X DELETE localhost:8000/files/7</code> returns <code>403</code> while the permission service is down. Any unhandled error in any route now returns only <code>{&quot;error&quot;:&quot;internal error&quot;,&quot;id&quot;:&quot;…&quot;}</code>; the stack trace goes to the log, not to the user.</p>
<p><strong>The fix.</strong> Decide the safe outcome for every failure <em>before</em> it happens: deny, roll back the whole transaction, stop the job. Catch errors where you can handle them, have one global handler for the rest, and set limits and timeouts so resources cannot run out.</p>

<h2 id="Exercise-3-—-Stored-XSS-in-a-comment-box"><a href="#Exercise-3-—-Stored-XSS-in-a-comment-box" class="headerlink" title="Exercise 3 — Stored XSS in a comment box"></a>Exercise 3 — Stored XSS in a comment box</h2>
<p>Comments are saved to a database and shown to everyone. The frontend does <code>div.innerHTML = comment.text</code>. Give two fixes, one of them a response header.</p>
<details>
<summary>Solution</summary>
<ol>
<li>Render as text: <code>div.textContent = comment.text</code> (or escape on the server with <code>html.escape</code>).</li>
<li>Send a Content Security Policy such as <code>default-src 'self'; object-src 'none'; base-uri 'none'</code>, which blocks inline scripts if escaping is ever missed.</li>
</ol>
</details>
<h2 id="Exercise-4-—-Fail-open-or-closed"><a href="#Exercise-4-—-Fail-open-or-closed" class="headerlink" title="Exercise 4 — Fail open or closed?"></a>Exercise 4 — Fail open or closed?</h2>
<p>A feature flag service times out. Code: <code>enabled = flags.get(&quot;new_admin_panel&quot;, default=True)</code>. What is wrong?</p>
<details>
<summary>Solution</summary>
<p>The default grants access when the service fails. That is failing open (A10). For anything that widens access, the default must be the safe choice: <code>default=False</code>. Also log the failure so someone notices the outage (A09).</p>
</details>
<h2 id="Exercise-5-—-Supply-chain-check"><a href="#Exercise-5-—-Supply-chain-check" class="headerlink" title="Exercise 5 — Supply chain check"></a>Exercise 5 — Supply chain check</h2>
<p>List three things to add to a Python project's CI so that A03 problems are caught before release.</p>
<details>
<summary>Solution</summary>
<p>Install with <code>pip install --require-hashes -r requirements.txt</code> from a locked, hashed file. Run <code>pip-audit -r requirements.txt</code> and fail the build on known vulnerabilities. Pin CI actions and base images to exact versions or digests, and produce an SBOM for each release.</p>
</details>
