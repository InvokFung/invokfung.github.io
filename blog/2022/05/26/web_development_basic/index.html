Web Development (Basic) — HTML, CSS, JavaScript, jQuery

Created2022-05-26|Updated2026-05-21|Programming
|Post View:

The foundation of every website on the open web is three languages: HTML for structure, CSS for presentation, and JavaScript for behaviour. Modern frameworks (React, Vue, Svelte) all compile down to those three. This post covers the basics that the advanced post and any future framework work assume — semantic HTML, the modern CSS layout systems (Flexbox + Grid), responsive design, vanilla JS DOM manipulation, jQuery (still found in older codebases), forms, and the accessibility minimum.

Learning Outcome

  • Write semantic, valid HTML5.
  • Lay out pages with Flexbox and CSS Grid.
  • Make a site responsive with media queries.
  • Manipulate the DOM with vanilla JavaScript and jQuery.
  • Build accessible forms and handle their submission.
  • Set up a minimal local development environment.

Chapter 1 — How the web works (one paragraph)

A browser sends an HTTP(S) request to a server; the server replies with an HTML document; the browser parses it, loads any linked CSS + JS + images, builds the DOM (the in-memory tree of elements) and CSSOM (the matched style tree), and renders pixels. JavaScript can later mutate the DOM and styles, triggering re-renders. Every "fancy" feature ultimately reduces to those moves.

Terminology

  • HTML — HyperText Markup Language; the structural language of web pages.
  • CSS — Cascading Style Sheets; selectors + property declarations that style HTML.
  • DOM — Document Object Model; the tree of nodes that the browser builds from HTML.
  • JavaScript (ES) / ECMAScript — the language that runs in the browser and (via Node.js) on servers.
  • Viewport — the visible area of the browser window.
  • Selector — a CSS pattern that targets HTML elements.

Chapter 2 — HTML essentials

Minimal HTML5 document

Always:

  • <!doctype html> — first line.
  • lang="en" (or the right language) — accessibility + SEO.
  • <meta charset="utf-8"> — avoid mojibake.
  • <meta name="viewport" ...> — required for mobile responsiveness.
  • defer on <script> — runs after HTML parsed; almost always correct.

Semantic elements

Use the right element for the meaning, not just <div> everywhere:

Element Use
<header> top of a page or section
<nav> main navigation links
<main> unique page content (only one per page)
<section> thematic grouping
<article> self-contained piece (blog post, comment)
<aside> sidebar, callout
<footer> bottom of a page or section
<figure> + <figcaption> image with caption
<button> clickable action
<a href="..."> navigation

Semantics matter for accessibility (screen readers), SEO, and code readability. <button> is keyboard-accessible by default; a <div onclick="..."> is not.

Common elements quick-reference

Trick: the alt attribute on <img> is not optional. Use a meaningful description; or alt="" if purely decorative. Empty alt tells screen readers to skip it.

Chapter 3 — CSS basics

Linking

Selectors

The cascade

When multiple rules match, the winner is decided by:

  1. Origin + importance — !important user styles → !important author styles → author styles → user → browser default.
  2. Specificity — inline (1000) → id (100) → class/attr/pseudo (10) → element (1).
  3. Source order — later wins on ties.

Avoid !important in normal code; it almost always means the cascade was lost. Refactor instead.

Box model

Every element has: content → padding → border → margin.

Set this globally in every project.

Useful units

Unit Meaning
px absolute pixels
rem multiple of the root font size (1rem = 16px by default)
em multiple of the parent's font size
% percentage of the parent
vw / vh percent of viewport width / height
clamp(min, val, max) bounded fluid value

rem for font sizes; px for tight UI details; % / vw for fluid layouts.

Chapter 4 — Flexbox

Flexbox is the right layout choice for one-dimensional arrangements (row or column).

Key parent properties:

Property Effect
flex-direction row / column / row-reverse / column-reverse
gap space between children
justify-content main-axis: start / end / center / space-between / space-around / space-evenly
align-items cross-axis alignment
flex-wrap nowrap (default) or wrap

Key child properties:

Property Effect
flex-grow grow ratio when extra space
flex-shrink shrink ratio when not enough
flex-basis preferred size before growing/shrinking
flex: 1 shorthand for 1 1 0 — equal share
align-self override align-items for one child

Chapter 6 — Responsive design

The mobile-first pattern: write base styles for small screens, add complexity at larger breakpoints with @media.

Standard breakpoints (rough): 480 (large phone), 768 (tablet), 1024 (laptop), 1280+ (desktop).

Use container queries (@container) in modern browsers when component layout should depend on the container's width, not the viewport's.

Chapter 8 — jQuery (still found in older codebases)

jQuery dominated 2008-2018. Modern browsers shrank its job — but you'll still see it in legacy code, WordPress themes, and many enterprise apps.

Vanilla-JS equivalents:

jQuery Modern JS
$('.x') document.querySelectorAll('.x')
$.ajax / $.get / $.post fetch(url, options)
$(el).addClass('y') el.classList.add('y')
$(el).on('click', fn) el.addEventListener('click', fn)
$(el).fadeIn() CSS transitions on opacity

Trick: for new projects, skip jQuery. The vanilla DOM API is good enough since ~2017. For legacy projects, keep jQuery — re-platforming costs more than the bytes.

Chapter 10 — Accessibility minimum

Rule Why
Use semantic HTML screen readers + keyboard get correct affordances for free
<label for="id"> on every form input inputs need labels
Sufficient colour contrast (WCAG AA: 4.5:1 for text) low-vision users
:focus styles visible keyboard users must see where they are
alt on every image screen readers; SEO
Heading hierarchy (one h1, then h2, h3...) document outline
lang on <html> pronunciation, translation
Use aria-* sparingly — only when no semantic HTML fits "no ARIA is better than bad ARIA"
Test with keyboard only (Tab, Shift+Tab, Enter) the cheapest accessibility test

Run axe DevTools or Lighthouse for automated checks.

Open DevTools (F12 / Cmd+Opt+I) often:

  • Elements — inspect + edit live HTML/CSS.
  • Console — JS REPL, log output.
  • Network — every request, headers, timings.
  • Application — cookies, localStorage, service workers.

Practice Exercises

Exercise 1 — Personal page

Build a one-page personal site: header, hero, about, projects (cards), contact form. Use semantic HTML + a Grid skeleton + Flexbox inside components. Responsive at 480/768/1024.

Exercise 2 — Todo list (vanilla JS)

Static HTML; on form submit, append a new <li> with the entered text + a delete button. Persist to localStorage across reloads.

Exercise 3 — Fetch + render

Call https://jsonplaceholder.typicode.com/users with fetch; render each user as a card with name, email, city.

Exercise 4 — Responsive gallery

A grid of 12 images. At < 600px → 1 column. 600-900 → 2 cols. > 900 → 3 cols. Use Grid + minmax(...).

Exercise 5 — Form validation

A signup form (name, email, age, password). Use HTML5 attributes for native validation. Add a JS-side check that the password is ≥ 8 chars and contains a digit. Show errors below each input without losing focus.
