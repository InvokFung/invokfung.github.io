Java Development [Basic] Part 1 — Language, OOP, Exceptions, I/O, Threads

Created2022-05-26|Updated2026-05-21|Programming
|Post View:

Java is a statically-typed, class-based, compiled-to-bytecode language that runs on the Java Virtual Machine (JVM). It powers Android, large enterprise backends (Spring), big-data tools (Hadoop, Kafka), and most banking infrastructure. Part 1 of this two-part series covers the language core: from "hello world" through OOP, generics, exceptions, file I/O, and the basics of multithreading. Part 2 picks up with GUI, events, functional programming, collections, and the Stream API.

Learning Outcome

  • Compile and run Java programs with javac + java (and via an IDE).
  • Use primitives, wrappers, control flow, arrays, and strings idiomatically.
  • Define classes with constructors, fields, methods, access modifiers, and static.
  • Use inheritance, polymorphism, abstract classes, and interfaces.
  • Apply solid OOD principles (SOLID, encapsulation, composition over inheritance).
  • Write and use generic classes + methods.
  • Handle errors with try / catch / finally / throws and custom exceptions.
  • Use assert for development-time invariants.
  • Read and write files using the modern java.nio.file API.
  • Run code on multiple threads and recognise the standard concurrency utilities.

Chapter 1 — Introduction

Terminology

  • JDK — Java Development Kit: compiler + standard library + tools.
  • JRE — Java Runtime Environment: enough to run compiled code (rarely separated from JDK anymore).
  • JVM — Java Virtual Machine: executes bytecode.
  • Bytecode — the .class file format produced by javac.
  • Class — the template for objects.
  • Object — an instance of a class.
  • Package — a namespace; maps to a directory.
  • Main method — the JVM entry point: public static void main(String[] args).

Chapter 2 — Objects and Classes

Terminology

  • Field — class-level variable (state).
  • Method — class-level function (behaviour).
  • Constructor — special method called when new creates an instance.
  • this — reference to the current instance inside a method.
  • static — belongs to the class, not an instance.
  • Access modifiers — public, protected, package-private (default), private.
  • Record (Java 16+) — concise immutable data carrier.

Chapter 3 — Inheritance & Polymorphism

Terminology

  • extends — declares a subclass.
  • super — refers to the parent.
  • Override — replace a parent's method in a subclass.
  • Polymorphism — call a parent-typed reference, dispatch to the actual subclass.
  • final — prevents inheritance (on class) or overriding (on method).

Example

Always use @Override — the compiler verifies you really did override (catches typos).

Chapter 4 — Abstract Class, OOD Principles

Terminology

  • Abstract class — declared with abstract; cannot be instantiated; may contain abstract methods.
  • Interface — pure contract; can have default and static methods (Java 8+) and private helpers (Java 9+).
  • SOLID — five design principles (Single-responsibility, Open/closed, Liskov substitution, Interface segregation, Dependency inversion).

Abstract class

Interface

A class can extends only one class but implements many interfaces — the standard answer to "multiple inheritance" in Java.

OOD quick-reference (SOLID)

Principle Plain English
Single responsibility each class has one reason to change
Open / closed open for extension, closed for modification
Liskov substitution subtypes must work wherever the supertype works
Interface segregation many small interfaces beat one fat one
Dependency inversion depend on abstractions, not concretes

Also fundamental: composition over inheritance (prefer containing collaborators to subclassing them).

Chapter 6 — Exception handling

Terminology

  • Throwable — root.
  • Error — JVM-level (OutOfMemoryError); usually don't catch.
  • Exception — recoverable; subclasses include the checked family (must be declared/handled) and RuntimeException (unchecked).
  • Checked exceptions — IOException, SQLException, InterruptedException, etc.
  • Unchecked — NullPointerException, IllegalArgumentException, IllegalStateException, etc.

try / catch / finally

try-with-resources (auto-close)

Implementing AutoCloseable lets your own classes participate.

Custom exceptions

Trick: prefer unchecked exceptions for programming errors (bug-style: bad arg, missing key). Reserve checked exceptions for genuinely recoverable I/O. Modern Java style leans towards fewer checked exceptions.

Chapter 7 — Assertion

assert checks a development-time invariant. Disabled by default in production unless run with -ea (enable assertions).

Rules:

  • Never use assert for argument validation in public APIs — use if + throw new IllegalArgumentException(...).
  • Use assert for invariants that should never be false if the code is correct.
  • Assertions are stripped at runtime by default — don't put side effects inside.

Chapter 9 — Multithreading

Terminology

  • Thread — a unit of execution scheduled by the OS.
  • Runnable — functional interface for a unit of work.
  • Thread-safe — correct when accessed from multiple threads simultaneously.
  • Race condition — outcome depends on thread interleaving.
  • synchronized — mutual-exclusion keyword.
  • volatile — guarantees visibility of writes across threads.
  • Virtual thread (Java 21+) — lightweight, JVM-scheduled; millions can run concurrently.

Threads the modern way

Virtual threads were the headline Java 21 feature. They make blocking I/O efficient at scale without rewriting code as async.

Synchronisation

Or with explicit locks for finer control:

java.util.concurrent essentials

Type Use
AtomicInteger, AtomicLong, AtomicReference<T> lock-free counters / refs
ConcurrentHashMap thread-safe map
BlockingQueue<T> producer-consumer
CountDownLatch, CyclicBarrier, Semaphore coordination primitives
CompletableFuture<T> async pipelines
ExecutorService thread pool
ScheduledExecutorService periodic / delayed tasks

Trick: for most server workloads in 2026, Executors.newVirtualThreadPerTaskExecutor() + plain blocking code is the right answer. Reach for CompletableFuture only when you really need composition of async pipelines.

Practice Exercises

Exercise 1 — Class basics

Build a BankAccount class with deposit, withdraw (reject if overdraw), balance(). Override toString(). Add a transferTo(BankAccount other, double amount) method.

Exercise 2 — Inheritance

Define Shape (abstract double area()), Circle, Rectangle, Triangle. Put them in an array; print the total area.

Exercise 3 — Generics

Implement Stack<T> with push, pop, peek, isEmpty, size. Use an underlying ArrayList<T>.

Exercise 4 — Exception flow

Read a file path from args[0]; print its content. Catch NoSuchFileException and IOException separately, exit with different exit codes (2 and 3 respectively).

Exercise 5 — Concurrency

Spawn 1000 virtual threads, each downloading https://httpbin.org/uuid. Collect the responses into a List<String> (thread-safe!) and print the count of unique values.
