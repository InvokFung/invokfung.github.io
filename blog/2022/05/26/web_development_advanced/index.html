Web Development (Advanced) — Node.js, React, Vue, Build Tools, UI Frameworks

Created2022-05-26|Updated2026-05-21|Programming
|Post View:

The basic post covered HTML, CSS, vanilla JS, jQuery. Modern web development sits on top of that base: Node.js as a JS runtime everywhere, package managers to wire dependencies, bundlers (Vite, esbuild, webpack) to produce production assets, component frameworks (React, Vue, Svelte) to manage state + UI, CSS frameworks (Tailwind, Bootstrap) to keep styles consistent, icon sets (Font Awesome, Lucide) for visuals, and a deployment story for shipping the result. This post is a survey of the stack and the trade-offs. (3D / WebGL / Three.js has its own dedicated series — see the link at the end.)

Learning Outcome

  • Install and use Node.js + npm / pnpm / yarn.
  • Initialise a project with Vite, understand the dev server + build output.
  • Read and write a React or Vue component with state, props, events.
  • Pick between React, Vue, Svelte for a new project.
  • Use a CSS framework (Tailwind / Bootstrap) effectively.
  • Add icons with Font Awesome or Lucide.
  • Call REST / GraphQL APIs from the browser.
  • Deploy a static site (Vercel / Netlify / Cloudflare Pages / S3+CloudFront).

Chapter 1 — Node.js as a JS runtime

Node.js is V8 (Chrome's JS engine) outside the browser. It powers:

  • Build tools (Vite, webpack, esbuild, Rollup).
  • Local dev servers.
  • The package manager (npm).
  • Many backend frameworks (Express, Fastify, NestJS, Next.js API routes).
  • Build pipelines in CI.

Chapter 3 — Build tools (Vite + ESM)

Old days: webpack + Babel + a 200-line config; cold start 30 sec, HMR 2-5 sec. Modern: Vite uses native ES modules in dev (zero bundling) and esbuild / Rollup for production builds. Cold start < 500 ms, HMR < 100 ms.

Templates: vanilla, vanilla-ts, react, react-ts, vue, vue-ts, svelte, svelte-ts, solid, lit, preact, qwik. TypeScript is the default in modern teams.

Why ESM matters

The browser fetches each import-ed module separately. Dev servers serve them un-bundled — only re-process the file you changed. Production builds still bundle (fewer requests, tree-shaking).

Chapter 4 — React vs Vue vs Svelte

The three live framework families. Brief comparison:

React Vue Svelte
Released 2013 2014 2016
Maintainer Meta core team core team
Component file .jsx / .tsx .vue (HTML+JS+CSS in one) .svelte
State hooks (useState, useReducer) reactivity (ref, reactive) language-level (let x = 0)
Templating JSX (JS-like) HTML template + directives HTML + minimal directives
Bundle size baseline ~45 KB gzipped ~30 KB ~5 KB (compiles away)
Job market dominant strong, especially APAC growing
Best for huge ecosystem, hiring balance of approachability + power smallest output, first-time learners

There is no universally best. React if hiring + ecosystem matters most. Vue for a balanced learning curve. Svelte for performance + simplicity at small-to-medium scale.

Chapter 5 — React essentials

Rules of thumb:

  • JSX — HTML-like syntax that compiles to React.createElement(...).
  • useState for local state.
  • useEffect for side effects (data fetching, subscriptions).
  • Props are read-only inputs from parent.
  • Always give array children a stable key prop.
  • Component names are PascalCase.

Fetching data

For real apps, use TanStack Query (@tanstack/react-query) or SWR instead of hand-rolling effects.

Routing

React itself does not include routing. Add React Router (react-router-dom) for SPA routes, or use Next.js / Remix for a more opinionated framework with file-based routing + server rendering.

Chapter 6 — Vue essentials (composition API)

Single-file components bundle template + logic + styles. ref wraps a value; access with .value in JS, unwrapped automatically in templates.

Routing: vue-router. State: pinia. Full-stack framework: Nuxt.

Chapter 7 — CSS frameworks

Approach Example When
Utility classes Tailwind, UnoCSS rapid prototyping, design systems, modern teams
Component CSS Bootstrap, Bulma quick admin/dashboard, less custom design
CSS-in-JS styled-components, Emotion React apps with dynamic styling
CSS Modules (built into Vite) scoped styles per component, no framework
Hand-written nothing full control, small projects, design-led

Tailwind (the modern default)

Install:

Configure content: ["./index.html", "./src/**/*.{js,jsx,ts,tsx,vue}"] in tailwind.config.js and include @tailwind base; @tailwind components; @tailwind utilities; in your CSS entry.

Bootstrap (still widely used)

Heavier visual opinion, faster to assemble admin dashboards. Pair with the JS plugins (modals, dropdowns, tooltips).

Trick: mixing Tailwind + Bootstrap in the same project usually fights — both impose layout opinions. Pick one. For new projects, Tailwind almost always wins; for legacy + content-heavy, Bootstrap can still shine.

Data-fetching libraries (the time-saver)

Hand-rolling fetch + loading + error state in every component is repetitive. Use:

  • TanStack Query (@tanstack/react-query, @tanstack/vue-query)
  • SWR (React)
  • Pinia Colada (Vue)

They handle caching, deduplication, retries, background refresh, pagination, and devtools. Standard in modern apps.

Chapter 10 — TypeScript (briefly)

JavaScript with optional static types. Catches whole classes of bugs at compile time + improves IDE autocomplete.

Vite templates ship with TS preconfigured. Use TS for any project bigger than a one-page demo — the productivity payoff comes quickly.

Chapter 12 — Performance baseline

Hit these targets in Lighthouse for a polished site:

Metric Target
LCP (Largest Contentful Paint) < 2.5 s
INP (Interaction to Next Paint) < 200 ms
CLS (Cumulative Layout Shift) < 0.1
First-load JS (uncompressed) < 200 KB
Image format AVIF / WebP, not PNG/JPG raw
Fonts font-display: swap, subset, self-host

Tools: Lighthouse (in DevTools), PageSpeed Insights, WebPageTest.

Common wins:

  1. Lazy-load below-the-fold images (loading="lazy").
  2. Code-split routes (React.lazy, dynamic import()).
  3. Compress images (use a build-time tool — @astrojs/image, sharp).
  4. Preload the hero font.
  5. Remove unused JS (the bundle analyzer flags it).

Practice Exercises

Exercise 1 — Vite + React/Vue starter

npm create vite@latest. Build a single-page counter app. Push to GitHub. Deploy to Vercel.

Exercise 2 — TanStack Query

Fetch https://jsonplaceholder.typicode.com/users with TanStack Query. Render the list with loading + error states. Add a refresh button.

Exercise 3 — Tailwind UI

Build a 3-card pricing layout with Tailwind. Responsive: stacked on mobile, 3 columns on desktop. Use Lucide icons in the feature lists.

Exercise 4 — Full mini-app

A note-taking app: list + create + delete + edit. State via React Context or Pinia. Data fetched via TanStack Query against a mock JSON server (json-server). TypeScript. Tailwind. Deploy to Vercel.
