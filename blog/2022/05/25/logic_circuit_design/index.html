Logic Circuit Design

Created2022-05-25|Updated2026-06-07|Circuit Design
|Post View:

Every processor, memory controller, radio baseband and washing-machine timer is built from the same small vocabulary: a handful of logic gates, a clock, and a discipline for reasoning about them. Digital design is the bridge between "a transistor is an analogue switch" and "this chip runs an operating system". This post walks that whole bridge in one pass — number representations, Boolean algebra, gates and their CMOS reality, combinational minimisation, the standard blocks, sequential logic and timing, finite state machines, memory and programmable logic, and finally how all of it is actually written today in a hardware description language.

Learning Outcome

  • Convert between number bases, and explain why two's complement beat its rivals.
  • Manipulate Boolean expressions with the axioms, De Morgan's laws and duality; build any gate from NAND alone.
  • Explain what a CMOS gate physically is, and reason about fan-out, propagation delay and power.
  • Minimise combinational logic with Karnaugh maps (2–4 variables, don't-cares included), fix hazards, and know when to reach for Quine–McCluskey.
  • Assemble adders, comparators, multiplexers, decoders and encoders into an ALU.
  • Distinguish latches from flip-flops, compute a design's maximum clock frequency, and design an FSM end to end in both Moore and Mealy form.
  • Describe SRAM, DRAM, ROM, PLA/PAL and FPGA architecture, then write synthesisable Verilog — FSM and testbench included — and simulate it with free tools.

Chapter 1 — Number systems and codes

Terminology

  • Radix (base) — how many distinct digits a positional system uses.
  • MSB / LSB — most / least significant bit: the leftmost and rightmost bit of a word.
  • Word — a fixed-width group of bits handled as a unit (8, 16, 32, 64 bits).
  • Code — an assignment of bit patterns to things that are not plain numbers (BCD, Gray, ASCII).

Conversion. Binary ↔ octal and binary ↔ hexadecimal are trivial because 8 = 2³ and 16 = 2⁴: group bits in threes or fours from the LSB.

Decimal → binary is repeated division by 2 for the integer part (read remainders bottom-up: 45 → 101101) and repeated multiplication by 2 for the fraction, reading the carries top-down: 0.625 → 1, 0.25 → 0, 0.5 → 1 gives 0.101.

Trick: memorise the sixteen hex digits and the powers of two to 2¹⁶. Nearly all "mental arithmetic" in digital design is pattern recognition on those two tables.

Signed representations

Scheme (8-bit) −5 encoded Range Zeros Addition hardware
Sign-magnitude 1000 0101 −127 … +127 two separate compare + subtract path
One's complement 1111 1010 −127 … +127 two adder plus end-around carry
Two's complement 1111 1011 −128 … +127 one ordinary unsigned adder, unchanged

Two's complement won for one reason: the same adder serves signed and unsigned operands — no correction step, no end-around carry, no second zero. Negation is "invert all bits, add one", and the MSB simply carries weight −2^(n−1) instead of +2^(n−1):

Two consequences: sign extension is replication of the MSB, and subtraction is A + (~B) + 1 — one adder, an inverter row, a forced carry-in.

Overflow

Overflow is not the carry-out. For two's-complement addition it occurs iff the carry into the MSB differs from the carry out of the MSB — equivalently, iff both operands share a sign and the result has the opposite one.

The same bit pattern is a valid unsigned answer, so hardware raises both C and V and lets the instruction set decide which matters.

Fixed point, floating point, and codes

Fixed point declares an implied binary point at a fixed position — a 16-bit Q8.8 value stores the real number times 2⁸ — so arithmetic is ordinary integer arithmetic plus a shift after multiplication: cheap, exact, the default in DSP and control loops. Floating point (IEEE 754 binary32: 1 sign bit, 8 exponent bits biased by 127, 23 stored fraction bits plus an implied leading 1) trades a wider dynamic range for variable absolute precision and considerably more silicon. Use fixed point when the signal range is known, floating point when it is not.

BCD stores each decimal digit in its own 4-bit field (59 → 0101 1001), leaving 1010–1111 unused, because displays, financial arithmetic and legacy instrumentation want exact decimal digits. Its addition needs a correction — if a digit sum exceeds 9, add 6:

Gray code orders values so consecutive ones differ in exactly one bit — 000 001 011 010 110 111 101 100 for three bits — and converts in one line each way: G = B ^ (B >> 1), and back, b[n-1] = g[n-1], b[i] = b[i+1] ^ g[i]. It has three genuine uses: absolute position encoders (a disc read mid-transition is off by at most one, instead of returning garbage as 0111 → 1000 would); Karnaugh map row/column ordering, which is exactly why adjacent cells differ in one variable; and clock domain crossing, where an asynchronous FIFO's Gray-coded pointers sample as either the old or the new value, never a nonsense mixture.

Text is just another code: ASCII is 7-bit (128 code points, 'A' = 0x41, 'a' = 0x61), and UTF-8 encodes Unicode in 1–4 bytes whose single-byte forms are exactly ASCII — which is why ASCII-era hardware and protocols survived the transition.

Chapter 2 — Boolean algebra

Terminology

  • Literal — a variable or its complement (A, A').
  • Product term — a conjunction (AB'C). Sum term — a disjunction (A + B' + C).
  • Dual — swap AND ↔ OR and 0 ↔ 1 throughout, leaving literals alone.

Notation: + is OR, juxtaposition or · is AND, ' is NOT, ^ is XOR.

Commutative A + B = B + A AB = BA
Associative A + (B + C) = (A + B) + C A(BC) = (AB)C
Distributive A + BC = (A + B)(A + C) A(B + C) = AB + AC
Absorption A + AB = A A(A + B) = A
Absorption (2nd) A + A'B = A + B A(A' + B) = AB
De Morgan (A + B)' = A'B' (AB)' = A' + B'
Consensus AB + A'C + BC = AB + A'C (A+B)(A'+C)(B+C) = (A+B)(A'+C)

A + BC = (A + B)(A + C) is the one that catches people: it has no arithmetic analogue. Verify it once from the truth table, then trust it.

Duality: the dual of any Boolean identity is also an identity — which is why every law above has two columns, and why SOP and POS minimisation are the same procedure applied to opposite cells of a K-map.

Watch out: the dual of an expression is not its complement. (A + B) has dual AB and complement A'B'. De Morgan is duality plus complementing the literals.

Chapter 3 — Logic gates

Terminology

  • Fan-in / fan-out — inputs a gate has / gate inputs one output drives.
  • Propagation delay (t_pd) — worst-case time from an input change to the resulting output change.
  • Contamination delay (t_cd) — time before which the output is guaranteed not to have started moving.
  • Functionally complete set — a set of gates from which every Boolean function can be built.

XOR is "the inputs differ", XNOR "the inputs are equal" — making XNOR the natural 1-bit equality comparator. Beyond two inputs XOR generalises to odd parity, which is why parity generators are XOR trees.

NAND and NOR are functionally complete

Tie both inputs of a NAND together and you have an inverter; everything else follows:

Check the XOR on A=1, B=1: X = 0, A NAND X = 1, B NAND X = 1, 1 NAND 1 = 0. Correct. The NOR duals are just as short: NOT A = A NOR A, A + B = (A NOR B) NOR (A NOR B), A·B = (A NOR A) NOR (B NOR B). This matters commercially — a process only has to characterise one gate cell to build anything.

What a CMOS gate actually is

A static CMOS gate is two complementary transistor networks between the supply rails with the output node between them. The pull-up network is PMOS to VDD (a PMOS conducts when its gate is low); the pull-down network is NMOS to GND (conducts when its gate is high). The two are duals — series in one is parallel in the other — so for any input combination exactly one conducts, the output is always driven, and statically no current flows rail to rail. A NAND2 is two series NMOS below, two parallel PMOS above; a NOR2 is the mirror image. Three consequences:

  1. CMOS gates are naturally inverting. NAND2 and NOR2 cost 4 transistors; AND2 and OR2 cost 6, being the inverting gate plus an inverter. Synthesis tools therefore prefer NAND/NOR/inverter forms — a "cheap" AND-OR schematic is not cheap silicon.
  2. NAND is faster than NOR at equal drive. NOR stacks PMOS in series, and holes have lower mobility than electrons, so that stack must be made wide — costing area and input capacitance. Standard-cell libraries are NAND-heavy for this reason.
  3. A gate input is a capacitor, not a resistor. It draws essentially no DC current.

Fan-out, delay and power

Because inputs are capacitive, CMOS has no hard DC fan-out limit the way bipolar TTL did (where fan-out was a real current budget of order 10–20 unit loads). What fan-out costs in CMOS is time: each load adds capacitance, and delay rises roughly linearly with the load being charged and discharged. Processes are commonly characterised by the FO4 delay — an inverter driving four copies of itself — precisely because it is a load-normalised yardstick. Delay is also asymmetric: t_pLH and t_pHL need not be equal, and datasheets quote both across process, voltage and temperature corners. Design to the maximum; use the contamination delay only for hold checks.

α is the activity factor — the fraction of cycles in which a node toggles. Three levers fall straight out: lower VDD (quadratic, hence dynamic voltage scaling), lower f, or lower α by clock-gating idle blocks. Static leakage was negligible in older processes and is a first-class problem in modern ones, which is why power gating exists.

Chapter 4 — Combinational design and minimisation

Terminology

  • Combinational circuit — output depends only on present inputs. No memory, no feedback.
  • Minterm (m_i) / maxterm (M_i) — a product term true for exactly one input row / a sum term false for exactly one row.
  • Implicant — a product term that implies the function. Prime implicant (PI) — one that cannot be enlarged further. Essential PI — the only PI covering some minterm.

Canonical forms

Take F(A,B,C) true for rows 1, 3, 5, 7:

The index sets are complements: whatever is not a minterm of F is a maxterm of F. For row i, the minterm takes each variable uncomplemented where its bit is 1; the maxterm does the exact opposite. Both forms implement directly — SOP as two-level AND-OR, POS as OR-AND — and both are usually far from minimal (Σm(1,3,5,7) is just C).

Karnaugh maps

A K-map redraws the truth table so that physically adjacent cells differ in exactly one variable — hence the Gray-code label order 00 01 11 10. Adjacent 1-cells then merge: a group of 2^k cells eliminates k variables. Groups must be rectangles of size 1, 2, 4, 8 …; they may wrap around both edges (the map is a torus); they may overlap; make each as large as possible and keep going until every 1 is covered.

Worked example 1 — three variables, F(A,B,C) = Σm(0,2,4,5,6)

The whole 00 and 10 columns (m0, m2, m4, m6) form a group of four, all with C = 0, eliminating A and B: term C'. Cells m4 and m5 (bottom row, columns 00 and 01) have A = 1, B = 0: term AB'. So F = C' + AB'. Both are prime and both essential — C' alone covers m0, m2, m6, and AB' alone covers m5.

Worked example 2 — four variables, F(A,B,C,D) = Σm(0,2,5,7,8,10,13,15)

The four corners m0, m2, m8, m10 are adjacent — the map wraps both ways — and all have B = 0, D = 0: term B'D'. The centre block m5, m7, m13, m15 all have B = 1, D = 1: term BD. So F = B'D' + BD = (B XNOR D) — sixteen literals in canonical form reduced to one XNOR gate. That is the payoff of the method, and a warning: the right answer here is invisible in the algebra and obvious in the picture.

Don't-care conditions

A don't-care (d) marks an input combination that cannot occur or whose output nobody reads. Treat each independently as 0 or 1 — whichever enlarges a group. Take "the BCD digit is 5 or greater": patterns 10–15 never occur.

The bottom half (rows 11 and 10, eight cells) gives A; m5, m7, m13, m15 (1, 1, d, d) give BD; m6, m7, m14, m15 (1, 1, d, d) give BC. So F = A + BD + BC with the don't-cares, against F = AB'C' + A'BD + A'BC without them — same behaviour on every input that can actually happen, noticeably less hardware.

Trick: don't-cares are free minimisation. Whenever a spec says "unused encoding", "never happens" or "output ignored while valid is low", write d into the truth table rather than picking 0 out of habit.

Essential prime implicants and cyclic maps

Circle every maximal group: those are the prime implicants. Take all essential ones first, then cover what remains as cheaply as possible. Sometimes none is essential — as for F(A,B,C) = Σm(0,1,2,5,6,7):

The PIs are A'B', A'C', B'C, AC, AB, BC' — six, each minterm covered by exactly two. This is a cyclic map with two equally minimal solutions, F = A'B' + AC + BC' and F = A'C' + B'C + AB. Neither is more correct; pick whichever shares terms with the rest of the design.

Quine–McCluskey

K-maps stop being drawable past about six variables and stop being reliable past four or five. Quine–McCluskey is the same idea made mechanical so a program can do it: (1) list all minterms and don't-cares as bit patterns, grouped by their number of 1s; (2) compare every term in group k with every term in group k+1, combining any pair that differs in exactly one bit into a term with - in that position, and ticking both parents; (3) repeat until nothing more combines — everything left unticked is a prime implicant; (4) build a prime-implicant chart (PIs as rows, real minterms as columns), select the essential PIs, delete their columns, and solve the remaining covering problem with Petrick's method or a heuristic.

It is exact and exhaustive, and therefore exponential. Real tools (Espresso, and the minimisers inside every synthesis flow) use heuristics — but knowing this shape tells you what your synthesiser is approximating.

Hazards

Minimisation assumes instantaneous gates. A two-level network whose inputs change can produce a brief wrong output — a glitch. A static-1 hazard is an output that should stay 1 dipping momentarily to 0; a static-0 hazard is the mirror image; a dynamic hazard is an output that should change once changing three or more times, which needs multiple reconverging paths of differing delay and so appears in multi-level rather than clean two-level networks.

The classic case is F = AB + A'C. Hold B = C = 1: then F = A + A' = 1 for both values of A, so the output should never move. But when A falls 1→0, AB drops immediately while A'C only rises after the inverter's delay, and for that window the OR sees two zeros. The fix is the consensus term — logically redundant, but it bridges the two groups that previously only touched on the K-map:

BC is 1 whenever B = C = 1 regardless of A, holding the OR high through the changeover, at the cost of one AND gate.

Watch out: a synthesis tool will happily remove a redundant term as an optimisation. If you need the hazard-free form (asynchronous logic, a latch enable, a clock-gating cell), mark it keep/dont_touch.

In fully synchronous design, glitches are usually harmless — they occur right after a clock edge and need only settle before the next setup window. Hazards become critical exactly where the synchronous discipline does not apply: asynchronous circuits, level-sensitive enables, reset trees and clock networks.

Chapter 5 — Standard combinational blocks

Adders

Cout is "at least two of three inputs are 1" — the majority function from Chapter 2 — and S is 3-input odd parity.

Chain n full adders carry-to-carry and you have a ripple-carry adder: small, simple, and with worst-case delay t ≈ (n−1)·t_carry + t_sum, linear in n. At roughly two gate delays per stage a 32-bit ripple adder costs over 60 gate delays, and since the adder normally sits on the critical path it caps the whole design's clock.

Carry-lookahead removes the chain. Per bit, define G_i = A_i·B_i ("generate" — this bit makes a carry regardless of the incoming one) and P_i = A_i ^ B_i ("propagate"). Then C_{i+1} = G_i + P_i·C_i, and expanding the recursion gives every carry as a two-level function of the inputs:

One gate delay for all P and G, two more for the carries — constant time. But fan-in grows with block width, so real designs use 4-bit lookahead blocks and apply the same trick a level up on block-level P and G, giving logarithmic delay overall. Carry-select, carry-skip and parallel-prefix adders (Kogge-Stone, Brent-Kung) are variations on trading area for that logarithm.

Subtraction and comparison

Subtraction needs no new datapath. XOR each B input with a SUB signal and feed SUB into Cin: SUB = 0 gives A + B, SUB = 1 gives A + ~B + 1 = A − B. Flags fall out of the same adder — Z = all sum bits zero, N = sum MSB, C = carry out, V = C_n ^ C_{n−1}. A dedicated comparator is simpler: one bit gives A > B : A·B', A < B : A'·B, A = B : A XNOR B. For n bits, equality is the AND of all bit XNORs; magnitude is resolved by scanning from the MSB down to the first position where the bits differ — which is exactly what the chained >, =, < inputs of a cascadable comparator (the 74x85 family) expose.

Multiplexers, demultiplexers, decoders

A 2:1 MUX is Y = S'·I0 + S·I1; a 4:1 MUX is Y = S1'S0'·I0 + S1'S0·I1 + S1S0'·I2 + S1S0·I3. A demultiplexer routes one input to one of 2^k outputs; a decoder is a demux with its data input tied to 1, so its outputs are precisely the minterms of the select inputs — a 2-to-4 decoder with enable is Y0 = E·A'B', Y1 = E·A'B, Y2 = E·AB', Y3 = E·AB.

Because a 2^n:1 MUX with the variables on its selects outputs the truth-table entry those variables address, any n-variable function is one MUX plus constants. Better still, with n−1 selects the data inputs take 0, 1, x or x' for the remaining variable (Shannon expansion). For F(A,B,C) = Σm(1,2,6,7) on a 4:1 MUX with A, B on the selects:

Encoders, priority encoders, and the ALU

A plain 2^k-to-k encoder outputs the index of the single active input and misbehaves badly if two are active, or none. A priority encoder fixes both — highest-priority active input wins, plus a valid flag:

This is how interrupt controllers pick a winner and how floating-point normalisers find the leading one.

An ALU is all of these blocks in parallel behind a multiplexer: adder/subtractor, AND, OR, XOR and a shifter fed the same A and B, with OpSel driving a MUX that chooses whose answer escapes and Z/N/C/V taken from the adder. Every unit computes every cycle, which is wasteful in power — real ALUs gate the unused ones — but logically that picture is the whole story.

Chapter 6 — Sequential logic

Terminology

  • Sequential circuit — output depends on present inputs and stored state: combinational logic plus feedback through memory elements.
  • Latch — level-sensitive storage, transparent while its enable is asserted.
  • Flip-flop — edge-triggered storage, sampling only at a clock edge.
  • Setup / hold time (t_su, t_h) — how long data must be stable before / after the clock edge.
  • Clock-to-Q (t_cq) — delay from the clock edge to a valid output.
  • Clock skew — difference in clock arrival time between two flip-flops.

Latches and the transparency problem

Cross-couple two NOR gates for an SR latch: S sets Q, R clears it, S = R = 0 holds, and S = R = 1 is forbidden (both outputs go low, and simultaneous release is a race). Add an enable and a data input for a gated D latch: while EN is high Q follows D; when EN falls, Q freezes.

That transparency is the problem. If the output feeds combinational logic that returns to its own input — exactly what a counter or state register does — the new value races round the loop during the enable window and can update the latch again in the same pulse, advancing the state an unpredictable number of times. The fix is to sample at an instant rather than over an interval: a master-slave pair of latches on opposite clock phases is never transparent in both halves at once, so data advances exactly one stage per edge.

Timing: where the clock frequency comes from

For a path leaving flip-flop A, crossing combinational logic and arriving at flip-flop B, data must be stable before B's setup window opens. The second inequality is the one beginners forget:

To go faster you must shorten the longest path — pipeline it, restructure the logic (lookahead instead of ripple), or use faster cells.

Watch out: a hold violation cannot be fixed by slowing the clock — T_clk does not appear in the inequality. The data arrives too early, not too late. Fix it with delay buffers on the data path or by reducing skew. Setup violations are the ones a slower clock cures.

Metastability and synchronisers

A flip-flop whose input changes inside its setup/hold window may go metastable: its output hovers between logic levels for an unbounded time before resolving arbitrarily. This is physics, not a bug to design away, but the probability of still being unresolved after time t_r falls exponentially — MTBF = exp(t_r / τ) / (T0 · f_clk · f_data), where τ and T0 are flip-flop characteristics and f_clk, f_data the sampling and event rates. Because the decay is exponential, buying resolution time is extremely effective — hence the two-flop synchroniser, which gives the first flop almost a full clock period to settle before the second samples it (three stages for very high clock rates or reliability targets). Two rules go with it:

  1. Never synchronise a multi-bit bus bit-by-bit. Each bit resolves independently, so the receiver can latch a combination that never existed. Cross a single-bit flag and use it to qualify a bus held stable (a handshake), Gray-code the value so only one bit changes at a time, or use a proper CDC FIFO.
  2. Synchronise once. Feeding one asynchronous signal into two synchronisers can give the two copies different answers in the same cycle.

Registers and counters

A register is n flip-flops sharing a clock; add a load enable and a mux and it holds or loads. A shift register wires each Q to the next D — serial-in/parallel-out, parallel-in/serial-out, bidirectional, or with taps and XOR feedback as a linear feedback shift register for pseudo-random sequences and CRCs.

Designing a modulo-6 synchronous counter

Count 0→1→2→3→4→5→0 with three D flip-flops Q2 Q1 Q0. States 6 and 7 are unreachable, so their next states are don't-cares.

Always finish by checking that the unused states cannot lock up. State 110 gives D2 = 1·1 + 1·0 = 1, D1 = 0 + 1·1 = 1, D0 = 1 → 111; state 111 gives D2 = 1·0 + 1·1 = 1, D1 = 0, D0 = 0 → 100, inside the legal ring. This counter is self-recovering: an illegal state caused by noise or power-up rejoins the sequence within two clocks. When that is not guaranteed, add a reset — which you should do anyway.

Chapter 7 — Finite state machines

Terminology

  • FSM — a sequential circuit given by a finite state set, a transition function and an output function.
  • Moore machine — outputs depend on the current state only.
  • Mealy machine — outputs depend on the current state and current inputs.
  • State assignment — the choice of bit pattern representing each state.
  • Equivalent states — states producing identical output for every input sequence, so mergeable.
Moore Mealy
Output is a function of state state and input
Output timing changes only after a clock edge; one cycle "late" responds in the same cycle
Output glitches none — a decode of registered state possible — input glitches pass through
State count usually more usually fewer or equal
Timing analysis clean input-to-output path crosses the module boundary

Practical guidance: use Moore for anything leaving the module (registered, glitch-free, easy to time), and Mealy inside a module when the one-cycle latency actually matters. A common hybrid is a Mealy machine with registered outputs — which is a Moore machine with extra steps, and often the cleanest of the three.

The flow is always: spec → state diagram → state table → state minimisation → state assignment → next-state and output equations → implementation.

Worked FSM: a "1011" sequence detector

Detect 1011 in a serial bit stream, with overlap (so 1011011 contains two occurrences). Moore version, states named by the longest prefix matched so far:

State Meaning on 0 on 1 Output
S0 nothing matched S0 S1 0
S1 1 S2 S1 0
S2 10 S0 S3 0
S3 101 S2 S4 0
S4 1011 — detected S2 S1 1

The non-obvious transitions are the failure ones, each found by asking what is the longest prefix of the pattern that is a suffix of what I have just seen? S3 on 0 leaves the stream ending 1010, whose longest such suffix is 10 → S2, not S0. S4 on 0 ends 10110 → also S2. S4 on 1 ends 10111, longest such suffix 1 → S1.

For the non-overlapping variant, S4 restarts from scratch: on 0 → S0, on 1 → S1. That single row is the entire difference, and it is worth being explicit about which one the spec wants.

The Mealy version needs only four states, because detection is signalled on the transition into the match rather than by a state representing it:

State on 0 (next / out) on 1 (next / out)
S0 S0 / 0 S1 / 0
S1 S2 / 0 S1 / 0
S2 S0 / 0 S3 / 0
S3 S2 / 0 S1 / 1

State minimisation

Two states are equivalent when, for every input, they give the same output and go to equivalent states. Two mechanical methods: partition refinement (split states into groups by output, then repeatedly split any group whose members transition, on the same input, into different groups, until nothing splits) and the implication chart (a triangular table of state pairs, crossing out pairs with different outputs and iterating on the implied pairs). Neither helps the 1011 detector — its five Moore states all differ — but both matter when a machine is written directly from an informal spec, where duplicate states are common.

State assignment: one-hot vs binary

Binary (encoded) One-hot
Flip-flops for N states ceil(log2 N) N
Next-state logic wider, deeper narrow — often one product term per transition
Output decode a decoder over the state bits a single wire
Best for ASIC, register-poor targets, large N FPGA, small-to-medium N, high f_max

FPGAs have flip-flops in abundance and are limited by logic depth, so one-hot usually wins there and is often what the tool picks regardless of how you wrote it. Gray-coded assignment suits a machine that mostly walks a linear sequence, minimising switching and hence power. Whatever the encoding, write a default branch returning to a safe state — a single upset bit in a one-hot register produces an all-zero or two-hot state that no legal transition covers.

Chapter 8 — Memory and programmable logic

Typical use caches, register files, FPGA block RAM main memory

The 6T SRAM cell is a bistable pair of inverters — the same feedback loop as an SR latch — with two pass transistors connecting it to the bit lines when its word line is selected. Being actively driven, it holds indefinitely while powered and reads without disturbance. The 1T1C DRAM cell holds charge that leaks, so reading dumps it onto the bit line where a sense amplifier compares it against a reference and rewrites the row. That destructive read plus refresh is the entire reason DRAM has a complicated protocol and SRAM does not. Both are volatile; neither survives power loss.

The non-volatile family

Type Programmed Erased Granularity Typical use
ROM (mask) at fabrication never — huge-volume fixed firmware
PROM once, by the user (fuses/antifuses) never — one-time configuration
EPROM electrically UV through a quartz window whole chip historical; development parts
EEPROM electrically electrically byte configuration and calibration stores
Flash (NOR) electrically electrically block erase; random reads code storage, execute-in-place
Flash (NAND) electrically electrically page write / block erase mass storage (SSD, SD, eMMC)

NOR gives random reads, so a CPU can fetch instructions directly; NAND gives density and is used where data is streamed. Both wear out as erase cycles degrade the oxide, which is why controllers do wear levelling.

Logic in a ROM, and the programmable arrays

A ROM with n address lines and m data lines is a full truth table for m functions of n variables: its decoder generates all 2^n minterms and the programmed array ORs the selected ones onto the outputs. No minimisation is needed or possible — you store the answer. The cost is exponential in input count (a 16-input function needs a 64K-word ROM), so ROM-based logic suits genuinely irregular functions: character generators, instruction decoders, microcode.

Between hard-wired gates and a full truth table sit the programmable arrays. A PLA has a programmable AND plane and a programmable OR plane — maximum flexibility, slower and more expensive. A PAL has a programmable AND plane and a fixed OR plane (a fixed number of product terms per output) — cheaper and faster; the classic 22V10 added an output macrocell with an optional flip-flop, which is what made PALs usable for state machines. A CPLD is an array of PAL-like blocks joined by global interconnect, with deterministic timing and instant-on behaviour — still the right answer for board glue logic and power sequencing.

FPGA architecture

An FPGA is a sea of configurable blocks plus programmable routing, its configuration held in SRAM and therefore loaded from external Flash at power-up:

  • LUT (look-up table) — a k-input SRAM, typically k = 4 or 6, holding 2^k configuration bits, implementing any function of k variables by storing its truth table. This is the MUX-as-arbitrary-function trick from Chapter 5, made programmable.
  • Flip-flop — one or two per logic cell, after the LUT with an optional bypass. Registers are effectively free, which is why one-hot encoding and deep pipelining suit FPGAs.
  • Carry chain — a dedicated fast path between adjacent cells, so adders and counters skip general routing delay.
  • Routing fabric — wire segments and programmable switch matrices. Routing, not logic, dominates delay, which is why timing closure is a place-and-route problem.
  • Block RAM — hard dual-ported SRAM blocks, usable as RAM, ROM or FIFO. DSP slices — hard multiply-accumulate units.
  • Clock management — PLLs/MMCMs plus dedicated low-skew global clock networks. Always use those networks for clocks; never route a clock through the general fabric.

Chapter 9 — HDL in practice (Verilog)

Terminology

  • HDL — hardware description language. It describes structure and behaviour, from which a synthesiser infers gates. It is not a program.
  • Synthesisable subset — the constructs a synthesis tool can map to hardware. Everything else is simulation-only.
  • RTL — the "registers, and the combinational logic between them" abstraction that synthesisable HDL describes.

The one thing to internalise: HDL is not sequential code. Every assign and every always block in a module is hardware that exists simultaneously and runs continuously. Statements inside an always block are evaluated in order during simulation, but what they describe is a network of gates that settles, not a sequence of steps executing over time. Reasoning "this line runs, then that line runs" produces code that simulates one way and synthesises another — the classic and most expensive bug in the field.

Module, ports, wire and reg

assign is a continuous assignment: the left side is recomputed whenever anything on the right changes. It drives a wire and describes combinational logic.

reg is Verilog's most misleadingly named keyword. It does not mean "flip-flop" — it means "a variable assigned inside a procedural block". A reg assigned in always @(*) is combinational logic; a reg assigned in always @(posedge clk) is a flip-flop. SystemVerilog's logic replaces both wire and reg in most contexts, which is one good reason to write -g2012 SystemVerilog where the tools allow it.

Blocking vs non-blocking

Use non-blocking (<=) in clocked blocks and blocking (=) in combinational blocks. Never mix the two in one block, and never drive one signal from two blocks.

Why it matters — the swap, and the accidental latch:

Non-blocking assignments schedule their updates and apply them together at the end of the time step — exactly what a bank of flip-flops does, every flop sampling the values that existed just before the edge. Blocking assignments take effect immediately, modelling a wire rather than a register. Get this backwards and simulation and synthesis disagree; the tools are not obliged to warn you. The latch rule is the same one from Chapter 6 seen from the language side: in a combinational block, assign every output on every path — including a default: in every case. SystemVerilog's always_comb makes the tool check this for you.

An FSM the canonical way

The 1011 Moore detector from Chapter 7, in three-block style: one clocked block for the state register, one combinational block for next-state logic, one for outputs.

Every transition in the table appears exactly once, default recovers from illegal states, and found is a pure decode of the state. For the Mealy form, drop S4 and write found = (state == S3) && din; — noting that found now depends on an input and can therefore glitch. Two-block style (merging blocks 2 and 3) is equally fine, as is one-block style with registered outputs; mixing styles inside one module is how people end up with a signal driven from two places.

A testbench

Driving stimulus on the falling edge and checking after the next falling edge keeps the testbench clear of the design's setup and hold windows — a habit worth forming early.

Synthesisable or not

Construct Synthesisable?
assign, always @(*), always @(posedge clk) yes
case, if/else, for with constant bounds (unrolled) yes
localparam, parameter, generate yes
initial blocks no for ASIC; FPGA tools accept them for register initial values
#10 delays, wait, fork/join no — simulation only
$display, $monitor, $finish, $dumpvars no — simulation only
real, dynamic arrays, classes, data-dependent while no

Common pitfall: a #5 delay inside a design module simulates beautifully and synthesises to nothing (or an error). Timing in real hardware comes from the clock and from cell delays, never from delay statements in your source.

A toolchain you can install today

Add nextpnr to place and route for the open-toolchain FPGA families (Lattice iCE40 and ECP5), or use the vendor tools — AMD/Xilinx Vivado, Intel/Altera Quartus Prime, Lattice Radiant — whose free editions cover the parts on most dev boards.

Trick: run verilator --lint-only -Wall on every file before simulating. It finds inferred latches, incomplete sensitivity lists and width mismatches in a second, which is faster than finding them in a waveform.

Where to go deeper

  • Computer architecture — the natural sequel. With an ALU, a register file and an FSM controller in hand, a single-cycle then pipelined RISC-V or MIPS datapath is a two-week project.
  • CMOS VLSI — the layer below this post: transistor sizing, logical effort, layout, and where the timing numbers you were handed come from.
  • Static timing analysis and timing closure — constraints, clock trees, multi-corner analysis, false and multi-cycle paths. This is most of the day-to-day work in real FPGA and ASIC flows.
  • Clock domain crossing and asynchronous design — handshakes, async FIFOs, reset synchronisation. The failures are intermittent and expensive; read the literature properly.
  • SystemVerilog and verification — logic, always_ff/always_comb, interfaces, assertions, constrained-random stimulus, UVM.
  • Get a board. An iCE40 or ECP5 runs entirely on the open toolchain; an Artix or Cyclone gets you the vendor flow. Nothing here is properly learned until a blinking LED has been debugged with a logic analyser.
