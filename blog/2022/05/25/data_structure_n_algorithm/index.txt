<h2 id="Josephus-Problem"><a href="#Josephus-Problem" class="headerlink" title="Josephus Problem"></a>Josephus Problem</h2>
<p>People are standing in a circle waiting to be executed.<br>
Counting begins at a specified point in the circle and<br>
proceeds around the circle in a specified direction. After<br>
a specified number of people are skipped, the next<br>
person is executed. The procedure is repeated with the<br>
remaining people, starting with the next person, going in<br>
the same direction and skipping the same number of<br>
people, until only one person remains, and is freed</p>
<p>The problem — given the number of people (n), starting<br>
point, direction, and number to be skipped (k) — is to<br>
choose the position in the initial circle to avoid execution.<br>
(guessing who is the survivor)</p>

<h2 id="Introduction-of-Hashing"><a href="#Introduction-of-Hashing" class="headerlink" title="Introduction of Hashing"></a>Introduction of Hashing</h2>
<p>Hashing is generally <strong>[ Indexing ]</strong>.</p>
<p>If you have learnt what <strong>[ index ]</strong> is, you may understand it as <strong>positioning</strong> or <strong>classifying</strong> objects with duplicated meaning for a smaller size of data and better searching.</p>
<h3 id="Steps-for-Indexing"><a href="#Steps-for-Indexing" class="headerlink" title="Steps for Indexing"></a>Steps for Indexing</h3>
<ol>
<li>Define an array with a specific purpose.</li>
<li>Define meaning for each index in the array.</li>
<li>Classify the input and determine the size of the array.</li>
<li>Map the input to the array.</li>
</ol>
<h3 id="Example-of-Indexing-Minimal-Perfect-Hashing"><a href="#Example-of-Indexing-Minimal-Perfect-Hashing" class="headerlink" title="Example of Indexing (Minimal Perfect Hashing)"></a>Example of Indexing (Minimal Perfect Hashing)</h3>
<p>Given A string [foo] = &quot;abacbdef&quot;.<br>
<strong>Precondition:</strong> there will only be alphabets inside the string.<br>
If you want to find how many 'a' occured inside the string, you may use Indexing.</p>
<ol>
<li>Define an array for storing the occurrence of letters.</li>
<li>Each index represents an alphebet.</li>
<li>There are a total of 26 alphabets as potential input, so the size of array will be 26.</li>
<li>Similar to the ASCII table, we can take index [0] representing the occurrence of 'a', index [1] representing the occurrence of 'b', and so on...</li>
<li>Loop over the string and map the character to corresponding index.</li>
</ol>
<p>However, there are still some differences between Hashing and Indexing.<br>
In Hashing, we convert ASCII char to key directly with <code>array[i] - 'a'</code> so that 'a' = 0, 'b' = 1, and so on...<br>
which allows us to map the data easier and faster.</p>
<hr>
<h2 id="Hash-function"><a href="#Hash-function" class="headerlink" title="Hash function"></a>Hash function</h2>
<p>A function <strong>f(k)</strong> is known as defined with specific formula,<br>
it can be either <strong>One-to-one</strong>, or <strong>Many-to-one</strong>,<br>
Under this property,<br>
it can convert a large variable-sized amount of data into a small datum by transforming data into keys.</p>
<p>A <strong>Hash table</strong> arr[ ] is an array that will be created to hold the keys after conversion.</p>
<p>A <strong>Hash value</strong> is usually an integer that may serve as an index to an array.</p>

<h2 id="Hash-Collision"><a href="#Hash-Collision" class="headerlink" title="Hash Collision"></a>Hash Collision</h2>
<p>Collision occurs when <strong>two distinct data own the same hash value</strong>.<br>
Collisions are usually unavoidable when a large set of data is mapped into small datum.<br>
It will increase the average cost of lookup operations.</p>
<p>Solutions to Hash Collision</p>
<ul>
<li>Open Addressing</li>
<li>Closed Addressing</li>
</ul>
<p><strong>Load factor</strong> represents the length of data in each index,<br>
larger load factor brings lower performance</p>
<hr>
<h3 id="Open-Addressing"><a href="#Open-Addressing" class="headerlink" title="Open Addressing"></a><strong>Open Addressing</strong></h3>
<p>Place the key in other free slot when collisions occured.</p>
<p>An index only maps to 1 key.<br>
Theoretical <strong>max load factor</strong> = 1</p>
<p>Advantages</p>
<ul>
<li>No size overhead apart from the hash table array</li>
<li>Better memory locality and cache performance. Memory allocation is laid out linearly</li>
<li>Performs better when the number of keys is known in advance and the churn is low.</li>
</ul>
<p>Example of Open Addressing:</p>
<ul>
<li>Linear Probing</li>
<li>Quadratic Probing</li>
<li>Double Hashing</li>
<li>Hopscotch hashing</li>
<li>Robin Hood hashing</li>
<li>Cuckoo hashing</li>
<li>2-Choice hashing</li>
</ul>

<h3 id="Closed-Addressing"><a href="#Closed-Addressing" class="headerlink" title="Closed Addressing"></a><strong>Closed Addressing</strong></h3>
<p>Place the key in the same slot even when collisions occured.</p>
<p>An index can map to multiple keys.<br>
Theoretical <strong>max load factor</strong> = depends</p>
<p>To achieve placing multiple keys in same slot</p>
<ul>
<li>Separate chaining using linked lists</li>
<li>Separate chaining using dynamic arrays</li>
<li>Using self-balancing binary search trees</li>
</ul>
<p>Advantages</p>
<ul>
<li>Easier removal</li>
<li>Assign quicker with high load factor</li>
<li>No issues with Clustering</li>
